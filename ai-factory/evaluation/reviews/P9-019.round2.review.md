**BLOCKING**

1. `sdk/typescript/src/capability-manifest.ts`, added `isReferenceSyntax`: `const scheme = asciiLowercase(value.slice(0, separator));`

   This makes the TS `keyReference` format stricter than the Go oracle. `agent/capabilities/identity/identity.go` lowercases URI schemes with Go `strings.ToLower` before applying `schemePattern`, so Unicode case mappings such as `K://ref` normalize to `k://ref` and are accepted by the agent. The TS implementation only ASCII-lowercases, leaving `K` unchanged and rejecting it. That violates the contract’s manifest≡agent requirement for `keyReference`. Add lock-in vectors for Unicode-folding scheme cases and make TS match Go’s lowercasing behavior or harden the agent first in a separate change.

**NOTES**

- The TS identity conformance test does not actually exercise duplicate raw JSON keys: duplicate-key vectors are stored as JSON strings and passed directly to `validateIdentity`, so they reject as a top-level string rather than as duplicate-key objects. The Go conformance harness does unwrap those raw strings, so this is not my blocker, but it is weak TS-side coverage.
