BLOCKING

- `os/x86_64/verity.mjs` `buildFormatArgs`: the modeled `veritysetup format` command is not runnable/correct. It uses `--type 1` instead of the verity format option and passes the salt policy string (`deterministic-root-image-sha256-slot-salt:root-a`) as `--salt`, which should be an actual hex salt or modeled separately as unresolved policy. This fails the contract’s “models `veritysetup format`” requirement even though the test codifies the bad args.

- `os/x86_64/verity.mjs` `buildFormatArgs`: the format command ignores `rootImagePath` and `hashTreePath` and instead uses runtime `/dev/disk/by-partlabel/...` paths. The upstream offline build step is supposed to format the produced root image and hash tree artifact; these device paths are not build inputs and the planned `HashTreePath` is effectively unused.

- `os/x86_64/verity.mjs` `buildBoundCmdline`: the UKI cmdline uses invented/unsupported-looking tokens (`verity=1`, `verity.data_device=...`, `verity.hash_device=...`) while leaving `root=LABEL=...` pointed at the raw root. As written, the plan does not demonstrate that the boot path will actually mount the dm-verity mapping rather than the unverified root device, so it does not satisfy “so the kernel verifies the root at boot.”

- `os/x86_64/verity.mjs` `snapshotPlainObject`: transparent `Proxy` inputs are accepted if their traps return ordinary descriptors. AGENTS.md explicitly requires trust-boundary validators to reject proxies/exotic objects; this new `planVerity(input?: unknown)` boundary only tests accessors/symbol iterator and misses that class.

NOTES

- No existing tests appear weakened or skipped in the diff, but the new tests overfit the current implementation and assert the invalid verity arguments instead of validating real `veritysetup`/boot semantics.

- `produced-plan-inputs` is mounted read-write in this plan, unlike the neighboring UKI/image-layout planners where generated plan inputs are read-only. If a future runner consumes this mount model, that is unnecessary writable surface.

- The helper code is largely copied from P1-012/P1-014 instead of shared/reused as the contract requested. Not the main blocker, but it increases drift risk in security-sensitive validators.
