BLOCKING

1. `packages/catalog/src/lockfile-policy.ts` around `collectDependencyDeclarations`: dependency containers are only validated when the value is an object. If a lockfile has `dependencies: ["jsr:@scope/pkg@^1.0.0"]` or any array-style nested dependency declaration, the code just recurses over strings and never enforces exact version or a resolved integrity-bearing entry. That violates the round-2 requirement to walk every dependency at any depth and is especially relevant to JSR-style lock data. Non-object dependency containers should be rejected or explicitly normalized into declarations.

2. `packages/catalog/src/lockfile-policy.ts` around `inspectLifecyclePolicy`: lifecycle script names are only denied inside `scripts` / `lifecycle` / `lifecycleScripts` objects. A package entry with a direct `preinstall`, `install`, `postinstall`, or `prepare` field is accepted if the value is not a URL. The contract says any lifecycle script is denied by default, so direct lifecycle-script fields must also fail closed.
