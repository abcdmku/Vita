**BLOCKING**

- `sdk/typescript/src/backup-model.ts` only rejects inline recovery-key material when it appears under specific field names like `keyMaterial`, `seedPhrase`, or `privateKey`. The allowed reference fields themselves are only checked as non-empty strings. That means `validateRecoveryKeyEnrollment` accepts an enrollment where `recoveryKeyRef.handle` or `recoveryKeyRef.id` contains literal key material, e.g. a PEM/private key/seed phrase string. This violates the contract’s “Secrets-as-references only” requirement and spec §13.1. Existing repo validators for reference-bearing fields use reference-syntax and embedded-material checks; this model needs the same kind of fail-closed validation for recovery key refs, and likely other `*Ref` fields such as `credentialRef`.

- `sdk/typescript/test/backup-model.test.ts` does not cover the bypass above. The inline-secret test only adds forbidden field names, so it passes even though literal key material can be placed in the documented reference value. Add regression coverage for literal key material inside `recoveryKeyRef.handle`/`id` and other secret reference fields.
