## Per-axis

### 1. Hardening composition (decisive) — TIE (both COMPLETE)
Diffed each candidate's property block against `os/x86_64/ts-overlay/.../vita-ts.service` line-for-line.
**Both** emit the full profile: `DynamicUser=yes`, empty `CapabilityBoundingSet=` + `AmbientCapabilities=`,
`NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome/PrivateTmp/PrivateDevices/ProtectControlGroups/
ProtectKernel{Tunables,Modules,Logs}/ProtectClock/ProtectHostname/ProtectProc=invisible`,
`RestrictSUIDSGID/RestrictNamespaces/RestrictRealtime`, `RestrictAddressFamilies=AF_UNIX`,
`LockPersonality`, `SystemCallArchitectures=native`, the **three** `SystemCallFilter` lines
(`@system-service`; `~@privileged @resources @mount @swap @reboot @raw-io @cpu-emulation @obsolete`;
`pkey_alloc pkey_free pkey_mprotect`), `UMask=0077`, `RuntimeDirectory`+mode, and the cgroup caps
`MemoryMax`(ramMiB×1MiB), `CPUQuota`(cores×100%), `TasksMax`. No cap-drop / NoNewPrivileges / seccomp is
missing in either. **No BLOCKING issue on the decisive axis.** Tie.

### 2. Manifest-only composition / injection (ADR-0009 cond. 5) — slight B
Both compose ONLY from the re-validated manifest + the static template; no raw runtime text reaches a
property, `ExecStart`, or a shell. Both pass `--property=Name=Value` as single argv elements via
`exec.CommandContext` (no shell); control chars are blocked by `validCapsuleID`/`controlCharacter`.
B is marginally more defensive:
- **Unit naming.** B = `vita-capsule-<slug>-<sha256(id)[:4]>.service` (collision-resistant).
  A = `capsuleUnitToken` collapses non-alnum to `-` (lossy → theoretical cross-capsule unit-name
  collision). Not exploitable (one registry entry per id), but B's is the better design.
- **Entrypoint.** B hard-pins to exactly `"main.ts"` (`TypeScriptExecution.Validate`). A allows any
  pattern-validated relative path (`^[A-Za-z0-9._/-]+$` + `path.Clean` + no `..`/leading-`/`). A is safe
  but a wider surface.
- **Resource limits.** B bounds upper limits (cpuCores≤64, ramMiB/storageMiB/tasksMax caps). A only checks
  positivity — a hostile manifest could request an absurd `MemoryMax`. First-party baked manifest this
  slice, so not a live vuln, but B is more robust.

### 3. Launch mechanism — slight B
Both chose `systemd-run` (explicitly acceptable per ADR-0009 + the contract for the first slice). Both
confirm start via `systemctl is-active --quiet` and capture the DynamicUser uid. B reads `systemctl show
--property=UID` first with a `/proc/<MainPID>/status` fallback; A reads `/proc/<MainPID>/status` only.
B also inserts the `--` separator before the command argv (`execute.go` launcher); A omits it
(`args = append(args, spec.ExecStart...)`). A's first ExecStart token is the absolute `/usr/lib/vita/deno`
(not `-`-prefixed), so it is **not** misparsed today — not a vulnerability — but B's `--` is the correct
defensive idiom. Both pass the workload args exec-form (no injection).

### 4. Fail-closed + transactional undo — TIE (both correct)
Both: unknown/invalid/disabled/wrong-version capsule → REJECTED, **no unit started** (proven by tests:
`launcher.starts == 0`). Both mirror `services.go` validate→act→record-undo. Undo stops + unlinks
(`stop` + `reset-failed`). A additionally proves cleanup on a start-failure-after-launch
(`TestExecuteStartFailureCleansUpTransientUnitBeforeReturningError`); B performs the equivalent cleanup
inside the launcher (`stopAndUnlinkTransientUnit` on is-active/uid failure). Both fail closed correctly.

### 5. ts-service only / no fetch / no OCI (ADR-0009 cond. 1) — TIE
Both gate `packageClass == "ts-service"` and reject `oci-service` (tested). Both run the pinned
`/usr/lib/vita/deno` against the BAKED test capsule; no artifact fetch, no OCI/WASM. Honored.

### 6. Test quality + markers — B (broader coverage)
- **Package tests:** A is richer (4 reject sub-cases incl. unsafe-entrypoint + start-failure cleanup).
  B has 3 (unknown, invalid-manifest/oci, wrong-request-type) — fewer because B hard-pins entrypoint so
  the unsafe-path case is structurally impossible.
- **Transport tests:** **B updated `server_test.go`** so `capsule.execute` is exercised through the real
  `/apply` + `/operations` + `/state` surface end-to-end (correct decoder/request type, commit ordering).
  **A did NOT** — A's transport package has ZERO coverage of the new capability (its transport tests use a
  hand-built mock registry that never registers execute, so they pass unchanged). For a NEW transport-
  routed capability, this integration coverage is the higher-value test. Net edge to B.
- **Markers:** Both emit `VITA-CAPSULE-EXECUTED: id=… unit=… uid=… health=OK status=OK`,
  `VITA-CAPSULE-EXECUTE-REJECT: reason=… status=OK`, and `VITA-CAPSULE-EXECUTE-ERROR: status=FAILSAFE` on
  every transport-failure path; all prior markers kept. B's forced-invalid uses `local.missing.capsule`
  (well-formed but unregistered → exercises the registry **fail-closed** path — the actual security
  property). A's uses `"not an id"` (rejected at input validation, before the registry check — a weaker
  representation of fail-closed). Edge B on host-verify realism.

## VERDICT: approve (B = `task/P1-044B`)

No BLOCKING issue: the full hardening profile is present (no missing cap-drop / NoNewPrivileges /
seccomp), and there is no runtime-string→unit-property injection path. Build/vet/acceptance/full-suite all
green. Approve for merge **subject to the standing R3 gate**: orchestrator host-verify on Borg51 — the
baked capsule actually runs as a hardened transient unit on the serial (`VITA-CAPSULE-EXECUTED … health=OK`,
`systemctl` shows the unit + a DynamicUser uid), the forced-invalid emits `VITA-CAPSULE-EXECUTE-REJECT`,
agentd up, and **cgroup limit ENFORCEMENT re-confirmed on the real node boot** (ADR-0009 condition 2 —
recorded-only on WSL is insufficient).

### PORT from A (loser) — non-blocking, fold in post-merge or as a follow-up
1. **`TestExecuteStartFailureCleansUpTransientUnitBeforeReturningError`** — A's explicit test that a
   start failure *after* a partial launch triggers stop/cleanup before returning. Worth adding to B's
   suite to lock that path.
2. **`--allow-read=<capsuleDir>` on ExecStart** — A scopes the Deno workload's read grant to its own
   capsule dir. B passes no `--allow-*` (relies on default-deny). Both run the trivial capsule fine
   (module load is not `--allow-read`-gated), but A's explicit scoped grant is the right shape once a
   `ts-service` needs to read its own assets — adopt when the capsule actually reads files.
