## Verification results

### 1. Read-only + no new privilege — PASS
- `pds-read.ts` imports only `agent-client`, `capability-manifest`, `safe-normalize`,
  `unix-socket-transport`. No `Deno.*`, no `/var`, no `readFile`/`openSync`, no `Deno.permissions`,
  no `fetch`. (`os/x86_64/ts-overlay/usr/lib/vita/ts/vita/pds-read.ts:1-7`)
- Uses the **read-only** transport `createDenoUnixSocketAgentTransport`, which hard-rejects any
  non-GET method (`unix-socket-transport.ts:28-30` — `throw "on-device agent transport is
  read-only"`). The apply transport is NOT used by pds-read; `main.ts` keeps it only for apply.
- `getState` issues `GET /read/pds.sync-state` over AF_UNIX (`agent-client.ts:328-333`,
  `unix-socket-transport.ts:85` `Deno.connect({ transport: "unix" })`). No write/apply call.
- **No agentd change**: diff touches only `os/`. The `/read/pds.sync-state` route already exists
  (`agent/transport/server.go:356-357`, request registered at `server.go:313`) and the capability
  is registered in `agent/cmd/agentd/main.go:58`. The runtime gains zero new authority.

### 2. Safe untrusted-response parsing — PASS
- Response is funneled through `safeNormalize` (`pds-read.ts:68`) **and** the PDS validator
  (`PDS_SYNC_STATE_VALIDATOR({ desired: state })`, `pds-read.ts:127`). Note: defense-in-depth —
  `agent-client.getState` already `safeNormalize`s + JSON-parses inside `#request`
  (`agent-client.ts:432`, `readResponseObject`), so the second `safeNormalize` in the parser is
  redundant-but-harmless and also protects the `parsePdsSyncStateReadResponse` direct-call path used
  by the hostile-shape tests.
- **Accessor rejection verified at the source**: `safeNormalize.normalizeObject` reads via
  `Object.getOwnPropertyDescriptor` + `isDataDescriptor` (rejects descriptors lacking a `value`),
  so a getter property is rejected and **never invoked** — the test asserting `getterReads === 0`
  is genuinely satisfied, not coincidentally.
- **Cyclic rejection verified**: `safeNormalize` tracks `ancestors` and returns
  `"Cycles are not accepted."` Confirmed by the passing cyclic test.
- Every failure path returns `rejectRead(...)` (a safe `{ ok:false }`); the only `throw` site is the
  transport error inside `client.getState`, which is caught by the `try/catch` in
  `readPdsSyncStateSummary` (`pds-read.ts:43-50`) → `rejectRead`. The oneshot never sees an
  exception escape.

### 3. Marker correctness — PASS
- `formatPdsSyncStateReadMarker` prints `VITA-PDS: repo=<did|none> cursor=<n> head=<cid|none>
  status=OK` from the real payload, `VITA-PDS-ERROR: status=FAILSAFE` on `ok:false`
  (`pds-read.ts:118-130`). `null` repo/head render as `none`.
- **Ordering**: emitted at `main.ts:282` via `emitPdsReadMarker`, AFTER `readAgentStateSummary` →
  `emitApplyMarkers` (which emits `VITA-APPLY`). Connect-failure branch emits the FAILSAFE PDS
  marker before returning (`main.ts:269`). Consistent (PDS last in both paths).
- **Empty/uninitialized PDS → clean `none`/0**: agentd returns `ReadResponse{Exists:false}` →
  wire `{"exists":false,"state":{"repo":"","cursor":0,"repoHead":""},"raw":null}`
  (`pdssync.go:200-202`, `ReadResponse` at `pdssync.go:135-141`). The parser short-circuits on
  `exists===false` → `EMPTY_PDS_STATE` (repo=none/cursor=0/head=none) WITHOUT validating `state`
  (`pds-read.ts:90-101`). This is correct AND necessary: `repo:""` would otherwise fail the
  `didPlcOrWeb` validator. Wire shape matches the test exactly.
- All prior markers retained: TS, EVAL, EVAL-REJECT, PREVIEW, PREVIEW-NOOP, PREVIEW-ERROR, EXPLAIN,
  CONNECT, STATE, APPLY (+ their *-ERROR variants) — verified present in `main.ts`.

## NOTES (non-blocking)

1. **Redundant `safeNormalize`.** `client.getState` already normalizes the body inside
   `agent-client.#request`; `parsePdsSyncStateReadResponse` normalizes again. Harmless and arguably
   good (it hardens the exported `parsePdsSyncStateReadResponse` for the direct-call test path), but
   worth a one-line comment so a future reader doesn't "optimize" it away.
2. **Strict top-level allowlist.** `expectFields` rejects any top-level field beyond
   `{exists,state,raw}`. If a future agentd version adds a field to `ReadResponse`, the on-device
   read fails-closed to `VITA-PDS-ERROR: FAILSAFE` until pds-read is updated. Acceptable (and
   safe-by-default) for a read marker, but note the coupling for the S5/federation follow-ups.
3. **`raw` is parsed but unused.** The base64 `raw` blob is validated to `string|null` and then
   ignored. Fine for now (the canonical fields come from `state`); flagging in case S5's write path
   wants to round-trip it.
4. **Boot host-verify still owed (orchestrator).** Per the contract DoD, confirm
   `VITA-PDS: ... status=OK` on the Borg51 serial after `VITA-APPLY`, plain + verity. This review
   covers code + unit behavior only.
