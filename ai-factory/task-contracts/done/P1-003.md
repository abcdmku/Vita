## Objective
Define the typed **catalog entry** that wraps a published package (spec §9.2 signing/SBOM/EOS, §9.3
trust tiers). A `CatalogEntry` carries: a reference to/embedded `PackageContract` (reuse P1-001),
**signing publisher** identity, `signatures` (non-empty array of references — not embedded keys),
`sbom` reference + vulnerability status, `endOfSupport`, immutable `digest`, and **trust tier**
(`verified | community`, spec §9.3 — community runs at a lower tier). Provide
`validateCatalogEntry(value: unknown)` — fail-closed + intrinsic-safe (the **full checklist**: reject
partial/cyclic/method-shadowed/hostile-iterator/throwing-proxy/exotic-prototype objects; wrap so any
throw → rejection), enforcing §13.1 secrets-as-references and ≥1 signature (like the capsule
validator). Reuse `validatePackageContract` for the embedded contract.

## User value
The catalog entry is what the controller/catalog lists and trusts before install (spec §9, §4.1
signed application catalog). Precise typing + fail-closed validation underpins supply-chain safety.

## Non-goals
- No signature verification/crypto, no registry/network, no install — types + structural validation.

## Dependencies
P1-001 (`PackageContract`, `validatePackageContract`).

## Acceptance tests
`acceptance_command`. Must prove:
1. A complete valid `verified` entry validates; trust tier round-trips.
2. Missing signatures (empty), embedded secret in a ref field, missing required field, or unknown
   trust tier → rejected with precise paths.
3. Fail-closed: the full adversarial set (incl. exotic Date/Map/Proxy) ⇒ reject, never throws.

## Performance & security constraints
Pure/deterministic, no I/O. Secrets-as-references (§13.1). Fail-closed + intrinsic-safe (full set).
