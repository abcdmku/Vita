## Objective
Per **architecture/adr/0013-desktop-hydration.md** (READ it first). Build: Hydrate the Settings/Appearance screen (screens/settings.ts). Depends ONLY on `@vita/desktop-sdk` types;
NO framework, NO vdom, NO remote/heavy deps (Vita forbids them) — vanilla TS + the tiny reactive core only.
- ADR-0013: \`ui_kits/desktop/screens/settings.ts\` (manifest on the Settings view-model: setTheme/setAccent/setLayout verbs; segment + switch class toggles; accent as a CSS custom property on the root) + \`Settings.html\` anchors. Test (DOM stub) covering a theme change reflected to the root class + accent var.

## User value
The hydration runtime that turns the static flagship HTML into a LIVE, functional desktop driving the EXISTING headless view-models.

## Non-goals
- NO framework/vdom/remote dep. NO platform internals. NO CEF (the engine renders the HTML; this is in-surface binding).
  Do NOT change view-model logic or the design's visuals/CSS classes (only ADD `data-vita-*` anchors where a slice says so).

## Acceptance
`acceptance_command` passes. DOM-dependent code is tested against a MINIMAL hand-rolled DOM stub (NO jsdom/linkedom — heavy
dep) implementing only the methods used (querySelectorAll, closest, addEventListener, classList.toggle, textContent,
setAttribute, dataset, cloneNode, append/removeChild). Deterministic; typecheck clean.

## Security/constraints
- `@vita/desktop-sdk` types only; fail-closed (degraded host, per-screen isolation, inert-on-failure); plain-JSON across the
  bridge. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- The files named in ADR-0013 §6 for this slice + tests under `sdk/typescript/test/ui-kits/`; deterministic; typecheck clean. R1.
