## Objective
The **dm-verity PLAN** for read-only verified roots (spec §11; Phase 1 reliability/integrity): for each
A/B root slot (P1-014), `planVerity()` models the verity hash-tree creation (`veritysetup format`, an
upstream privileged step) and the resulting **root hash**, then binds that root hash into the slot's UKI
cmdline (`roothash=<…>` / `verity` options) so the kernel verifies the root at boot. Deterministic +
offline plan (like P1-012/P1-014), NOT a real `veritysetup` run.
- `os/x86_64/verity.conf`: pinned verity params (hash algo sha256, data/hash block sizes, salt policy),
  per-slot data/hash device mapping. No eval-time network.
- `os/x86_64/verity.mjs`: `planVerity()` (pure) returning the normalized byte-deterministic verity plan;
  the per-slot **root hash is an UNRESOLVED external precondition** (it depends on the real root image
  content, produced upstream — unresolved blocks the bind). Reuse P1-012/P1-014's external-precondition,
  canonical-path, and sentinel-digest-rejection helpers. The plan asserts each slot's root hash is bound
  into THAT slot's UKI cmdline (coherent with P1-014's slot-specific UKIs).

## User value
dm-verity is the integrity guarantee for the immutable root (spec §11) — a tampered root fails
verification at boot. This plan pins the verity config + the root-hash→boot binding the real build fills in.
