## Objective
Implement `explainPlan(plan: CanonicalPlan): string` — a deterministic, human-readable summary of a
full canonical plan so a user can understand exactly what a configuration declares before applying
it (spec §3.3, §8.4 "the plan is inspectable before application"; complements the P0-004 *diff*,
which compares two plans — this *explains* one). The summary should cover identity, storage, apps
(id + key config), and backups in a stable, readable layout. Pure, no I/O.

## User value
"Understand exactly what data, network, and compute an app receives" is part of the definition of
success (spec §28.5). A clear plan explanation is how the UI/CLI renders that.

## Non-goals
- No apply/transaction; no Go-agent; no policy evaluation.
- Not a diff (that's P0-004) — this summarizes a single plan.

## Dependencies
P0-001 (`CanonicalPlan`).

## Acceptance tests
`acceptance_command`. `sdk/typescript/test/explain.test.ts` must prove:
1. A representative plan produces a stable, non-empty explanation containing its apps, storage, and
   backups.
2. The output is deterministic (same plan → identical string).
3. An empty/minimal plan explains without throwing.

## Performance & security constraints
Pure/deterministic, no I/O. Node built-ins only.
