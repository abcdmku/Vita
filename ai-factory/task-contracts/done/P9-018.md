## Objective
Migrate the `accounts` capability (op `accounts.config` — verify the exact `Name`) end-to-end. The REAL
entrypoint `transport.DecodeJSONRequest[accounts.ApplyRequest]`+`Validate()` is the ORACLE. Read
`agent/capabilities/accounts/accounts.go` and match `normalizeAccount`/`normalizeConfig`/`validAccountName`/
`validGroupName`/`isPrivilegedGroup`/`isAllowedShell` EXACTLY (AGENTS.md manifest≡agent + the 8 traps). This
is the most-new-primitive cap.
- **`schema/capabilities/accounts.json` = the full request** `{ desired: { object: { accounts: array of object
  { name: string posixAccountName; uid: integer [minManagedUID, maxManagedUID]; primaryGroup: string groupName
  +notPrivileged; groups: array of (groupName +notPrivileged) with DEDUP; shell: enum(allowlist); enabled:
  boolean REQUIRED } } } }`.
- **FORMATS / OPTIONS (structured; match the agent EXACTLY; ground-truth cross-check vs accounts.go):**
  - **`posixAccountName`** = `accountNamePattern` `^[a-z_][a-z0-9_-]{0,31}$`, and **`groupName`** =
    `groupNamePattern` (IDENTICAL pattern). VERIFY whether P9-012's existing `posixUsername`/`groupName`
    formats match these EXACTLY (manifest≡agent — P9-012 built them WITHOUT a cap consumer, so they may
    DIVERGE; if so, fix the format to match accounts.go, ground-truth cross-checked). Include any data:/PEM/
    longBase64 screen ONLY if `validAccountName`/`validGroupName` actually applies it (the pattern already
    excludes `:`,uppercase,>32 — verify before adding, else STRICTER).
  - **integer `uid`** with `minimum: minManagedUID` (1000) and `maximum: maxManagedUID` (READ the exact const).
    Required (absent ⇒ Go zero ⇒ `< 1000` ⇒ reject — matches the agent's non-pointer int).
    **ROUND-2 BLOCKING (probe, GROUND-TRUTH confirmed): the integer validator is LOOSER than the agent on
    integer-valued FLOAT/EXPONENT tokens.** The agent decodes uid into a Go `int` via `json.Decoder.Decode`,
    which REJECTS `1000.0`, `1e3`, `1.0e3`, `1000.00000` (verified: Go err on each; only the bare integer
    literal `1000` decodes). The manifest's integer validator (Go `UseNumber`→`isSafeInteger` Trunc==value; TS
    `scanRawJsonNumber` permits `.`/`e`/`E` then `Number.isSafeInteger`) ACCEPTS `1000.0`/`1e3` ⇒ manifest
    LOOSER ⇒ manifest≢agent. **FIX (the shared INTEGER primitive, BOTH planes):** an integer field must reject
    any JSON number token whose raw text contains `.`, `e`, or `E` (require a true integer literal
    `-?[0-9]+`), matching Go's int-decode, BEFORE the range/safe-integer check. (This is the FIRST integer
    field across all migrated caps — the fix corrects the primitive for storage.quotaGiB / network.port too.)
    Add lock-in conformance vectors uid `1000.0`, `1e3`, `1.0e3`, `60000.0` ⇒ REJECT (rejectCode
    `desired/accounts/0/uid`) so the dual-validator harness enforces it.
  - **`notInEnum`** (NEW dialect primitive — value blocklist): reject if the string is in
    `privilegedGroups` {`admin`,`root`,`sudo`,`wheel`}; apply to `primaryGroup` AND each `groups` item. (enum
    is allowlist-only; this is the complement.)
  - **`dedupItems`** (NEW — normalize keep-first, NOT reject): `groups` silently DEDUPES duplicates
    (seenGroups keep-first) — do NOT model as `uniqueItems` (which REJECTS ⇒ STRICTER, AGENTS trap 3).
  - **`shell`** = enum of the allowlist {`/bin/bash`,`/bin/sh`,`/usr/bin/bash`,`/usr/bin/zsh`,
    `/usr/sbin/nologin`,`/bin/false`} (exact set from `allowedShells`).
  - **`enabled`** = boolean, REQUIRED via the `*bool` presence rule (nil/absent ⇒ reject; AGENTS absent≠zero).
  - **`groups`** array: non-nil required (absent/`null` ⇒ reject; empty `[]` ⇒ accept — match the agent).
  - **`accounts` whole-list uniqueness**: READ `normalizeConfig` — if it dedups/rejects by `name` AND `uid`
    as TWO independent keys, add **multi-key `uniqueBy: ["name"]` + `uniqueBy: ["uid"]`** (extend P9-013's
    single-key uniqueBy to multiple independent single-field keys). Match the agent's exact behavior
    (reject-vs-dedup, which key).
- **Conformance ≡ agent** `schema/capabilities/conformance/accounts.json` (≥ 28 full-request vectors) via BOTH
  the manifest AND `DecodeJSONRequest[accounts.ApplyRequest]`+`Validate()`. Cover: valid account, bad name
  (uppercase/too-long/leading-digit), uid below 1000 / above max / boundary, privileged primaryGroup AND
  privileged group member (reject), duplicate group (DEDUP→accept, normalized), duplicate name across accounts
  (per the agent), duplicate uid, non-allowlisted shell, absent enabled (reject), groups absent/null/empty,
  dup JSON key, unknown field. The REAL entrypoint is the oracle.
- **Register** accounts (regenerate; orchestrator updates the registry test) + evaluator coverage. Agent UNCHANGED.
