## Objective
Define the typed **simulation profiles** a package/capsule must pass before verified publication
(spec §13 capsule.simulation, §20.1 CI lanes, FR-021). Provide:
- A `SimulationProfile` discriminated union for the required profiles: `low-memory`, `offline`,
  `no-accelerator`, `architecture-migration` (x86↔arm64), `power-loss`, `network-partition` — each
  with its typed parameters (e.g. low-memory `memoryMiB`, migration `from`/`to` arch) and the
  expected health checks / failure tests to assert.
- `REQUIRED_PROFILES` — the minimum set every verified package must declare (spec §13.1, §6 exit
  gates), and `coversRequiredProfiles(declared): { ok; missing }`.
- `validateSimulationProfiles(value: unknown): { ok; profiles } | { ok:false; errors }` — fail-closed
  + intrinsic-safe (the full checklist: reject partial/cyclic/method-shadowed/hostile-iterator/
  throwing-proxy; wrap so any throw → rejection; never call methods on untrusted input).

## User value
"Required simulations run automatically before verified package publication" is a Phase-6 exit gate
(spec §21). Typed profiles make that gate machine-checkable and let capsules declare their coverage.

## Non-goals
- No simulation *runner*/execution, no QEMU — types + required-set logic + structural validation only.

## Dependencies
None (the package contract / capsule will reference these profile ids).

## Acceptance tests
`acceptance_command`. `simulation/profiles/test/profiles.test.ts` must prove:
1. A valid profile set validates; `coversRequiredProfiles` reports missing required profiles.
2. An unknown profile kind / partial profile is rejected with a precise path.
3. Fail-closed: partial/cyclic/method-shadowed/hostile-iterator/throwing-proxy input ⇒ reject, never
   throws (regression test for each).

## Performance & security constraints
Pure/deterministic, no I/O. Fail-closed + intrinsic-safe (full checklist).

## Hardware profiles
Models the no-accelerator / low-memory / offline / migration profiles themselves.

## Allowed tools & network
Offline. Node built-ins only. No new deps.
