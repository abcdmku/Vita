## Objective
Now that the foundation (object dialect + full-request, P9-008) and the `hostnameOrIp` format (P9-009) exist,
timesync can be FAITHFULLY migrated (previously deferred: its servers accept IP literals which the
hostname-only manifest rejected). Make it a real, registered migration.
- **`schema/capabilities/timesync.json` = the full request** `{ desired: { object: { enabled: boolean req;
  servers: array of `hostnameOrIp` strings (the agent accepts hostname OR IP), with the `enabled`⟺`servers`
  cross-field rule under the object } } }`. Use the object-type primitive + `hostnameOrIp` + `uniqueItems` +
  `maxItems` matching the agent EXACTLY. **Do NOT put `noInlineSecrets` on `servers`** — the agent's timesync
  validator does NOT reject base64ish hostnames (a valid `hostnameOrIp` like `pool.AAAA…AAAA.org` is ACCEPTED
  by the agent), so adding `noInlineSecrets` makes the manifest STRICTER than the agent (manifest≢agent). Match
  the agent: omit it, and the conformance corpus must include a long base64ish-but-valid hostname asserted
  ACCEPTED by BOTH planes (do NOT remove that vector — its presence is what proves the equivalence). REMOVE
  `defaultRegistry:false` (now faithful → in the default registry). Regenerate (`npm run gen:manifests`).
  (NOTE: whether §13.1 should reject inline-secret-shaped hostnames is a SEPARATE systemic decision — if so,
  HARDEN the agent first, then the manifest follows; not in this migration.)
- **CRITICAL — `hostnameOrIp` must equal the agent's `normalizeServer` EXACTLY (round-2 BLOCKING).** P9-009
  built `hostnameOrIp` WITHOUT a real cap consumer, so it was never validated manifest≡agent — timesync is
  its first consumer and exposes a divergence: the agent (`agent/capabilities/timesync/timesync.go`
  `normalizeServer`:422) does `netip.ParseAddr(value)` and on failure FALLS BACK to `validHostname`:437,
  which ACCEPTS all-numeric labels (label regex `^[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?$`, NO
  not-all-numeric rule), so `1.2.3.999` (fails IP, valid 4-label hostname) is ACCEPTED. The manifest's
  `hostnameOrIp` rejects numeric dotted quads after IP-parse fails ⇒ STRICTER ⇒ manifest≢agent. **FIX:** make
  `hostnameOrIp(v) = netip.ParseAddr(v) succeeds OR validHostname(v) succeeds` in BOTH planes, where
  `validHostname` matches the agent EXACTLY: non-empty, `== TrimSpace`, not ending `.`, no `..`, none of
  `:/?#[]@`, no control char `[\x00-\x1f\x7f]`, byte-len ≤ 253, each `.`-label 1–63 chars matching that label
  regex — **all-numeric labels ALLOWED**. Add corpus vectors `1.2.3.999`, `256.1.1.1`, `999.999.999.999`
  (each ACCEPT as hostname) to BOTH the timesync corpus AND P9-009's `schema/capabilities/formats/ip-conformance.json`
  if it has a conflicting reject vector (correct it — the agent accepts). Re-run TS≡Go + manifest≡agent.
- **Conformance ≡ the AGENT via the real entrypoint.** Update `agent/internal/capmanifest/conformance_test.go`
  (the timesync conformance) to full-request `{"desired":{…}}` vectors run through BOTH the manifest validator
  AND `transport.DecodeJSONRequest[timesync.ApplyRequest]` (+ `ApplyRequest.Validate`); they MUST agree —
  INCLUDING IP-literal server vectors (now ACCEPTED by both: agent via netip, manifest via hostnameOrIp) and
  canonical-equivalent IP dedup. Update the TS `timesync-conformance.test.ts` to the full-request shape too.
- **Evaluator + registry:** the default registry now = { hostname.set, node.config, time.sync }; extend the
  registry test + an evaluator test that `evaluateNodeConfig` accepts a full timesync request.
- The agent timesync cap is UNCHANGED (P9-010 already bounded its dup-key scan); only the manifest +
  conformance move to full-request + register it.
