## Objective
The flagship desktop menubar shows a **frozen, hardcoded** clock: an identical
`<span class="clk">10:24</span>` (no binding) sits in the `.v-status` bar of `index.html:5`,
`Activity.html:5`, `Files.html:5`, `Notifications.html:5`, `Settings.html:5`, and `Shell.html:5`.
It never moves — CEF (`vita-cef-live.sh`) renders the same `10:24` on every live screen. Contrast
`Lock.html:5`, whose clock IS bound via `data-vita-bind-text="lock.time"` and driven by the
`Lock.ts` view-model's `tick(now)` / `clockDisplay` mechanism.

Replace the placeholder with REAL functionality:
- Add a pure, headless, deterministic **statusbar clock view-model** at
  `ui_kits/desktop/viewmodels/statusbar-clock.ts` — `createStatusbarClockViewModel({ initialNow? })`
  exposing `snapshot()` and `tick(now: unknown)` returning a frozen `{ time, date, epochMs, iso }`
  display (same shape/formatting discipline as `LockClockDisplay` in `ui_kits/desktop/viewmodels/Lock.ts`,
  reusing its time/date formatting so the menubar clock matches the lock clock). `tick` must
  fail-closed on a non-finite / non-Date timestamp (mirror `normalizeInstant` → `INVALID_TIME`),
  never throwing. No DOM, no I/O, no ambient `Date.now()` in the pure path — the instant is injected.
- Bind it in markup: replace the bare `<span class="clk">10:24</span>` with
  `<span class="clk" data-vita-bind-text="statusbar.time">10:24</span>` in ALL six screens listed in
  `target_paths` (the `10:24` literal remains only as static fallback text behind the live binding).
  Do NOT touch `Lock.html` (already bound to `lock.time`) or `Tiling.html` (its `10:24` is an
  unrelated `tiling.layout` placeholder, out of scope here).
- Wire it: register a `statusbar.time` (and `statusbar.date`) bind resolver and have
  `ui_kits/desktop/runtime/bootstrap.ts` drive the view-model's `tick` on an interval (the same
  bootstrap-driven cadence Lock uses), so the rendered clock advances. The interval/scheduler must be
  injectable so the test is deterministic (no real timers).
- Tests at `sdk/typescript/test/ui-kits/statusbar-clock.test.ts`, run by the exact acceptance command.

## User value
Every live desktop screen shows the actual current time instead of a dead `10:24`, on the same
binding+view-model mechanism the lock screen already uses — turning a hardcoded mockup artifact into
real, testable behavior the CEF-rendered HTML hydrates against.

## Non-goals
- NO new visual design / CSS changes (markup edit is limited to adding the `data-vita-bind-text`
  attribute on the existing `.clk` span). NO change to `Lock.html` or `Tiling.html`. NO timezone/locale
  settings UI. Do NOT reach for ambient wall-clock time inside the pure view-model — the instant is
  injected; only `bootstrap.ts` may source real time and feed it through `tick`.

## Acceptance
`acceptance_command` passes. The deterministic test MUST prove the placeholder is gone and real
behavior is present:
1. **No hardcoded sample:** advancing the view-model via `tick(t1)` then `tick(t2)` (distinct
   injected instants) yields DIFFERENT `time` strings — asserting the clock is NOT a frozen constant.
   Assert a freshly injected instant of `10:24` is produced ONLY when that instant is actually
   injected, never as a baked-in default for an arbitrary `tick`.
2. **Real data from the injected port/instant:** `snapshot().time` equals the formatted value of the
   injected `initialNow`, and after `tick(now)` equals the formatted value of `now` (byte-identical to
   the `Lock.ts` formatting for the same instant).
3. **Honest fail-closed:** `tick` of a non-finite number / invalid `Date` / non-Date object returns a
   structured `INVALID_TIME`-style error result (not a throw, not a silently retained stale value).
4. **Determinism/frozen:** identical injected instants produce byte-identical (`JSON.stringify`-equal)
   frozen snapshots; outputs are `Object.isFrozen`.
5. **Markup is bound:** the test reads the six target `.html` files and asserts each `.clk` span now
   carries `data-vita-bind-text="statusbar.time"` (placeholder GONE), and that `Lock.html` /
   `Tiling.html` are unchanged.

`npm run typecheck` is clean. Pure, headless — no real timers, no network.

## Security/constraints
- Injected instant + injected scheduler only (no ambient I/O / `Date.now()` in the pure view-model);
  fail-closed on malformed input; pure/deterministic — same inputs → byte-identical snapshot. No remote
  imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons. R1: isolated,
  non-privileged desktop-ts UI logic + an attribute-only markup edit; no controller/boot/storage surface.

## Definition of done
- `ui_kits/desktop/viewmodels/statusbar-clock.ts` (pure ticking clock view-model) + a `statusbar.time`/
  `statusbar.date` bind resolver wired and driven by `ui_kits/desktop/runtime/bootstrap.ts` on an
  injectable interval.
- All six screens (`index.html`, `Activity.html`, `Files.html`, `Notifications.html`, `Settings.html`,
  `Shell.html`) have `data-vita-bind-text="statusbar.time"` on the `.clk` span; `Lock.html` and
  `Tiling.html` untouched.
- `sdk/typescript/test/ui-kits/statusbar-clock.test.ts` deterministic and green; typecheck clean. R1.
