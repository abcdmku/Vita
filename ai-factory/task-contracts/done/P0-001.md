## Objective
Implement the foundational TypeScript types and the **canonical normalizer** for the desired-state
plan model (spec §8). Provide:
- A `DesiredState` type describing the user-facing desired system state (identity, storage, apps,
  backups — minimal but typed; expand later). Keep it small and well-typed; this is a seed.
- `normalize(state: DesiredState): CanonicalPlan` that converts a desired state into a **canonical**
  plan: deterministic key ordering, stable array handling, no `undefined`, no environment/clock/IO
  reads. The output must be byte-identical for inputs that are semantically equal regardless of key
  insertion order (spec §8.4: "same inputs must produce the same plan").
- `planHash(plan: CanonicalPlan): string` using `node:crypto` (built-in) over the canonical JSON.

## User value
The plan model is the heart of the product (spec §8). Determinism (§8.4) is what makes plans
inspectable, diffable, signable, and safe to apply through the Go agent.

## Non-goals
- No signing, no transaction application, no Go-agent calls.
- No I/O, no network, no filesystem reads in plan code.
- Do not model every subsystem — a minimal typed seed is correct here.

## Dependencies
None.

## Acceptance tests
`acceptance_command` above. The test file `sdk/typescript/test/plan.test.ts` must prove:
1. **Determinism**: normalizing the same input twice yields identical canonical strings and hashes.
2. **Key-order independence**: two `DesiredState` values that differ only in object key insertion
   order normalize to the identical canonical string.
3. **Shape**: a representative state normalizes to a plan with the expected top-level keys.

## Performance & security constraints
Pure/deterministic, no I/O (spec §8.2). No remote imports; only `node:` built-ins (spec §9.3).
