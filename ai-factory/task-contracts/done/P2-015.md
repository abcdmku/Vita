## Objective
Let the controller READ current per-capability state via the new agent read endpoint (P1-023):
1. Add `getState(capability)` to the P2-006 `AgentClient` (controller/agent-client): GET `/read/{capability}`,
   parse the response fail-closed via `safeNormalize` (malformed ⇒ a typed client error, no throw). Match
   the agent wire shape (read `agent/transport/server.go`).
2. `controller/state/node-state.ts`: `buildNodeState(client, capabilities)` reads each named capability's
   state via `getState` and returns a typed `{ states: Record<capability, { ok: true, state } | { ok:
   false, error }> }` — a per-capability map where an unreadable/errored capability is recorded as a typed
   error entry (NOT a throw, NOT silently dropped). Fail-closed throughout.

## User value
The dashboard's current-state view (FR-008): the controller can now read node-config / network / storage /
backup / identity state from the agent and show it, with per-capability error isolation.

## Non-goals
- No real network/agent; injected client only (mock in tests). No mutation. Do NOT change the agent or the
  P2-006 apply/preview paths beyond adding `getState`.

## Dependencies
P2-006 (agent client), P1-023 (read endpoint). Both merged.

## Acceptance tests
`acceptance_command` — `node-state.test.ts` (mock client): `getState` parses a well-formed capability
state; a malformed/garbage state response ⇒ typed client error (no throw); `buildNodeState` over several
capabilities ⇒ a map with ok entries for readable caps and typed error entries for failing ones (one
failing cap does NOT fail the whole read, and is NOT silently dropped); a client that throws ⇒ typed error
entry. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Deterministic. Injected client (no network). Fail-closed via `safeNormalize` (never throw); per-capability
error isolation. Wire shape matches the agent's `/read`. Strict TS (no `any`). R2 → reviewer-gated.
