## Objective
W5-S7 (ADR-0010 approach B — full OCI fidelity, owner-greenlit "do them all"): add a SECOND OCI execution path that
runs the assembled rootfs via the **crun** OCI runtime (honoring the OCI Runtime Spec) as the workload inside the SAME
ADR-0009/0010 hardened transient unit — vs the P1-052 `RootDirectory=` path (image-as-rootfs under our policy). A
capsule selects it via `runtime.oci.executor=crun` (default stays `rootdir`/systemd). crun is the documented escalation
for images needing real OCI-runtime semantics (config.json mounts/caps/userns) that `RootDirectory=` ignores.

STAGE crun the SAME WAY as the pinned Deno (download-at-build + sha256-verify; NOT committed):
- **PIN** (orchestrator-verified — downloaded from the official release over HTTPS, static ELF, no dynamic deps):
  - Version: `crun 1.21`
  - URL: `https://github.com/containers/crun/releases/download/1.21/crun-1.21-linux-amd64`
  - sha256: `322c6c94b33a749ccd9f6f5ad48b0dd976eef559bbcfe15afd507a289dcdbe91`
- Add this pin to a conf (mirror `os/x86_64/ts-image.conf`'s Deno block — e.g. a Crun* block in `agent-image.conf`)
  and a staging step that FETCHES the URL, VERIFIES the sha256, and stages the binary at `/usr/lib/vita/bin/crun`
  (0755, root-owned) — mirror `os/x86_64/ts-image.mjs`'s deno fetch+verify+stage. Support an offline override env
  (e.g. `VITA_CRUN_BIN=/path/to/crun`) like `VITA_DENO_ZIP`. The build (Borg51) downloads+verifies; the binary is a
  build artifact, NOT committed.
- **Launcher wiring** (`oci.go`): when `executor=crun`, agentd composes the hardened transient unit with `ExecStart=`
  `/usr/lib/vita/bin/crun run --bundle <bundle> <id>` (rootless: `--rootless` + the DynamicUser; or crun under the
  DynamicUser with `--root` in a writable runtime dir). crun sets up the container from the OCI config; the OUTER
  systemd unit still applies DynamicUser, no ambient caps, seccomp, cgroup caps (crun must NOT re-grant caps — pass
  `--no-new-keyring`, drop caps, no setuid). Compose ONLY from the validated manifest. Reuse the P1-053 assembled
  rootfs + an agentd-generated minimal OCI `config.json` (agentd-authored from the manifest, NOT image-supplied, for
  the entrypoint/env — same "our policy over the image" stance).
Markers: `VITA-CAPSULE-OCI-CRUN: id=<id> runtime=crun rootless=yes health=OK status=OK`;
`VITA-CAPSULE-OCI-CRUN-REJECT: reason=<specific> status=OK`; `VITA-CAPSULE-OCI-CRUN-ERROR: status=FAILSAFE`. Keep ALL
prior markers. Bake a first-party test capsule with `executor=crun`.

## REVISION REQUIRED (cross-review verdict: REVISE — 2026-06-23)
The security floor is INTACT (no privilege re-grant, agentd-authored config.json, sha256-staging fail-closed — all
verified). But TWO real problems:
1. **crun cannot actually RUN under the full hardening — and the boot marker was FALSELY health=OK.** `composeOCICrunTransientUnit`
   reuses `hardenedTransientUnitProperties` verbatim (`RestrictNamespaces=yes`, `SystemCallFilter` denies `@mount @privileged`,
   empty caps, `NoNewPrivileges`) and `authoredOCIRuntimeSpec` emits NO `linux` section. So rootless `crun run` EPERMs:
   `unshare(CLONE_NEWUSER)` is blocked by `RestrictNamespaces=yes`; entering `Root.Path` needs `pivot_root`/`mount`
   (denied `@mount`) or `chroot` (denied `@privileged`). The boot showed `VITA-CAPSULE-OCI-CRUN … health=OK` ALONGSIDE
   an `res=failed` audit for the unit — i.e. the unit FAILED but the marker reported OK (a false-success, the P1-055
   lesson). FIX: (a) derive a crun-SCOPED MINIMAL allowlist — relax `RestrictNamespaces` to permit ONLY the namespace(s)
   rootless crun strictly needs (user + mnt + pid) and allow ONLY the specific syscalls it needs (unshare, and the
   mount/pivot_root it uses INSIDE the userns) — WITHOUT granting any host capability (caps stay empty, NoNewPrivileges
   stays). Document why this is safe (a user-namespace + zero-caps + NoNewPrivileges process cannot gain host privilege).
   Do NOT grant CAP_SYS_ADMIN/CAP_SYS_CHROOT or drop the cap/NoNewPrivileges floor. (b) The `health=OK` marker MUST
   reflect crun's REAL execution (MEASURED — the unit active/the workload's own readiness, res=success), NEVER emitted
   when the unit res=failed. If a safe minimal allowlist that lets crun run cannot be found, keep crun explicitly
   UNSUPPORTED (reject) rather than emit a false success — RootDirectory (P1-052) remains the primary OCI path.
2. **REBASE before merge (hygiene):** task/P1-056 was cut before P1-055/057/058 + ADR-0011/0012 — rebase onto current
   main so integration doesn't disturb those newer files.
ALSO (non-blocking, fold in): a JS test that a wrong-hash crun artifact makes `stageCrun` fail-closed (stage nothing);
`--rootless=true` (unambiguous); bundle dir under the unit RuntimeDirectory (lifecycle-reaped).
Verify via go-in-docker (linux) + the Borg51 boot must show crun GENUINELY running (health=OK + res=success). Re-review
re-runs the gate.

## REVISION 3 (host-verify: STILL res=failed + the marker is STILL falsely health=OK — 2026-06-23) — FINAL ATTEMPT
2nd boot: the crun unit goes `res=success` (start) then `res=failed`, AND `VITA-CAPSULE-OCI-CRUN … health=OK` STILL
emits. Two unresolved defects, both blocking:
1. **The health marker is FALSE — it emits health=OK while the unit ends res=failed.** This is the P1-055 gamed-evidence
   class, NOT yet fixed. The marker MUST be gated on the unit's GENUINE sustained outcome: if the crun unit ends
   `res=failed` (or the workload didn't reach real readiness), emit `VITA-CAPSULE-OCI-CRUN-REJECT: reason=<specific>`
   (read the unit's `systemctl show`/`Result`/`ExecMainStatus` + journal into the reason) — NEVER `health=OK`. A
   transient "active" moment is NOT health=OK.
2. **Diagnose + resolve WHY res=failed.** Capture the crun unit's journal/exit code. Either (a) crun EPERMs (the minimal
   allowlist is still insufficient — derive the exact namespace/syscall set, still NO host cap re-grant), or (b) crun
   runs the /init which exits and crun exits non-zero (make the baked test /init a clean LONG-RUNNER so the unit stays
   active res=success, or set the unit Type/SuccessExitStatus appropriately). The unit MUST end res=success on a real boot.
3. **FALLBACK (if 1+2 can't both hold):** if crun cannot run to res=success under a minimal-SAFE allowlist (no cap
   re-grant, no loosened NoNewPrivileges/cap floor), make crun executor EXPLICITLY UNSUPPORTED — `executor=crun` →
   `VITA-CAPSULE-OCI-CRUN-REJECT: reason=crun_unsupported_under_hardening status=OK` (a clean, honest reject), and
   document that RootDirectory (P1-052, DONE+verified) is THE OCI path. A clean unsupported-reject is ACCEPTABLE; a
   false health=OK is NOT. This is the FINAL crun attempt — deliver either a genuinely-running crun OR a clean
   unsupported reject, no third state.
