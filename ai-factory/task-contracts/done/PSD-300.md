## Objective
A **pure, headless input-routing core** inside `vita_compositor_core` (`packages/compositor-core/src/lib.rs`)
that maps a stream of libinput-style `InputEvent`s (the existing `InputEvent::PointerMotion` /
`PointerButton` / `Key` already returned by `RenderBackend::poll_input_events` — lib.rs:204-218,
lib.rs:388) to a concrete target `SurfaceId` plus surface-local `(x, y)` coordinates, given the
current surface placements and focus that the `Compositor` already tracks (`placements: Vec<Placement>`,
`focus: Option<SurfaceId>` — lib.rs:401-408, lib.rs:623-635).
- Add an `InputRouter` (or equivalent pure struct/fn) that owns: an **absolute cursor** in output
  coordinates and the current **focus**. It consumes one `InputEvent` at a time against a snapshot of
  `&[Placement]` + output bounds (`output_width`/`output_height`) and returns a typed
  `RoutedInputEvent`.
- **PointerMotion**: accumulate the relative `dx_micropixels`/`dy_micropixels` into the absolute
  cursor (convert micropixels→pixels deterministically, no float drift) and **clamp** the cursor to
  `0..=width-1` / `0..=height-1`. The routed motion targets the top-most surface currently under the
  cursor with surface-local `(x, y)`; if no surface covers the cursor → a **dropped** routed event
  (cursor still updates; no panic).
- **PointerButton**: hit-test the top-most surface under the current cursor (highest `z_index`, ties
  broken by `surface_id` to match `update_placements` ordering — lib.rs:539-543). A *press* over a
  surface **changes focus** to that surface; routed button event carries the target + surface-local
  `(x, y)`. Press/release over no surface → dropped (focus unchanged on a drop).
- **Key**: route to the currently **focused** surface (no hit-test); no focus → dropped.
- Emit a typed `RoutedInputEvent` enum (e.g. `Pointer { surface_id, local_x, local_y, .. }`,
  `Key { surface_id, .. }`, `Dropped { reason }`). NO GPU, NO CEF, NO I/O — operates only on the
  in-memory placement snapshot. Optionally expose a thin `Compositor::route_input_event(&InputEvent)`
  wrapper that feeds the router from `self.placements` / `self.focus` / output bounds and updates
  focus through the existing `set_focus` invariant (focus must reference a registered surface).
- Define `pub const VITA_INPUT_ROUTE_MARKER: &str = "VITA-INPUT-ROUTE";` and a `marker_line()` on a
  small routing self-test report so a boot-time self-test can later print a stable, asserted line
  (e.g. `VITA-INPUT-ROUTE: cursor=<x>,<y> target=<surface-or-none> focus=<surface-or-none> status=OK`).
- Keep the crate **self-consistent**: every new public item is exercised by `#[cfg(test)]` tests in
  the same `input_routing` test module; `cargo test --locked` and `rust-in-docker.mjs` build stay green.

## User value
This is the core that turns the live CEF desktop from a static picture into an interactive OS: real
pointer/keyboard events from `poll_input_events` get routed to the right window surface with correct
local coordinates and click-to-focus — the missing link between libinput and the per-surface CEF
input injection that follows. Pure + headless means it is fully testable without a GPU or a VM boot.

## Non-goals
- NO GPU, NO CEF, NO libinput FFI, NO network, NO file I/O — pure in-memory routing only.
- Do NOT change the `RenderBackend` trait, the existing `InputEvent` variants, the wire/marker shapes
  of `VITA-COMPOSITOR`, or any `composite`/damage/placement behavior. Additive only.
- NO input *injection* into CEF and NO drag/resize/window-management gestures (later slices).
- Do not weaken or edit any existing test.

## Acceptance
`acceptance_command` passes: `tools/build/rust-in-docker.mjs` builds the compositor for linux x86_64
in the pinned `rust:1.88.0-bookworm` container, and `cargo test --locked --lib input_routing` is green
in that same container. The `input_routing` test module must concretely cover, against a hand-built
stacked placement layout:
- motion accumulates relative deltas into the absolute cursor and **clamps** to `0` and `width-1` /
  `height-1` at both edges;
- a press over overlapping surfaces resolves the **top-most** covering surface (highest `z_index`,
  `surface_id` tie-break) with **correct surface-local** `(x, y)`;
- a key routes to the **focused** surface, and a press **updates focus** (subsequent key follows);
- cursor/press over **no** surface yields a `Dropped` routed event (no panic, focus unchanged);
- the exact `VITA-INPUT-ROUTE: ... status=OK` marker string is asserted.
(The `--lib input_routing` filter selects the new module by name, so an empty/stub branch with no such
tests runs zero matching tests and the build+self-consistency floor still fails it — no wildcard globs.)

## Security/constraints
Pure/deterministic (same events + placements → identical routing, byte-identical marker); no ambient
I/O, no FFI, no native addons, no remote imports; `Cargo.lock` stays committed and `--locked` is used;
no package lifecycle scripts. Coordinate math must not overflow or panic on out-of-range/empty inputs
(fail-closed to `Dropped`). R2 (compositor input path) — orchestrator runs the independent Codex
reviewer (`npm run review -- PSD-300`) before merge per the R2 gate.
