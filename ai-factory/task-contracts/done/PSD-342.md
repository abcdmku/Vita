## Objective
Make the per-package host router in `createDesktopHostForPackage` (`sdk/typescript/src/desktop-sdk/loader.ts:424`)
the **single host-side capability enforcement point**: every routed method is gated by its required
manifest grant via `hasDesktopCapabilityGrant` (`loader.ts:408`) **before** any backend port is
touched, and **fails closed** with a uniform `CAP_DENIED` result when the grant is missing or denied.
- **Default-deny by capability map.** Each routed method declares its required `DesktopCapability`
  (`sdk/typescript/src/desktop-sdk/ui-package.ts:25`): `launchApp`→`apps.launch`, `stopApp`→`apps.stop`,
  `requestFile`→`files.read`/`files.write` (by op, as `fileCapabilityForRequest` already derives),
  `readSetting`→`settings.read`, `previewSetting`/`applySetting`→`settings.write`,
  `emitLauncherIntent`→`launcher.launch`, `postNotification`→`shell.notifications.post`,
  `registerTrayItem`→`shell.tray.register`. A routed method with **no** mapped/known capability is
  denied (reserved/unknown capability ⇒ deny), never silently passed through.
- **Fail-closed BEFORE the backend.** On a missing/denied grant the gate returns the uniform denial
  shape (host methods → `{ ok: false, error: { code: "CAP_DENIED", message, path } }`; the files port,
  which uses the `FilesErrorResponse` shape, → `{ error: { code: "CAP_DENIED", message } }`) and **must
  not** invoke the wrapped backend port. Replace the current ad-hoc `MISSING_CAPABILITY` denials with
  this single uniform `CAP_DENIED` code so callers have one denial contract.
- **TOCTOU-safe grant snapshot.** Snapshot the manifest's grant set **once at mount** (when
  `createDesktopHostForPackage` is constructed) into a frozen internal structure, and decide every
  later call against the snapshot. A post-mount mutation of the original manifest's `capabilityGrants`
  must NOT widen (or narrow) what the mounted package can reach.
- Granted calls still reach the backend unchanged (existing normalization/validation order preserved:
  validate/normalize the request first, then the grant check, then the backend).

## User value
Collapses capability enforcement to one auditable choke point with one denial code (`CAP_DENIED`),
making the desktop host's least-privilege boundary reviewable and impossible to bypass per-method —
the security floor every desktop UI package is mediated through.

## Non-goals
- No new capabilities/grants and no change to the `DesktopCapability` union. No DOM/CSS/CEF/rendering.
- Do not change request normalization/validation logic, the shell-component reserved-id rule, or the
  fallback/known-good mount path semantics. Do not add ambient I/O. No new public types beyond what is
  needed to export the denial code constant if used.

## Acceptance
`acceptance_command` passes. Author `sdk/typescript/test/ui-kits/capability-enforcement-gate.test.ts`
(imports the SDK exactly as `ui_kits/desktop/package.ts` does — public `@vita/desktop-sdk` exports only:
`createDesktopHostForPackage`, `hasDesktopCapabilityGrant`) with deterministic `node:test` cases:
1. **Denied → fail-closed, backend untouched.** A manifest **missing** `settings.write` calls
   `applySetting`; result is `{ ok: false, error: { code: "CAP_DENIED" } }` AND a spy on the underlying
   host's `applySetting` is **never** invoked. Repeat the spy-not-invoked assertion for at least one
   other gated method (e.g. `launchApp` without `apps.launch`).
2. **Granted → reaches backend.** With the matching grant present, the same method reaches the wrapped
   backend (spy called once with the normalized request) and returns its result.
3. **Grant snapshot (TOCTOU).** After mount, mutate the original manifest object's `capabilityGrants`
   to add a grant; a subsequently denied method still returns `CAP_DENIED` (snapshot not widened).
4. **Reserved/unknown capability denied.** A routed path with no mapped capability is denied closed.
`npm run typecheck` is clean. R2: also requires `npm run review -- PSD-342` ⇒ `VERDICT: approve`.

## Security/constraints
- Single enforcement point; default-deny; fail-closed; least privilege. Grant set snapshotted at mount
  (no time-of-check/time-of-use gap). Injected ports only — no ambient I/O. Pure/deterministic decision
  given (snapshot, method, normalized request). No remote imports; lockfile mandatory; no package
  lifecycle scripts; no FFI/native addons.
