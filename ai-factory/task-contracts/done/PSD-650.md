## Objective
Extend the files capability (`agent/capabilities/files/files.go`, currently `list`/`read`/`write`/`stat`
under `/var/lib/vita/files`) with the folder-model operations the desktop Files app needs:
- **copy** (src → dst, within scope, file or directory recursive),
- **move/rename** (src → dst within scope; rename is move where parents match),
- **mkdir** (create a directory under scope, 0o700),
- **delete** (recursive, fail-closed),
- **recursive list** (depth-bounded directory walk).

New ops are added to the `Operation` enum (`OperationCopy`, `OperationMove`, `OperationMkdir`,
`OperationDelete`, `OperationListRecursive` or a `recursive`/`depth` field on `list` — implementer's
choice, but the request shape MUST go through `Request.Validate` + `Request.UnmarshalJSON`
(`jsonsafe.DecodeStrict`, no unknown fields)). Both `path` (src) and, for copy/move, a `dest` path
MUST be resolved INDEPENDENTLY through `ResolveWithinScope(base, …)` (`scope.go`), which refuses
symlinks, `..`, absolute, and backslash paths. Reuse the existing grant resolution, role/access
gate, `ensureGrantRoot`, and `jsonsafe`. Preserve the `MaxFileBytes` (8 MiB) / `MaxRequestBodyBytes`
(12 MiB) DoS caps — for copy/recursive ops, cap aggregate bytes and entry count so a deep/wide tree
cannot exhaust the agent. Preserve `directoryMode` 0o700 and `fileMode` 0o600 on every created node.

This is pure filesystem-under-scope. NO new transport, NO new agentd socket surface, NO new grant
types — the existing `Handle(ctx, Request)` dispatch grows new cases.

## User value
The flagship desktop Files app can copy, move, rename, create folders, delete, and browse nested
trees against the owner's on-device data — the personal-data product of Phase 5 — entirely
capability-mediated and fail-closed, with no new attack surface.

## Non-goals
- NO new transport / agentd endpoint / RPC — only the in-process `files.Handler` dispatch grows.
- NO new grant kinds or cross-grant moves (src and dst resolve under the SAME grant root).
- NO symlink following or creation; NO following of `..`/absolute paths (refuse, per `scope.go`).
- NO change to `read`/`write`/`stat`/`list` existing semantics, modes, or error codes.
- NO UI / TS / CEF (that is the desktop pod's separate view-model work).

## Acceptance
`acceptance_command` passes. The new Go tests (in `agent/capabilities/files`, e.g.
`copy_test.go` / `move_test.go` / `delete_test.go` / `list_recursive_test.go`) MUST cover, against a
real temp `StateRoot`:
- **copy**: file copy and recursive directory copy preserve content and 0o600/0o700 modes; dst that
  already exists is rejected (fail-closed, no clobber); copying onto/under itself is rejected.
- **move/rename**: file and directory move; rename within same parent; src gone + dst present after.
- **mkdir**: creates 0o700 dir; existing path rejected; nested-without-parent rejected.
- **delete**: recursive delete of a populated directory succeeds; deleting a non-existent path → 404
  `not_found`; delete is fail-closed (a refused/erroring sub-path leaves no partial-but-claimed-success).
- **recursive list**: returns entries to the configured depth cap and STOPS at it (depth-capped, does
  not walk unbounded); symlink children are skipped/`symlink-skipped`, never traversed.
- **`TestMutatingOpScopeEscape`** (adversarial): for EACH mutating op, a `path`/`dest` that escapes
  the grant root via `../`, an absolute path, a backslash path, or a symlink is **REFUSED** with the
  existing `400 path_traversal` code — both the source and the destination are checked independently.
- **`TestMutatingOpReadOnlyGrant`** (adversarial): a read-only grant (and a role whose
  `EffectiveAccess` is read-only) **rejects every mutating op** (copy/move/mkdir/delete) with
  `403 read_only_grant` / `403 role_forbidden`, exactly as `write` does today (mirror the
  `OperationWrite && effectiveAccess != AccessReadWrite` gate in `files.go`).

Re-running the command twice MUST be green and deterministic (no leftover temp state; tests own their
`StateRoot`).

## Security/constraints
- **Risk R2** (controller/agent capability surface, owner data). Per CLAUDE.md §3 / spec §16,
  signing / recovery / TPM keys are **owner-held** and unavailable to dev agents; this contract does
  NOT touch them. R2 gate: independent verification + a GPT-5.5 xhigh reviewer (`npm run review -- PSD-650`)
  must return `VERDICT: approve` before merge; component-owner human approval per the active
  auto-merge override's quality floor.
- Fail-closed: any resolution/scope failure, any sub-path error, any cap breach → abort the WHOLE op
  with a `RequestError` and leave the tree as untouched as practical (mkdir/copy/delete must not
  report success after a partial failure).
- Capability-mediated: every path (src AND dst) goes through `ResolveWithinScope`; no ambient FS
  access; no following symlinks; no `..`/absolute. Enforce role/access gate BEFORE any mutation.
- DoS caps preserved: `MaxFileBytes` per file; bound aggregate bytes + entry count for
  copy/delete/recursive-list; honor `ctx.Err()` between filesystem steps as the existing ops do.
- Pure Go stdlib; no new dependencies; no remote imports; no network (`allowed_network: false`).
