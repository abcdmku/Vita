## Objective
A transactional capability `agent/capabilities/update/` that stores a validated **RAUC A/B update
desired-state** (the on-host counterpart to the SDK P8-002 update model) to a FIXED agent state path,
applied atomically with rollback — the proven nodeconfig (P1-007) pattern. A typed `Plan` = targetSlot
(a|b) + bundle (ref + SRI integrity + version). `Handle` reads the current update state; `Apply`
validates a desired plan and writes it via a single atomic commit point (temp + rename — nothing fallible
after the rename), returning an `Undo` that restores prior bytes. Integrate with the transaction engine
(commit + rollback proven). Implements `Validate()` for the transport pre-transaction gate (P1-008).
Injected FS facade for tests.
- **Validate fail-closed**: targetSlot ∈ {a,b}; bundle ref well-formed; integrity a real SRI
  (sha256/384/512-…); version non-empty; reject embedded bundle bytes (reference + integrity only,
  never inline). Absent required field ⇒ reject (not defaulted). No `os/exec`, no real RAUC.

## User value
The on-host update desired-state (FR-023) the controller stages before the actual A/B bundle apply —
records WHICH slot + WHICH integrity-pinned bundle, transactionally. Real RAUC bundle apply + slot swap
is a later host contract (needs a privileged build host).

## Non-goals
- No real RAUC/bundle download/apply/slot-swap/dm-verity (needs a privileged host — later). Store +
  validate the typed update plan only. No `os/exec`. No `cmd/agentd/main.go` edits (wiring is a follow-up).

## Dependencies
P1-006 (engine), P1-007 (atomic-file capability pattern). Both merged. Mirror the P8-002 SDK invariants.

## Acceptance tests
