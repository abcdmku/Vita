## Objective
Let the controller discover the agent's operations and validate a plan BEFORE submitting it (FR-004/006):
1. Add `getOperations()` to the P2-006 `AgentClient` (controller/agent-client): GET `/operations`, parse
   `{operations:[…]}` fail-closed via `safeNormalize` (malformed ⇒ typed client error, no throw). Match
   the agent's wire shape (read `agent/transport/server.go`).
2. `controller/plan/plan-preview.ts`: `previewPlan(client, plan)` fetches the operation set via
   `getOperations()`, checks every plan op names a DISCOVERED operation (FR-006 show plan / catch
   unknown-capability before submit), and returns a typed preview (ops + any unknown-op rejections).
   Fail-closed: client error/unknown op ⇒ a typed preview error, never a throw.

## User value
The controller can show "here is the plan, all ops are valid for this node" (FR-006) and reject a plan
with unknown operations before it ever reaches the agent — the management-plane plan-diff foundation.

## Non-goals
- No HTTP server/UI, no real network/agent, no /apply call. Discovery + plan validation only. Reuse the
  SDK plan types; do not change the agent or the P2-006 apply path.

## Dependencies
P2-006 (agent client), P1-015 (/operations endpoint). Both merged.

## Acceptance tests
`acceptance_command` — `plan-preview.test.ts` (mock client): `getOperations` parses a well-formed list;
a malformed/garbage operations response ⇒ typed client error (no throw); `previewPlan` with all-known
ops ⇒ valid preview; a plan naming an unknown op ⇒ typed preview rejection (not a throw); a client that
errors ⇒ typed preview error. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Deterministic. Injected client (no network). Fail-closed via `safeNormalize` (never throw). Wire shape
matches the agent's `/operations`. Strict TS (no `any`). R2 → reviewer-gated.
