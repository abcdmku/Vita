## Objective
SDK type model + fail-closed validator for the W3C/AT-Proto **DID document** (spec §13/§15): `VerificationMethod`
(id + type + controller + publicKeyMultibase REFERENCE), `Service` (id + type + serviceEndpoint HTTPS),
and `DidDocument` (id = the DID, alsoKnownAs handles, verificationMethod[], service[]).
`validateDidDocument(input)` uses `safeNormalize`, then validates on the trusted plain value. Reuse the
P5-001 identity validators for the DID/handle/HTTPS-endpoint shapes (import them; do not re-implement).
- **Validate fail-closed**: `id` is a valid DID (P5-001); each verificationMethod id is `<did>#<fragment>`;
  `type` from a closed set (e.g. Multikey); `publicKeyMultibase` a multibase REFERENCE (`z…`), NOT inline
  private key material (§13.1 — reject PEM/seed/private-key patterns); service endpoints HTTPS; reject
  duplicate verificationMethod/service ids; absent required field ⇒ reject.

## User value
The typed DID document contract the PDS publishes + the controller/federation consume (§13/§15, FR-016/018)
— validated deterministically; public keys by multibase reference, never inline private material.

## Non-goals
- No DID resolution/network/crypto/signature verification. Types + pure validators only. Do NOT modify
  `identity-model`; import its validators. No shared-index edits.

## Dependencies
P0-015 (safeNormalize), P5-001 (DID/handle/HTTPS-endpoint validators). Both merged.

## Acceptance tests
`acceptance_command` — `did-document-model.test.ts`: a valid DID document validates; malformed DID/
verification-method-id/service-endpoint rejected with paths; invalid method `type` rejected (closed set);
**inline private key material in publicKeyMultibase rejected** (§13.1); duplicate vm/service ids rejected;
missing required field rejected; hostile/partial input fails closed via safeNormalize. Orchestrator also
runs `npm run typecheck`.

inline private material). Strict TS (no `any`). R1 → orchestrator-reviewed.
