## Objective
Ship **Files** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), built on the app-package SDK foundation
(PSD-361). Three artifacts mirroring the flagship-package pattern (`ui_kits/desktop/package.ts` manifest + entry +
`ui_kits/desktop/viewmodels/files.ts` view-model + test):
1. **App package** under `apps/files/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` from
   `@vita/desktop-sdk` (`sdk/typescript/src/desktop-sdk/app-package.ts`) — `id: "vita.app.files"`, a `version`,
   `sdkVersion: SDK_VERSION`, `entry: "index.html"`, and the MINIMAL `capabilityGrants` Files needs (`files.read`,
   `files.write` from the `DesktopCapability` union, `ui-package.ts:25-34`) — and a `WebAppDescriptor`
   (`appshell/index.ts:85`: `surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-files" }`,
   `title:"Files"`, sensible `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/files/index.html` — a static HTML/CSS shell for the app surface (the web bundle the
   compositor renders), following the design-of-record style of `ui_kits/desktop/Files.html` (CSS-var tokens, no inline
   JS — behavior comes from the view-model via the binder convention, ADR-0013). Keep it minimal/static; it is NOT the
   acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/files-app.ts` — the app's interaction logic in
   the SAME injected-port, frozen-`snapshot()`, discriminated-union-result style as `ui_kits/desktop/viewmodels/files.ts`,
   built ONLY on injected `@vita/desktop-sdk` public ports (the files capability port + the app's own surface model). State:
   current path, breadcrumb segments, directory entries (name/kind/size/modified), selection. Actions: `navigate(path)`,
   `up()`, `select(entry)`, `refresh()`. All directory reads go through the injected files port, **fail-closed if the grant
   is missing/denied**. Deterministic ordering (folders first, then name). NO DOM/CSS/rendering, NO platform internals, NO
   ambient I/O.

## User value
Files becomes a swappable first-party package the dock/launcher lists + launches into its own WM-managed window (not a
shell built-in), with real testable behavior on the SDK files port — proving the app-package pattern end-to-end for a
data-bearing app.

## Non-goals
- NO DOM/CSS/rendering/CEF logic in the view-model; NO platform internals; NO new SDK ports (consume PSD-361 + existing).
- Do NOT bake Files into the desktop shell or modify `ui_kits/desktop/package.ts` / `viewmodels/files.ts`. Do NOT add file
  operations beyond read/navigate/select/refresh (no move/delete here). OFFLINE only.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at `sdk/typescript/test/ui-kits/files-app.test.ts`
cover the manifest (`defineAppPackage` accepts the Files manifest; `hasAppCapabilityGrant` is true for `files.read`/
`files.write` and false otherwise; descriptor url === entry) and the view-model state transitions + fail-closed paths
(navigate/up/select/refresh against fake ports; missing/denied files grant fails closed; deterministic ordering).
`npm run typecheck` is clean. Pure, headless. (The exact test path exists only when the work lands — an empty branch
fails.)

## Security/constraints
- MINIMAL capabilityGrants (only `files.read`/`files.write`); injected ports only; capability-mediated + fail-closed;
  pure/deterministic view-model. OFFLINE (`allowed_network:false`). No remote imports; lockfile; no lifecycle scripts.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed for the view-model/test).

## Allowed tools + network
Local filesystem + Node test runner + `npm run typecheck` only. `allowed_network: false`.

## Compute/time budget
`budget_minutes: 120`, single worker.

removal leaves the desktop and OS unchanged.

## Definition of done
- `apps/files/` ships a valid `AppPackage` (manifest + web entry) with minimal grants; the headless `files-app.ts`
