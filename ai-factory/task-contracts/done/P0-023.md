## Objective
SDK type + fail-closed validator for the node's OBSERVED health/metrics report (spec FR-008 — the
counterpart to the desired-state models; this is REPORTED state, not authored). `ResourceMetric`
(used + total, both ≥ 0, used ≤ total), `CapabilityHealth` (capability name + status:
"healthy"|"degraded"|"failed" + optional message), and `NodeHealth` (healthy flag, uptimeSeconds,
cpu/memory/storage `ResourceMetric`s, per-capability health list). `validateNodeHealth(input)` uses
`safeNormalize`, then validates on the trusted plain value.
- **Validate fail-closed**: numeric fields are finite, non-negative integers; `used ≤ total` for each
  metric (reject impossible reports); status from the closed set; capability names well-formed + unique;
  uptimeSeconds ≥ 0. Absent required field ⇒ reject. No secrets in a health report (§13.1: reject any
  field that looks like inline key material — a health report must never carry secrets).

## User value
The typed contract for the health/metrics the agent reports + the controller dashboard displays (FR-008)
— validated so a malformed/impossible report (used > total, negative uptime) is rejected, not shown.

## Non-goals
- No real metric collection, no agent, no I/O. Types + pure validator only. No shared-index edits.

## Dependencies
