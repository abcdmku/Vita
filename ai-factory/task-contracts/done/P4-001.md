## Objective
The first concrete first-party app instances (spec §9, Phase 4 foundation): `notes` and `search`
manifests authored against the EXISTING catalog/package-contract types (P1-003) — a Deno TS-service
class declaring the app id, runtime tier, requested capabilities (least-privilege), and resource
limits. No new core types; REUSE the merged catalog schema. A test validates each manifest against the
catalog validator so the instances are provably well-formed.

## User value
Gives the platform real first-party apps to install/run (FR-010/011) and a worked example of the
least-privilege capability request pattern other apps will copy.

## Non-goals
- No app business logic, no runtime execution, no install pipeline — manifests + validation only.
- Do NOT modify the catalog/package-contract source; only import + use it.

## Dependencies
P1-003 (catalog entry / package contract) — merged. Permission-broker capability vocabulary — merged.

## Acceptance tests
`acceptance_command` — `manifests.test.ts`: each manifest parses + passes the existing catalog
validator; requested capabilities are within the allowed vocabulary; resource limits within bounds;
ids/handles well-formed. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Least-privilege capability requests (no broad grants). Deterministic. Strict TS (no `any`). Manifests
reference packages by pinned identity (no remote imports). R1 → orchestrator-reviewed.
