## Objective
A fail-closed validator enforcing the package-supply-chain policy (spec §9.3): a lockfile must pin
every dependency to an exact version + integrity hash, declare no remote/URL imports in production
artifacts, and **deny package lifecycle scripts** (npm `preinstall`/`install`/`postinstall`/etc., and
the JSR equivalents). `lockfile-policy.ts` exports `validateLockfilePolicy(input): Result` returning
precise violations. NEW validator ⇒ use the canonical `safeNormalize` for the untrusted lockfile input,
then inspect the trusted plain value. Standalone new file — do NOT edit existing catalog source.

## User value
This is the supply-chain gate: no unpinned deps, no lifecycle-script code execution at install
(§9.3 / §16 security). Directly protects every package install.

## Non-goals
- No actual install/resolve/network fetch; no registry calls. Pure policy validation of a provided
  lockfile structure. Do NOT modify existing `catalog-entry.ts` or other catalog source.

## Dependencies
P1-003 (catalog) — merged. P0-015 (`safeNormalize`) — merged.

## Acceptance tests
`acceptance_command` — `lockfile-policy.test.ts` covers: a fully-pinned, script-free, no-remote
lockfile passes; an unpinned/range version is rejected; a missing integrity hash is rejected; **any
lifecycle script is rejected** (preinstall/install/postinstall/prepare + JSR analog); a remote/URL
dependency is rejected; fail-closed on hostile input (garbage/cyclic/accessor) via safeNormalize.
Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Pure/deterministic, no I/O/network. Fail-closed via `safeNormalize`. Default-deny: anything not proven
pinned+script-free+local is rejected. Strict TS (no `any`/suppressions). R2 → reviewer-gated (supply-chain).

## Reviewer revision (round 2 — BLOCKING, from P4-002.review.md)
1) **Transitive deps must also be pinned**: every dependency at ANY depth must have a resolved entry
   with an exact version AND an integrity hash. Walk the full dependency tree (on the normalized plain
   value); a nested dep named with only a version string (no resolved+integrity entry) is rejected.
2) **Lifecycle-script indicators are default-DENY**: reject `hasInstallScript`/`requiresBuild`/script
   fields when the value is truthy-or-ambiguous, not only boolean `true` — string `"true"`, `1`, `{}`,
   etc. ⇒ reject. Anything not provably `false`/absent ⇒ reject.
3) Enforce real SRI syntax on `integrity` (e.g. `sha512-<base64>`), not placeholder-looking digests.
Add regressions for each (transitive dep without integrity ⇒ reject; non-boolean script indicator ⇒
reject; malformed integrity ⇒ reject).

## Reviewer revision (round 3 — BLOCKING, from P4-002.review.md round 2)
1) **Non-object dependency containers must not bypass validation.** Round-2 `collectDependencyDeclarations`
   only validated OBJECT containers; array-/string-style nested declarations (e.g.
   `dependencies: ["jsr:@scope/pkg@^1.0.0"]`) recursed over strings and never enforced
   version+integrity — a JSR-style bypass. Every dependency at every depth, regardless of container
   shape (object, array, string spec), must resolve to an entry with an exact version AND integrity, or
   be rejected. Non-object containers ⇒ reject (or normalize then enforce); never silently accept.
2) **Lifecycle-script fields are denied ANYWHERE, not only inside `scripts`/`lifecycle` objects.** A
   package entry with a DIRECT `preinstall`/`install`/`postinstall`/`prepare` (etc.) field must be
   rejected fail-closed — default-deny across the whole normalized entry, not just within a named
   scripts container.
Add regressions: an array/string-form transitive dep without integrity ⇒ reject; a direct top-level
`preinstall` field ⇒ reject.

## Reviewer revision (round 4 — BLOCKING, ARCHITECTURAL, from P4-002.review.md round 3)
Rounds 2–3 failed the same way: a DENYLIST (enumerate known dependency-container fields / known bad URL
schemes) always misses a shape (round 3 missed JSR `specifiers` maps and `ipfs:`/`data:`/protocol-relative
`//` URLs). **Switch to DEFAULT-DENY / closed-allowlist — the validator must PROVE the lockfile is fully
pinned, script-free, and local-only, and REJECT anything it cannot prove:**
- Parse into an EXPLICIT closed model of exactly the accepted lockfile shapes (npm `lockfileVersion: 3`
  packages map + JSR/Deno `specifiers`+resolved). Any key/container/shape NOT in that explicit model ⇒
  REJECT (never silently ignore an unknown container like `specifiers`).
- Every dependency edge in EVERY accepted container (`dependencies`, `packages`, `specifiers`, peer/opt)
  MUST resolve to an entry with an exact version AND valid SRI integrity, else reject.
- Every `resolved`/`source`/`url`/`sourceUrl` value MUST exactly match an ALLOWLIST of permitted forms
  (bare `name@exactversion`, or a configured local-mirror prefix). ANY URL scheme (`http`,`https`,`ipfs`,
  `data`,`file`,git+…), protocol-relative `//…`, or non-matching value ⇒ reject. Do NOT enumerate bad
  schemes — allow only the known-good forms.
Add regressions for the round-3 misses (JSR `specifiers` without integrity ⇒ reject; `resolved: ipfs://…`,
`data:…`, `//cdn…` ⇒ reject) AND an "unknown container shape ⇒ reject" case.
