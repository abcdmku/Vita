- **FORMATS (structured, NO regex engine; match the agent regexes EXACTLY via FROZEN corpora; ground-truth
  cross-check vs identity.go):**
  - **`didPlcOrWeb`** = `did:plc:` + `didPlcIdentifierPattern` `^[a-z2-7]{24}$`  OR  `did:web:` + the did:web
    host/path grammar (`didWebHost` + optional `:`-separated path segments each matching
    `didWebPathSegmentPattern` `^(?:[A-Za-z0-9._~-]|%[0-9A-Fa-f]{2})+$`). Match `validDID` EXACTLY incl.
    trim/control/length.
  - **`atprotoHandle`** = `validHandle` (`isDomainHandle`): 3..`maxHandleLength`(253), lowercase-equality, ≥2
    `.`-separated labels each `handleLabelPattern` `^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$`, TLD ≥2 chars and
    not all-digits. Match EXACTLY.
  - **`keyReference`** = `validKeyRef` (`isReferenceSyntax`): `opaqueRefPattern`
    `^[A-Za-z0-9][A-Za-z0-9._:@-]{0,255}$`  OR  a non-inline `scheme://` URI (`schemePattern`
    `^[a-z][a-z0-9+.-]*$`), with the pre-gate trim/control/forbidden-rune + the identity SECRET scanner
    (below). READ `validKeyRef` and match it.
    **ROUND-3 BLOCKING (probe→Codex, GROUND-TRUTH confirmed): the SCHEME lowercasing must use Go
    `strings.ToLower` (UNICODE), not ASCII-lowercase.** The agent does `strings.ToLower(value[:sep])` before
    `schemePattern`, so a Unicode-fold scheme like `Ｋ://ref` (Kelvin sign U+212A) folds to `k://` and is
    ACCEPTED (verified: `strings.ToLower(Kelvin)="k"`, `isReferenceSyntax` → true). The manifest's TS
    `isReferenceSyntax` used `asciiLowercase`, leaving Kelvin unchanged ⇒ `schemePattern ^[a-z]` REJECTS ⇒
    manifest STRICTER ⇒ manifest≢agent. **FIX:** lowercase the SCHEME with Unicode `.toLowerCase()` (TS) /
    `strings.ToLower` (Go capmanifest) — verified `'Ｋ'.toLowerCase()==='k'` so TS≡Go≡agent. Add a lock-in
    vector `Ｋ://ref` (Kelvin scheme) ⇒ ACCEPT. **IMPORTANT — this is SCHEME-only:** the SECRET SCANNER stays
    ASCII-lowercase (correct — the agent's scanner is a Go `(?i)` RE2 regex which does NOT fold non-ASCII;
    ground-truth: `(?i)secret` does NOT match `ſecret`; round-1's "scanner looser" was a FALSE POSITIVE). Match
    the agent's EXACT lowercasing PER CHECK: `strings.ToLower`=Unicode (scheme) vs `(?i)`=no-non-ASCII-fold (scanner).
    **ROUND-4 BLOCKING (Codex): JS `.toLowerCase()` is NOT Go `strings.ToLower` for the dotted capital I
    (U+0130).** Go does SIMPLE per-rune folding (U+0130 -> single ASCII `i`); JS does FULL folding (U+0130 ->
    two chars `i`+combining-dot U+0307), so a `<U+0130>://ref` scheme is ACCEPTED by the agent but the JS
    result fails `^[a-z]` -> manifest STILL STRICTER. **FIX:** the TS scheme lowercase must replicate Go
    `strings.ToLower` = per-rune `unicode.ToLower` (SIMPLE). Concretely SPECIAL-CASE code point U+0130 -> `"i"`
    (the only char whose Go-simple-lower is single-ASCII but JS-full-lower is multi-char; Kelvin U+212A->`k`
    already works via `.toLowerCase()`; every OTHER divergent char folds to non-ASCII and is rejected by the
    pattern anyway). To PROVE completeness, the conformance MUST FUZZ the TS scheme-lowercase against Go
    `strings.ToLower` over a wide BMP rune range (0 divergences) — like the round-1 scanner fuzz. Add lock-in
    vectors: a U+0130 scheme AND a U+212A scheme -> BOTH ACCEPT. (If exact Go-ToLower parity proves
    intractable across more chars, FALL BACK to hardening the agent's `isReferenceSyntax` to ASCII-only scheme
    chars — a security improvement that makes both reject homoglyph schemes — but try the faithful fix first.)
  - **the identity SECRET scanner** (identity.go:44-49+`containsInlineSecretMaterial`): pemBlock + privateKey
