## Objective
`fetchNodeSnapshot(transport)` (controller/state/src/snapshot-client.ts): consume the agent's aggregate
`GET /state` endpoint (P7-004) through an injected transport function and return a validated, fail-closed
whole-node snapshot. Transport is an injected async function `(path: string) => Promise<{ status: number;
body: unknown }>` (same pattern as P2-023; NO real socket — tests inject a fake). Behavior:
- Call `transport("/state")`. Non-200 ⇒ `{ ok: false, reason }` (fail-closed). A transport that
  throws/rejects ⇒ `{ ok: false, reason: "transport_error" }`.
- `safeNormalize` the body, then validate the envelope shape `{ capabilities: { <name>: <config-or-error> } }`
  (P7-004 returns each capability's current config, or `{ error }` for a capability whose read failed).
  Reject accessors/exotic/non-object. For each capability entry, classify: a `{ error }` entry ⇒ a typed
  per-capability `errors[name]`; otherwise the raw config value is carried as `configs[name]` (this client
  does NOT know each capability's schema — it returns the per-capability JSON as-is for callers/section
  validators to interpret; it MUST NOT execute methods off the untrusted config — keep it as normalized
  plain data).
- Return `{ ok: true, configs, errors, capabilityNames } | { ok: false, reason }`. `capabilityNames` is the
  sorted list of keys. Never throw.

## User value
The operator's one-call whole-node snapshot (FR-004/008) — every capability's current config (or a typed
read-error) fetched in a single request and validated as plain trusted data, replacing N per-capability
round-trips.

## Non-goals
- No real HTTP/socket/network (inject the transport). No per-capability SCHEMA validation here (each
  capability's config is returned as normalized plain JSON; section validators interpret it). Do NOT modify
  P2-006 — mirror its injected-transport pattern.

## Dependencies
P2-006 (injected-transport client pattern), P7-004 (agent GET /state), P0-015 (safeNormalize). Merged.

## Acceptance tests
`acceptance_command` — `snapshot-client.test.ts`: a 200 with a valid `{capabilities:{...}}` ⇒ `ok:true`
with `configs` + sorted `capabilityNames`; a capability whose entry is `{error}` ⇒ surfaced in `errors`,
not `configs`; a non-200 ⇒ `ok:false`; a transport that throws ⇒ `transport_error`; a body missing
`capabilities` / non-object ⇒ fail-closed; a config value carrying a hostile accessor ⇒ the accessor is
NEVER invoked (external-counter probe stays 0) and the value is returned as normalized plain data (or the
entry rejected) — no method executed off it. Orchestrator runs `npm run typecheck`.

## Performance & security constraints
Deterministic; no real I/O (injected transport). Fail-closed: safeNormalize the body; never execute methods
off untrusted config values; never throw. Strict TS (no `any`). R2 → reviewer-gated.
