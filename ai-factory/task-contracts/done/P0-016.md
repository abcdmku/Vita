## Objective
The new type-check lane (`npm run typecheck`, tsc 6.0.3 strict) reports ~48 strict-TS errors across
already-merged code — the `node --experimental-strip-types` acceptance erases types and never
type-checked them. Make `npm run typecheck` exit with **0 errors**, fixing the types **properly**.

Most are in test files (loose casts / unchecked indexed access under `noUncheckedIndexedAccess`),
plus ~8 in source: `sdk/typescript/src/explain.ts`, `sdk/typescript/src/plan.ts`,
`sdk/typescript/src/validate.ts`, `storage/capsules/src/capsule.ts`,
`packages/catalog/src/catalog-entry.ts`, `controller/api/src/dispatcher.ts`,
`simulation/profiles/src/profiles.ts`. Run `npm run typecheck` to see the current list.

Rules:
- **No `any`, `@ts-ignore`, `@ts-expect-error`, or unsound casts** to silence errors. Fix the actual
  types — guard indexed access (`arr[i]` is `T | undefined`), handle optional/`exactOptionalPropertyTypes`
  correctly, narrow result unions properly (the `r.errors` on `never` errors come from asserting the
  wrong branch — narrow on `r.ok` instead).
- If a type error reveals a **real bug** (e.g. `explain.ts`/`plan.ts` handling an array where a
  primitive was assumed), fix the behavior, not just the type.
- **Do not weaken or delete tests**; their assertions must remain. Every existing `node --test` suite
  must still pass after your changes.

## User value
Strict TypeScript is the product's core safety property (spec §5, §20.1). 48 unchecked violations are
latent bugs; closing them and enforcing the lane prevents recurrence.

## Non-goals
- No behavior changes beyond what a type error legitimately requires; no refactors for taste.
