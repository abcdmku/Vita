## Objective
Close the security gap the P1-048 cross-review surfaced: `agent/cmd/agentd/main.go` binds a SECOND privileged control
surface on loopback TCP (`127.0.0.1:8786`, `tcpServer.ListenAndServe`) serving the SAME handler as the unix socket —
but ONLY the unix socket received P1-048's SO_PEERCRED/SO_PEERGROUPS peer authentication. So any local process (NOT in
`vita-agent`) can reach `capsule.execute` / `/apply` / host-mutating ops over TCP and BYPASS the peer-cred gate. TCP
loopback has no SO_PEERCRED equivalent, so it cannot be peer-authenticated — therefore the production agentd must NOT
expose it. The TS runtime already uses the unix transport (`VITA-CONNECT transport=unix`), so TCP is vestigial.

Implement: the production/shipped agentd listens ONLY on the peer-cred-gated unix socket. Make the TCP listener
**dev-only** — bound behind an explicit opt-in (env `VITA_AGENT_DEV_TCP=1` OR a `//go:build dev` tag), OFF by default
and OFF in the shipped image. When the opt-in is absent, agentd MUST NOT bind any TCP port; `serveUntilStopped` runs
the unix server alone. Keep the existing loopback-only guard for the dev path (defense-in-depth if someone sets the
flag). Audit-log which transports are active at startup.

Concretely:
- `main.go`: gate the TCP `http.Server` creation + `serveHTTP("tcp", …)` behind the dev opt-in; default path =
  unix-only (`serveUntilStopped` tolerates a nil tcpServer). Log `transports=unix` (or `unix+tcp(dev)`).
- Confirm the unix path is unchanged (peer-cred auth intact) and the runtime still connects.
- TS side: `VITA-CONNECT` unchanged (already unix). Optionally assert no TCP fallback. Keep all markers.

## User value
The privileged agent — which can spawn workloads + mutate the host — exposes a SINGLE, peer-authenticated control
surface in production. Closes the unauthenticated-local-process bypass that made P1-048's peer-cred gate moot.

## Non-goals
NO token/mTLS for TCP (TCP is removed from prod, not re-secured). Don't break the unix path or the dev workflow
(keep TCP available behind the explicit dev opt-in). NO change to request semantics.

## Dependencies
P1-048 (peer-cred auth on the unix socket) — review-approved. Read `agent/cmd/agentd/main.go` (the dual-listener
`serveUntilStopped`/`serveHTTP`), `agent/transport/server.go`, and ADR-0008 (unix socket = the transport).

## Acceptance tests
`acceptance_command` — Go tests: with the dev opt-in ABSENT, agentd configures NO TCP listener (only unix) — assert
`serveUntilStopped`/the setup binds unix alone (nil/absent tcpServer, no `:8786`); with the opt-in PRESENT, the dev
TCP listener is created (loopback-only guard still enforced). Existing transport/cmd tests stay green; vet/build
clean. Orchestrator host-verifies on Borg51: boot, the runtime still connects over unix (`VITA-CONNECT transport=unix
healthz=OK`), AND no process is listening on `127.0.0.1:8786` on the node (`ss -ltn` / `/proc/net/tcp` shows no
:8786); full chain still PASS.

## Performance & security constraints
Production = unix-socket-only, peer-cred-gated (single authenticated control surface). Dev TCP is explicit opt-in,
loopback-only, OFF in the image. Fail-safe: an unknown opt-in value → no TCP. No keys. R3 (privileged-daemon attack
surface reduction) → parallel-candidate + reviewer gate.
