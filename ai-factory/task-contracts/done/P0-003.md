## Objective
Implement the immutable typed capability snapshot (spec §8.2) and the accelerator model (spec §14.1),
plus deterministic device-selection logic used by the SDK (spec §8.3 `device.ai.bestAvailable`):
- The `AcceleratorCapability` discriminated union exactly as in spec §14.1.
- A `DeviceSnapshot` type (memoryGB, architecture, accelerators[], tpm, virtualization, …) that is
  deeply readonly.
- `bestAvailable({ prefer, requireFallback })`: given a preference order (e.g. `["npu","gpu","cpu"]`)
  and a required fallback, return the best available accelerator. **CPU fallback is mandatory**
  unless a requirement cannot be met, in which case it must surface a clear, typed refusal — never
  silently pick an invalid device (spec §3.9, §14).

## User value
Capability-based placement (spec §14.2) with guaranteed CPU fallback is a core product principle.

## Non-goals
- No real hardware probing (that's the Go agent / FR-004 runtime later). This is the *typed model +
  pure selection logic* only, fed a snapshot.

## Dependencies
None (other SDK modules may import these types later).

## Acceptance tests
`acceptance_command` above. `sdk/typescript/test/capabilities.test.ts` must prove:
1. `bestAvailable` honors the `prefer` order (npu before gpu before cpu).
2. With no accelerators present, it returns the declared CPU fallback.
3. When a hard requirement cannot be satisfied and no fallback is allowed, it returns the typed
   refusal rather than an invalid device.

## Performance & security constraints
Pure/deterministic, no I/O. Snapshot is readonly.

## Hardware profiles
Models x86_64, arm64, and the no-accelerator profile (spec §20.1).

## Allowed tools & network
Offline. Node built-ins only.
