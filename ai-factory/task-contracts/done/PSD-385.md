## Objective
Headless, deterministic **idle/lock controller** view-model that drives the session state machine
(PSD-380, `ui_kits/desktop/viewmodels/session.ts`) back to `locked` on inactivity OR on an explicit
lock command, and idempotently tears down the desktop surface on session end. Today the session
machine exposes `tick(now)` and `lock(reason: "manual" | "idle")` but nothing TRACKS activity to
decide WHEN to fire idle re-lock, and there is no first-class manual-lock command (menu/shortcut)
or session-end teardown. This slice is the missing activity tracker + command + dispose wiring.
- State: an idle accounting model over an **injected clock** — `lastActivityMs`, `idleBudgetMs`,
  `remainingMs`, and a derived `armed` flag (only while the session is `unlocked`). Actions:
  `activity(now)` (an input/activity tick resets the idle timer; ignored unless `unlocked`),
  `tick(now)` (advances accounting; when `now - lastActivityMs >= idleBudgetMs` while `unlocked`,
  drives the session machine `lock("idle")` and tears down the desktop surface), and a manual
  `lockCommand()` (menu/shortcut) that immediately drives `lock("manual")` + teardown regardless of
  remaining idle budget.
- Session end: a single idempotent `dispose()` that calls the injected host `unmount()` exactly once
  (the established `unmount()` teardown contract from `ui_kits/desktop/package.ts` / PSD-022) and
  leaves the controller inert (further `activity`/`tick`/`lockCommand` are no-ops/fail-closed). A
  re-lock transition likewise tears down the live desktop surface via the same idempotent unmount
  path (never double-unmounts).
- Pure deterministic timer logic: time enters ONLY through `activity(now)`/`tick(now)` (epoch ms);
  NO `Date.now()`, NO `setTimeout`/`setInterval`, NO wall-clock dependency. Each action returns a
  frozen result `{ ok, state, transition?, error? }`; the snapshot is the frozen idle state.
- Put the code under `ui_kits/desktop/viewmodels/idle-lock.ts` and tests under
  `sdk/typescript/test/ui-kits/idle-lock.test.ts`. Import the SDK exactly as the other view-models do
  (relative `../../../sdk/typescript/src/desktop-sdk/index.ts`); consume the PSD-380 session
  view-model and the host `unmount()` contract through injected ports only — use ONLY public exports.

## User value
Closes the re-lock gap: the desktop actually re-locks on inactivity and on an explicit
menu/shortcut lock command, and ends sessions cleanly (one host unmount). Without this the session
machine can transition to `locked` but nothing ever decides WHEN, and the live desktop surface
leaks on session end. This is the deterministic policy `bootstrap`/the command registry binds to.

## Non-goals
- NO DOM/CSS/rendering/CEF, NO real timers/clock (idle is driven purely by injected
  `activity(now)`/`tick(now)`). NO platform internals, NO ambient I/O. Do NOT re-implement the
  session state machine or the Lock auth/credential normalization — drive the PSD-380 session
  view-model. Do NOT re-implement host mount/unmount — consume the injected `unmount()` contract.
  NO new visual design, NO shortcut/keymap binding here (the command is exposed as a callable;
  wiring it into the command registry / chord map is a separate slice).

## Acceptance
`acceptance_command` passes. Deterministic unit tests in
`sdk/typescript/test/ui-kits/idle-lock.test.ts` (node test runner, no DOM) cover, against fake
injected ports (a fake/driven session view-model exposing `lock(reason)` + `kind`, and a fake host
recording `unmount()` calls): an `activity(now)` while `unlocked` resets `remainingMs` to the full
budget; a `tick(now)` that crosses the idle budget while `unlocked` drives the session
`lock("idle")` exactly once and unmounts the surface exactly once; a `tick` BEFORE the budget
elapses does nothing (still `unlocked`, no unmount); `lockCommand()` while `unlocked` immediately
drives `lock("manual")` + one unmount regardless of remaining budget; `activity`/`tick`/`lockCommand`
while NOT `unlocked` are inert no-ops (idle accounting disarmed); `dispose()` calls host `unmount()`
exactly once and is idempotent (second `dispose()` does NOT unmount again, returns ok-inert); a
re-lock that already unmounted is NOT double-unmounted by a subsequent `dispose()`; malformed/bad
`now` (NaN/non-finite/negative) fails closed without mutation; frozen snapshots
(`Object.isFrozen`); byte-stable deterministic output for identical input sequences. Typecheck clean.

## Security/constraints
- Injected ports only (no ambient I/O, no real clock/timers); fail-closed on every edge (bad `now`,
  out-of-order/duplicate dispose, actions while not `unlocked`). Pure/deterministic — same input
  sequence produces byte-identical state/transition results. Frozen state + frozen results (no
  caller mutation). `unmount()` invoked at most once per session (idempotent teardown). No remote
  imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons.
