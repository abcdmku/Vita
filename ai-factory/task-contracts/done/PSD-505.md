## Objective
**Remove the placeholder** baked fake inbox from the flagship Mail surface and replace it with the
**real** mailbox view-model, hydrated by the desktop binder over an **injected `LocalMailboxPort`**.

Today `apps/mail/index.html` is a static mockup: it hardcodes folder rows (Inbox/Sent/Outbox/Archive
with counts `2/0/1/0`), two fake message rows (`Welcome to offline Mail`, `Queued compose flow`), and
a fixed reader pane (lines 234–282). It carries `data-vita-viewmodel="mail-app"`/`data-bind="…"`
attributes that **nothing in runtime code consumes**, has **no `<script>`**, and has **no
`data-vita-screen` attribute** — so `bootstrapDesktop` (which only finds roots by `[data-vita-screen]`
and only knows `DEFAULT_SCREEN_MODULES`) never hydrates it. `createMailAppViewModel`
([`ui_kits/desktop/viewmodels/apps/mail-app.ts:161`](../../../ui_kits/desktop/viewmodels/apps/mail-app.ts)),
including its `LocalMailboxPort` contract, exists and is fully tested but is **instantiated only in
tests** — never in shipped runtime code. The Mail surface is dead chrome.

Wire it, exactly mirroring the **already-shipped** Files pattern
([`ui_kits/desktop/screens/files.ts`](../../../ui_kits/desktop/screens/files.ts) +
[`ui_kits/desktop/runtime/bootstrap.ts:57`](../../../ui_kits/desktop/runtime/bootstrap.ts)):

1. **Add `ui_kits/desktop/screens/mail.ts`** exporting a `mailScreen` `ScreenModule`
   (`id: "desktop/mail"`) that:
   - `createViewModel(ports)` constructs `createMailAppViewModel(...)` (the REAL view-model — do NOT
     reimplement it). When a mailbox port is present it is passed through; the view-model's existing
     fail-closed `MISSING_MAILBOX_PORT` path is preserved when absent.
   - `selectPorts(host)` derives a **real `LocalMailboxPort` from the host** (use the same
     `optionalHostPort(host, …, guard)` / `readOwnData` helpers in
     [`ui_kits/desktop/screens/shared.ts`](../../../ui_kits/desktop/screens/shared.ts) that
     `filesScreen` uses). It returns the port when the host exposes one and `undefined` otherwise — no
     baked seed, no hardcoded sample mailbox in the screen module.
   - `binds` maps `folders`, `messages`, and `selectedMessage.*` from the live view-model snapshot to
     binder **list templates** (`VitaListItem[]`, via `textListItem`) and text binds — including an
     **empty-inbox** state bind that is truthy/visible when the active folder has zero messages.
   - `actions` wire `mail.selectFolder` / `mail.selectMessage` (and compose/queue) to the view-model
     methods via `datasetValue`, exactly as `filesScreen` does for files.* actions.
2. **Register `mailScreen` in `DEFAULT_SCREEN_MODULES`**
   ([`ui_kits/desktop/runtime/bootstrap.ts:57`](../../../ui_kits/desktop/runtime/bootstrap.ts)) so the
   surface is hydrated at boot.
3. **Rewrite `apps/mail/index.html`** so the `<main>` root carries `data-vita-screen="desktop/mail"`,
   the four hardcoded `<li>` folder rows and two hardcoded `<li>` message rows are **deleted** and
   replaced with binder list-template containers (the single template `<li>` the binder clones), the
   reader pane binds to `selectedMessage`, and an empty-inbox element renders when there are no
   messages. **No hardcoded folder labels/counts and no sample emails may remain** in the markup. The
   surface must load the desktop runtime the same way the other hydrated surfaces do.

## User value
Mail stops being a screenshot. On launch the folders, message list, and reader render **live** from
the injected local mailbox port; an empty mailbox shows a real empty-inbox state instead of a fake
"Welcome to offline Mail". This is the binder hydration path the CEF-rendered flagship desktop relies
on, and it removes a surface that silently lied about being functional.

## Non-goals
- Do **NOT** reimplement `createMailAppViewModel`, `LocalMailboxPort`, or the in-memory mailbox port —
  consume the existing ones (`ui_kits/desktop/viewmodels/apps/mail-app.ts`).
- NO new mail backend/transport, no network send path, no IMAP/SMTP. The host-side concrete mailbox
  implementation is out of scope; this slice wires the surface to whatever `LocalMailboxPort` the host
  injects and fail-closes cleanly when none is present.
- NO redesign of the Mail visual language; keep the existing CSS/layout. Only the data wiring and the
  baked rows change.
- Do not touch the production KMS/CEF compositor path or other screens' modules.

5. **Fail-closed honesty:** hydrate with a host that injects **no** mailbox port and assert the
   view-model surfaces its real `MISSING_MAILBOX_PORT` denied state (status `denied`) — an honest

## Security/constraints
- Injected ports only (capability-mediated `LocalMailboxPort` from the host); pure/deterministic
  view-model; fail-closed when the grant/port is absent. No ambient I/O in the view-model.
- No remote imports in production artifacts; lockfile mandatory; no package lifecycle scripts; no
  FFI/native. Import the SDK exactly as the sibling screens do (public exports only).
- No network (`allowed_network: false`). No new privileged surface; the surface only reads the
  mailbox port and queues drafts to the local Outbox (existing view-model behavior) — no send path.
