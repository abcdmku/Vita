## Objective
Headless, deterministic **Export Center** app view-model for the flagship desktop, built ONLY on
`@vita/desktop-sdk` public ports plus an injected export port (the host bridge to the existing
export capability: `agent/capabilities/export` + the ts-overlay export client
`os/x86_64/ts-overlay/usr/lib/vita/ts/vita/export-client.ts` / SDK `export-bundle.ts`, marker
`VITA-EXPORT`). Implements FR-019: the user can export **all first-party data** to ordinary
files / documented structured formats with **no active subscription**, and the export path
**works with vendor domains blocked** (the §11 / Phase-5 exit gate). NO DOM/CSS/rendering/CEF,
NO platform internals.
- **State:** the enumerated set of first-party data domains (the `ExportEntryKind` surface —
  `file` user files, `config` device state, `pds` sync state — each domain enumerable
  independently), per-domain selection, a previewed **manifest** of the documented export formats
  (format version + per-entry `path`/`kind`/`integrity`), and run status
  (`idle`/`enumerating`/`ready`/`forbidden`/`exporting`/`done`/`failed`).
- **Actions:** `listDomains()` (unprivileged read-listing — never requires the export grant,
  never touches data bytes), `select(domain)`, `previewManifest()` (documented formats only),
  `export()` (capability-gated — fail-closed if the export grant is missing → `forbidden`),
  `reset()`. All export bytes flow through the **injected export port**; the view-model holds no
  ambient I/O.
- **No-subscription invariant:** the view-model must NEVER consult or require any subscription/
  entitlement signal to enumerate, preview, or export. A test runs the full flow against a stub
  whose `subscriptionActive=false` AND whose `vendorDomainsBlocked=true` and asserts a complete
  bundle is still produced.
- **Fail-closed:** if the injected export port reports a partial/failed run (any
  `ExportBundleRejectReason`, a missing domain blob, or a per-domain error), the view-model
  surfaces `failed` and emits **no bundle handle** — it must NOT present a silently-incomplete
  bundle as success. Deterministic domain ordering (stable: `file`, `config`, `pds`).
- Put the code under `ui_kits/desktop/viewmodels/apps/export-center.ts` and tests under
  `sdk/typescript/test/ui-kits/export-center.test.ts`. Import the SDK exactly as the sibling app
  view-models do (e.g. `ui_kits/desktop/viewmodels/apps/files-app.ts`) — relative import of
  `sdk/typescript/src/desktop-sdk/index.ts`, public exports only; consume the export-bundle types
  from `sdk/typescript/src/export-bundle.ts`.

## User value
A real, testable desktop Export Center: the user owns their data and can walk out with all of it as
ordinary documented files at any time, with no subscription and with vendor servers unreachable —
the personal-data-product promise (FR-019) made concrete as the logic the CEF-rendered HTML
hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO new visual design. NO platform internals or ambient I/O.
- Do NOT re-implement the export capability, bundle builder, or integrity hashing — consume the
  injected port and the existing `export-bundle.ts` types. No new on-wire/bundle format.
- No subscription/billing logic of any kind (its absence is the point).

## Acceptance
`acceptance_command` passes. `node --test` covers, against fake SDK + fake export ports
(deterministic, no real I/O): (1) `listDomains()` enumerates every first-party domain without the
grant; (2) `previewManifest()` produces a manifest of documented formats for the selected domains;
(3) the full enumerate→preview→export flow succeeds under `subscriptionActive=false` +
`vendorDomainsBlocked=true`; (4) a missing export grant yields `forbidden` with no bundle; (5) a
partial/failed port result yields `failed` and emits no bundle handle (fail-closed). `typecheck`
clean. Pure, headless, deterministic.

## Security/constraints
- Injected ports only (no ambient I/O); read-listing unprivileged, export action capability-mediated
  and fail-closed; no subscription/entitlement dependency; deterministic. No remote imports;
  lockfile; no package lifecycle scripts (spec §9.3).
