## Objective
A strict, fail-closed Semantic Versioning 2.0.0 utility `sdk/typescript/src/semver.ts` so callers (capsule
/ update previews) can order versions by real precedence instead of natural-string compare.
- `parseSemver(input): { ok: true, value: Semver } | { ok: false, reason }` — accept ONLY a valid semver
  string `major.minor.patch` with optional `-prerelease` and `+build`, per the spec: numeric identifiers
  have no leading zeros; prerelease/build are dot-separated alphanumeric-or-hyphen identifiers. Use
  `safeNormalize` on the input first; reject anything non-conforming (empty, leading `v`, leading zeros,
  out-of-range, exotic input) fail-closed.
- `compareSemver(a, b): -1 | 0 | 1` over two PARSED `Semver` values implementing spec §11 precedence:
  compare major, then minor, then patch numerically; a version WITH a prerelease has LOWER precedence than
  the same version without; compare prerelease identifiers per spec (numeric < non-numeric, numeric
  compared numerically, ASCII otherwise, more fields wins when all prior equal); BUILD metadata is IGNORED
  for precedence. Total order, deterministic.
- `isValidSemver(input): boolean` convenience over `parseSemver`.

## User value
Correct version ordering across the OS (FR-012 capsule upgrades/downgrades, update bundles) — `1.10.0 >
1.9.0`, `1.0.0-alpha < 1.0.0`, build metadata ignored — replacing the natural-string limitation noted in
the P2-020/P2-018 previews.

## Non-goals

  No edits to existing modules — new files only (callers adopt it later).

zero, leading `v`, missing component, empty, non-string/exotic) rejected fail-closed; `compareSemver`

(`1.0.0+a` compares equal to `1.0.0+b`); compare is a total order (antisymmetric/transitive on samples);
hostile input to parse fails closed. Orchestrator also runs `npm run typecheck`.
