## Objective
SDK type model + fail-closed validator for AT Protocol federation (spec §15): `RelayConfig` (relay
endpoint + subscribe policy), `FederationPeer` (peer DID + handle + endpoint + trust: "allow"|"block"),
and `FederationConfig` (relays + a peer allow/block list). `validateFederationConfig(input)` uses
`safeNormalize`, then validates on the trusted plain value. Reuse the P5-001 identity model's DID/handle
+ HTTPS-endpoint validators (import them; do not re-implement). NEW validator ⇒ safeNormalize boundary,
then validate.
- **Validate fail-closed**: relay/peer endpoints are HTTPS base URLs; peer DIDs/handles well-formed
  (P5-001 rules); `trust` is the closed set {allow, block}; reject duplicate peer DIDs; default-deny
  posture (a peer not in the list is implicitly blocked — never an implicit allow). Absent required field
  ⇒ reject. §13.1: no embedded key material.

## User value
The typed contract for who this node federates with (§15, FR-018/019) — relays + an explicit peer
allow/block list, validated deterministically before any network federation.

## Non-goals
- No real federation/network/relay subscription, no crypto. Types + pure validators only. Do NOT modify
  `identity-model`; import its DID/handle/endpoint validators. No shared-index edits.

## Dependencies
P0-015 (safeNormalize), P5-001 (identity DID/handle/endpoint validators). Both merged.
