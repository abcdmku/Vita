## Objective
Pure, offline parsers/validators for the **SBOM** and **vulnerability-status** records that
`CatalogEntry` already references, so an entry's `sbom` (`CatalogSbomReference`) and
`vulnerabilityStatus` (`VulnerabilityStatus`) can be produced from a **pre-produced offline scan
artifact** and its digest bound into the signed entry (spec §9.3 "scanned"; §18.1 SBOM/provenance).
- Consume a `format: "spdx-json" | "cyclonedx-json"` SBOM document plus a vulnerability-status
  record. Parse and validate them against the existing shapes in
  `packages/catalog/src/catalog-entry.ts` (`CatalogSbomReference` = `{format, ref, digest,
  generatedAt}`) and `sdk/manifests/src/package-contract.ts` (`VulnerabilityStatus` = `{status,
  scannedAt?, critical, high, medium, low}`, status ∈ `clean | known-vulnerabilities |
  scan-pending | scan-unavailable`; `ImmutableDigest` = `{algorithm ∈ sha256|sha384|sha512,
  value}`).
- **Digest linkage:** verify `sbom.digest` is the digest of the referenced SBOM bytes the caller
  supplies (recompute over the bytes, compare `algorithm`+`value` constant-time); reject on
  mismatch.
- **Status enum + counts:** reject unknown `status`; reject negative/non-integer
  critical/high/medium/low; require `status: clean` to be consistent with zero counts (reject a
  `clean` record that reports any non-zero count).
- **Freshness:** validate `scannedAt`/`generatedAt` are RFC3339 date-times and enforce a
  caller-supplied max-staleness window (reject a scan older than the window — fail-closed; do NOT
  treat a missing/`scan-pending`/`scan-unavailable` status as acceptable for binding).
- **Fail-closed + hostile-input-safe:** every entry point returns a structured result
  (`{ ok: true, value } | { ok: false, errors }`) and **never throws** on malformed/adversarial
  input (non-object, wrong types, extra fields, NaN/Infinity, prototype-pollution keys, oversized
  strings).
- Put the code under `packages/catalog/src/sbom-scan.ts` and tests under
  `packages/catalog/test/sbom-scan.test.ts`. Import the existing types/validators from
  `./catalog-entry.ts` and `../../../sdk/manifests/src/package-contract.ts` exactly as the
  sibling sources do; reuse — do NOT re-implement — the existing digest/date validators where
  exported, otherwise mirror their fail-closed behavior. No network scanner.

## User value
Lets the app-catalog supply chain bind a verifiable, offline-scanned SBOM + vulnerability status
into a signed `CatalogEntry` — the trust precondition (spec §9.3) for an entry being installable —
without any network scanner or ambient I/O.

## Non-goals
- NO network/online scanner, NO fetching CVE feeds, NO live OSV/NVD lookups. NO signing or
  publishing (that is the entry signer's job — this only validates the inputs it will bind). NO
  new on-disk format — consume the shapes `CatalogEntry`/`VulnerabilityStatus` already define. Do
  NOT re-implement `validateCatalogEntry`; this is the upstream ingestion guard.

## Acceptance
`acceptance_command` passes. `node --experimental-strip-types --test
packages/catalog/test/sbom-scan.test.ts` must cover, deterministically: (1) a valid `spdx-json`
report and a valid `cyclonedx-json` report each parse and have their `digest` link verified
against supplied bytes; (2) a digest-mismatch report is rejected; (3) an unknown/invalid `status`
is rejected; (4) a stale scan (older than the supplied window) is rejected; (5) `status: clean`
with non-zero counts is rejected; (6) hostile inputs (non-object, wrong types, extra fields,
NaN/Infinity, `__proto__`/`constructor` keys) are each rejected via the result type and **never
throw**. `npm run typecheck` clean.

## Security/constraints
- Pure/deterministic, no ambient I/O, offline (`allowed_network: false`). Fail-closed: anything not
  provably valid is rejected. Constant-time digest comparison. No remote imports; lockfile
  mandatory; no package lifecycle scripts; no FFI/native addons (spec §9.3). Treat all scan input
  as untrusted/adversarial.

## Definition of done
- `packages/catalog/src/sbom-scan.ts` + `packages/catalog/test/sbom-scan.test.ts`, deterministic,
  hostile-input-safe (never throws), typecheck clean, `allowed_network: false`. R1.
