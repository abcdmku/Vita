## Objective
Build the **portable, transport-agnostic skeleton** of the controller API (spec §7 controller API,
FR-008 "UniFi-style overview and node health"; FR-006 plan diff). This is the first R2 task — it will
be independently reviewed before merge. Provide:
- **Typed request/response contracts** (`contracts.ts`) for an initial v0.1 endpoint set:
  - `getOverview(): OverviewResponse` — node count, health summary, protection/exposure summary
    (stub data is fine; types must be real).
  - `getNodeHealth({ nodeId }): NodeHealthResponse` — status, uptime, capability summary.
  - `previewPlan({ desiredState }): PlanPreviewResponse` — uses the SDK: `validatePlan` →
    `normalize` → `diff` (vs a supplied/empty current plan) → `explain`. Returns `{ ok, validation,
    diff, explanation }`. Invalid/overprivileged input returns a typed error result, not a throw.
- A **typed handler interface** (`ControllerApi`) and an **in-memory dispatcher** (`dispatcher.ts`)
  that routes a `{ method, params }` request to the handler and returns a typed result — no network,
  no protobuf codegen yet (that needs the buf/protoc toolchain — a follow-up once a host is set up).
- Node-native tests proving the endpoints behave (esp. `previewPlan` happy-path + rejected-overprivilege path).

## User value
The controller API is the product's control surface (spec §7, §28). A typed, SDK-backed skeleton lets
the UI and later transport layers build against a stable contract, and proves the plan pipeline
end-to-end (validate → normalize → diff → explain) behind one call.

## Non-goals
- No HTTP/Connect/protobuf transport yet (needs toolchain); no auth/identity; no real host data.
- No mutation/apply — `previewPlan` is read-only preview (FR-006), not apply (FR-007).

## Dependencies
SDK: P0-001 (plan/normalize), P0-004 (diff), P0-005 (validate), P0-009 (explain) — all merged.

## Acceptance tests
`acceptance_command`. `controller/api/test/dispatcher.test.ts` must prove:
1. `getOverview`/`getNodeHealth` return well-typed responses via the dispatcher.
2. `previewPlan` with a valid desired state returns `ok:true` with validation pass, a diff, and an
   explanation (using the real SDK).
3. `previewPlan` with an overprivileged/invalid desired state returns a typed error result
   (`ok:false` + validation errors), and does NOT throw.

## Performance & security constraints
No network. Import the SDK from `sdk/typescript` (do not duplicate plan logic). Deterministic. The
dispatcher must reject unknown methods with a typed error (fail-closed). R2 → reviewer-gated.
