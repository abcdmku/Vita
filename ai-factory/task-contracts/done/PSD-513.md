## Objective
The editor surface (`apps/editor/index.html`) ships **static placeholder fields the runtime ignores**. Lines 122-148 use `data-view-model="editor-app"`, `data-bind="document.title"` (`Untitled`), `data-bind="document.path"` (`No file open`), `data-bind="document.language"` (`Plain Text`), `data-bind="document.dirty"` (`Saved`), `data-bind="document.cursor"` (`Ln 1, Col 1`), and `data-action="open|undo|redo|save"`. These attributes are **not** the desktop binder scheme (the binder consumes `data-vita-bind-text` / `data-vita-action` / `data-vita-path`, as the wired files app uses at `apps/files/index.html:218-220`), so they are bound by **nothing** — the toolbar/status imply a working editor that cannot open or save. Meanwhile the **real** `createEditorAppViewModel` (`ui_kits/desktop/viewmodels/apps/editor-app.ts:116`, driven by a `FilesCapabilityPort`) is never wired.

Remove the placeholder pretense and ship real behavior:
1. **Rename the editor HTML bind/action attributes to the binder scheme** in `apps/editor/index.html`: `data-view-model="editor-app"` → the binder's view-model attribute; each `data-bind="document.*"` → `data-vita-bind-text="editor.*"`; each `data-action="<x>"` → `data-vita-action="editor.<x>"`. No raw `data-bind` / `data-action` / `data-view-model` attribute may remain in the file.
2. **Add `apps/editor/editor-launch.ts`** exporting a pure launch/hydrate function that instantiates `createEditorAppViewModel` with an **injected** `FilesCapabilityPort` (+ grant) and returns the live view-model wired to the binder field names used in the HTML — so `editor.title`, `editor.path`, `editor.language`, `editor.dirty`, `editor.cursor`, `editor.content`, `editor.lineNumbers` reflect the view-model snapshot, and `editor.open/undo/redo/save` dispatch to the view-model. The hydrated snapshot must come from the injected port — NOT the hardcoded HTML sample strings.
3. The static sample strings (`Untitled`, `No file open`, `Plain Text`, `Saved`, `Ln 1, Col 1`, gutter `1`) remain only as inert default DOM text; the live values are produced by the view-model after hydrate.

Import the SDK exactly as the other apps/view-models do; use ONLY public `@vita/desktop-sdk` exports. Pure, headless interaction logic — no DOM rendering engine, no CEF.

## User value
Turns a fake editor chrome (fields nothing updates) into a real editor wired to the files capability — open/save/undo/redo and the status line are live and capability-mediated, instead of a mockup that cannot open or save.

## Non-goals
- NO new visual design (the HTML layout/CSS is the design of record — only the binding attributes change). NO DOM/CSS rendering engine or CEF. NO re-implementing `createEditorAppViewModel` or the files port — consume them. NO ambient I/O.

## Acceptance
`acceptance_command` passes. `sdk/typescript/test/ui-kits/editor-launch.test.ts` (deterministic, headless) MUST assert, against the real `apps/editor/index.html` contents and a **fake injected** `FilesCapabilityPort`:
- **Placeholder is GONE:** the `index.html` source contains NO `data-view-model`, NO `data-bind=`, and NO `data-action=` attribute; and it DOES contain `data-vita-bind-text="editor.path"`, `data-vita-bind-text="editor.title"`, and `data-vita-action="editor.save"` (binder scheme present).
- **Real behavior present (data from the injected port, not the HTML sample):** launching via `editor-launch.ts` with a fake `FilesCapabilityPort` whose read returns a known document (path/content/language distinct from the placeholders) yields a view-model whose `editor.path` / `editor.title` / `editor.content` equal the **port's** values — and assert they are NOT the literal placeholder strings `"No file open"` / `"Untitled"`.
- **Honest fail-closed:** launching with NO files grant (or a fake port that denies the grant) makes `save`/`open` fail closed (surface the view-model error) rather than silently pretending `Saved` — assert the error path, not a hardcoded success.
