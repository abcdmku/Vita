## Objective
Land the **Phase-3 EXIT-GATE** deliverable: *"Full data restore to replacement x86 … nodes"* (spec §21 Phase 3
exit gates, line 1100; FR-015 "Back up and restore a complete node"). P1-066 (merged) gave us `backup.archive`
(content-addressed create→verify→restore of `/var` authoritative data — capsule StateDirectory volumes
`/var/lib/vita/runtime/volumes` + the agent state root `/var/lib/vita-agent` holding `pds-sync-state.json` and
`backup-policy-desired-state.json`). But that round-trip restores back onto the SAME node, into a side
destination dir. The exit gate is the **cross-node, replacement-node** case: a backup taken on **node A**
restores onto a **FRESH node B** (a clean QEMU image with an EMPTY `/var`) and **B comes up with A's data
intact** — the capsule volumes, the PDS sync-state, and the agent config that lived on A are present and
verified on B.

This is a THIN vertical slice that adds a **`restore.replacement` privileged Go capability** (a SECOND
capability in a new `agent/capabilities/restore` package — built ON TOP of `backup.archive`, reusing its
verify-before-apply + atomic single-commit-point machinery; do NOT re-roll digesting/manifest logic) plus the
on-device orchestration + a fresh-/var QEMU sim that proves the gate. Concretely:

1. **`restore.replacement` capability (new, ON TOP of `backup.archive`).** Exposes a CLOSED typed op via the
   existing typed-request pattern (mirror `agent/capabilities/backup/archive.go`'s `ApplyRequest` +
   `jsonsafe.DecodeStrict` + `RejectDuplicateObjectKeys`; gate the linux build with `//go:build linux` and a
   `restore_unsupported.go` stub exactly like `archive_unsupported.go` so cross-platform `go build` stays
   green). A single `replace` operation takes a re-validated request `{ backupSource, expectFrom?, plan }`:
   - `backupSource` = a validated ABSOLUTE path to an EXTERNAL/portable backup target (the directory written
     by `backup.archive` create on node A — a `manifest.json` + `objects/` content store; the SAME on-disk
     format, no new format). This is an attached-volume / portable path, NOT cloud, NOT network.
   - `plan` = a CLOSED, validated list of `{ name, backupRoot, destinationRoot }` mappings naming WHICH source
     roots from the backup manifest land at WHICH live `/var` destination on node B (default = the two
     canonical roots: `capsule-volumes` → `/var/lib/vita/runtime/volumes`, `vita-agent` →
     `/var/lib/vita-agent`). Destinations are FIXED, code/grant-controlled keys re-validated by agentd — NEVER
     raw runtime text used directly as a path.
   - The op **VERIFIES FIRST** (delegate to `backup.archive`'s verify: recompute every object digest AND the
     manifest digest against `backupSource`). ONLY if verification passes does it materialize each mapped root
     into its live destination via `backup.archive`'s proven staging-dir → fsync → atomic rename / RENAME_EXCHANGE
     single-commit-point (so a crash mid-restore never leaves a half-restored authoritative tree; each
     destination is replaced as one commit point with a restoring `Undo`). If verify FAILS, restore REFUSES and
     mutates NOTHING (fail-CLOSED). Restoring onto an EMPTY/absent destination (the fresh-node-B case) uses the
     plain `os.Rename` first-time path (no pre-existing dest to exchange) that `archive.go` already handles.
   - `expectFrom` (optional): a node-identity assertion. If the backup manifest records the originating node's
     identity and the request supplies `expectFrom`, agentd asserts the backup REALLY came from the expected
     node A and REFUSES on mismatch (fail-closed). If the manifest carries no identity, treat `expectFrom` as
     absent-not-empty (do not synthesize a match). Keep this minimal — it is a guard, not a new identity system.
   - Returns a typed status: which roots restored, total files, `from`/`to` node markers, and per-mapping
     verified=true. A no-op / always-ok restore MUST fail the suite.
   - **Register it** by adding `restore.NewCapability()` to the `capabilities.NewRegistry(...)` constructor list
     in `agent/cmd/agentd/main.go:53` (that is where `backup.NewArchiveCapability()` is wired — NOT in
     `capabilities/registry.go`, which only defines the Registry type). Add the `restore` import; do NOT disturb
     the existing entries.

2. **On-device replacement-restore orchestration (`restore-replacement.ts`).** A thin driver (mirror
   `os/.../ts/vita/backup.ts`) that, over the existing agentd unix transport, asks `restore.replacement` to
   consume an EXTERNAL backup and materialize it into the live `/var` roots, then PROVES the data is intact by
   re-reading the restored roots' content digests and confirming they match the backup MANIFEST's recorded
   digests (the P1-066 REVISION-5 lesson: measure round-trip integrity against the POINT-IN-TIME manifest, not
   a live mutating source). Emit a MEASURED marker (never synthesized):
   `VITA-RESTORE-REPLACEMENT: from=A to=B restored=OK verified=OK files=<n> id=<manifestDigestPrefix> status=OK`
   gated on: the restore committed AND every restored entry's bytes hash-match its manifest digest AND the
   live destination roots on B now contain A's data. Plus a fail-CLOSED reject
   `VITA-RESTORE-REPLACEMENT-REJECT: reason=<sanitized-step, e.g. verify_digest_mismatch | from_mismatch |
   non_absolute_source | unknown_op> status=OK` for a forced-invalid case (a tampered external backup whose
   recorded digest does NOT match its content → restore REFUSES), and
   `VITA-RESTORE-REPLACEMENT-ERROR: reason=<specific step+errno> status=FAILSAFE` on transport/setup failure.
   Keep ALL prior markers intact (the VITA-TS→EVAL→PREVIEW→EXPLAIN→CONNECT→STATE→APPLY→CAPSULE-*→PDS→FILES→
   PDS-REPO→DRIFT→BACKUP chain).

3. **The replacement-node QEMU sim (orchestrator host-verify — the REAL floor).** Prove the gate end-to-end on
   Borg51, simulating two nodes with a fresh-/var reboot consuming an EXTERNAL backup:
   - **Node A leg:** boot normally; the merged `VITA-BACKUP` round-trip already creates a content-addressed
     backup of A's authoritative `/var` data at the backup target. Stage that backup onto an EXTERNAL/portable
     location that survives B's wipe — EITHER a second virtio "backup" disk attached to both boots, OR a path
     that is preserved while `/var` is wiped (e.g. the backup target on the persistent backup volume that is
     NOT the wiped `/var` data partition). Make A's data DISTINGUISHABLE (a known sentinel under a capsule
     volume + a known PDS sync-state cursor) so "B has A's data" is checkable, not vacuous.
   - **Node B leg (the replacement):** boot a FRESH node B = the SAME image with an EMPTY `/var` (a freshly
     repartitioned/wiped `vita-data`, no capsule volumes, no agent state). On B's first boot, the
     `restore-replacement` driver consumes the EXTERNAL backup and restores A's roots into B's live `/var`.
     The serial then shows `VITA-RESTORE-REPLACEMENT: from=A to=B restored=OK verified=OK …` ONLY if B really
     came up with A's sentinel + A's PDS cursor present and digest-verified.
   - Add a `wsl-verify.sh` mode (e.g. `restore-replacement`) that drives this two-leg (or fresh-/var-reboot
     consuming the external backup) flow and gates PASS on the MEASURED marker, and assert the forced-tampered
     reject fires. The prior full marker chain still PASSES on the node-A boot.

## User value
This IS the Phase-3 exit gate (spec §21, line 1100; FR-015): the owner can lose node A entirely (dead disk,
stolen, fried) and bring a clean replacement node B up to A's state from an independent backup — capsule app
data, the AT-Proto PDS sync-state, and node config all intact and integrity-verified. Disaster recovery is the
floor of a "personal node" being trustworthy with the owner's only copy of their data. Backup (P1-066) was
half the promise; restore-to-a-fresh-node is the half that makes a backup worth taking.

## Performance & security constraints
- **Security model (encode it):** the TS runtime is UNPRIVILEGED; ALL privileged FS mutation (reading the
  external backup, writing/swapping the live `/var` destination roots) belongs ONLY to the narrow Go agentd.
  agentd acts ONLY from a RE-VALIDATED typed request (validated absolute `backupSource`, a CLOSED
  code/grant-controlled destination map, optional `expectFrom`) — NEVER from raw runtime text used directly as
  a path. The op set is CLOSED; arbitrary commands/paths are rejected; unknown/invalid ⇒ fail-CLOSED.
- **Verify-before-apply, fail-CLOSED:** restore VERIFIES the external backup's content + manifest digests
  before mutating B; a tampered/bit-rotted backup is REFUSED and NOTHING on B is changed. A guard over
  untrusted input MUST NOT throw at the trust boundary (a throw is a DoS — return a rejection); prove with a
  malformed/cyclic regression.
- **Atomicity / single commit point (R3, AGENTS.md §2):** each destination root is published via the proven
  staging-dir → fsync → atomic `os.Rename` (empty/first-time dest) or `RENAME_EXCHANGE` (existing dest) single
  commit point; no fallible step after the irreversible effect; exactly two outcomes (success + working Undo,
  or error with the live tree UNCHANGED) — never mutated-but-reported-failed.
- **NO real keys / TPM / recovery keys** — owner-held (§16). TEST data + TEST fixtures only; never generate or
  commit production key material. The backup payload is NOT encrypted this slice (non-goal). NO inline secret
  material in restore metadata/markers (reuse `containsInlineSecretMaterial`; `markerToken`-sanitize every
  reject reason so no path/secret leaks to the serial).
- **Determinism / integrity:** content-addressed (the backup id IS the manifest digest); the measured marker is
  gated on restored-bytes == manifest-digests, never on status/count alone.
- **No remote imports; vendored deps only; offline; no package lifecycle scripts; lockfiles mandatory.**
- R3 (privileged TCB mutation of authoritative data + a boot/recovery path) → **reviewer gate**
  (`npm run review -- P1-090`) `VERDICT: approve` AND independent host-verify before merge.
