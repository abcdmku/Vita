## Objective
Implement the desktop SDK `requestFile` host-bridge port against the real agentd **files** capability
(`agent/capabilities/files/files.go`) so the flagship Files app reads/writes real
`/var/lib/vita/files` content. The port takes a surface `FilesRequest` (`sdk/typescript/src/files-grant.ts:41`),
talks to the agentd files responder, and returns a `FilesResponse` / `FilesErrorResponse`
(`sdk/typescript/src/files-grant.ts:57`, `:65`) — mapped **1:1** onto the Go `Response`/`Entry` shape
(`agent/capabilities/files/files.go:81`, `:89`).
- Support all four ops `list | read | write | stat` (Go `OperationList/Read/Write/Stat`,
  `files.go:37`). Surface `op/grant/path/data` map to the Go `Request` fields (`files.go:64`).
- Map response fields exactly: `entries[]` ({name, kind, size, mtime}); `read` -> base64 `data` +
  `size` + `mtime`; `stat` -> `kind`/`size`/`mtime`; `write` round-trips to `kind: "file"` + `size`.
  Preserve the Go `Kind` domain `file | dir | symlink-skipped` onto `FilesEntryKind`
  (`files-grant.ts:48`, mirrors `files.go:46`).
- Enforce `files.read` for `list/read/stat` and `files.read`+`files.write` for `write` at the bridge
  (grant-mediated, fail-closed). Honor `MaxFileBytes` (8 MiB, `files.go:21`): oversize reads/writes
  surface a `FilesErrorResponse`, never a partial payload.
- Add a narrow surface guard `isFilesResponse(value): value is FilesResponse` and export it next to
  the existing types in `sdk/typescript/src/files-grant.ts`; every success path returns a value that
  passes it and every failure path returns a `FilesErrorResponse` (which does NOT pass it).
- Fail closed: any agentd error / unknown grant / denied role / missing grant / not-found / traversal
  becomes a `FilesErrorResponse` with `{ code, message }` carried from the Go `RequestError`
  (`files.go:115`); never throw across the port boundary, never leak the host transport object.
- Import the SDK exactly as the existing host-bridge code does; use ONLY public exports; injected
  transport (no ambient I/O). Put the port impl under `sdk/typescript/src/desktop-sdk/host-bridge/`
  and the test at `sdk/typescript/test/ui-kits/files-backend.test.ts`.

## User value
Makes the Files app real: browse/open/save operate on actual on-device `/var/lib/vita/files` content
through the capability-mediated agentd files responder, instead of static mock data.

## Non-goals
- NO DOM/CSS/rendering/CEF and NO new visual design (the Files HTML is the design of record).
- Do NOT re-implement the Go files handler, the grant resolver, or scope/path-traversal logic — the
  bridge consumes the agentd responder, it does not re-derive its rules.
- No new network surface; no changes to `agent/capabilities/files/*.go`.

## Acceptance
`acceptance_command` passes. Deterministic, headless test (`files-backend.test.ts`) drives the port
against a **fake agentd files responder** and asserts the 1:1 mapping and fail-closed behavior:
- `list` -> `entries[]` with name/kind/size/mtime (folders/files), deterministic;
- `read` -> base64 `data` + `size` + `mtime`;
- `write` round-trips (request data echoed back on a follow-up `read`) -> `kind: "file"` + `size`;
- `stat` -> `kind`/`size`/`mtime`;
- a symlink child surfaces `kind: "symlink-skipped"`;
- oversize (> `MaxFileBytes`), denied role, missing/unknown grant, and not-found each return a
  `FilesErrorResponse` that fails `isFilesResponse`, while every success value passes it.
Typecheck clean.

## Security/constraints
- Capability-mediated, fail-closed; `files.read`/`files.write` grants enforced at the bridge; injected
  transport only (no ambient I/O); pure mapping otherwise.
- Errors are reduced to `{ code, message }` — no host objects, stack traces, or absolute paths leak.
- No remote imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons.
- `allowed_network: false`.
