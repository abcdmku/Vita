## Objective
Author **ADR-0015** (`architecture/adr/0015-desktop-host-bridge.md`, status **Proposed**) that fixes the
load-bearing architectural gap in the live desktop: `createSurfaceHost(transport)`
(`ui_kits/desktop/runtime/host-bridge.ts:180`) marshals every desktop SDK call into a
`SurfaceHostRequest` and forwards it across a `SurfaceHostTransport`, but **there is no counterparty on the
host side** — nothing answers the request, and `ui_kits/desktop/package.ts:161` `mount(host: DesktopHost)`
is never handed a real, backend-wired `DesktopHost`. The ADR decides the host-side design, not the code.
It MUST decide and record:
- **(a) Where the host-side `DesktopHost` lives** — the process/module that owns the transport counterparty
  (the CEF browser-process side that receives a `SurfaceHostRequest` and produces the
  `DesktopHostResult`/`ShellResult`/response JSON the bridge's guards expect).
- **(b) The CEF<->host channel transport** — choose the concrete carrier (`CefProcessMessage` IPC vs. an
  injected `window.vitaDesktopBridge`) and how it binds to one of the renderer globals the bootstrap
  already probes (`bootstrap.ts:67` `TRANSPORT_GLOBALS` = `vitaDesktopBridge`, `vitaHostBridge`,
  `vitaBridge`, `__vitaDesktopBridge`), preserving the JSON-only wire contract enforced by
  `host-bridge.ts` (`snapshotJson`/`MAX_JSON_DEPTH`, finite numbers, plain objects).
- **(c) The backend port map** — every `SurfaceHostMethod` (`host-bridge.ts:44`) routed to its host
  backend: `launchApp`->capsule.execute, `stopApp`->capsule.stop, `requestFile`->files capability,
  `readSetting`/`previewSetting`/`applySetting`->settings store, `emitLauncherIntent`->launcher,
  `postNotification`/`registerTrayItem`->shell notification/tray sink, `registerComponent`/`previewShell`/
  `applyShell`/`rollbackShell`/`currentShell`->compositor/shell layout engine, `readTheme`->theme store.
- **(d) Capability enforcement stays in the host proxy as the single point** — the host-side proxy is the
  one place that checks each method against the package's `capabilityGrants`
  (`DEFAULT_PACKAGE_GRANTS`, `host-bridge.ts:110`) and fails closed, mirroring the renderer's fail-closed
  contract. No backend trusts the renderer's claims.
- **The slice DAG**: enumerate the follow-on implementation slices (host proxy module, per-backend
  adapters, channel binding, conformance tests) and their dependency edges so the build can fan out.

Put the ADR at `architecture/adr/0015-desktop-host-bridge.md`. Cross-link ADR-0013
(`0013-desktop-hydration.md`) and ADR-0014 (`0014-cef-live-render.md`). Add a small deterministic guard
test at `sdk/typescript/test/ui-kits/adr-0015.test.ts` that asserts the ADR exists and contains the
required sections (so an empty branch fails).

## User value
Closes the one architecture decision that currently blocks a real, capability-enforced desktop: it tells
every follow-on worker exactly where the host `DesktopHost` lives, how CEF and the host talk, which backend
each method hits, and where enforcement sits — turning the orphaned `createSurfaceHost` transport into a
buildable, fan-outable plan.

## Non-goals
- NO implementation of the host proxy, adapters, channel binding, or backends — this is a decision record.
- Do NOT modify `host-bridge.ts`, `bootstrap.ts`, `package.ts`, or any runtime/SDK source.
- Do NOT change the JSON wire contract or the `SurfaceHostMethod` set; the ADR documents them, not edits.
- No new visual design; no DOM/CSS/CEF code.
