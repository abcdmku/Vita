## Objective
W5-S5 (ADR-0010's BLOCKING GATE before ANY untrusted OCI capsule runs): PROVE that the OCI hardened transient unit's
cgroup caps (`MemoryMax`/`CPUQuota`/`TasksMax` from the manifest `resourceLimits`, already composed by P1-052) actually
ENFORCE against a deliberately HOSTILE workload on a REAL node — and the NODE SURVIVES. An arbitrary OCI binary will
fork-bomb / OOM / CPU-spin with intent, so "recorded but enforcing?" must become "confirmed enforcing."

Bake a HOSTILE first-party OCI rootfs (`os/x86_64/ts-overlay/usr/lib/vita/capsules/local.hostile-oci.capsule/`) — a
trivial STATIC binary that on start does all of: (a) fork/clone in a tight loop (hit TasksMax), (b) allocate well past
MemoryMax, (c) spin CPU. Its manifest sets TIGHT `resourceLimits` (e.g. MemoryMax=64M, TasksMax=16, CPUQuota=25%).
Run it via the P1-052 OCI launcher. agentd CONFIRMS enforcement (introspect the unit's cgroup: `memory.max` set +
`memory.events` shows max/oom hit; `pids.max` set + `pids.events` max hit; `cpu.max` set/throttled — OR observe the
workload OOM-killed/fork-blocked) and emits:
`VITA-CAPSULE-OCI-LIMITS: id=<id> mem=enforced tasks=enforced cpu=enforced status=OK`. If a cap is NOT enforcing →
`VITA-CAPSULE-OCI-LIMITS: ... status=FAIL` (a cap not actually throttling is a BLOCKING gate failure). Keep all prior markers.

CRITICAL: the NODE MUST SURVIVE — the hostile capsule is contained/killed by its cgroup, the rest of the control plane
(other markers, agentd) keeps running. If the node OOMs/locks, the gate FAILS.

## User value
The safety gate that makes running untrusted OCI workloads sound: a hostile container cannot exhaust the node — its
cgroup caps demonstrably throttle/kill it while the node stays healthy. This is the precondition ADR-0010 requires
before any untrusted OCI capsule is permitted.
