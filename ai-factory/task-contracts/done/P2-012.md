## Objective
`previewNetworkChange(current, desired)` (controller/network): given current + desired `NetworkConfig`
(the P8-001 SDK model), validate BOTH via `validateNetworkConfig`, then compute a typed, fail-closed
**change diff** — WITHOUT applying anything: interfaces added/removed/modified, and firewall rules
added/removed (keyed by protocol+port+sourceCidr). Surface a `wideningInbound` flag when the desired
firewall ADDS an allow rule not present in current (so the operator sees the exposure increase).
Return `{ valid, diff, wideningInbound, rejections }`. Fail-closed: invalid either side ⇒ typed rejection,
no diff, never a throw.

## User value
The management-plane "what will this network change do, and does it widen inbound exposure" view
(FR-017/006) — on validated inputs only, before any host apply.

## Non-goals
- No real nftables/network apply, no agent call, no network. Validate + diff only. Do NOT modify the
  P8-001 `network-model`; import it.

## Dependencies
P8-001 (network model: validateNetworkConfig), P0-015 (safeNormalize, via the model). Merged.

## Acceptance tests
`acceptance_command` — `network-preview.test.ts`: identical configs ⇒ empty diff, wideningInbound false;
an added allow rule ⇒ in the diff + wideningInbound true; removed rule / changed interface ⇒ classified;
invalid current OR desired ⇒ typed rejection (no diff, no throw); hostile input ⇒ fail-closed. Orchestrator
also runs `npm run typecheck`.

## Performance & security constraints
Deterministic, no I/O/network. Fail-closed (reuse `validateNetworkConfig`; never throw). `wideningInbound`
correctly flags exposure increases. Strict TS (no `any`). R2 → reviewer-gated.
