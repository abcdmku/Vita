## Objective
A pure, standalone SDK type model + fail-closed validator for the node's identity (spec: AT Protocol
identity / PDS): `identity-model.ts` exports the types (`Did`, `Handle`, `PdsConfig`,
`IdentityConfig`, `SigningKeyRef`, etc.) and `validateIdentityConfig(input): Result`. NEW validator ⇒
use `safeNormalize` for the boundary, then validate structure on the trusted plain value.
- **Syntax validation**: `Did` must match a supported DID method (`did:plc:` / `did:web:`) with a
  well-formed identifier; `Handle` must be a valid domain-style handle (DNS labels, no scheme/path);
  reject anything else fail-closed.
- **Secrets-as-references (§13.1)**: signing/rotation keys are referenced by id/handle only — reject any
  config that embeds literal key material (PEM/seed/private-key/long blobs).
- Standalone module — do NOT edit any shared barrel/index file.

## User value
The typed contract the PDS, controller, and Go identity capability will share — lets identity
desired-state be authored + validated deterministically before it touches the host or the network.

## Non-goals
- No real DID resolution, no network, no PDS server, no crypto/key generation, no agent code. Types +
  pure validators only. No shared-index edits.

## Dependencies
P0-015 (`safeNormalize`) — merged.

## Acceptance tests
`acceptance_command` — `identity-model.test.ts` covers: valid `did:plc:`/`did:web:` + handle validate;
malformed DID/handle rejected with clear paths; embedded key material rejected (§13.1); fail-closed on
hostile input via safeNormalize. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Pure/deterministic, no I/O/network. Fail-closed via `safeNormalize`. §13.1 secrets-as-references. Strict
TS (no `any`/suppressions). R1 → orchestrator-reviewed.
