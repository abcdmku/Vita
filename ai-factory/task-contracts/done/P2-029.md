## Objective
`runOperatorSession(transport, desiredChangeSet)` (controller/workflow): a thin orchestration that exercises
the controller management plane END-TO-END against an injected agent transport (no real socket), composing
the EXISTING units to prove they cohere. Given `transport: (path) => Promise<{status, body}>` and a desired
`NodeChangeSet`:
1. `fetchNodeSnapshot(transport)` (P2-024) ⇒ the whole-node `/state` snapshot.
2. `fetchAuditTrail(transport)` (P2-023) ⇒ the validated `/audit` trail; feed it to `summarizeAuditLog`
   (P2-021).
3. Build a `NodeOperationsReport` via `summarizeNodeHealth` (P2-019) over a health input read from the
   snapshot/transport + `buildNodeOperationsReport` (P2-022).
4. `previewNodeChangeSet(currentChangeSet, desiredChangeSet)` (P2-028) where `currentChangeSet` is the
   caller-supplied current state (the snapshot→change-set mapping is out of scope — accept current as a
   `NodeChangeSet` arg too).
Return a single typed `{ ok: true, snapshot, auditSummary, operationsReport, changePreview } | { ok: false,
stage, reason }` — fail-closed: if ANY stage returns its fail-closed result, surface `{ ok:false, stage }`
naming which stage failed, never throwing. A transport error at any GET ⇒ `{ ok:false, stage }`.

## User value
Confidence the controller plane composes correctly as an operator workflow (FR-005/008) — discovery →
state snapshot → audit/health report → whole-node change preview — and that one stage's fail-closed result
short-circuits the session cleanly, never throwing. The controller-side counterpart to the agent lifecycle
scenario (P7-011).

## Non-goals
- No real HTTP/network (inject the transport). No new domain logic — ORCHESTRATE the existing units; do NOT
  modify any imported module. No apply submission (preview only).

## Dependencies
P2-024 (snapshot client), P2-023 (audit client), P2-021 (audit viewer), P2-019 (health monitor), P2-022
(operations report), P2-028 (change-set preview). All merged.

## Acceptance tests
`acceptance_command` — `operator-session.test.ts`: a happy-path fake transport (valid /state, /audit, health)
+ a valid desired change-set ⇒ `ok:true` with a coherent snapshot + audit summary + operations report +
change preview; a transport returning 503 for /audit ⇒ `ok:false, stage:"audit"` (no throw); an invalid
desired change-set ⇒ `ok:false, stage:"preview"`; a transport that throws ⇒ `ok:false` (no throw); the
session NEVER throws for any input. Orchestrator runs `npm run typecheck`.

## Performance & security constraints
Deterministic; no real I/O (injected transport). Fail-closed: any stage's fail-closed result short-circuits
with a named stage; never throws. Strict TS (no `any`). R2 → reviewer-gated.
