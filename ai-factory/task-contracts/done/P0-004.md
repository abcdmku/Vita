## Objective
Implement `diffPlans(before: CanonicalPlan, after: CanonicalPlan): PlanDiff` (spec §8.2 step 6,
FR-006 "Show plan diff before applying system changes"). Provide:
- A structured `PlanDiff` describing what changed: a list of changes each with a JSON-pointer-style
  `path`, a `kind` of `"added" | "removed" | "changed"`, and (for changed) `before`/`after` values.
- Deterministic ordering of changes (stable by path) so the same plans always yield the same diff.
- `renderPlanDiff(diff: PlanDiff): string` — a concise human-readable rendering (e.g. `+ apps/atproto-pds`,
  `~ storage/dataVolume/encryption: optional → required`).

Build on the `CanonicalPlan`/`normalize` from P0-001. Pure, no I/O.

## User value
The plan diff is what a user inspects before applying a change (spec §3.3, §8.4 "the plan is
inspectable before application"). It must be accurate and stable.

## Non-goals
- No apply/transaction logic, no Go-agent calls, no signing.
- Don't re-implement normalization — consume `CanonicalPlan` from P0-001.

## Dependencies
P0-001 (uses `CanonicalPlan`).

## Acceptance tests
`acceptance_command`. `sdk/typescript/test/diff.test.ts` must prove:
1. Identical plans → empty diff.
2. Added / removed / changed entries are each detected with the correct `path` and `kind`.
3. The diff is deterministic (same inputs → identical structured diff and identical rendered string).
4. `renderPlanDiff` output is stable and reflects every change.

## Performance & security constraints
Pure/deterministic, no I/O (spec §8.2). Node built-ins only.
