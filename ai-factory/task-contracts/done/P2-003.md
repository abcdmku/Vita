## Objective
Extend the controller API (R2 → reviewer-gated) with app endpoints that tie together the package
contract (P1-001) and the permission broker (P2-002):
- `listApps(): AppSummaryResponse` — installed/available apps with id, version, status (stub data
  fine; types real).
- `previewAppInstall({ packageContract, policy }): AppInstallPreviewResponse` — validate the package
  contract via `validatePackageContract` (P1-001), run `decideGrants` (P2-002) against the supplied
  node `policy`, and return a typed preview: `{ ok, validation, grantedCapabilities,
  deniedCapabilities, reasons }`. This is the surface that lets a user **understand exactly what
  data, network, and compute an app would receive** before installing (spec §28.5, §11). Invalid
  contract or malformed input ⇒ typed error result, never a throw (fail-closed; intrinsic-safe per
  AGENTS.md — the broker already normalizes, but the controller must not throw on bad input either).

## User value
"Understand exactly what data/network/compute an app receives" is a definition-of-success item
(spec §28.5). This endpoint makes the grant decision visible at the control surface.

## Non-goals
- No actual install/apply (FR-010 install action is later); this is **preview** only.
- No transport/HTTP; extend the in-memory dispatcher. No new deps.

## Dependencies

## Acceptance tests
`acceptance_command` (controller suite — existing tests must still pass, no weakening). Add:
1. `previewAppInstall` with a valid least-privilege app returns `ok:true`, a validation pass, and the

3. An invalid/malformed package contract (incl. method-shadowed/partial) returns a typed error,

## Reviewer revision (round 2 — BLOCKING, from P2-003.review.md)
Two fail-closed gaps at the controller boundary:
1. **Don't equate "no denials" with success.** `previewAppInstall` returns `ok:true` when
   `decision.denied.length === 0`, but an app requesting ZERO capabilities (empty data.volumes /
   network) + a malformed/partial policy yields no denials → silently accepted. **Validate the node
   `policy` shape itself** (fail-closed: malformed/partial policy ⇒ typed error, not ok) before
   trusting the decision; success requires a well-formed policy AND validation pass AND no denials.
2. **Never throw at the controller boundary.** `clonePlainArray()` reads `value.length` from
   untrusted input outside a catch, and `previewAppInstall` has no outer catch — a hostile **proxy**
   whose `.length`/element getter throws makes the API throw instead of returning an
   `AppInstallPreviewResponse`. Wrap all untrusted reads + the whole `previewAppInstall` so ANY thrown
   error becomes a typed error result. Prefer delegating untrusted-input handling to the broker's
   normalizer rather than re-cloning in the controller (also addresses the duplication note).
3. **Regression tests** at the controller boundary: a hostile proxy/throwing-getter contract or
   policy → typed error (no throw); a valid zero-capability app + malformed policy → typed error (not
   ok:true). Keep existing tests.
