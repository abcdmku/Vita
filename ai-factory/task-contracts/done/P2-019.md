## Objective
`summarizeNodeHealth(report, thresholds)` (controller/health): given a node health report (the P0-023
SDK model) + resource-usage thresholds (warn fraction per resource, 0<f<1), validate the report via
`validateNodeHealth`, then produce a typed, fail-closed **issue summary**: overall status
("ok"|"warning"|"critical"), the list of degraded/failed capabilities, and the resources whose
`used/total` exceeds the warn threshold (with the fraction). Status = critical if any capability is
`failed`; warning if any capability is `degraded` OR any resource exceeds its threshold; else ok. Return
`{ ok: true, status, capabilityIssues, resourceIssues } | { ok: false, rejections }`. Fail-closed: an
invalid report OR invalid thresholds (out of (0,1)) ⇒ typed rejection, never a throw.

## User value
The dashboard's "is this node OK, and what's wrong" rollup (FR-008) — on a validated health report, with
thresholds the operator sets; surfaces failed/degraded capabilities + resource pressure.

## Non-goals
- No real metric collection, no agent call, no network. Validate + summarize only. Do NOT modify the
  P0-023 `node-health-model`; import it.

## Dependencies
P0-023 (node health model: validateNodeHealth), P0-015. Merged.

## Acceptance tests
`acceptance_command` — `health-monitor.test.ts`: a healthy report under thresholds ⇒ status ok, no
issues; a report with a degraded cap ⇒ warning; a failed cap ⇒ critical; a resource over its threshold ⇒
warning + listed with the fraction; an invalid report ⇒ typed rejection (no throw); thresholds out of
(0,1) ⇒ rejection; hostile input ⇒ fail-closed. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Deterministic, no I/O/network. Fail-closed (reuse `validateNodeHealth`; never throw); validate thresholds.
Strict TS (no `any`). R2 → reviewer-gated.
