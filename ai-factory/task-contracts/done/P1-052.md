## Objective
W5-S1 (ADR-0010 slice 1, ACCEPTED): the node runs an OCI capsule. Extend `capsule.execute` so a `packageClass=oci-service`
capsule launches a baked, FIRST-PARTY, pre-assembled OCI rootfs as a HARDENED systemd transient unit via systemd's
native **`RootDirectory=`** — NO separate OCI runtime binary (crun/runc). Reuse the EXACT ADR-0009 hardening profile
(DynamicUser, empty CapabilityBoundingSet/AmbientCapabilities, NoNewPrivileges, ProtectSystem=strict, ProtectHome,
RestrictNamespaces, RestrictAddressFamilies, SystemCallFilter=@system-service, PrivateDevices/Tmp, cgroup
MemoryMax/CPUQuota/TasksMax from the manifest `resourceLimits`) with ONLY these deltas vs ts-service:
- `RootDirectory=<agentd-managed RO rootfs>` (the workload sees the image as `/`, read-only).
- `ExecStart=` is the image entrypoint — agentd-resolved from the validated manifest, an ABSOLUTE in-rootfs path with
  an argv allowlist (control-char/shell-metachar rejected; NEVER via a shell), replacing the pinned Deno argv.
- Drop the Deno-specific `pkey_*` seccomp add (image binaries don't need it).

NO fetch/assembly yet (that's W5-S2/P1-053): use a BAKED first-party rootfs under
`os/x86_64/ts-overlay/usr/lib/vita/capsules/<oci-id>/rootfs/` — a trivial static entrypoint (e.g. a tiny statically
linked binary or a baked busybox-style `/init` that prints a readiness line + idles, NO dynamic libs / no network).
Markers: `VITA-CAPSULE-OCI-EXECUTED: id=<id> unit=<unit> uid=<dynuid> root=ro health=OK status=OK`;
`VITA-CAPSULE-OCI-EXECUTE-REJECT: reason=<code> status=OK` (non-oci-service class / absent rootfs / invalid entrypoint →
fail closed, NO unit started); `VITA-CAPSULE-OCI-EXECUTE-ERROR: status=FAILSAFE`.

Concretely:
- `agent/capabilities/capsule/oci.go` (new) holds the OCI unit composition; `execute.go` widens the
  `ExecutionManifest.Validate` packageClass gate to accept `oci-service` and branches: ts-service → existing Deno path,
  oci-service → the RootDirectory path. agentd composes the unit ONLY from the re-validated on-disk manifest (never raw
  runtime text); the runtime proposes only `{id,version,integrity}`.
- Reuse the existing StateDirectory-volume + health-supervisor + transactional-undo machinery unchanged.
- TS side (`main.ts`): propose execute for the baked OCI capsule → `VITA-CAPSULE-OCI-EXECUTED`; a forced-invalid
  (absent rootfs) → `VITA-CAPSULE-OCI-EXECUTE-REJECT`. KEEP all prior markers (ts-service execute/fetch/health/volume).

## User value
The node runs OCI container images (the standard packaging for existing server software, spec §13.1) — each in the
SAME hardened, unprivileged, cgroup-capped systemd jail proven for ts-service, composed by the privileged agent from a
validated manifest. systemd is the sole jailer; the image is just a rootfs + entrypoint under our policy.

## REVISION REQUIRED (host-verify FAILSAFE — 2026-06-23)
Review APPROVED (static), ts-service chain PASSES, but the BOOT FAILSAFEd: `VITA-CAPSULE-OCI-EXECUTE-ERROR:
reason=apply_failed status=FAILSAFE` — the `RootDirectory=` transient unit FAILS TO START on the real node, and the
generic `apply_failed` hides WHY (systemd's reason went to the journal, not the serial). Extend THIS branch
(task/P1-052); keep ts-service working.

BLOCKING:
1. **DIAGNOSABILITY FIRST.** On OCI unit start/run failure, agentd MUST capture + emit the SPECIFIC reason — query the
   transient unit's `Result` / `ExecMainStatus` / `ActiveState`/`SubState` (or the `StartTransientUnit` D-Bus job
   error) and surface it as `VITA-CAPSULE-OCI-EXECUTE-REJECT: reason=<specific>` (e.g. `exec_failed`,
   `namespace_setup_failed`, `permission_denied`, `rootfs_inaccessible`) — NOT generic `apply_failed`. Without this the
   next boot is undebuggable.
2. **Fix the RootDirectory= + DynamicUser + hardening composition so the baked rootfs actually runs.** Known
   requirements (the review flagged the DynamicUser/rootfs-access one): (a) `MountAPIVFS=yes` so `/proc`,`/sys`,`/dev`
   exist inside the new root (set it explicitly for the OCI path); (b) the DynamicUser (transient uid ≠ the agentd
   owner) must be able to READ + EXECUTE the rootfs tree AND `/init` — the baked rootfs dirs + entrypoint must be
   world-read/exec (e.g. 0755), since `RootDirectory=` drops into the DynamicUser inside the (RO) rootfs; (c) verify
   `ProtectProc`/`ProcSubset`/`ProtectHome`/`PrivateDevices`/`RestrictNamespaces`/`ProtectSystem=strict` all COMPOSE
   with `RootDirectory=`'s mount-namespace (some may need adjustment under a chroot); (d) confirm the static `/init`
   actually exec's under the seccomp `@system-service` filter (no Deno-specific pkey, but ensure no needed startup
   syscall is blocked).
3. Add a Go test asserting the OCI unit sets `MountAPIVFS=yes` (or whatever the working composition needs) + the
   diagnosability reason mapping.

Verify via go-in-docker (linux). Orchestrator re-boots: `VITA-CAPSULE-OCI-EXECUTED … root=ro health=OK` (the baked
rootfs RUNS, no FAILSAFE) + the forced-invalid reject; ts-service chain still PASS. Re-merge only after the BOOT passes.
