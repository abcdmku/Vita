## Objective
Fix the cross-cutting type-coherence findings from `ai-factory/evaluation/audits/sdk-core-2026-06-20.md`:
1. **Remove `JsonObject &` widening** from every `AcceleratorCapability` variant so the union matches
   the CLOSED spec §14.1 exactly (audit #2). Keep variants assignable where embedded in JSON config
   without re-opening them (the object-literal members of a `type` alias already carry implicit index
   signatures).
2. **One `DeepReadonly<T>`** shared from a single owner module; remove the verbatim duplicate (#3).
3. **One `DeviceSnapshot`** from a single owner; eliminate the two divergent public `DeviceSnapshot`
   types and the alias import (#4). `capabilities.ts` owns the accelerator/device model.
4. Use the canonical `AcceleratorSelectionResult` instead of longhand `AcceleratorSelection |
   AcceleratorRefusal` in define-system.ts (#10); drop the unused single-arg `bestAvailable` overload
   form (#11); rename validate.ts's `caps` param to `snapshot`/`device` for consistency (#12).
5. Fix `bestAvailable` so an **explicitly-preferred** CPU (cpu listed in `prefer`) is reported as a
   normal selection, NOT `fallback: true` (#7). Fallback is only when no preferred device matched.

## User value
The SDK is the foundation the controller will build on. One coherent, spec-faithful type model
prevents the parallel-island class of bug (which already cost a fix in P0-007) from recurring.
