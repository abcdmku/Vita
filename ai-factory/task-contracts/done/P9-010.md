## Objective
The R3 reviewer (P9-008) found the recursive duplicate-JSON-key pre-scan can be UNBOUNDED — a deeply-nested
untrusted `/apply` request (`{"extra":[[[[…]]]]}`) forces unbounded recursion in privileged agent decode
(stack/CPU DoS). The same `rejectDuplicateObjectKeys` pattern was copied into MANY capabilities; this fixes
it systemically with ONE shared, bounded scanner.
- **`agent/internal/jsonsafe/`** (new): a single audited `RejectDuplicateObjectKeys(raw []byte) error`
  (and any decode helper the caps share) that scans the JSON with a BOUNDED depth + total-node/byte budget —
  generous enough for legitimate requests, but a request nested past the bound returns a typed error (no
  panic, no runaway). Reject duplicate object keys at every level within the bound. Fail-closed.
- **Migrate every capability** that currently has its own `rejectDuplicateObjectKeys` / recursive dup-key
  pre-scan to call `jsonsafe.RejectDuplicateObjectKeys` (audit: nodeconfig, time, hostname, identity,
  network, storage, update, backup, pdssync, capsule, timesync, services, accounts — and any other). Remove
  the per-cap copies. Each cap's existing behavior (reject dup-keys + then decode + Validate) is preserved;
  only the scanner is centralized + bounded.
- Do NOT change `agent/internal/capmanifest` (it already has its own bounded scanner from P9-008) and do NOT
  touch `agent/transport/server.go` decoders beyond what a cap's own file needs.

## User value
A release-blocker-class systemic hardening: every privileged `/apply` request decode is now DoS-safe against
deeply-nested malformed input, via ONE audited bounded scanner instead of ~13 unbounded copies.

## Reviewer revision (round 2 — BLOCKING, from P9-010.review.md — fail-open unknown fields)
Adding `ApplyRequest.UnmarshalJSON` to identity/network/storage/time made them decode via a NON-strict
`jsonsafe.Decode` (wraps `json.Unmarshal`, ignores unknown fields), BYPASSING the transport decoder's
`DisallowUnknownFields` — so these caps now ACCEPT unknown top-level + nested fields they previously
REJECTED (fail-open). Round 2: the shared decode helper must be STRICT. Provide `jsonsafe.DecodeStrict(raw
[]byte, v any) error` = `RejectDuplicateObjectKeys(raw)` (bounded) THEN decode with a `json.Decoder` whose
`DisallowUnknownFields()` is set (and reject trailing data), so unknown fields are rejected exactly as
before. Every cap whose `UnmarshalJSON` P9-010 added/changed uses `DecodeStrict` (not the lax `Decode`).
Add a regression PER affected cap: a request with an unknown top-level field AND (for struct `desired`
payloads) an unknown nested field is REJECTED. Keep the bounded dup-key scan + all prior behavior. The
shared scanner's byte/depth/node bounds stay.
