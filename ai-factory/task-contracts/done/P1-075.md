## Objective
Phase 5 (spec §12.1) — the FIRST slice of the private remote-access mesh (FR-017): agentd brings up a node-level
WireGuard mesh interface (`vita-mesh0`) composed ENTIRELY from a re-validated mesh config, with **default-deny** so that
ONLY enrolled peers reach the node's **declared** services. This is the node-level analogue of the per-capsule
networking (P1-057..P1-061) — reuse that discipline (named-validators, fail-closed, MEASURED marker, sysdeps link
helpers) but at the node scope. NO public port exposure; the mesh is the private channel.

Concretely (`agent/capabilities/mesh/mesh.go` new, parallel to `capabilities/network/network.go`; sysdeps WireGuard
link helpers parallel to `CreateVeth`/`SetLinkUp`/`AddIPv4Address`):
- **Validated config → composed interface (NEVER raw runtime text).** A `MeshConfig` { node private-key REFERENCE (a
  keyfile path under the agentd-owned keystore — NOT inline key bytes), listen port, interface CIDR (mesh subnet),
  `Peers[]` each { peer PUBLIC key (base64, exactly 44 chars / 32 bytes decoded), allowed-IPs CIDR list, optional
  endpoint, optional persistent-keepalive } }. agentd re-validates EVERY field with named validators that REUSE the
  proven node-policy helpers (`network.NormalizeCIDR` host-bits-rejected + `sourceCoversAll` wide-open guard so a peer
  cannot claim `0.0.0.0/0`/`::/0` allowed-IPs without an explicit unsafe flag the manifest does not grant;
  `validNetworkPort`/`PortAll` rules; control-char / metachar rejection on every string). Then agentd creates the
  WireGuard link + sets the private key (read from the keyfile, never logged) + adds each peer (public key + allowed-IPs)
  + addresses the interface + brings it up — all in code via netlink/sysdeps, no shelling out to a config string.
- **DEFAULT-DENY / only enrolled peers reach declared services.** The mesh interface starts with NO peers reachable; a
  peer's traffic is accepted ONLY into the explicitly declared service ports for that peer (an nft input chain on the
  `vita-mesh0` interface, `policy drop`, reusing the egress.go ruleset discipline: a per-peer ACCEPT for the declared
  {proto,port} drawn ONLY from the validated config; established/related allowed; everything else DROPPED). A peer NOT
  in the config, or a packet to an undeclared port, is dropped. A wide-open allowed-IPs / undeclared-service grant /
  raw text in any field is REJECTED (fail-closed) before the interface is touched.
- **TEST KEYS ONLY (§16 — line 661 "release signing keys unavailable to development agents").** The build bakes a TEST
  node private key (generated into the gitignored test keystore at build/test time, NEVER committed, NEVER a production
  key) and TEST peer public keys. The owner provisions the REAL peer keys + holds the REAL node private key (§16,
  owner-held like TPM/recovery/signing material). NO key material — public or private — is committed or generated as
  production material; the keystore path + a `.gitignore` guard mirror the P1-027 Secure-Boot test-key pattern.
- **MEASURED marker (the P1-059/P1-061 lesson — NEVER synthesized).** The test stands up a SECOND netns playing a
  remote TEST peer (its own WireGuard endpoint over loopback/veth, TEST keypair), enrolls it, and proves a REAL
  WireGuard **handshake** completes (latest-handshake non-zero) AND the enrolled peer REALLY reaches a declared service
  port on the node over the mesh, AND a NON-enrolled peer (or a connect to an UNdeclared port) REALLY fails. The marker
  is gated on the handshake + the in-grant reach + the out-of-grant deny + agentd confirming the nft drop policy and the
  peer set match the validated config. Real-op (link create / WireGuard / netns) tests SKIP on EPERM under go-in-docker;
  the BOOT is the real floor.
- **Teardown / fail-closed:** on undo (transaction-engine undo, like the netns/volume teardown) tear down the interface +
  nft (no leak). Any setup error → NO interface up, never an open-all/no-peer-filter interface.

Markers: `VITA-MESH: peers=<n> handshake=OK reach=OK denied=<sanitized> drop=enforced status=OK` (the enrolled TEST peer
handshakes + reaches a declared service over the mesh AND a non-enrolled peer / undeclared port is denied — MEASURED);
`VITA-MESH-REJECT: reason=<specific step+errno> status=OK` (a wide-open allowed-IPs / inline key bytes / undeclared
service / bad port / raw-text field fails closed); `VITA-MESH-ERROR: status=FAILSAFE` (a setup error → no interface).
Keep ALL prior markers (the full chain through NET-INGRESS). Diagnosability: name the SPECIFIC step + errno (the
P1-059/P1-061 discipline — e.g. `mesh_link_create_EPERM`, `mesh_setkey`, `mesh_addpeer`, `mesh_nft_apply`).

## User value
FR-017 / spec §12.1: private remote access WITHOUT router configuration or public port exposure — the owner reaches the
node from outside the LAN through an encrypted mesh where ONLY their enrolled peers can connect, and even an enrolled
peer reaches ONLY the services the node declares. This is the security spine of remote access: outbound-established
encrypted mesh, default-deny, no public ingress. Proving a real handshake + a fail-closed reject on a TEST interface
establishes the channel the rest of Phase 5 (relay fallback, exposure reporting) builds on.

## Non-goals
NO relay fallback (spec §12.1 "replaceable encrypted relay" — a LATER slice). NO public ingress / LAN exposure (stays
OWNER-GATED, deferred — the mesh is the private channel only). NO automatic certificates, rate limiting, or the
exposure-reporting dashboard (later Phase-5 slices). NO DNS / service discovery over the mesh. NO real key material —
the owner provisions real peer keys + holds the real node private key (§16); this slice uses TEST keys ONLY and composes
the interface ONLY from the re-validated config (never raw runtime text). NO controller UI.

## Performance & security constraints

re-validated config in code (no raw runtime text, no shelled config string, no user-controlled args); the node private
key is a keyfile REFERENCE read by agentd and NEVER logged/echoed; TEST keys only — NO production key material committed
or generated (§16, owner-held); reuse the proven node-policy validators (not a weaker copy); the wide-open guard

error → no interface, never open-all). The unprivileged TS runtime only PROPOSES; the privileged mutation is in the
narrow agentd path from the re-validated config. No remote imports; lockfiles mandatory; no lifecycle scripts. R3 (a new
privileged network surface gating remote access) → reviewer gate (`npm run review`), and per the R3 dual-candidate
strategy two parallel worker attempts + the rubric judge.

## REVISION 2 (Codex R3 review: REVISE — 2 blocking — 2026-06-24)
1. **Measured marker can't emit:** the capability sets only Drop/Status, never `Handshake`/`Reach`/`Denied`, but main.ts
   reads the agent state via getState → the real boot path can NEVER emit the required `VITA-MESH: handshake=OK reach=OK
   denied=...` (the TS test uses a synthetic object). FIX: the agent capability must SET Handshake/Reach/Denied from REAL
   measurement (a peer handshake + a reach probe + a denied-peer probe) so the measured marker emits on the boot path.
2. **Teardown errors discarded (leak):** `_ = c.teardown(...)` on setup-failure swallows DeleteLink/DeleteNftTable errors
   — a partial setup can leave `vita-mesh0`/nft rules behind while Apply reports only the original error. FIX: surface/handle
   teardown failures (fail-closed, no leak) for this R3 privileged net surface.
Verify: go-in-docker + Borg51 boot — VITA-MESH handshake=OK reach=OK denied=<peer> drop=enforced (MEASURED) + no leaked
interface/rules on a forced setup failure.
