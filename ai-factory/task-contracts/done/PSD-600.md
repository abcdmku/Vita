## Objective
Harden and **lock** the already-written host-local ingress nftables rendering in
`agent/capabilities/capsule/ingress.go` behind a deterministic, table-driven Go unit suite. The
production rendering/validation code already exists — this slice adds the regression suite that
freezes its security-critical invariants; touch the implementation ONLY if a test exposes a real
defect (no behavior changes otherwise). The functions under proof are:
- `capsuleIngressConfigForUnit(unitName, policy)` — derives the ingress config from an
  `ExecutionNetwork` policy. Must reject `rule.Public == true` (host-local ingress is never public),
  reject `rule.Port == network.PortAll`, reject out-of-range ports, and require ≥1 grant (returns
  `*ExecuteInvalidRequestError`). Addresses/interfaces/table id come from the paired egress helpers
  (`capsuleEgressNames`, `capsuleEgressIPv4Pair`) so ingress and egress for the same `unitName` agree.
- `renderCapsuleIngressHostRuleset(config)` — host `ip <table>_nat` table, `chain output` with
  `type nat hook output priority dstnat`, one `ip daddr <hostAddr> <proto> dport <grantPort> dnat to
  <capsuleAddr>:<grantPort>` line per grant.
- `writeCapsuleIngressInputRules(b, config)` — per-grant netns `iifname "<vc…>" <proto> dport
  <grantPort> accept` lines.
- `verifyCapsuleIngressHostTable` / `verifyCapsuleIngressNetnsTable` — the table verifiers (host table
  must be `hook output`-scoped, never `prerouting`, never match `iifname`/`oifname`/`0.0.0.0/0`, and
  never contain the denied probe port; netns table must contain each granted accept and never the
  denied port).

Pure Go, no I/O, no network, no privileged calls — the suite must run on any host.

## User value
Closes the Phase-4 networking exit gate (S4a ingress) by making the host-DNAT + per-capsule-netns
ingress path **provably** fail-closed: a denied/non-granted port can never appear in either ruleset,
the host table can never expose a public interface or all-sources match, and the rendered ruleset is
byte-stable for a fixed `unitName`. This is the regression floor that lets ingress ship without a
silent privilege-escalation or port-leak regression slipping past review.

## Non-goals
- NO new ingress features, no policy-schema changes, no live `nft`/netns execution, no integration or
  boot test (this is a pure unit slice). Do not rewrite the renderer's output format — the existing
  byte layout is the spec of record; the test pins it.
- Do not weaken or delete any existing `verifyCapsuleIngress*` guard to make a test pass (forbidden by
  CLAUDE.md §5 / spec §18.6).

## Acceptance
`acceptance_command` passes deterministically. The new `ingress_test.go` is table-driven and proves,
for a fixed `unitName` (e.g. `"capsule-ingress-fixture"`) with a known multi-grant TCP+UDP policy:
1. **Render byte-stability** — `renderCapsuleIngressHostRuleset(config)` returns a byte-for-byte
   identical `[]byte` across repeated calls and against a golden literal; same for the assembled netns
   input rules via `writeCapsuleIngressInputRules`.
2. **Denied-port absent in BOTH tables** — the computed `ProbeDeniedPort` (and any non-granted port)
   appears in NEITHER the host ruleset NOR the netns input rules; `verifyCapsuleIngressHostTable` and
   `verifyCapsuleIngressNetnsTable` both reject a tampered table that injects it.
3. **Public-match rejection** — `verifyCapsuleIngressHostTable` returns an error if the host table
   contains `iifname`, `oifname`, `0.0.0.0/0`, or `hook prerouting`; and `capsuleIngressConfigForUnit`
   returns `*ExecuteInvalidRequestError` for an ingress rule with `Public: true` or
   `Port: network.PortAll`.
4. **Grant-port DNAT presence** — for every grant, the host table contains exactly
   `ip daddr <hostAddr> <proto> dport <port> dnat to <capsuleAddr>:<port>` and the netns table the
   matching `iifname "<capsuleIf>" <proto> dport <port> accept`.
5. **Egress pairing** — `config.HostAddr`/`CapsuleAddr`/`CapsuleInterface`/`HostNatTable` for the
   fixture `unitName` equal the values derived from `capsuleEgressIPv4Pair`/`capsuleEgressNames` (table
   id is `<names.table>_nat`), so ingress and egress agree on addresses/interfaces/table ids.
6. `go vet ./capabilities/capsule/` is clean.

## Security/constraints
- Pure/deterministic: no I/O, no goroutines spawning probes, no clock/network reads in the tests
  (`allowed_network: false`). Same inputs → byte-identical ruleset (spec §8.2).
- Fail-closed is the property under test: a non-granted port reachable in either table, or a public
  match in the host table, is a release blocker — the suite must assert its absence, not merely the
  presence of grants.
- Do not relax `validateCapsuleIngressConfig` or the `verifyCapsuleIngress*` guards.
