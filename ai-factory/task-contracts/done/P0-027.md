## Objective
A fail-closed update-gating policy `sdk/typescript/src/update-applicability.ts` deciding whether an update
bundle may be applied, building on P0-025 (`parseSemver`/`compareSemver`) + P0-026 (`SemverRange`/
`satisfies`). `evaluateUpdateApplicability(input)` where input =
`{ currentVersion: string, bundle: { version: string; compatibleRange?: SemverRange; allowDowngrade?: boolean } }`.
- Validate the whole object via `safeNormalize` (it's an object), reject unknown keys/accessors/exotic;
  `currentVersion` + `bundle.version` must `parseSemver`-validate; `compatibleRange` (if present) must
  `parseRange`-validate; `allowDowngrade` (if present) must be boolean.
- Decide a typed verdict `{ applicable: boolean; kind: "upgrade"|"downgrade"|"reinstall"|"incompatible";
  reason: string }`:
  - **incompatible** (applicable:false) if `compatibleRange` present and `bundle.version` does NOT satisfy
    it (the OS-version compatibility gate).
  - else compare `bundle.version` vs `currentVersion` via `compareSemver`: `>` ⇒ **upgrade** (applicable);
    `==` ⇒ **reinstall** (applicable:false by default — no-op; a reinstall is not auto-applied);
    `<` ⇒ **downgrade**, applicable ONLY if `allowDowngrade === true` (else applicable:false, reason cites
    rollback-protection).
- Pure, deterministic, never throws. Hostile/invalid input ⇒ `{ applicable:false, kind:"incompatible",
  reason }` (fail-closed), never a throw.

## User value
The decision the updater/controller needs (FR-012): may this bundle be applied to this node? — gated on
declared OS-version compatibility, with rollback/downgrade protection on by default and reinstall treated
as a no-op. Reuses the audited semver primitives instead of ad-hoc string compares.

## Non-goals
- No real apply, no RAUC slot logic, no I/O/network. Decision only. Do NOT modify `semver.ts`/
  `semver-range.ts` — import them. New files only.

## Acceptance tests
`acceptance_command` — `update-applicability.test.ts`: higher bundle version ⇒ upgrade applicable; lower
⇒ downgrade NOT applicable by default but applicable when `allowDowngrade:true`; equal ⇒ reinstall not
applicable; a version outside `compatibleRange` ⇒ incompatible (not applicable) even if it's higher;
invalid currentVersion/bundle.version/range ⇒ fail-closed (not applicable, no throw); hostile input
(accessor/unknown key) ⇒ fail-closed with an external-counter probe proving no accessor invocation.
Orchestrator also runs `npm run typecheck`.
