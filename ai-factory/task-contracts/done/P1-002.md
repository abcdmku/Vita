## Objective
Declare the **AT Protocol PDS module manifest** as a concrete `PackageContract` (from P1-001,
`sdk/manifests`) plus PDS-specific config (spec §18 "AT Protocol PDS as the first PDS module",
FR-018). Provide:
- `pdsManifest`: a typed, valid `PackageContract` for an `oci-service` PDS (spec §9.1) declaring:
  architectures (x86-64 + arm64), min resources, public ingress per app (spec §12.1), data classes +
  volumes, backup/quiesce + restore-verification hooks, health checks, export formats (spec §10.2,
  §13), end-of-support, and required simulation profiles.
- A small typed `PdsConfig` (handle/domain, public access toggle, storage volume) layered on top.
- A function `buildPdsManifest(config: PdsConfig): PackageContract` that produces a manifest which
  **passes `validatePackageContract`** from P1-001.

## User value
The PDS is the first real personal-data module (spec §15 FR-018, §4.1). Declaring it as a valid
package contract proves the contract model is expressive enough for a real app and seeds the PDS work.

## Non-goals
- No PDS runtime, no atproto networking, no OCI image — the **manifest/types only**.
- No secrets embedded (reference them per §13.1).

## Dependencies
P1-001 (`PackageContract`, `validatePackageContract`).

## Acceptance tests
`acceptance_command`. `protocols/atproto/test/pds-manifest.test.ts` must prove:
1. `buildPdsManifest(validConfig)` returns a manifest that `validatePackageContract` accepts.
2. The manifest declares public ingress, both architectures, and backup + restore-verification hooks.
3. A config that would produce an invalid manifest (e.g. missing required field) is surfaced as a
   validation failure, not a throw.

## Performance & security constraints
Pure/deterministic, no I/O. Secrets referenced not embedded. Fail-closed.

## Hardware profiles
x86_64, arm64 (the manifest declares both).

## Allowed tools & network
Offline. Node built-ins + in-repo SDK/manifests only.
