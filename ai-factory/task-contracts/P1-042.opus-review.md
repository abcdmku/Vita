### 2. Idempotency vs agentd's monotonic-cursor guard — PASS (committed-then-committed)
- `pdssync.go` guard (Apply): `if desired.Cursor < priorState.Cursor { reject "cursor must not
  regress" }`, then UNCONDITIONALLY `AtomicWrite`. The comparison is strict `<`, **not `<=`**.
- The fixed write is `cursor=42`. On boot 2, `42 < 42` is false → **no rejection** → it re-writes the
  same bytes → `outcome=committed` again. The same-N re-apply is accepted and idempotent (converged
  no-op at the value level; a byte-identical re-write at the fs level).
- **What the orchestrator's 2-boot verity check will actually show:**
  - Boot 1: `VITA-PDS-WRITE: outcome=committed repo=did:plc:ewvi7nxzyoun6zhxrhs64oiz cursor=42
    status=OK`, then same-boot re-read `VITA-PDS: repo=did:plc:ewvi7nxzyoun6zhxrhs64oiz cursor=42
    head=bafybei… status=OK`.
  - Boot 2 (SAME disk, no rebuild): `VITA-PDS: repo=…ewvi7… cursor=42 head=bafybei… status=OK`
    BEFORE the write marker (this is the S4 read at top-of-loop — **the real persistence proof**:
    /var survived reboot, root still verity-ro), AND `VITA-PDS-WRITE: outcome=committed …` again
    (NOT rejected — the equal-cursor re-apply commits). This is **committed-then-committed**, not
    committed-then-rejected. The persistence proof does not depend on the write marker on boot 2; it
    is the `VITA-PDS` read reflecting cursor=42 carried across the reboot.

## NOTES (non-blocking)
- **Committed marker fields are runtime-sourced, not agentd-echoed.** `outcome=committed repo/cursor`
  come from the local `desired`, not from agentd's `ReadResponse`. For this fixed idempotent write
  that is fine and matches the contract. If a future slice writes variable state, prefer echoing
  agentd's persisted values into the marker so the marker can't drift from what was actually stored.
- **Boot-2 expectation (restate for the orchestrator):** do NOT expect `VITA-PDS-WRITE: rejected` on
  boot 2. Equal-cursor re-apply is accepted (`<` guard) → boot 2 is committed-then-committed. The
  persistence evidence is the `VITA-PDS` READ showing `cursor=42` after reboot on the same verity
  disk, with root still verity-ro.
- `head=` in the `VITA-PDS` read marker derives from the stored `repoHead`; agentd round-trips
  `repoHead` faithfully, so boot 2's read head should equal the boot-1 written `bafybei…` CID.
