## WINNER: A

A wins on the two axes that matter most for an R3 *privileged-socket trust boundary*: it has a
**smaller, sharper privilege-perms model with fewer runtime failure modes**, and it **closes a
brief world-connectable TOCTOU window on the privileged socket that B leaves open**. B is also
correct and is in several respects more defensively coded, but its socket-ownership mechanism is
**redundant with its own unit config** while *adding* a fatal failure path, and it does not close
the creation-time permission window. Margin is moderate, not overwhelming — both are mergeable-grade
implementations.

### Axis 1 — agentd unix listener correctness — A ✓ / B ✓ (tie, slight edge A)
Both add `ListenUnixSocket` in `transport/server.go` that: removes a stale socket
(`os.Remove` tolerating `ErrNotExist`), `net.Listen("unix", …)`, sets mode 0660, and wrap the
listener so `Close()` unlinks the socket once (`sync.Once`, `ErrNotExist`-tolerant). Both serve the
**same `handler`** over the socket as over TCP (a second `http.Server` sharing the identical handler
mux). Both **keep TCP intact** (`127.0.0.1:8786` still served). Both add clean signal-driven
shutdown (SIGTERM/Interrupt) that `Shutdown()`s both servers.
- A: `cmd/agentd/main.go:107-156` — `serveUntilStopped` with a 2-buffered errCh, portable signal
  set split into `signals_unix.go` (SIGTERM+Interrupt) / `signals_other.go` (Interrupt). Clean.
- B: `cmd/agentd/main.go:93-155` — `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)` inline
  (compiles cross-platform; `syscall.SIGTERM` exists on Windows in Go). Equivalent.
- Slight edge **A** for the portable signal split (idiomatic) — immaterial to the Linux target.

### Axis 2 — Perms model (the hard part) — A ✓ (cleaner) / B ✓ (redundant + extra failure path)
Both reach the SAME end state — socket `root:vita-agent` mode 0660, `/run/vita-agent` 0750
root:vita-agent, DynamicUser in `vita-agent` via `SupplementaryGroups=` — but by different means:

- **A** lets **systemd** own group/perms: agentd.service `Group=vita-agent` (so agentd's *primary
  group* is vita-agent → the socket is born group-`vita-agent` with no chown needed) + `UMask=0007`
  (so the socket is born 0770, never world) + Go `os.Chmod(path,0660)`. The Go listener does NOT
  look up or chown the group. Fewer moving parts; the group ownership is declarative.
- **B** does it in **Go**: `user.LookupGroup("vita-agent")` → `os.Chown(path,-1,gid)` →
  `os.Chmod(path,0660)` — AND *also* sets `Group=vita-agent` on the unit. Because `Group=vita-agent`
  already makes the socket group-`vita-agent`, **B's LookupGroup+Chown is redundant**, yet it adds a
  hard failure path: if `/etc/group` lacks `vita-agent` when agentd starts (sysusers race), B's
  `ListenUnixSocket` errors → `log.Fatalf` → **agentd doesn't come up**. (Pure-Go `os/user` under
  `CGO_ENABLED=0` — which is how agentd is built, build-and-boot.mjs:165 — parses `/etc/group`
  directly; the `sysusers.d g vita-agent` line populates it before multi-user, so it normally
  resolves, but the dependency is real and gratuitous.)

Both chains correctly grant the DynamicUser access and are NOT world-accessible **at steady state**.
A's is the tighter, lower-risk design for R3.

### Axis 3 — TS HTTP-over-unix client (main.ts) — A ✓ (over-built but robust) / B ✓ (right-sized)
Both: convert `main()`→async, gate the connect behind a successful preview, `Deno.connect({transport
:"unix",path})`, hand-roll an HTTP request, parse status+body, emit
`VITA-CONNECT: transport=unix peer=agentd healthz=OK status=OK` on 200+healthy, and
`VITA-CONNECT-ERROR: status=FAILSAFE` on ANY failure (full try/catch around the probe). Both keep
ALL prior markers (VITA-TS/EVAL/EVAL-REJECT/PREVIEW/PREVIEW-NOOP/EXPLAIN). Both cap the response
size; both `conn.close()` in `finally`.
- **A** (+229): HTTP/1.1 with `Connection: close`, plus a full **chunked-transfer-encoding decoder**
  and header map. Correct, but the chunked path is effectively **dead code for this endpoint** —
  Go's `net/http` sends a small `/healthz` JSON with `Content-Length`, never chunked. Over-built.
- **B** (+137): HTTP/1.0 request (implies connection-close, no chunking), read-to-EOF, minimal
  status-line + body parse. **Precisely matches the actual server behavior**; leaner and equally
  correct. Right-sized.
- **One real robustness gap in A:** A's tail is `main().then((code)=>Deno.exit(code))` with **no
  `.catch()`**. After the async conversion, any rejection from `main()` outside the connect try/catch
  (e.g. `runPreview()` re-throwing a non-`TransactionPlanDiffError` at main.ts:170) becomes an
  **unhandled promise rejection → the oneshot fails** instead of exiting 0. **B keeps the safety
  net**: `.then(…Deno.exit).catch((c)=>{console.error(c);Deno.exit(1)})`. The connect path itself is
  guarded in both; this is a narrow but real top-level regression unique to A. **Port B's `.catch`
  into A** (see below). On the connect-specific "never crash" requirement both pass.

### Axis 4 — Hardening kept — A ✓ / B ✓ (tie)
Both retain `RestrictAddressFamilies=AF_UNIX`, add NO `AF_INET`, add NO `--allow-net`, and scope
Deno `--allow-read`/`--allow-write` to the **exact** socket path
`/run/vita-agent/agentd.sock` (not the parent dir). Every other sandbox knob (DynamicUser,
NoNewPrivileges, empty caps, ProtectSystem=strict, syscall filter, etc.) is untouched in both.
- Audit-log leak check: A's process-wide `UMask=0007` does NOT widen the audit trail — auditlog
  hard-`Chmod(0o600)`s the file (auditlog.go:316) and the state dir is `StateDirectoryMode=0700`
  (owner-only, blocks group traversal). So A's UMask is contained.
- **Edge to A on the socket-creation window:** Go does not chmod a unix socket at `net.Listen`; the
  socket is born at `0777 & ~umask`. B sets no `UMask=` on agentd → inherits systemd default
  **0022** → socket briefly **0755 = world-connectable** until B's chown+chmod lands (a TOCTOU on a
  privileged socket). A's `UMask=0007` makes the socket born **0770**, never world. For R3 this is a
  point in A's favor.

### Axis 5 — Completeness (ts-image.conf) — A correct / B's edit is harmless-but-unnecessary
B edits `os/x86_64/ts-image.conf` `[Service] ExecStart=` to mirror the new `--allow-read/--allow
-write`; A does not. **A did NOT miss a required sync.** I traced every consumer of ts-image.conf:
`ts-image.mjs:loadPin()` reads only the `[Runtime]` and `[Install]` sections (server.go n/a) — it
does **not** read `[Service]` / `ExecStart` at all (grep for `ExecStart`/`[Service]` in ts-image.mjs
= no matches; nothing in `tools/` consumes it either). The authoritative `ExecStart` is the unit
file `vita-ts.service`, which BOTH candidates updated. ts-image.conf's `[Service]` block is
documentation that *mirrors* the unit. So:
- B's ts-image.conf edit = **good hygiene** (keeps the doc-mirror in sync) but **not functionally
  required**; it changes no build output.
- A's omission = a minor **doc-drift** (the conf's ExecStart now lags the unit) but **not a
  correctness defect**. Worth porting B's one-line sync into A for tidiness (non-blocking).

### Axis 6 — Test quality — A ✓ / B ✓ (tie)
Both add a Go test covering all four required behaviors: stale socket replaced, `GET /healthz` over
the socket returns **200 + expected body** (decodes `status.Status`, asserts `Version=="test-version"`
& `Healthy`), socket mode **0660**, and **unlink on shutdown**. Both reuse the existing
`mustHandler`/`mustRegistry` helpers and neither weakens any existing test (B only *adds* to
server_test.go; A adds an isolated file — verified no `-` lines on existing tests).
- A: `transport/server_unix_test.go`, whole file `//go:build unix` (excluded off-unix; runs on the
  Linux boot target). B does not assert the group-chown path; A doesn't either (group ownership is
  systemd's job in A — correct to leave it to host-verify).
- B: in shared `server_test.go` with a `runtime.GOOS=="windows"` skip (compiles everywhere, runs on
  Linux/macOS). Slightly broader compile coverage; equivalent runtime coverage on the target.
Both adequate.

## VERDICT (winner A): **approve** — with one non-blocking fix recommended

A satisfies the contract DoD: serves the same API over the group-scoped 0660 socket, replaces a
stale socket + unlinks on shutdown, keeps TCP, keeps every hardening knob with socket-path-scoped
Deno grants + `SupplementaryGroups=vita-agent`, emits VITA-CONNECT / VITA-CONNECT-ERROR with all
prior markers, and ships the unix-listener test. `go build`/`go vet` clean. No protected-policy or
stop-condition trip. No BLOCKING issues.

The actual `VITA-CONNECT` marker on serial + group-reachability by the DynamicUser remains the
orchestrator's **Borg51 host-verify** (the one thing not provable on this Windows judge host); this
approval is contingent on that boot check passing, per the contract's acceptance section.

### Port from the loser (B) into A before/with merge
1. **(Recommended, robustness)** Add B's top-level `.catch()` to A's `main()` tail so an unexpected
   rejection can't fail the oneshot:
   `main().then((c)=>Deno.exit(c)).catch((e)=>{console.error(e);Deno.exit(1);});`
   (A currently: `main().then((code)=>{Deno.exit(code);});` — no catch.) Cheap, strictly safer.
2. **(Optional, hygiene)** Sync `os/x86_64/ts-image.conf` `[Service] ExecStart=` to add the two
   `--allow-read/--allow-write=/run/vita-agent/agentd.sock` flags (B's one-liner), so the doc-mirror
   matches the unit. No build impact.

Neither is blocking; #1 is the only one worth a re-touch and is a 1-line edit.

### Why not B
B is a solid, mergeable implementation and is in two ways *more* defensive (explicit catch; explicit
chown). But for an R3 privileged boundary it (a) makes socket group-ownership depend on a runtime
`user.LookupGroup` that is **redundant with its own `Group=vita-agent`** while adding a
`log.Fatalf`-on-miss path that can keep agentd from starting, and (b) leaves a brief
**world-connectable socket window** at creation (no `UMask=`). A avoids both. The items where B is
better (top-level catch, conf sync) are trivially portable into A; the items where A is better
(perms-model simplicity, closed TOCTOU window) are architectural and harder to retrofit. Hence A.
