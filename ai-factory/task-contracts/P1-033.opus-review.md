## How each concern was settled

### 1. safe-normalize Proxy guardian under DENO — SETTLED SAFE (ran it)
The vendored `vita/safe-normalize.ts` replaced upstream's `import { types as nodeTypes } from "node:util"` with an indirect resolver:
- `resolveNodeIsProxy()` (lines 403-420) reads `globalThis.process.getBuiltinModule("util").types.isProxy`.
- `isProxyObject(value)` (lines 399-401) = `nodeIsProxy?.(value) ?? false` — i.e. **fails OPEN** if the resolver returns `undefined`.

The orchestrator's prior host check covered `import {types} from "node:util"` + `globalThis.process`, but the shipped code path uses `process.getBuiltinModule` — a *different* API. So I executed the real path.

I staged the vendored tree and ran, under `deno run --no-remote` (Deno 2.8.3):
- `globalThis.process` → present; `process.getBuiltinModule` → function; `getBuiltinModule("util").types.isProxy` → function. **The resolver resolves.**
- Top-level `new Proxy({},{})` → REJECTED ("Proxy objects are not accepted.")
- Proxy nested in a plain object → REJECTED.
- Proxy passed as the options arg → REJECTED ("Options must be a plain object.")
- A prototype-lying adversarial Proxy (traps `getPrototypeOf`/`ownKeys`/`getOwnPropertyDescriptor` to masquerade as plain) → REJECTED.
- A genuinely plain object → ACCEPTED.
- **GUARDIAN VERDICT: PASS** — identical to upstream behavior under Deno. Not weaker.

The guardian is therefore NOT weakened on-device. This is the load-bearing finding and it is proven, not argued.

## NOTES (non-blocking)

- **N1 (latent fail-open, recommend the contract's intended fix).** `isProxyObject` = `nodeIsProxy?.(value) ?? false` degrades to accepting ALL Proxies if a future runtime ever lacks `process.getBuiltinModule` or `util.types.isProxy`. It is proven safe on Deno 2.8.3 + Node 22 today, but it is a guardian that fails OPEN. I verified that `import { types } from "node:util"` works under Deno 2.8.3 `--no-remote` (returns true for a Proxy, false for plain). The clean fix is to use the **direct** `import { types } from "node:util"` for true byte-parity with upstream and a guardian that is structurally guaranteed (a missing builtin becomes an import error at load, i.e. fail-closed, rather than a silent accept). The contract text itself anticipated a direct/inline approach. Recommend a follow-up to switch to the direct import; not blocking because the shipped path is proven to reject Proxies on the pinned runtime.
- **N2.** The `main.ts` plan hash (`stableStringify` + FNV-1a-64) is exercised end-to-end and shown deterministic, but is not unit-tested in `eval.test.ts`. The determinism test compares `JSON.stringify(plan)`, not the hash function. Minor; the hash is only a serial-marker fingerprint, not a security primitive.
- **N3.** `fnv1a64Hex` iterates UTF-16 code units and skips one unit for astral code points (correct for well-formed UTF-8); lone surrogates would diverge from real UTF-8 bytes, but plan content is ASCII/IPv6 literals so it is stable in practice. Cosmetic.
- **N4.** Contract text said the gap was an `isTypedArray` check; the actual upstream dependency is `types.isProxy`. The worker flagged this deviation in its report and handled the real dependency correctly. Update the contract wording for the record.
