## Objective
Open the unprivileged→privileged channel chosen in **ADR-0008**: agentd serves its HTTP API over a loopback **unix
domain socket** at `/run/vita-agent/agentd.sock`, and the on-device TS runtime CONNECTS to it (read-only `GET
/healthz`) — proving reachability before any apply. Marker: `VITA-CONNECT: transport=unix peer=agentd healthz=OK
status=OK` (and `VITA-CONNECT-ERROR: status=FAILSAFE` on failure — never crash the unit). This is the GATE for S2
(read) and S3 (apply). NO mutation in this slice.

Concretely:
- **agentd unix listener** (`agent/transport/server.go` + `agent/cmd/agentd/main.go`): serve the EXACT SAME HTTP
  handler/mux the TCP server already serves, additionally over a `net.Listener` on the unix socket
  `/run/vita-agent/agentd.sock`. Create the socket fresh each start (remove a stale one), set its permissions per the
  perms model below. Keep the existing TCP listener for now (do NOT break it) but the on-device path uses the socket.
  Clean shutdown closes + unlinks the socket.
- **Perms model (the hard part — the TS runtime is a systemd DynamicUser with a TRANSIENT uid):** the socket MUST be
  reachable by the TS runtime's identity and NOTHING else broad. Recommended: a fixed system group `vita-agent`
  (seed via the image, e.g. a `sysusers.d` snippet or the overlay); agentd's unit gets `RuntimeDirectory=vita-agent`
  (so `/run/vita-agent` exists, root-owned, group `vita-agent`, mode 0750) and the socket is group-`vita-agent`,
  mode 0660; the TS unit gains `SupplementaryGroups=vita-agent` so its DynamicUser can connect. (If you find a
  cleaner mechanism that is equally tight, use it — but justify it; do NOT make the socket world-accessible.)
- **vita-agentd.service** (`os/x86_64/agent-overlay/.../vita-agentd.service`): add `RuntimeDirectory=vita-agent`
  (+ mode/group) so `/run/vita-agent` exists with the right ownership before agentd binds.
- **vita-ts.service**: add `--allow-read=/run/vita-agent/agentd.sock --allow-write=/run/vita-agent/agentd.sock` to the
  `deno run` ExecStart (spike-confirmed the pinned Deno honors socket-path-scoped read/write), and
  `SupplementaryGroups=vita-agent`. KEEP `RestrictAddressFamilies=AF_UNIX` and EVERY other hardening knob (no
  `AF_INET`, no `--allow-net`). After=vita-agentd.service (already present).
- **main.ts**: after the existing markers, connect to the socket via `Deno.connect({ transport:"unix", path })`,
  issue `GET /healthz` (HTTP/1.1 over the socket — a minimal hand-rolled request is fine, or Deno's fetch over a
  unix connection if supported by the pinned build), parse the status/version, print `VITA-CONNECT`. On ANY error
  print `VITA-CONNECT-ERROR: status=FAILSAFE` and continue (oneshot still exits 0). Keep all prior markers
  (VITA-TS/EVAL/EVAL-REJECT/PREVIEW/PREVIEW-NOOP).

## User value
The unprivileged runtime can finally TALK to the privileged executor over the most-secure local channel — the
prerequisite for reading host state and applying config on-device, with the runtime's network sandbox untouched.

## Performance & security constraints
The socket is the ONLY new channel; permissioned to the `vita-agent` group (NOT world). The TS runtime gains NO
network reach (AF_UNIX-only kept) and NO host-FS mutation authority — only connect rights to the one socket. agentd
stays the sole privileged mutator. Fail-closed marker on connect failure. No keys/secrets. R3 (privileged daemon
surface + a runtime sandbox change) → parallel-candidate + reviewer gate.
