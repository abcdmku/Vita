## Objective
`buildNodeDashboard(client, capabilities)` (controller/dashboard): the single typed view the management
UI renders, COMPOSING the existing pieces — `buildNodeOverview` (P2-007: health + hardware capabilities),
`getOperations` (P2-008: applicable operations), and `buildNodeState` (P2-015: per-capability current
state). Returns a typed `NodeDashboard { overview, operations, states, reachable }`. Fail-closed: each
section degrades INDEPENDENTLY — if the overview is unreachable the dashboard still returns with that
section marked degraded/unreachable and the others populated; a failure in one section never throws or
blanks the whole dashboard. The agent client is injected (mock in tests; NO network).

## User value
The complete dashboard data model (FR-008) — one call yields health, what the node can do, and current
per-capability state, with per-section error isolation. The UI layer consumes this.

## Non-goals
- No UI rendering/HTML, no real network/agent, no mutation. Pure aggregation over the existing
  overview/operations/state builders. Do NOT modify P2-007/P2-008/P2-015 source — import + compose them.

## Dependencies
P2-007 (overview), P2-008 (getOperations/previewPlan), P2-015 (buildNodeState/getState), P2-006 (client). All merged.

## Acceptance tests
`acceptance_command` — `node-dashboard.test.ts` (mock client): a healthy agent ⇒ a dashboard with
overview ready, operations listed, states populated, reachable true; an agent where the overview errors
⇒ overview section degraded but operations/states still populated (per-section isolation, no throw); a
fully-unreachable client ⇒ all sections degraded + reachable false, still a typed dashboard (no throw);
malformed responses ⇒ fail-closed per section. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Deterministic. Injected client (no network). Fail-closed, per-section error isolation (never throw/blank).
Strict TS (no `any`). R2 → reviewer-gated.

## Reviewer revision (round 2 — BLOCKING, from P2-016.review.md)
The ERROR-handling path itself must be fail-closed: `clientErrorDetails()` reads `agentError` off an
injected `AgentClientError` and probes it with an UNGUARDED `isRecord`/`Array.isArray`, so a revoked
`Proxy` or exotic value there THROWS during error handling, rejecting the whole `buildNodeDashboard`
instead of degrading the section. Make every nested error-detail probe non-throwing — wrap the extraction
in try/catch (or run the nested value through `safeNormalize`) so error handling can NEVER throw. Add a
regression: an injected client error whose nested detail is a revoked Proxy / throwing-accessor value ⇒
the section degrades and the dashboard still returns (no throw).
