## Objective
Expose each capability's current state for reading (FR-008): add a read-only `GET /read/{capability}` to
the transport that looks up the named capability in the registry, calls its `Handle` (read) with the
capability's `ReadRequest`, and returns the typed response as JSON. This is the read counterpart to
`/apply` (write) — the transport currently has no way to read a capability's stored desired-state, so the
controller cannot show current per-capability state.
- Loopback-only, read-only (`Handle` performs no mutation). Unknown capability ⇒ 404; non-GET ⇒ 405;
  a capability whose `Handle` errors ⇒ a typed 4xx/5xx error (fail-closed, never a panic). The path
  segment is matched against the registered capability names only (closed set) — request data never
  becomes anything but a registry key lookup.

## User value
The controller can read current node-config / network / storage / backup / identity / pdssync state
(FR-008) to render the dashboard — currently impossible (the transport only writes). The read path.

## Non-goals
- No mutation, no /apply changes, no new capabilities. A read route + handler only. No `os/exec`.

## Dependencies
P1-008 (transport), P1-022 (all 9 caps registered). Both merged. Uses the registry's lookup + the
`Capability.Handle` already on every capability.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Add transport tests (httptest):
`GET /read/{name}` for a registered capability returns its `Handle` response as JSON (using injected
facades, e.g. a stored nodeconfig read back); an unknown capability ⇒ 404; non-GET on /read ⇒ 405; a
capability whose Handle returns an error ⇒ typed error response, no panic; existing /healthz, /capabilities,
/operations, /apply behavior unchanged.

## Performance & security constraints
TCB (transport). Loopback-only, READ-ONLY (no mutation via this route). Closed-set capability lookup;
fail-closed (no panic on unknown/error). `go vet` clean. R3 → reviewer-gated. Must not alter /apply or the
other routes.
