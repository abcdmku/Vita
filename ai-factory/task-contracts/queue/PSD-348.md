## Objective
Wire the desktop host's `launchApp`/`stopApp` ports to the agentd `capsule.execute` capability
(`agent/capabilities/capsule/execute.go`, hardened transient systemd-run units) so that clicking the
dock actually **runs an app** as a sandboxed capsule and binds it to a desktop window/surface. Build
the **apps backend** on the SDK desktop-host surface (`sdk/typescript/src/desktop-sdk`) on top of the
agentd AF_UNIX host client (PSD-343) and the launch-intent plumbing (PSD-347), using ONLY public SDK
ports + the injected host transport — NO platform internals, NO DOM/rendering.

- **launch**: `launchApp(app: DesktopLaunchableApp)` →
  1. resolve the capsule descriptor for the app's `surfaceKind` (`web` / `tsx`),
  2. issue a `capsule.execute` request through the injected host transport (the PSD-343 agentd
     client) to start a hardened capsule,
  3. on success, allocate a `surfaceId` / `windowId` / `textureId` for the new surface,
  4. compute `WindowManagerIntent[]` for the new window (via the SDK
     `computeWindowManagerIntents` / `collectWindowManagerIntents` exports),
  5. return/emit a `DesktopAppLaunch { app, surfaceId, windowId, textureId, intents }` that passes the
     SDK `isDesktopAppLaunch` guard.
- **stop**: `stopApp(...)` → tear down the capsule (stop the transient unit through the host
  transport), release the allocated surface/window/texture ids, and return/emit a `DesktopAppStop`.
- **grant-gated + fail-closed**: both flows are mediated by the `apps.launch` / `apps.stop`
  capability grants — if the grant is missing or the transport is absent, fail closed (no capsule,
  no surface allocation, structured `DesktopHostError`).
- **idempotent stop**: stopping an already-stopped (or never-launched) window is a no-op success — no
  second `capsule.execute` teardown, no error.
- **no dangling surface on reject**: if `capsule.execute` rejects/throws, the launch fails closed and
  leaves NO allocated surface/window/texture and no `DesktopAppLaunch` emission.
- Import the SDK exactly as `sdk/typescript/src/desktop-sdk/index.ts` re-exports
  (`DesktopAppLaunch`, `DesktopAppStop`, `DesktopLaunchableApp`, `WindowManagerIntent`,
  `isDesktopAppLaunch`, `computeWindowManagerIntents`, `collectWindowManagerIntents`); consume the
  host transport shape used by `ui_kits/desktop/runtime/host-bridge.ts` — do not re-implement it.
- Put the backend under `sdk/typescript/src/desktop-sdk/` and the tests under
  `sdk/typescript/test/ui-kits/apps-backend.test.ts`.

## User value
Makes the dock real: clicking an app launches a hardened capsule and opens its window on the live
desktop, and closing it tears the capsule down. This is the missing seam between the rendered desktop
shell and the on-device capsule runtime — the OS goes from "shows a desktop" to "runs apps".

## Non-goals
- NO DOM/CSS/rendering/CEF, NO actual GPU texture creation (allocate the `textureId` identifier only;
  compositor binding is a later slice).
- NO changes to `agent/capabilities/capsule/execute.go` or any Go agent code — this slice talks to it
  ONLY through the injected host transport; the test uses a fake `capsule.execute` responder.
- NO new capability dialect entries, NO grant-policy changes, NO networking logic.
- Don't re-implement the WindowManager intent math or the SDK host bridge — consume the public
  exports.

## Acceptance
`acceptance_command` passes. `sdk/typescript/test/ui-kits/apps-backend.test.ts` drives the backend
against a **fake `capsule.execute` responder** + fake host transport and asserts, deterministically:
- `launchApp` issues one `capsule.execute` start and returns/emits a `DesktopAppLaunch` carrying
  `surfaceId`, `windowId`, `textureId`, and `intents` that **passes `isDesktopAppLaunch`** (and whose
  `intents` are the SDK-computed `WindowManagerIntent[]`);
- `stopApp` issues the capsule teardown and returns/emits a `DesktopAppStop` for the same window;
- **double-stop is idempotent** — the second `stopApp` is a no-op success with no extra teardown call;
- **execute reject → fail-closed launch** — when the fake responder rejects, `launchApp` returns a
  structured `DesktopHostError` and NO surface/window/texture id is allocated and no `DesktopAppLaunch`
  is emitted;
- **grant-gated / no-transport → fail-closed** — missing `apps.launch`/`apps.stop` grant (or absent
  transport) fails closed without contacting the capsule.
Typecheck clean. Pure, headless, deterministic (no ambient I/O, no real sockets, fixed id allocation).
