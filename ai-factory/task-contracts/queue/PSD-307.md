## Objective
Add DMABUF (DRM PRIME) surface import to the `compositor-core` Rust crate so CEF's GPU output can be
consumed zero-copy on the live KMS path, while every recording/test/non-GPU backend keeps working
unchanged via a failsafe default. This is the **M3 gate** rung of ADR-0014 (the ADR's PSD-053).
Three concrete pieces, all grounded in the existing crate at
[packages/compositor-core/src/lib.rs](packages/compositor-core/src/lib.rs):
- **Trait method.** Extend the `RenderBackend` trait (`lib.rs:335`) with
  `fn import_dmabuf_surface(&mut self, fd: DrmPrimeFd, width: u32, height: u32, format: TextureFormat) -> Result<Self::Texture, CompositorError>`
  with a **default body that fails closed** — returns `CompositorError::Unavailable("dmabuf_import_unsupported")`
  — so `RecordingBackend` and the stub backend need no changes and never silently claim GPU import.
  Add a `DrmPrimeFd` type that carries a real PRIME file descriptor plus `stride: u32` and
  `modifier: u64` (DRM format modifier). `TextureHandleKind::DrmPrimeFd` already exists (`lib.rs:100`);
  reuse it for `export_handle`.
- **Compositor method.** Add `register_dmabuf_surface(&mut self, id, fd, width, height, format)` to
  `Compositor<B>` (`lib.rs:410`) mirroring `register_buffer_surface` (`lib.rs:461`): validate dims +
  duplicate-id (`DuplicateSurface`), call `backend.import_dmabuf_surface`, insert `SurfaceState`,
  return `SurfaceRegistration`. On backend `Unavailable`, propagate the error (caller fails closed to
  the buffer-surface path) — do NOT panic, do NOT leave a half-registered surface.
- **Protocol command + fd passing.** Add a `registerDmabufSurface` command to the command protocol
  (parsed in `main.rs`). The PRIME fd MUST travel **out of band** — in-process when CEF is embedded,
  else `SCM_RIGHTS` over the existing unix control socket — **never** as a number on the stdin text
  stream (a text-stream fd is a forgery/UAF hazard). The text command carries only id/dims/format/
  stride/modifier; the parser binds them to the most-recently-received ancillary fd and errors
  (`CompositorError::Protocol`) if no fd was received.

The GBM round-trip self-test lives behind the linux GPU backend
([packages/compositor-core/src/platform/linux.rs](packages/compositor-core/src/platform/linux.rs),
extending the `Egl`/`Gl` dlopen structs already there): allocate a GBM `bo`, export a PRIME fd
(stride+modifier), import it as an `EGLImage` bound to a GL texture
(`eglCreateImageKHR`/`glEGLImageTargetTexture2DOES`), composite it, read it back, and assert the
pixels round-trip. If vmwgfx rejects the modifier (or the `EGL_EXT_image_dma_buf_import(_modifiers)`
/`GL_OES_EGL_image` extensions are absent), the test path **fails closed to the buffer-surface path**
and emits an honest failsafe marker — it never fakes a GPU success.

Emit a new marker line: on success
`VITA-DMABUF: import=OK gpu=vmwgfx modifier=<hex> present=kms status=OK`; on the failsafe path
`VITA-DMABUF: import=FAILSAFE gpu=<gpu> reason=<reason> status=OK` (status=OK because falling back is
the correct, expected behaviour — failsafe is a clean outcome, not a crash). Wire the boot path in
`main.rs`/the selftest service so the VMware boot prints exactly one `VITA-DMABUF:` line.

## User value
Lets the flagship CEF desktop hand its GPU framebuffer to the compositor without a CPU readback on the
live KMS path — the zero-copy foundation PSD-054 (accelerated OSR) consumes — while guaranteeing every
non-GPU/test/recording backend and the existing buffer-surface path keep working untouched. The
honest OK/FAILSAFE marker means the boot log never lies about whether real GPU import happened.

## Non-goals
- NO CEF `OnAcceleratedPaint` wiring (that is PSD-054); NO resize/damage lifecycle (PSD-055); NO boot
  service packaging (PSD-056).
- Do NOT change the buffer-surface (`register_buffer_surface`/`update_buffer_surface`) path or the
  recording/stub backends' behaviour — the trait default keeps them compiling and fail-closed.
- Do NOT pass fds over the stdin text stream. Do NOT weaken or delete any existing test in
  `lib.rs` (the reposition + desktop-demo + buffer-surface suites must stay green).
- NO claiming `present=kms status=OK import=OK` from a recording/test backend (mirror the existing
  `recording_backend_never_emits_kms_ok_acceptance_marker` invariant for the new marker).

## Acceptance
`acceptance_command` passes via `tools/verify/rust-in-docker.mjs` (NEVER `typecheck` alone — Rust does
not compile on the Windows worker; the docker path is mandatory). Both invocations must compile clean
(`--locked`, no network) and run a NON-empty set of named tests:
- `cargo test ... dmabuf::` runs new tests covering: the trait default returns
  `Unavailable("dmabuf_import_unsupported")`; `Compositor::register_dmabuf_surface` rejects duplicate
  ids and propagates backend `Unavailable` without leaving a registered surface; `DrmPrimeFd` carries
  stride+modifier and `export_handle` yields `TextureHandleKind::DrmPrimeFd`; the `VITA-DMABUF:` marker
  shapes (OK and FAILSAFE) are byte-exact; a recording/test backend can NEVER emit
  `import=OK ... present=kms`.
- `cargo test ... protocol::register_dmabuf` runs new tests covering: the `registerDmabufSurface` text
  command parses id/dims/format/stride/modifier; it errors `Protocol(...)` when no ancillary fd was
  received; no fd is ever read from the text payload.
Both filters must select ≥1 test (an empty branch matches zero tests → cargo prints "0 filtered out
of N" but the new symbols are absent, so the named modules don't exist and the build/test fails — the
contract is NOT vacuously satisfiable). Independent host-verify: a Borg51/VMware GPU boot prints
exactly one honest `VITA-DMABUF:` line and the buffer-surface present=kms path still works.

## Security/constraints
- R2 (compositor / privileged render path) → Codex reviewer gate (`npm run review -- PSD-307`,
  VERDICT: approve) + independent GPU-boot host-verify before merge.
- fd passing is capability-mediated and out-of-band (in-process or `SCM_RIGHTS`); fail-closed on
  missing fd, rejected modifier, or absent EGL/GL extensions; PRIME fd lifetime owned by the
  importing texture and closed on drop (no fd leak, no double-close).
- Deterministic, no ambient I/O in the pure path; no remote imports; `--locked` lockfile; no package
  lifecycle scripts; no new FFI beyond the existing dlopen'd `Egl`/`Gl` structs in `linux.rs`.
- `allowed_network: false`. No production keys/secrets.

## Rollback plan
Single task branch `task/PSD-307`; revert the merge commit. The trait change is additive with a
failsafe default, so reverting restores the prior crate with no migration. No on-disk/format state is
introduced, so rollback is a clean `git revert` with no data cleanup.
