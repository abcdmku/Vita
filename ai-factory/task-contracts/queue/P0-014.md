## Objective
Eliminate duplicated plan-shape knowledge flagged by reviewers (P0-011 note + P2-001 note). Provide a
single exported structural type-guard `isCanonicalPlan(value: unknown): value is CanonicalPlan` in
`sdk/typescript/src/plan.ts` that validates the full CanonicalPlan shape (version + apps/backups
arrays of well-formed entries + identity/storage objects). Then:
- `envelope.ts` `verifyEnvelope` must use `isCanonicalPlan` instead of its own inline structural
  check (remove the duplication; same fail-closed behavior).
- `controller/api/src/dispatcher.ts` must use `isCanonicalPlan` to validate any caller-supplied
  `currentPlan` instead of the unchecked `as CanonicalPlan` cast (P2-001 reviewer note) — reject with
  the existing typed error if it is not a valid plan.

## User value
One source of truth for "is this a valid canonical plan" removes the drift risk two reviewers
independently flagged, and closes a real unchecked-cast at the controller boundary.

## Non-goals
- No new validation rules beyond structural shape (semantic/overprivilege checks stay in validate.ts).
- No behavior change to verifyEnvelope's result for valid/invalid inputs.

## Dependencies
P0-001 (`CanonicalPlan`).

## Acceptance tests
`acceptance_command` (full SDK suite) plus the controller suite must still pass (verified at
integration). Existing tests unchanged in intent (no weakening). Add to `plan.test.ts`:
- `isCanonicalPlan` returns true for a normalized plan and false for malformed inputs (missing
  version, wrong-typed apps, non-object).
