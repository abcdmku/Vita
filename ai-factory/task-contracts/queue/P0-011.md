## Objective
Make the plan envelope's integrity guarantee honest (audit
`ai-factory/evaluation/audits/sdk-core-2026-06-20.md` #1, #9, #14):
1. **Naming/semantics honesty.** `verifyEnvelope` is an UNKEYED recomputable hash — it detects
   corruption, not tampering, and is NOT a signature (real signing is the TCB/Go agent's job per spec
   §7.1, §16). Either rename to corruption-honest names (e.g. `hashEnvelope`/`checkEnvelopeHash`) OR
   keep `seal`/`verify` but document clearly in code that it is corruption-detection only and not an
   authenticity/signature boundary. Whichever you choose, update the example/exports/tests
   consistently and keep the diff within `sdk/typescript`.
2. **Structural validation.** `verifyEnvelope` must structurally validate that `env.plan` is a
   well-formed `CanonicalPlan` (required `version/apps/backups/identity/storage` with correct types)
   before returning true — a malformed plan that matches its own hash must NOT verify (#1).
3. **Bind provenance.** Include `createdAtRef` (and `schemaVersion`) in the hashed/encoded bytes so
   altering them is detected (#9).

## User value
A true result must not be mistaken for a trust boundary the SDK does not provide; and the envelope
must actually detect the mutations it claims to (spec §8.2 step 5, §8.4).

## Non-goals
- No real cryptographic signing / keys in the SDK (spec §16). Defer authenticity to the Go agent.
