## Objective
W6-S2 (ADR-0011 slice 2 — SAFE isolation, NO external reachability): for a capsule whose validated manifest declares
network grants (P1-057), agentd creates a PER-CAPSULE ephemeral Linux network namespace + joins the hardened transient
unit to it, with ONLY loopback inside (no veth/NAT/nft yet — that's S3). Proves the netns lifecycle + teardown + that
the hardened profile still holds. A network-granted capsule's `RestrictAddressFamilies` widens to AF_INET/AF_INET6/
AF_NETLINK (needed to open sockets at all), but with NO route off the namespace → the capsule can bind/connect only on
its OWN loopback; it CANNOT reach the host or any external network. Capsules WITHOUT grants are unchanged (AF_UNIX,
no namespace).

Concretely (`agent/capabilities/capsule/netns.go` new + `execute.go` wiring):
- agentd creates an ephemeral netns under `/run/vita-agent/netns/<unit>/` (agentd-owned, tmpfs); the transient unit
  joins it via `NetworkNamespacePath=` (systemd) or `PrivateNetwork` + a setup, composed from the VALIDATED manifest
  only. Loopback (`lo`) up inside; NO veth/host bridge.
- Conditional `RestrictAddressFamilies` (AF_INET/INET6/NETLINK) ONLY for granted capsules; non-granted keep AF_UNIX.
  ALL other hardening knobs UNCHANGED (DynamicUser, empty caps, NoNewPrivileges, ProtectSystem=strict, seccomp, cgroup).
- `TeardownNetns` on undo: tear down the namespace (the transaction-engine undo, like volumes). Ephemeral, no leak.
- The baked test capsule (with grants) binds+connects on its OWN loopback (succeeds) and ATTEMPTS to reach an external
  addr (must FAIL — no route). The marker is MEASURED from the workload's real result + an agentd-side check that the
  capsule has its OWN netns (cannot see host interfaces).
Markers: `VITA-CAPSULE-NET-NS: id=<id> netns=<name> loopback=OK isolation=enforced status=OK`;
`VITA-CAPSULE-NET-NS-REJECT: reason=<specific> status=OK`; `…-ERROR: status=FAILSAFE`. Keep ALL prior markers (incl.
NET-PARSE). Apply the lessons: MEASURED marker (no synthesized OK — gate on the workload's real loopback success +
external-FAIL), and a long-running test workload so the unit holds active (res=success) for a clean health read.

## User value
Per-capsule network isolation — each network-granted capsule gets its OWN namespace (its own loopback, cannot see the
host or other capsules' networking), the kernel-enforced foundation for default-deny egress/ingress (S3/S4). Still NO
external reachability (safe).

agentd composes the netns ONLY from the validated manifest (never raw runtime text).

## REVISION 2 (host-verify FAILED on the real node — 2026-06-23)
Linux unit tests PASS but the QEMU boot FAILED: `VITA-CAPSULE-NET-NS-ERROR: reason=capsule_netns_failed status=FAILSAFE`
(cascading to EXECUTE/VOLUME — the netns failure blocks the whole execute). The cross-review APPROVED **statically** but
explicitly gated merge on this boot, and flagged the cause-enabling gap: **every Go test wires a FAKE `recordingNetnsManager`
— the REAL `defaultCapsuleNetnsManager` (Create/Check/withCapsuleNetns) has ZERO coverage, so a no-op netns would pass
`go test`.** The boot is the real floor and it failed. Fix:

1. **PRIMARY — make the netns genuinely work on the node.** The named-netns Create or the unit's join fails at runtime.
   Investigate + fix the likely causes (the worker can't boot — reason carefully + add diagnosability so the boot names it):
   - **(a) mount propagation:** `/run/vita-agent/netns` must be a real mount point with SHARED propagation **visible to
     PID1/systemd's mount namespace** — else the bind-mounted ns file is invisible to the transient unit's
     `NetworkNamespacePath=`. If agentd runs in a private mount namespace, the bind-mount won't propagate to systemd.
   - **(b) unshare thread safety:** `unshare(CLONE_NEWNET)` MUST run on a `runtime.LockOSThread()`'d goroutine (or forked
     child) that is then DISCARDED — never agentd's shared threads (it would move agentd itself into the capsule netns
     and break agentd's own networking, failing every subsequent op).
   - **(c) setns restore:** on a FAILED restore to agentd's original netns, do NOT `runtime.UnlockOSThread()` — let the
     tainted thread terminate (the runc/CNI idiom; the review flagged the current unconditional unlock). A botched
     restore corrupts the agent.
2. **DIAGNOSABILITY (HARD REQ — the P1-055 lesson):** the failure reason MUST name the SPECIFIC step + errno, e.g.
   `capsule_netns_failed:bindmount_EACCES` / `:unshare_EPERM` / `:join_unit` / `:check_lo` — never the bare
   `capsule_netns_failed`. The next boot must tell me exactly which syscall failed if any remains.
3. **FALLBACK (acceptable):** if the named-netns can't be made to work on the node this iteration, use systemd
   **`PrivateNetwork=yes`** for S2 — systemd natively creates a private netns with ONLY loopback (no veth/route/external),
   which IS exactly this slice's goal (loopback-only isolation). Defer the named-netns (bind-mounted ns file, needed only
   when agentd must ENTER the netns to program nft) to S3. Either way the BOOT must show real isolation.
4. **TEST FLOOR (the review's major finding — close it):** add linux-gated (`//go:build linux` or `runtime.GOOS`) tests
   exercising the REAL manager, not the fake — `capsuleNetnsName` (suffix-strip + unsafe-rune scrub + injection),
   `validateCapsuleNetns` (reject paths outside `/run/vita-agent/netns`, wrong basename, root dir), `Check`
   only-lo⇒enforced vs lo+eth0⇒not-enforced via an INJECTED interface lister; proof negative-paths
   (external=REACHABLE⇒FAIL, status=FAIL, mismatched-id leaves Loopback unset); granted-OCI + granted-wasm compose tests
   (NetworkNamespacePath present + NetNS set + AF widened); a `main.ts`/capsule.test.ts case (NET-NS fires only on the
   full netns+loopback=OK+isolation=enforced triple, else FAILSAFE). A no-op netns impl must NOT pass.
Verify: go-in-docker (linux) + Borg51 boot (`VITA-CAPSULE-NET-NS: loopback=OK isolation=enforced` MEASURED — own netns,
external UNREACHABLE, host ifaces invisible — unit res=success; a specific-reason reject for forced-invalid; prior chain
incl. NET-PARSE still PASS).
