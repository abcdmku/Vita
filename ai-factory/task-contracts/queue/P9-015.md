## Objective
WAVE 1 of the [migration-roadmap](../migration-roadmap.md): expose the shared STRING-FIELD validation substrate
that nearly every remaining cap (update, capsule, accounts, identity, backup, pdssync) layers on. Most of the
hard logic ALREADY EXISTS in `agent/internal/capmanifest/capmanifest.go` (ported + conformance-validated in
P9-013) — this contract EXPOSES it as reusable, composable `string` field-schema OPTIONS in BOTH planes, adds
the missing pieces, and pins each to its Go reference via a frozen corpus. One dialect-touching contract.
- **`noInlineMaterial: true`** (string option) — the SERVICE-GRADE secret scanner. **DEPRECATE/REMOVE the WEAK
  `noInlineSecrets`** (alias it to the strong scanner — done in round 1, keep). NOTHING may reference the weak
  semantics.
- **ROUND-2 BLOCKING (adversarial probe, CONFIRMED by inspection): the capmanifest token-list scanner is
  WEAKER than the agent ground truth `agent/capabilities/services/services.go:546` — it ACCEPTS whitespace-
  separated secret keywords the agent REJECTS.** The agent uses regexes with a `[-_\s]?` separator class:
  `privateKeyPattern = (?i)\b(?:private[-_\s]?key|openssh[-_\s]?private[-_\s]?key|age[-_\s]?secret[-_\s]?key|
  xprv|seed[-_\s]?phrase|mnemonic|recovery[-_\s]?phrase)\b` and `secretAssignment =
  (?i)\b(?:private[-_\s]?key|api[-_\s]?key|access[-_\s]?token|refresh[-_\s]?token|password|secret)\s*[:=]`.
  `[-_\s]?` matches ONE optional separator from {`-`,`_`} ∪ RE2 `\s` = {space,`\t`,`\n`,`\f`,`\r`} (NOT `\v`).
  The substrate's `containsBoundedToken` does EXACT substring match over a token list with only `-`/`_`/empty
  variants, so `"private key"`, `"seed phrase"`, `"api key="`, `"access token: x"` ⇒ agent REJECTS, substrate
  ACCEPTS (verified: services.go regex matches the space). **FIX (both planes, structured — NO regex engine,
  keep TS≡Go):** extend the keyword matching so a single optional separator between keyword segments may be
  `-`, `_`, OR exactly one RE2-`\s` char (space/`\t`/`\n`/`\f`/`\r`, NOT `\v` — fix `isASCIIWhitespace`'s `\v`
  over-rejection too), matching `[-_\s]?` EXACTLY (ONE optional char, so `"private  key"` with TWO spaces does
  NOT match). Mirror it for the assignment path. 
- **ROUND-2 BLOCKING (harness is SELF-REFERENTIAL — structurally blind to the drift above).**
  `string_substrate_conformance_test.go:151` asserts the corpus against capmanifest's OWN
  `containsInlineServiceMaterial` ⇒ it only proves manifest≡manifest, never manifest≡agent. **FIX:** the Go
  conformance MUST assert `noInlineMaterial` decisions against the REAL agent ground truth — vendor a copy of
  services.go's EXACTLY FOUR regexes (privateKeyPattern, secretAssignment, longHex, longBase64) into the test as
  the ORACLE (or import the services pkg if its scanner is exported) and assert capmanifest's scanner ≡ that
  oracle on every vector. Add corpus vectors using LITERAL-whitespace-separated keywords on BOTH the
  private-material AND assignment paths (e.g. `"private key"`, `"seed phrase"`, `"api key=x"`,
  `"access token: y"` ⇒ reject; `"private  key"` two-space ⇒ accept), plus the `\v`-boundary case. The harness
  must now FAIL on the round-1 scanner.
- **ROUND-3 BLOCKING (ground-truth confirmed): do NOT add a `seedWords` 12-24-word-run regex.** The roadmap's
  "seedWords 12-24-word run" claim was WRONG about services.go; the REAL `services.go:546
  containsInlineServiceMaterial` is ONLY `privateKeyPattern || secretAssignment || longHexPattern ||
  longBase64Pattern` (lines 548-552) — NO standalone word-run. VERIFIED: services.go ACCEPTS a bare 12-word
  run `"alpha bravo … lima"` (returns false) and REJECTS only the KEYWORDS (`"seed phrase"`, `"mnemonic"`,
  `"recovery phrase"` via `privateKeyPattern`). Round 2 ADDED a `stringSubstrateOracleSeedWords` regex (NOT in
  services.go) ⇒ the oracle+scanner now reject bare word-runs the agent ACCEPTS ⇒ STRICTER. **FIX:** REMOVE
  the seedWords regex from BOTH the oracle AND the capmanifest scanner (both planes). The oracle must be
  BYTE-FOR-BYTE services.go's four regexes — nothing more, nothing less. Corpus: a bare 12-24-word run (no
  secret keyword) ⇒ ACCEPT; `"seed phrase"` keyword ⇒ reject.
  **IMPORTANT — there are TWO distinct agent scanners; this option models the SERVICE one ONLY.**
  `services.go:containsInlineServiceMaterial` (4 patterns, no seedWords, `[-_\s]?` separators) DIFFERS from
  `backup.go`/`identity.go:containsInlineSecretMaterial` (which ADD `seedWordsPattern`
  `\b[a-z]{3,12}(?:\s+[a-z]{3,12}){11,23}\b` AND use `openssh\s+private\s+key`/literal `age-secret-key`). This
  WAVE-1 `noInlineMaterial` option = the SERVICE variant EXACTLY (validated vs the services.go oracle). The
  SECRET variant (seedWords + `\s+`/literal openssh/age) is a SEPARATE governed option to be added WITH the
  backup/identity migrations (WAVE 4), each validated vs ITS OWN cap's `containsInlineSecretMaterial` oracle.
  Do NOT try to make one option match both — they are genuinely different agent behaviors.
- **`stringScreenBundle` pieces as options** (compose freely on a string field):
  `noControlChars: true` (reject `[\x00-\x1f\x7f]` — reuse `capmanifest.go:containsControlCharacter`);
  `trimmed: true` (value MUST equal Go `strings.TrimSpace(value)` — Go `unicode.IsSpace`, NOT ASCII-only);
  `maxBytes: N` (UTF-8 BYTE length ≤ N, NOT JS UTF-16 `.length` — AGENTS.md trap 4);
  `minLength: N` / treat `nonEmpty` (reject empty). Define char-vs-byte for each to MATCH the Go references.
- Both planes byte-identical; pin with `schema/capabilities/formats/string-substrate-conformance.json`
  (≥ 30 vectors total: PEM/key-assignment/seed-run/hex≥32/std+url-base64≥48 ACCEPTED-as-material → reject;
  benign strings → pass; control chars; surrounding Unicode whitespace; multibyte strings at the byte boundary
  e.g. a 3-byte char making byteLen=maxBytes+2 while `.length`=maxBytes-1) run by BOTH planes; drift fails CI.
- NO cap manifest/migration here (the consuming caps wire these options in later contracts). NO cross-field
  primitive. NO agent cap change — the agent reference functions are the GROUND TRUTH; do not alter them.
