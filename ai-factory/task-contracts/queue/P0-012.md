## Objective
Close the correctness/coverage gaps from `ai-factory/evaluation/audits/sdk-core-2026-06-20.md`:
1. **The flagship spec §8.3 example must pass the SDK's own `validatePlan`** (audit #5). Currently the
   shipped example fails validation and its test never checks it. Make the example a valid,
   least-privilege plan AND add a test asserting `validatePlan(exampleState, snapshot).ok === true`.
   If validation rules genuinely conflict with the §8.3 shape, prefer adjusting the example/grants to
   be valid; do not weaken the validator.
2. **Cover validatePlan's untested branches** (#6): accelerator tamper-detection and the
   embedded-refusal rejection path — add explicit tests.
3. **repro.ts** (#8): `assertDeterministic`/`isDeterministic` must correctly treat a deterministic
   function that returns `undefined` (or other non-JSON-but-stable values) as deterministic; add a
   test.
4. **AppOptions** (#13): expose the `allowedCapabilities`/`capabilities` fields that `validate.ts`
   treats as first-class app config, so authored apps can declare them through the typed API.
5. **accelerators.test.ts** (#15): assert the returned `prefer`/`available` arrays on accelerator
   results are immutable (frozen / readonly-enforced).

## Reviewer revision (round 2 — BLOCKING, from P0-012.review.md)
The previous attempt's `repro.ts` undefined/NaN/bigint handling used **sentinel objects**
(e.g. `{ __vitaDeterminismType: "undefined" }`) that **collide with legitimate plain-object return
values** — a function alternating between `undefined` and that exact literal object serialized
identically and was falsely reported deterministic (same for `1n` vs its sentinel). This is a false
positive in the determinism gate (violates spec §8.2).
- Use a **collision-free** typed serialization: encode the value's *type tag* in a way a normal
  user object cannot reproduce (e.g. a discriminated `{ kind, repr }` tuple built by the serializer
  itself and never derived from the user value's own keys; or compare `(typeof + structuredClone/
  String tag + JSON)` tuples rather than embedding a magic key into the JSON).
- Add **negative tests** proving the collision is NOT misreported: a deterministic function that
  always returns the literal `{ __vitaDeterminismType: "undefined" }` (or any object resembling a
  sentinel) must NOT be confused with one returning `undefined`, and a function alternating between
  `undefined` and such a look-alike object must be reported **non-deterministic**.
