## Objective
An ADDITIVE proof-of-concept for ADR 0007 (`architecture/adr/0007-shared-capability-schema.md`) — does NOT
touch the agent/TCB or any existing model; it stands alone to prove a single declarative capability manifest
can drive fail-closed validation INCLUDING a cross-field invariant. In
`sdk/typescript/src/capability-manifest.ts`:
- **Dialect types** for a restricted, CLOSED capability manifest:
  - `FieldSchema` = a discriminated union by `type`: `"string"` (optional `pattern`, `maxLength`, `enum`,
    `lowercase` [an explicit canonicalization primitive — when true the value is lowercased before the
    `uniqueItems`/return step], `noInlineSecrets`), `"integer"` (`minimum`/`maximum`), `"boolean"`,
    `"array"` (`items: FieldSchema`, `minItems`/`maxItems`, `uniqueItems`). Each field has
    `required: boolean` (explicit-presence: required-absent ⇒ reject; absent is distinct from a present
    zero/empty).
  - `CrossFieldRule` = a CLOSED, small set keyed by a boolean control field:
    `requireNonEmptyArrayWhenTrue` and `requireEmptyArrayWhenFalse` (control: a boolean field; target: an
    array field) — the bounded way the dialect expresses invariants like timesync `enabled`⟺`servers`
    WITHOUT becoming a general language. A constraint outside this closed set is a governance decision to
    extend the dialect (document in the header).
  - `CapabilityManifest` = `{ capability: string; fields: Record<string, FieldSchema>; crossFieldRules:
    CrossFieldRule[] }`.
- `compileCapabilityValidator(manifest): (input: unknown) => { ok: true; value } | { ok: false; rejections }`
  — `safeNormalize` the input first; reject unknown keys; validate each field per its schema (presence,
  type, constraints, `lowercase` canonicalization, §13.1 `noInlineSecrets` via PEM/`data:`-anywhere/
  long-base64-or-base64url detection); apply cross-field rules; fail-closed, never throws.
- **A concrete manifest constant `TIMESYNC_MANIFEST`**: `enabled` boolean required; `servers` array of
  strings, each an **RFC-1123 hostname** (`^[A-Za-z0-9]([A-Za-z0-9-]{0,61}[A-Za-z0-9])?(\.[A-Za-z0-9]
  ([A-Za-z0-9-]{0,61}[A-Za-z0-9])?)*$`, total length ≤ 253), `lowercase: true` + `uniqueItems` (so
  `["A.ORG","a.org"]` dedupes), `noInlineSecrets`, with `requireNonEmptyArrayWhenTrue(enabled, servers)` +
  `requireEmptyArrayWhenFalse(enabled, servers)`.

**Scope note (authoritative — read before flagging "missing IP support").** The agent's timesync ALSO
accepts IP-literal servers, but this PoC scopes `servers` to **RFC-1123 hostnames ONLY**. IP-literal /
format-canonicalization support is DEFERRED — it is precisely the part ADR 0007 says must be code-generated
/ shared, not hand-written: an earlier revision of this PoC hand-wrote an IP validator that drifted from the
agent's Go `netip` across three review rounds (IPv4-mapped, canonical-dedup, dotted-tail). See ADR 0007
"Empirical evidence". Hostname-only is a deliberate, fully-conformant scope for THIS PoC, not a gap — the
header must state this. Do NOT add IP-literal parsing.

## User value
A concrete, additive demonstration (de-risking the ADR 0007 owner decision) that one declarative manifest
drives fail-closed validation matching a real capability's *declaratively-expressible* rules — including the
`enabled`⟺`servers` cross-field invariant — while empirically showing (via the deferred IP support) that
format-canonicalization primitives are the part needing codegen. The dialect a closed config→plan evaluator
(P9-001) would consume.

## Acceptance tests
`acceptance_command` — `capability-manifest.test.ts`: the compiled TIMESYNC validator accepts
`{enabled:true, servers:["pool.ntp.org","time.cloudflare.com"]}`; rejects enabled-true-with-empty-servers;
rejects disabled-with-non-empty-servers; accepts `{enabled:false, servers:[]}`; rejects a malformed hostname
(spaces, underscores, leading/trailing hyphen, over-length, AND an IP literal like `10.0.0.1`/`::1` — IPs
are out of scope here so they are rejected as non-hostnames); dedupes case-insensitively
(`["A.ORG","a.org"]` ⇒ duplicate rejected); rejects absent `enabled`; rejects unknown keys; rejects inline
key material (PEM / `data:` anywhere / long base64 or base64url, incl. mid-string); each field + cross-field
rule rejects its violation; hostile input fails closed (external-counter accessor probe). Orchestrator runs
`npm run typecheck`.

TS (no `any`). R2 → reviewer-gated.
