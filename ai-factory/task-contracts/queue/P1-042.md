## Objective
Close the PDS loop: the unprivileged runtime WRITES persistent state through agentd (no direct /var) and it SURVIVES
REBOOT. Use agentd's EXISTING, transactional `pds.sync-state` capability (`agent/capabilities/pdssync/pdssync.go`,
atomic-write + undo of `pds-sync-state.json`) — driven through the proven S3 `/apply` path. At boot, after `VITA-PDS`
(the S4 read), `main.ts` applies a FIXED, idempotent `pds.sync-state` (a deterministic test repo DID + cursor + head)
and prints `VITA-PDS-WRITE: outcome=committed repo=<did> cursor=<n> status=OK` (or `outcome=rejected reason=<code>`
on a deliberately invalid sync-state proving agentd fails closed, or `VITA-PDS-WRITE-ERROR: status=FAILSAFE`).

Concretely:
- **No new agentd handler.** `pds.sync-state` already exists + is writable via Apply (confirm in `pdssync.go`). Drive
  it through the vendored apply path (S3 `apply-node-config.ts` + the `/apply` transport) — the same
  propose-by-runtime / validate-by-agent boundary. If `pds.sync-state` is NOT in the evaluator's manifest registry,
  NOTE it (a manifest gap) rather than forcing it.
- **New module** `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/pds-write.ts`: builds a `pds.sync-state` config (the
  fixed test repo/cursor/head matching agentd's request shape) + drives the apply + formats the `VITA-PDS-WRITE`
  marker from agentd's outcome. Idempotent (the SAME desired sync-state every boot → agentd's transactional apply is
  a no-op once converged — so re-applying on every boot is safe). Reuse the vendored agent-client/apply path; no new
  transport surface (only `/apply` + GETs).
- **`main.ts`**: after the S4 `VITA-PDS` read, do the write + print `VITA-PDS-WRITE`; then OPTIONALLY re-read so the
  same-boot `VITA-PDS` reflects the just-written state. Keep ALL prior markers. agentd RE-VALIDATES the sync-state;
  TS is untrusted.

## User value
Persistent, durable node state written on-device through the privileged boundary — the write half of the PDS, the
basis for identity/federation. Proves the node REMEMBERS across reboot (the whole point of the persistent /var).

## Non-goals
NO direct /var write from the runtime (agentd owns the store). NO record-level collection writes yet (a richer
`pds.write-record` handler is a later slice — this slice uses the existing sync-state capability). NO new agentd
capability. NO new transport surface. Benign/idempotent.

## Acceptance tests

config + drive `applyNodeConfig` against a MOCK apply transport — assert the right `/apply` body, committed-parse
into `VITA-PDS-WRITE` fields, a deliberately-invalid sync-state → `rejected` (fail-closed), transport error →
`VITA-PDS-WRITE-ERROR`. Orchestrator host-verifies on Borg51 — **the PERSISTENCE proof requires a VERITY image
(persistent /var) booted TWICE on the SAME disk**: boot 1 → `VITA-PDS-WRITE: committed` (+ `VITA-PDS` shows the
written state); reboot the SAME disk (do NOT rebuild) → `VITA-PDS: repo=<did> cursor=<n>` (the written state PERSISTED
across reboot), root still verity-ro. (The orchestrator will run this 2-boot check.)
