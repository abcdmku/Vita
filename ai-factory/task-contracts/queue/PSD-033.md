## Objective
Headless, deterministic **view-model** for the flagship desktop's `theme` screen, built ONLY on `@vita/desktop-sdk` public ports
(the SDK theme tokens (PSD-023) + settings port) — injected ports, NO platform internals, NO DOM/rendering (pure interaction logic the rendered design binds to later).
- State: active theme (light/dark/graphite), accent, layout density — the package-level appearance that the Settings pane + the ⌘K "Toggle Dark Mode" command drive. Actions: setTheme(t)/setAccent(c)/setLayout(l) -> persist via settings + expose the resolved token set + the .v-screen class set (theme-dark/mode-tiling) the rendered design toggles. Deterministic mapping from appearance -> token overrides + class list; reject unknown values fail-closed. This is the single source the hydration layer reads to re-theme screens.
- Code under `ui_kits/desktop/viewmodels/theme.ts`, tests under `sdk/typescript/test/ui-kits/theme.test.ts`. Import the SDK exactly as `ui_kits/desktop/package.ts` does; ONLY public exports.
- If the SDK lacks the exact port, define a MINIMAL injected port interface in the view-model module (typed, fail-closed) that a later slice implements — the view-model must be fully testable against a fake of that port now.

## User value
Turns the static `theme` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design. Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the described state transitions + fail-closed paths against fake ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/theme.ts` + `sdk/typescript/test/ui-kits/theme.test.ts`, deterministic, typecheck clean. R1.
