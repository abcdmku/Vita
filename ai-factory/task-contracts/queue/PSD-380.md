## Objective
Headless, deterministic **session view-model** that owns the whole-desktop lifecycle as a frozen
state machine, layered ABOVE the existing per-screen Lock view-model (`ui_kits/desktop/viewmodels/Lock.ts`).
Today `Lock.ts` only handles the unlock micro-interaction (`locked`/`authenticating`/`unlocked`,
`submit`/`cancel`/`tick`); nothing sequences `lock <-> desktop`, and there is no re-lock (idle/manual)
or logout/shutdown intent. This view-model is the missing top-level sequencer.
- States (frozen discriminated union, `kind` tag): `cold-boot` -> `locked` -> `authenticating`
  -> `unlocked` (active desktop) -> back to `locked` (idle timeout OR manual lock) -> `shutdown`
  (logout/shutdown intent). Actions: `boot()` (cold-boot -> locked), `submit(credential)`
  (locked -> authenticating, then unlocked on accept / locked on reject), `lock(reason: "manual" | "idle")`
  (unlocked -> locked), `requestShutdown(reason)` (-> shutdown intent), `tick(now)`
  (deterministic idle accounting; fires the idle re-lock when the idle budget elapses while unlocked).
- Each action returns a frozen transition result `{ ok, state, transition?, error? }`; the snapshot
  is the frozen union state. `bootstrap` (`ui_kits/desktop/runtime/bootstrap.ts`) is the intended
  consumer — it reads the union `kind` to decide which surface/screens to hydrate (lock surface vs.
  full desktop), so the union and transition shapes must be stable and serializable.
- Reuse the Lock view-model for the `authenticating` sub-step (inject a `LockAuthPort` exactly as
  `Lock.ts` defines it; do NOT re-implement credential/auth normalization — delegate to / mirror it).
- Put the code under `ui_kits/desktop/viewmodels/session.ts` and tests under
  `sdk/typescript/test/ui-kits/session.test.ts`. Import the SDK exactly as the other view-models do
  (relative `../../../sdk/typescript/src/desktop-sdk/index.ts`); use ONLY public exports.

## User value
Gives the desktop a real top-level lifecycle: the OS knows whether it is booting, at the lock screen,
authenticating, live, or shutting down — the single source of truth `bootstrap` needs to pick which
surface to hydrate and to re-lock on idle. Without it, lock and desktop are unsequenced and the
session never re-locks.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals, NO ambient I/O, NO timers (idle is driven purely
  by injected `tick(now)`). NO re-implementation of the Lock auth/credential normalization — consume
  the `Lock.ts` port. NO new visual design.

## Acceptance
`acceptance_command` passes. Deterministic unit tests in `sdk/typescript/test/ui-kits/session.test.ts`
(node test runner, no DOM) cover, against fake injected ports: `cold-boot -> boot() -> locked`;
`submit -> authenticating`; auth accept `-> unlocked`; auth reject `-> locked` (fail-closed, error
surfaced); idle `tick` past the budget while `unlocked` `-> locked` (reason "idle"); manual
`lock("manual")` while `unlocked` `-> locked`; `requestShutdown` `-> shutdown` intent. Assert frozen
snapshots (`Object.isFrozen`), fail-closed on malformed/out-of-order input (e.g. `submit` while
already `unlocked`, bad `now`), and byte-stable deterministic output for identical inputs. Typecheck
clean.

## Security/constraints
- Injected ports only (no ambient I/O, no real clock/timers); capability-mediated and fail-closed;
  pure/deterministic — same inputs produce byte-identical state/transition results. Frozen union +
  results (no caller mutation). No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/session.ts` + `sdk/typescript/test/ui-kits/session.test.ts`, both
  present and non-vacuous; deterministic; typecheck clean; acceptance command green on a populated
  branch and FAILING on an empty branch (exact test path, no glob). R1.
