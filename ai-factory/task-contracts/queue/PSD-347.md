## Objective
A host-side **app registry/catalog** that is the single source of launchable apps for the desktop.
Today there is none: the index dock hardcodes 6 app ids (`ui_kits/desktop/viewmodels/dock.ts:13`),
the ⌘K palette/search derives its app list ad-hoc from `DEFAULT_INDEX_PALETTE_COMMANDS`
(`ui_kits/desktop/viewmodels/search.ts:1043`), and `launchApp` /
`emitLauncherIntent` (`sdk/typescript/src/desktop-sdk/index.ts:130`, `DesktopLauncherIntent.appId`
at `index.ts:117`) have no resolver from an app id to a `DesktopLaunchableApp` descriptor.
Build a pure, headless registry in `sdk/typescript/src/desktop-sdk/app-registry.ts`:
- **Descriptor model.** A `DesktopRegistryApp` = `{ app: DesktopLaunchableApp; title; requiredGrants: readonly DesktopCapabilityGrant[] }`
  where `app` is the existing `DesktopLaunchableApp` union (`surfaceKind: "tsx" | "web"`, with
  `runtime` (`TsxComponentRef` componentId / `WebviewRuntimeRef` url) and optional `defaultWindow`
  `AppWindowHints`) — do NOT introduce a parallel descriptor shape; reuse the SDK union.
- **Seed sources, both validated.** `createAppRegistry({ firstParty, installedCapsules })` seeds from
  (a) **SRI'd first-party manifests** — each first-party seed carries an `integrity` SRI string over
  the serialized descriptor it attests; reject (drop, fail-closed) any seed whose integrity does not
  parse via `parseSriIntegrity` (`sdk/typescript/src/sri.ts:21`) or whose recomputed digest does not
  match — and (b) the **installed-capsule set** (already-validated app descriptors passed in). No
  ambient I/O: both sources are injected.
- **Query API (resolve + list only — NO exec in this slice).** `list()` returns the seeded apps in a
  deterministic order (by app id, ascending). `resolve(appId)` returns the matching
  `DesktopRegistryApp` or `undefined` (unknown/unlisted id ⇒ `undefined`, never a throw). `has(appId)`.
- **Launch validation (validate-only, fail-closed).** `validateLaunch(manifest, appId)` resolves the
  id and checks the requesting package manifest holds `apps.launch` for it via the SDK's
  `hasDesktopCapabilityGrant` (`sdk/typescript/src/desktop-sdk/loader.ts:408`): returns
  `{ ok: true, value: DesktopRegistryApp }` on a listed id with the grant present, else
  `{ ok: false, error: { code, message, path } }` — `UNKNOWN_APP` for an unknown/unlisted id and
  `CAP_DENIED` for a missing `apps.launch` grant (matching the uniform denial code PSD-342 introduces).
  This slice does **not** call `launchApp`/spawn anything; it only resolves + authorizes.
- **Launcher-intent resolution.** `resolveLauncherIntent(intent: DesktopLauncherIntent)` returns the
  `DesktopRegistryApp` for a `"launcher.launch"` intent whose `appId` is listed, else `undefined`
  (other intent types / missing appId ⇒ `undefined`).
- All public types/functions are exported and re-exported from
  `sdk/typescript/src/desktop-sdk/index.ts`; import the SDK exactly as
  `ui_kits/desktop/viewmodels/dock.ts` does (public `@vita/desktop-sdk` surface only). Pure,
  deterministic, frozen outputs — no DOM/CSS/CEF, no platform internals, no re-implementing existing
  ports/loader/SRI logic (consume them).

## User value
Gives the dock, ⌘K palette/search, and `launchApp`/`emitLauncherIntent` one authoritative, signed,
grant-aware catalog of launchable apps — replacing the hardcoded 6-id dock list and the ad-hoc
palette derivation — so app discovery and launch authorization come from a single auditable source.

## Non-goals
- NO actual app launch / process or surface spawn (resolve + list + validate only). NO `launchApp`
  invocation, no compositor/window-manager calls, no capsule execution.
- NO DOM/CSS/CEF/rendering, no platform internals, no ambient filesystem/network I/O (seeds injected).
- No new `DesktopCapability` values; no changes to the loader's enforcement gate (PSD-342 owns it),
  the SRI module, or the `DesktopLaunchableApp` union. Do not rewire the dock/search view-models in
  this slice (that is a follow-up consumer slice) — only build + export the registry.

## Acceptance
`acceptance_command` passes. Author `sdk/typescript/test/ui-kits/app-registry.test.ts` (imports the
SDK exactly as `ui_kits/desktop/viewmodels/dock.ts` does — public `@vita/desktop-sdk` exports only:
`createAppRegistry`, `hasDesktopCapabilityGrant`, and any registry types) with deterministic
`node:test` cases:
1. **Seeded list + declared grants.** A registry seeded with first-party + capsule apps `list()`s
   them in app-id order; each `DesktopRegistryApp` carries its declared `requiredGrants`.
2. **`validateLaunch` authorizes + fails closed.** With a manifest holding `apps.launch` for a listed
   id, `validateLaunch` returns `{ ok: true, value }`; an **unknown/unlisted** id returns
   `{ ok: false, error.code: "UNKNOWN_APP" }`; a manifest **missing** `apps.launch` returns
   `{ ok: false, error.code: "CAP_DENIED" }` (refused at launch).
3. **Descriptor shape valid.** Every seeded `app` satisfies the `DesktopLaunchableApp` union — assert
   `surfaceKind` ∈ {`tsx`,`web`} with the matching `runtime` field present (the test acts as the
   `isDesktopLaunchableApp` check).
4. **Launcher-intent resolution.** `resolveLauncherIntent({ type: "launcher.launch", appId })` for a
   listed id returns its descriptor; an unlisted/absent appId or a non-`launcher.launch` type ⇒
   `undefined`.
5. **SRI fail-closed.** A first-party seed with a malformed/mismatched `integrity` is dropped from
   the catalog (`resolve`/`has` report it absent); a valid one is listed.
`npm run typecheck` is clean. Pure/headless.

## Security/constraints
- Injected sources only (no ambient I/O); first-party seeds SRI-verified via `parseSriIntegrity`,
  dropped fail-closed on parse/digest mismatch. Launch authorization is capability-mediated
  (`hasDesktopCapabilityGrant`, `apps.launch`) and fail-closed (`UNKNOWN_APP`/`CAP_DENIED`).
  Pure/deterministic given the seeds; frozen, byte-stable outputs. No remote imports; lockfile
  mandatory; no package lifecycle scripts; no FFI/native addons.
