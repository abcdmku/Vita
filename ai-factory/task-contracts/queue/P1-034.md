## Objective
Wave-2 slice 2. P1-033 put the config→plan **evaluator** on-device (`evaluateNodeConfig(config) → TransactionPlan`,
where `TransactionPlan = { operations: { capability, request }[] }`). This slice adds the on-device config-change
**PREVIEW**: given a CURRENT config and a DESIRED config, evaluate BOTH via the vendored evaluator and **diff their
TransactionPlans by capability**, printing a grep-able marker:
- real change →  `VITA-PREVIEW: added=<A> removed=<R> changed=<C> status=OK`
- current == desired → `VITA-PREVIEW-NOOP: status=OK`

This proves the deterministic preview pipeline (evaluate → diff) runs on-device on the EVALUATOR'S OWN output.

## IMPORTANT — corrected design (this supersedes the round-1 approach)
Round-1 vendored the OLD plan model (`sdk/typescript/src/{plan,diff,explain,validate}.ts`, which operate on
`DesiredState`/`CanonicalPlan`) and diffed `DesiredState` directly. That model is DISTINCT from and DISCONNECTED to
the ADR-0007 evaluator's `TransactionPlan`, so the preview never exercised the evaluator (Codex BLOCKING #1), and
the vendored `validate.ts` shipped an unsafe `accelerators.forEach` (Codex BLOCKING #2). Both are resolved by
diffing the evaluator's TransactionPlans instead and NOT vendoring the old model.

Concretely:
1. **New UPSTREAM module** `sdk/typescript/src/transaction-plan-diff.ts` exporting a pure, deterministic
   `diffTransactionPlans(current: TransactionPlan, desired: TransactionPlan): TransactionPlanChange` where
   `TransactionPlanChange = { added: readonly string[]; removed: readonly string[]; changed: readonly string[] }`
   (capability names, each list SORTED for determinism). Semantics: a capability is `added` if it has an operation
   in desired but not current; `removed` if in current but not desired; `changed` if in both but the `request`
   differs (deep structural compare). Import the `TransactionPlan`/`PlanOperation` types from
   `runtime/evaluator/src/evaluate.ts` (or re-declare the minimal structural types if a cross-package import is
   awkward — keep them structurally identical). **Trust-boundary SAFE (AGENTS.md):** iterate with indexed
   `for` loops over `Object.keys(...)`/the operations array — do NOT call `.forEach`/`.map`/methods off the operation
   arrays in a way a shadowed method could subvert; build a null-prototype map keyed by capability; deep-compare
   requests without invoking attacker-controlled accessors (canonical-JSON or a structural walk that reads own
   enumerable keys). Fail-closed.
2. **Test** `sdk/typescript/test/transaction-plan-diff.test.ts`: determinism (same inputs → identical, sorted
   result across repeats); correctness (a known add / remove / changed-request → exact expected lists; identical
   plans → all-empty); and a trust-boundary case (an operations array / request object with a shadowed `forEach`
   or a throwing getter does NOT make the diff throw or silently skip — it still produces a correct, fail-closed
   result).
3. **On-device:** VENDOR ONLY `transaction-plan-diff.ts` into `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/`
   (byte-identical to upstream except a `// Vendored from …` header + import-path adjustment to the already-vendored
   `evaluate.ts`). **REMOVE the round-1 old-model vendored files** `vita/{plan,diff,explain,validate,capabilities}.ts`
   (not used by the corrected preview). Reuse the P1-033-vendored evaluator/manifest/safe-normalize/registry.
4. **`main.ts`:** define a representative CURRENT config and a DESIRED config (capability-keyed, differing in a few
   capabilities — e.g. add one, drop one, change one), `evaluateNodeConfig` BOTH against `DEFAULT_CAPABILITY_MANIFESTS`;
   if both `ok`, `diffTransactionPlans(currentPlan, desiredPlan)` → print `VITA-PREVIEW: added=A removed=R changed=C`.
   Also a current==desired case → `VITA-PREVIEW-NOOP`. Keep the existing `VITA-TS` + `VITA-EVAL` + `VITA-EVAL-REJECT`.
   PURE: no FS/network.

## User value
The device can show an operator EXACTLY which capabilities a config change adds/removes/changes — computed from the
real evaluator's output, deterministically, locally, before anything is applied. The preview half of safe on-device
reconfiguration; `transaction-plan-diff` is also the shared primitive the controller's preview will reuse.

## Acceptance tests
`acceptance_command` runs BOTH the upstream sdk test and the on-device preview test under
`node --experimental-strip-types --test`. They MUST assert:
1. **Determinism** — identical inputs → identical, sorted diff across repeats.
2. **Upstream parity** — the vendored `transaction-plan-diff` produces results identical to the upstream module on a
   corpus of plan pairs (import BOTH, deep-compare) — proves zero vendoring drift.
3. **Correctness** — known add/remove/changed → exact lists; identical plans → empty; and the evaluate→diff path in
   `main.ts`'s configs yields the expected counts.
4. **Fail-closed / trust boundary** — shadowed-method / throwing-getter inputs don't break the diff.
Orchestrator host-verifies on Borg51: build smoke, boot, confirm `VITA-PREVIEW: added=.. removed=.. changed=..` AND
`VITA-PREVIEW-NOOP` on the serial; `deno check` of the vendored tree passes.

## Reviewer revision (round 1) — BLOCKING (Codex cross-review)
1. **Preview bypassed the evaluator** (`main.ts:220`): went `DesiredState → normalize` directly; the contract
   requires evaluating configs via the evaluator first. ROOT CAUSE: the evaluator's `TransactionPlan` and the old
   `plan.ts` `CanonicalPlan` are distinct, disconnected models. FIX: diff the evaluator's TransactionPlans (above) —
   drop the old model entirely.
2. **`validate.ts:287` `accelerators.forEach`** executes a method off an attacker-controlled array after only
   `Array.isArray` → a shadowed/throwing `forEach` defeats fail-closed validation (AGENTS.md trust boundary). FIX:
   `validate.ts` is no longer vendored (not needed by the corrected preview). The NEW `transaction-plan-diff` must
   itself be written trust-boundary-safe (indexed loops, null-proto maps, no accessor subversion) with a regression
   test.
