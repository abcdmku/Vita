## Objective
Wave-2 slice 2. P1-033 put the config→plan **evaluator** on-device (`evaluateNodeConfig(config) → TransactionPlan`,
where `TransactionPlan = { operations: { capability, request }[] }`). This slice adds the on-device config-change
**PREVIEW**: given a CURRENT config and a DESIRED config, evaluate BOTH via the vendored evaluator and **diff their
TransactionPlans by capability**, printing a grep-able marker:
- real change →  `VITA-PREVIEW: added=<A> removed=<R> changed=<C> status=OK`
- current == desired → `VITA-PREVIEW-NOOP: status=OK`

This proves the deterministic preview pipeline (evaluate → diff) runs on-device on the EVALUATOR'S OWN output.

## IMPORTANT — corrected design (this supersedes the round-1 approach)
Round-1 vendored the OLD plan model (`sdk/typescript/src/{plan,diff,explain,validate}.ts`, which operate on
`DesiredState`/`CanonicalPlan`) and diffed `DesiredState` directly. That model is DISTINCT from and DISCONNECTED to
the ADR-0007 evaluator's `TransactionPlan`, so the preview never exercised the evaluator (Codex BLOCKING #1), and
the vendored `validate.ts` shipped an unsafe `accelerators.forEach` (Codex BLOCKING #2). Both are resolved by
diffing the evaluator's TransactionPlans instead and NOT vendoring the old model.

Concretely:
1. **New UPSTREAM module** `sdk/typescript/src/transaction-plan-diff.ts` exporting a pure, deterministic
   `diffTransactionPlans(current: TransactionPlan, desired: TransactionPlan): TransactionPlanChange` where
   `TransactionPlanChange = { added: readonly string[]; removed: readonly string[]; changed: readonly string[] }`
   (capability names, each list SORTED for determinism). Semantics: a capability is `added` if it has an operation
   in desired but not current; `removed` if in current but not desired; `changed` if in both but the `request`
   differs (deep structural compare). Import the `TransactionPlan`/`PlanOperation` types from
   `runtime/evaluator/src/evaluate.ts` (or re-declare the minimal structural types if a cross-package import is
   awkward — keep them structurally identical). **Trust-boundary SAFE (AGENTS.md):** iterate with indexed
   `for` loops over `Object.keys(...)`/the operations array — do NOT call `.forEach`/`.map`/methods off the operation
   arrays in a way a shadowed method could subvert; build a null-prototype map keyed by capability; deep-compare
   requests without invoking attacker-controlled accessors (canonical-JSON or a structural walk that reads own
   enumerable keys). Fail-closed.
2. **Test** `sdk/typescript/test/transaction-plan-diff.test.ts`: determinism (same inputs → identical, sorted
   result across repeats); correctness (a known add / remove / changed-request → exact expected lists; identical
   plans → all-empty); and a trust-boundary case (an operations array / request object with a shadowed `forEach`
   or a throwing getter does NOT make the diff throw or silently skip — it still produces a correct, fail-closed
   result).
3. **On-device:** VENDOR ONLY `transaction-plan-diff.ts` into `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/`
   (byte-identical to upstream except a `// Vendored from …` header + import-path adjustment to the already-vendored
   `evaluate.ts`). **REMOVE the round-1 old-model vendored files** `vita/{plan,diff,explain,validate,capabilities}.ts`
   (not used by the corrected preview). Reuse the P1-033-vendored evaluator/manifest/safe-normalize/registry.
4. **`main.ts`:** define a representative CURRENT config and a DESIRED config (capability-keyed, differing in a few
   capabilities — e.g. add one, drop one, change one), `evaluateNodeConfig` BOTH against `DEFAULT_CAPABILITY_MANIFESTS`;
   if both `ok`, `diffTransactionPlans(currentPlan, desiredPlan)` → print `VITA-PREVIEW: added=A removed=R changed=C`.
   Also a current==desired case → `VITA-PREVIEW-NOOP`. Keep the existing `VITA-TS` + `VITA-EVAL` + `VITA-EVAL-REJECT`.
   PURE: no FS/network.

## Reviewer revision (round 3) — BLOCKING (Codex cross-review)
The throw-not-empty + safeNormalize-per-operation work is good, but there is STILL a fail-open bypass: a **lying
Proxy over an array** passes `Array.isArray` and can report a fake `length: 0` WITHOUT throwing → the per-operation
loop iterates zero operations → nothing reaches `safeNormalize` → benign empty/no-change diff. Round-3 tests only
covered a THROWING proxy trap, not a non-throwing lying one.

COMPLETE FIX — normalize the WHOLE plan envelope up front (single gate, no bypass):
- At the START of `diffTransactionPlans`, run EACH plan (the entire `TransactionPlan` object, not per-operation)
  through `safeNormalize`. If `{ ok: false }` → throw `TransactionPlanDiffError`. `safeNormalize` rejects Proxies
  (incl. a Proxy array — `util.types.isProxy`) and exotic/accessor values at EVERY level, so a lying Proxy array is
  rejected here, before any length/index is trusted.
- After normalization you hold guaranteed-plain `PlainJson` (a real array, real strings, real plain objects). THEN
  do structural checks on the normalized value (`operations` is a real array; each op has a string `capability` + a
  plain-object `request`) → else throw — and diff on that plain data. Remove the iterate-then-validate path
  (`Array.isArray` + `readArrayLength` on the raw input) — it is the bypass.
- TEST the lying proxy explicitly: a `new Proxy(realOpsArray, { get(t,k){ return k==='length' ? 0 : t[k] } })` as
  `operations` (non-throwing, reports length 0 hiding real ops) MUST throw `TransactionPlanDiffError`, NOT return an
  empty diff. Keep all prior tests (throwing proxy, accessor request, exotic prototype, determinism, parity,
  correctness, FAILSAFE marker).

## Reviewer revision (round 2) — BLOCKING (Codex cross-review)
The evaluate→diff wiring + marker shape are CORRECT and ACCEPTED. The new `transaction-plan-diff` module is not
genuinely fail-closed — 3 findings, ONE root cause: on malformed/exotic input it returns a benign result (empty diff
or "unchanged") instead of refusing. That is fail-OPEN (it silently says "no changes" when it couldn't compute).
1. Top-level `catch` returns an EMPTY diff → a Proxy operations array (whose ownKeys/descriptor access throws) yields
   "no added/removed/changed". MUST NOT silently skip.
2. An accessor `request` collapses to `undefined` and is indexed → two accessor requests both become `undefined` →
   capability treated UNCHANGED. AGENTS.md: reject accessor properties at every level.
3. Exotic-prototype requests (`Date`/`Map`/etc., no enumerable string keys) compare EQUAL → a malformed request hides
   a changed capability. The header claims exotic shapes compare not-equal; the impl doesn't enforce it.

UNIFYING FIX — **validate-or-throw, never a benign fallback**, and REUSE THE PROVEN GUARDIAN:
- For EACH operation in both plans, run the operation (and/or its `request`) through the already-vendored
  `safeNormalize` (the JSON guardian from P1-033 — it already rejects Proxies, accessor/getter properties, and
  non-plain values). If `safeNormalize` returns `{ ok: false }` for ANY operation/request → the TransactionPlan is
  malformed → **THROW a typed `TransactionPlanDiffError`** (fail-closed by REFUSING). Do NOT return an empty diff and
  do NOT coerce unreadable values to `undefined`.
- Compare requests by their `safeNormalize`d canonical form (deterministic PlainJson), so "changed" is decided on
  validated data only. FIRST verify `safeNormalize` REJECTS (does not silently coerce) exotic-prototype objects like
  `Date`/`Map`; if it coerces, add an explicit plain-prototype gate (`Object.getPrototypeOf` ∈ {Object.prototype,
  null}) so exotic requests throw, not compare-equal.
- Iterate the operations array safely: validate it's a real array (else throw); snapshot length; index access inside a
  try that rethrows as `TransactionPlanDiffError` (a Proxy index-trap throw must surface, not be swallowed to empty).
- `main.ts`: wrap the diff in try/catch — on `TransactionPlanDiffError` print a fail-closed marker
  `VITA-PREVIEW-ERROR: status=FAILSAFE` (NOT a bogus `added=0 removed=0 changed=0`). In the normal path (evaluator
  output is always clean) this never triggers, but it proves the fail-closed wiring.
- TESTS must assert THROW (or the FAILSAFE marker), not empty/equal, for: Proxy operations array; accessor `request`
  on both sides; `Date`/`Map`/exotic-prototype `request`; throwing getter. Keep determinism + upstream parity +
  correctness. Upstream + vendored stay byte-identical (except header/import path).
