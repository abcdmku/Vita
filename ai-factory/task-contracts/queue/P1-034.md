## Objective
Wave-2 slice 2. P1-033 put the config→plan **evaluator** on-device; this adds the **operator PREVIEW path** — the
"what will change" view — running under the same Deno runtime. Given a CURRENT config and a DESIRED config, the
device evaluates BOTH → normalizes to canonical plans → **diffs** them → **explains** the diff in human terms, and
prints a grep-able marker:
- `VITA-PREVIEW: added=<A> removed=<R> changed=<C> status=OK` (a real config change → a structured diff summary)
- `VITA-PREVIEW-NOOP: status=OK` (current == desired → empty diff, proving the no-change case is clean)

This proves the deterministic preview pipeline (evaluate → normalize → diff → explain) executes on-device.

Concretely:
- **Vendor the remaining pure preview modules** into the EXISTING `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/`
  (alongside the P1-033-vendored `evaluate.ts` / `capability-manifest.ts` / `safe-normalize.ts` / generated registry
  — REUSE those, do not re-vendor). The new ones (all pure/deterministic, spec §8.2):
  - `sdk/typescript/src/plan.ts` (`normalize` → `CanonicalPlan`; computes canonical plan digests)
  - `sdk/typescript/src/validate.ts` (plan validation)
  - `sdk/typescript/src/diff.ts` (diff two canonical plans → structured change set)
  - `sdk/typescript/src/explain.ts` (render a diff as human-readable text)
  - any pure helper these import transitively (vendor exact source; reuse already-vendored ones).
- **VENDOR EXACT SOURCE — no logic forks.** Copy upstream; only header comments + import-path adjustments for the
  vendored layout are allowed. Keep a `// Vendored from <upstream path>` header on each new file.
- **Deno builtins are FINE — do NOT over-engineer.** `plan.ts` imports `node:crypto` (`createHash`) for plan
  digests. Deno supports `node:crypto` AND `node:util` NATIVELY under `--no-remote` (they are built-ins, not remote
  fetches — VERIFIED for `node:util` in P1-033). So KEEP the upstream `import { createHash } from "node:crypto"` (and
  any `node:util`) — do NOT replace them with indirect resolvers or polyfills. Confirm the vendored tree loads under
  BOTH `deno run --no-remote` and `node --experimental-strip-types`.
- **`main.ts`**: add a preview step — define a representative CURRENT config and a DESIRED config (differing in a few
  capability requests), evaluate both via the vendored evaluator, normalize to canonical plans, diff, explain, and
  print `VITA-PREVIEW` (with added/removed/changed counts). Also run a current==desired case → `VITA-PREVIEW-NOOP`.
  Keep the existing `VITA-TS` + `VITA-EVAL` + `VITA-EVAL-REJECT` markers. PURE: no FS, no network.

## User value
The device can now show an operator EXACTLY what a config change would do (a deterministic, human-readable diff)
BEFORE anything is applied — the preview half of safe on-device reconfiguration, all local, no cloud roundtrip.

## Acceptance tests
`acceptance_command` — `preview.test.ts` (runs under `node --experimental-strip-types --test`, no Deno needed) MUST
assert:
1. **Determinism** — same (current, desired) inputs → byte-identical diff + explanation across repeated calls.
2. **Upstream parity (no drift)** — for a corpus of config-change pairs, the vendored normalize→diff→explain output
   EQUALS the upstream `sdk/typescript/src/{plan,diff,explain}.ts` output (import BOTH, deep-compare). Proves
   vendoring introduced zero behavioral change.
3. **Correctness** — a known change (add/remove/modify a capability request) yields the expected added/removed/
   changed counts; current==desired yields an EMPTY diff (no-op).
Orchestrator host-verifies on Borg51: build smoke, boot, confirm `VITA-PREVIEW: added=.. removed=.. changed=..` AND
`VITA-PREVIEW-NOOP` on the serial; `deno check` of the vendored tree passes.
