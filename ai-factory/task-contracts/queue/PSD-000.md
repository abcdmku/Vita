## Objective
Spec §6.3 de-risking SPIKE (gates the engine choice before production decomposition): prove the **CEF accelerated-OSR →
shared GPU texture/surface → composited by a native core** path. Build a minimal standalone spike (`spikes/cef-osr/`)
that:
- Embeds CEF (Chromium) in **accelerated offscreen-rendering** mode (`OnAcceleratedPaint` / shared-texture handle),
  loads a heavy web app, and hands the rendered surface to the GPU as a **shared texture** (NO CPU bitmap readback in
  the normal path — readback only for the test screenshot).
- A minimal native compositor (wgpu/GL) imports that shared texture and **composites + drag/animates** it; measure
  frame time while moving/animating with the web content NOT repainting (the content texture is reused).
- Records measured FPS + a frame-time histogram + a screenshot, and a clear PASS/FAIL vs the ≥60fps budget.
- If CEF accelerated-OSR misses budget or the shared-texture handoff is unavailable on the target, implement the **WPE
  WebKit fallback** path and re-measure; record which engine meets budget.

## User value
De-risks the single biggest Phase-6 unknown (can the chosen engine deliver accelerated-OSR + shared-texture compositing
at frame budget?) BEFORE committing the production compositor/bridge slices to an engine.

## Non-goals
- NOT production code — a throwaway spike under `spikes/`. No substrate-interface integration, no WM, no shell.
- Don't wire it into the OS image.

## Dependencies
- None (standalone). Verified on the **VMware Workstation Pro GPU target** (3D accel) — see PHASE6-PLAN.md. The build
  + the measurement run there; document the numbers.

## Acceptance
- `acceptance_command` passes (any TS harness around the spike typechecks); the spike BUILDS. The decisive output is the
  measured report (FPS, no-repaint proof, engine verdict) captured on the VMware GPU target — this is a SPIKE so the
  deliverable is the EVIDENCE + a recommendation (CEF vs WPE), not a boot marker. Record results in
  `spikes/cef-osr/RESULTS.md`. Be honest if the GPU target isn't available yet (deliver the buildable spike + the
  measurement harness; flag the run as pending the VM).

## Definition of done
- Spike builds; accelerated-OSR → shared-texture → composite path implemented (CEF, with WPE fallback path); a
  measurement harness that records FPS + no-repaint proof + screenshot; `RESULTS.md` with the engine recommendation
  (or, if the VM isn't ready, the harness + a clear "run pending VMware target" note). R1 (throwaway spike).
