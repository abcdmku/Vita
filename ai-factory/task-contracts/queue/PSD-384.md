## Objective
A **session-driven surface router** for the in-surface desktop runtime. Today `ui_kits/desktop/runtime/bootstrap.ts`
discovers the screen roots once, hydrates them, and returns a static runtime — there is no controller that swaps
surfaces when the session transitions (boot/locked -> authenticating -> unlocked -> re-locked, per PSD-380's session
view-model). Add `ui_kits/desktop/runtime/session-router.ts` that subscribes to the session view-model and, on each
session-state change, hydrates the appropriate screen set and disposes the others:
- **locked / authenticating** -> hydrate ONLY the lock screen (root `data-vita-screen="desktop/lock"`); dispose
  shell/dock/desktop roots if present.
- **unlocked** -> dispose the lock screen; hydrate the desktop shell + dock screen set (`desktop`, `desktop/shell`,
  and remaining non-lock roots discovered in the document).
- **re-lock** (unlocked -> locked) -> reverse: dispose the shell/dock set, re-hydrate the lock screen.
- Reuse the existing primitives — `hydrateScreen` / `disposeScreen` from `ui_kits/desktop/runtime/hydrate.ts` and the
  `ScreenModule` registry shape from `ui_kits/desktop/runtime/screen.ts`. Per-screen hydration MUST stay fail-closed
  and isolated: a screen factory that throws aborts ONLY that screen (a `HydratedInertScreen` or skip), never the rest
  of the set, mirroring the try/continue loop in `bootstrapDesktop`.
- `dispose()` on the router (and on each managed screen) MUST be **idempotent** — second call is a no-op (the
  hydrate layer already guards this; the router must not double-dispose or leak subscriptions).
- The router takes the session view-model (a subscribe/snapshot source matching PSD-380's contract), the discovered
  roots, the `DesktopHost`, and the screen-module registry via **injected parameters** — NO ambient DOM scan inside
  the router, NO platform internals, NO rendering/CEF. Pure interaction/lifecycle logic, headless and deterministic.
- Put the code under `ui_kits/desktop/runtime/session-router.ts`; tests under
  `sdk/typescript/test/ui-kits/session-router.test.ts`. Import the SDK exactly as the other runtime modules do
  (`../../../sdk/typescript/src/desktop-sdk/index.ts`), using ONLY public exports + the existing runtime modules.

## User value
Makes the desktop actually transition between the lock surface and the live shell/dock as the session locks and
unlocks — the missing controller that turns the static one-shot `bootstrap` hydration into a session-reactive
surface lifecycle, without any new visual design.

## Non-goals
- NO DOM/CSS/rendering/CEF; NO document scanning inside the router (roots are injected). NO platform internals.
- Do NOT re-implement `hydrateScreen`/`disposeScreen` or the session view-model — consume them.
- NO new visual design (the screen HTML and lock/shell view-models are the design of record).
- Do NOT modify the production `bootstrapDesktop` boot path's behavior (the router is additive/composable).

## Acceptance
`acceptance_command` passes. Deterministic unit tests against a fake session view-model + fake screen modules +
fake roots cover: (1) initial `locked` -> hydrates the lock screen ONLY; (2) `unlocked` -> disposes lock, hydrates
shell + dock; (3) re-lock -> reverse (shell/dock disposed, lock re-hydrated); (4) router `dispose()` is idempotent
(second call no-ops, subscription released); (5) a screen factory that throws aborts ONLY that screen and the rest
of the set still hydrates (fail-closed isolation). Typecheck clean; pure and headless.

## Security/constraints
- Injected ports/sources only (no ambient I/O, no DOM scan); capability-mediated, fail-closed per-screen; pure and
  deterministic. No remote imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons.
