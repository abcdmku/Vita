## Objective
Make `Compositor<B>` (`packages/compositor-core/src/lib.rs`) hold **N buffer surfaces with explicit z-order and
per-surface placement rects**, recompositing the whole stack each present. Today the live path effectively drives a
single `cef:desktop` buffer surface; the demo (`desktop_demo_surfaces`) stacks test surfaces but there is no stable,
incremental, focus-aware **stacking protocol** for the WM to drive arbitrary CEF surfaces. Extend the existing
`register_buffer_surface` / `update_buffer_surface` / `update_placements` seam (lib.rs:461-573) plus `Placement.z_index`
(lib.rs:140-196) so the compositor:
- Holds **multiple overlapping buffer surfaces** simultaneously, composited back-to-front by `(z_index, surface_id)`
  (the existing total order at lib.rs:539-543) every `composite()`.
- Supports **raise-on-focus**: a new `raise_surface(&SurfaceId)` and `set_z(&SurfaceId, i32)` protocol command that
  reorders the stack (raise = move to top of the current z range) and returns a `DamageReport` covering only the
  affected surfaces' rects — WITHOUT re-uploading any untouched surface texture (`source_repaint_count()` must not
  change for surfaces whose pixels did not change; reuse the no-repaint invariant proven at lib.rs:826/970).
- Supports **removal mid-stack** (`remove_surface`, lib.rs:575-600) leaving the other surfaces' GPU textures intact (no
  re-upload) and damaging only the removed surface's vacated rect.
- **Reconciles out-of-order async updates to the latest snapshot** (subsumes PSD-013's reconcile-to-current-truth
  consistency, REV 6): when buffer/placement/z updates arrive for a surface, the composited result reflects the LATEST
  registered state for every surface — never a stale frame from an earlier update — and damage is limited to the rects
  actually affected.

This is **pure compositor logic** over the `RenderBackend` trait (lib.rs:335-391); it is verified entirely against the
in-tree `RecordingBackend` test double (lib.rs:1636+), no GPU/FFI/KMS. The production KMS/live-render path is untouched
except via the same public methods.

## User value
The WM can drive a real stacking desktop: many CEF windows layered with stable z-order, click-to-raise focus, and
windows opening/closing mid-stack — recompositing each frame without re-uploading untouched window textures and without
ever showing a stale frame from an out-of-order async update. This is the compositor floor the multi-window flagship
desktop renders on; it generalizes today's single-`cef:desktop`-surface live path to N surfaces.

## Non-goals
- NO new `RenderBackend` impl, NO KMS/linux/vmwgfx/GPU/FFI changes — verify against `RecordingBackend` only. Do NOT
  touch `packages/compositor-core/src/platform/*`.
- NO new dependencies, NO remote imports, NO network, NO changes to the marker shape semantics (`SelfTestReport`
  marker_line at lib.rs:705-731 stays byte-compatible; `surfaces=N` already reports the live count).
- NOT window decorations, input routing, or hit-testing beyond the `raise_surface`/`set_z` z-order commands (focus is
  mechanism-only, as today at lib.rs:623-635 — `raise_surface` reorders z; it does not invent input policy).
- Do NOT re-implement the WM intent layer in Rust — this is the compositor primitive the TS WM (PSD-013) drives.

## Acceptance
`acceptance_command` runs the new Rust integration test offline in `rust:1.82` (rust-in-docker, no network) and it
passes. The acceptance is a NEW test target `packages/compositor-core/tests/stacking.rs` (Cargo integration test, so
the exact path `--test stacking` exists only when the work lands — an empty branch fails) that, using
`RecordingBackend`, asserts:
1. Register **3 overlapping buffer surfaces** with distinct z; `composite()` then `output_readback_rgba()` shows the
   top surface's pixels where they overlap (back-to-front order honored); `CompositeReport.surfaces == 3`.
2. `raise_surface(middle)` reorders the stack so `middle` is composited on top; the returned `DamageReport` covers only
   the affected rects; `source_repaint_count()` is UNCHANGED (no texture re-upload on a pure z-order change).
3. `remove_surface(middle)` leaves the other two surfaces' readback pixels and `source_repaint_count()` unchanged (no
   re-upload of untouched surfaces); damage covers the vacated rect; subsequent `composite()` shows the remaining two.
4. Out-of-order async updates reconcile to the latest snapshot: apply `update_buffer_surface`/z updates for a surface in
   a non-monotonic order and assert the final composited frame reflects the LATEST state for every surface (no stale
   frame), with damage limited to affected rects.
5. The self-test / demo marker still emits a well-formed line; a multi-surface run prints, to stdout from the test, a
   line of shape `VITA-COMPOSITOR: ... surfaces=3 ... status=OK` (assert the substring `surfaces=3` and `status=OK`).
Re-run independently: the same `cargo test --offline` is green and the existing `cargo test` suite (the lib.rs `#[cfg(test)]`
module, all current passing tests) stays green.

## Security/constraints
- Pure/deterministic compositor logic over the `RenderBackend` trait; same inputs → identical composited bytes and
  identical `DamageReport`/`CompositeReport`. No I/O beyond the existing readback/PNG seam. No ambient state.
- Fail-closed: `raise_surface`/`set_z`/removal on an unknown surface return `CompositorError::UnknownSurface` (mirror
  lib.rs:575-578, 623-628); never panic, never leave a placement referencing a removed surface.
- No remote imports; offline build (`--offline`); no added crates; no lifecycle/build scripts; no FFI/native addons.
- Determinism floor: the `(z_index, surface_id)` total order (lib.rs:539-543) is the ONLY tie-break — keep it stable.
