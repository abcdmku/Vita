## Objective
SDK type + fail-closed validator for the enabled-services config (the authoring/controller counterpart to
the P7-007 agent services capability — same shape so the controller can author/preview what the agent
stores). `ServiceEntry { name: string; enabled: boolean }` and `ServicesConfig { services: ServiceEntry[] }`.
`validateServicesConfig(input)` uses `safeNormalize`, then validates on the trusted value.
- **Validate fail-closed**: each `name` is a valid systemd unit name — non-empty, bounded length (≤ 256),
  charset `[A-Za-z0-9:._@-]` only; reject path separators (`/`,`\\`), `..`, whitespace, and anything that
  looks like inline key material (§13.1: PEM / `data:` / long base64). `enabled` must be a boolean and
  PRESENT (absent ⇒ reject — explicit presence). Reject duplicate service names. `services` must be present
  and an array (an explicit empty array `[]` = "no managed services" is VALID and distinct from absent;
  absent ⇒ reject). Reject unknown keys on each entry and on the envelope.

## User value
The typed contract the controller uses to author + preview a node's enabled-services set (FR-007),
validated identically to the agent so a malformed/ambiguous config is rejected before it reaches the node.

## Non-goals
- No real systemctl, no agent, no I/O. Types + pure validator only. No shared-index edits. Do NOT import
  the Go capability (this is the independent TS model with the same rules).

## Dependencies
P0-015 (safeNormalize). Merged.

## Acceptance tests
`acceptance_command` — `services-model.test.ts`: a valid config validates; explicit empty `services: []`
validates (distinct from absent, which is rejected); a malformed unit name (path sep / `..` / whitespace /
bad charset / inline content) rejected; absent or non-boolean `enabled` rejected; duplicate service names
rejected; unknown entry/envelope key rejected; hostile/partial input fails closed via safeNormalize.
Orchestrator also runs `npm run typecheck`.
