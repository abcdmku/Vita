## Objective
`previewUpdate(currentConfig, plan)` (controller/update): given the current `UpdateConfig` + a proposed
`UpdatePlan` (both the P8-002 SDK model), produce a typed, fail-closed **update preview** — WITHOUT any
real apply: validate both via the P8-002 validators; check the plan via `validatePlanAgainstConfig`
(A/B safety — must target the INACTIVE slot); and return a typed preview {targetSlot, activeSlot,
bundle (ref+integrity+version), safe: boolean, rejections}. Fail-closed: any validation failure or a
plan targeting the active slot ⇒ a typed preview rejection, never a throw.

## User value
The management-plane "stage this A/B update" check (FR-023/006) — surfaces the target slot + integrity-
pinned bundle and refuses an unsafe plan (active-slot overwrite) before anything is applied.

## Non-goals
- No real RAUC/bundle apply/download, no agent call, no network. Validation + preview only. Do NOT modify
  the P8-002 `update-model`; import it.

## Dependencies
P8-002 (update model: validateUpdateConfig/validateUpdatePlan/validatePlanAgainstConfig), P0-015. Merged.

## Acceptance tests
`acceptance_command` — `update-preview.test.ts`: a valid config + inactive-targeting plan ⇒ safe preview;
a plan targeting the ACTIVE slot ⇒ unsafe/rejected (not a throw); a malformed config/plan ⇒ typed
rejection via the P8-002 validators; hostile input ⇒ fail-closed (no throw). Orchestrator also runs
`npm run typecheck`.

## Performance & security constraints
Deterministic, no I/O/network. Fail-closed (reuse P8-002 validators; never throw). A/B safety enforced.
Strict TS (no `any`). R2 → reviewer-gated.
