## Objective
Define the typed **capsule** structure (spec §13) — the portable bundle of app contract, runtime
artifacts, state, policy, and simulation — plus a fail-closed structural validator. Model the five
sections from §13:
- `manifest`: package contract (reuse `PackageContract` from P1-001), versions, signatures (as
  references, not embedded keys — §13.1), SBOM.
- `runtime`: OCI image index refs, WASM components, TS source/compiled artifact (as descriptors).
- `state`: application-consistent snapshot descriptor, canonical export descriptors, migration metadata.
- `policy`: data grants, network grants, resource limits, identity bindings.
- `simulation`: required profiles, expected health checks, failure tests.
Provide `validateCapsule(value: unknown): { ok: true; capsule: Capsule } | { ok: false; errors: {...} }`
that is **fail-closed and intrinsic-safe** (per AGENTS.md — normalize/validate untrusted input without
executing its methods; reject partial/exotic/cyclic shapes; secrets must be references not embedded).

## User value
The capsule is how apps + data move between machines/architectures (spec §13, FR-020). A precise,
validated type is the basis for x86↔ARM migration and portable backup/restore.

## Non-goals
- No packing/unpacking, no encryption/signing implementation, no real artifacts — **types + structural
  validation only** (spec §13: capsules are encrypted+signed, but that's the storage layer later).

## Dependencies
P1-001 (`PackageContract`).

## Acceptance tests
`acceptance_command`. `storage/capsules/test/capsule.test.ts` must prove:
1. A complete valid capsule validates and yields the typed `Capsule`.
2. A capsule missing a required section/field (or with an embedded secret instead of a reference) is
   rejected with a precise path.
3. Fail-closed: malformed/partial/cyclic/method-shadowed input ⇒ rejected, never throws.

## Performance & security constraints
Pure/deterministic, no I/O. Secrets referenced not embedded (§13.1). Fail-closed + intrinsic-safe.
