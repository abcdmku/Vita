## Objective
Promote the P9-002 dialect from an inline TS constant to a SHARED, language-neutral JSON artifact both planes
will load (ADR 0007 step 1). This is the single source of truth file.
- **`schema/capabilities/timesync.json`**: the `timesync` capability manifest expressed as JSON data in the
  P9-002 dialect — `{ "capability":"timesync", "version":1, "fields": { "enabled": {...}, "servers": {...} },
  "crossFieldRules": [...] }` — mirroring exactly the merged `TIMESYNC_MANIFEST` (hostname-only `servers`,
  `lowercase`+`uniqueItems`, `noInlineSecrets`, `enabled`⟺`servers`). Include a top-level `"version": 1`.
- **`loadCapabilityManifest(raw: unknown)`** (added to `sdk/typescript/src/capability-manifest.ts`): parse +
  validate the manifest STRUCTURE itself fail-closed — `safeNormalize` the input, require `capability`
  (non-empty string), `version` (the supported integer), `fields` (a record of valid `FieldSchema` per the
  dialect — reject unknown schema keys / bad types), `crossFieldRules` (each a valid closed `CrossFieldRule`
  referencing existing fields of the right types). Return `{ ok: true, manifest: CapabilityManifest } | {
  ok: false, reason }`. A malformed manifest (unknown field type, bad cross-field reference, unsupported
  version, unknown top-level key) ⇒ rejected — the LOADER is itself a trust boundary on the schema file.
- Refactor so the public `TIMESYNC_MANIFEST` is OBTAINED by loading `timesync.json` (or prove equivalence):
  `compileCapabilityValidator(loadCapabilityManifest(<timesync.json>).manifest)` must validate identically
  to the inline constant — i.e. the JSON file is now authoritative.

## User value
The capability schema becomes a real shared artifact (ADR 0007) — a checked-in JSON file the TS plane loads
and validates, ready for the Go plane (P9-005) and the evaluator (P9-001) to load the SAME file, eliminating
the TS/Go drift that blocked the config→plan evaluator.

## Non-goals
- No Go changes yet (P9-005), no evaluator (P9-001), no migration of caps, no IP-literal support, no codegen.
  Additive + a refactor of the P9-002 module. Do NOT change validation BEHAVIOR (the timesync rules are
  unchanged — only their source moves to JSON).

## Dependencies
P9-002 (the dialect + `compileCapabilityValidator` + `TIMESYNC_MANIFEST`), P0-015 (safeNormalize). Merged.

## Acceptance tests
`acceptance_command` — `capability-manifest-loader.test.ts`: loading `schema/capabilities/timesync.json` via
`loadCapabilityManifest` succeeds and the compiled validator accepts/rejects the SAME corpus as the P9-002
inline manifest (hostnames accept; IP/`::1` reject as out-of-scope; enabled⟺servers; case-insensitive dedup;
absent enabled; unknown key; inline secret) — i.e. behavior is unchanged; a MALFORMED manifest (unknown
field `type`, a cross-field rule referencing a missing/non-boolean field, an unknown top-level key, an
unsupported `version`) ⇒ `loadCapabilityManifest` returns `{ ok:false }` (no throw); hostile manifest input
fails closed. Orchestrator runs `npm run typecheck`.

## Performance & security constraints
Pure/deterministic, no network (read the JSON via Node fs in the TEST only; the loader takes parsed data).
The loader is fail-closed (the manifest file is a trust boundary — reject malformed schemas). Behavior
parity with P9-002 (the JSON is authoritative). Strict TS (no `any`). R2 → reviewer-gated.

## Reviewer revision (round 2 — BLOCKING, from P9-003.review.md)
1. **No production import-time I/O.** The round-1 build read `timesync.json` via `createRequire` at module
   import — production filesystem I/O that conflicts with the pure/no-I/O TS surface. Round 2: `loadCapability
   Manifest(raw)` stays PURE (operates on already-parsed data); `TIMESYNC_MANIFEST` is a PURE INLINE constant
   (no I/O on import). Take the contract's "or PROVE EQUIVALENCE" path: keep the JSON file as the shared
   artifact, and add a TEST (Node `fs` in the TEST only) that reads `schema/capabilities/timesync.json`,
   parses it, runs it through `loadCapabilityManifest`, and asserts the result DEEP-EQUALS the inline
   `TIMESYNC_MANIFEST` (so the JSON is authoritative-by-CI: if the file and the constant drift, the test
   fails). Remove all `createRequire`/fs from the production module.
2. **Deep-freeze.** Freeze EACH cross-field rule object + each field schema object in the exported
   `TIMESYNC_MANIFEST` (round 1 only froze the rules array) — restore the P9-002 immutability.

## Rollback plan
