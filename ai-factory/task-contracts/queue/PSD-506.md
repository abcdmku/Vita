## Objective
Remove the placeholder fabricated boot/process transcript that renders on the live GPU in degraded/no-host mode, and replace it with REAL behavior: the live `shell.output` buffer is the single source of truth for the shell `data-vita-bind-list` container.

Evidence of the placeholder:
- `ui_kits/desktop/Shell.html:13-21` hardcodes an invented success session inside the `data-vita-bind-list="shell.output"` container: `✓ kernel ready · 0.42s`, `✓ mounted vfs at /`, `✓ compositor online · 60fps`, and `k.processes.where(p => p.cpu > 1)` → `[ { pid: 14, name: "compositor", cpu: 3.8 } ]`.
- A real `ShellSessionPort` exists (`ui_kits/desktop/viewmodels/Shell.ts:21-23`, selected at `ui_kits/desktop/screens/shell.ts:71-81`); the viewmodel already fail-closes (`submit()` returns `SHELL_SESSION_PORT_UNAVAILABLE` when no session — `viewmodels/Shell.ts:197-206`) and starts with an **empty** `outputBuffer`.
- Root cause is in the binder: `applyListTarget` (`ui_kits/desktop/runtime/binder.ts:683-744`) only removes list children that carry a `data-vita-key` (`vitaKey`). The hardcoded transcript divs have **no** `data-vita-key`, so they are never tracked or removed. In the CEF live boot there is no host bridge, `shell.output` binds to the empty buffer, but the un-keyed seed survives → the invented transcript renders on the GPU.

Required fix:
1. `ui_kits/desktop/runtime/binder.ts` — when `applyListTarget` resolves a list bind, it MUST remove pre-existing **un-keyed** seed children of the bind-list container (children with no `data-vita-key`), not just stale keyed nodes. After the first apply, the container's rendered children must be exactly the keyed nodes derived from the live `shell.output` items — and ONLY those. An empty buffer ⇒ zero rendered child rows (honest "not connected"/empty state), never the fabricated success transcript. Keep the existing template-capture behavior intact (the un-keyed template node used for cloning must still be usable; clear the *seed instances*, not the cloning template, and do not regress other bind-lists).
2. `ui_kits/desktop/Shell.html` — delete the hardcoded transcript lines at `Shell.html:13-21` (the `// Vita shell` comment line and the invented `import/const/await/✓ …/k.processes.where… / [ { pid: 14 … } ]` lines). The container keeps its `data-vita-bind-list="shell.output"` and may retain ONLY a keyed cloning template node (`data-vita-key` template) the binder uses — no invented sample content.

## User value
On the live GPU at boot (no host bridge), the flagship shell no longer lies — it shows the real, empty/“not connected” state instead of an invented success transcript. Once a `ShellSessionPort` host method is wired, the same container renders the live buffer with no placeholder to fight.

## Non-goals

- NO new visual design; NO change to the viewmodel’s fail-closed contract; do NOT weaken any other screen’s bind-list rendering.
