## Objective
SDK type + fail-closed validator for a single audit-trail entry (spec §17 provenance / FR-008 — who did
what to which capability, with what outcome). `AuditEvent`: `sequence` (monotonic non-negative integer),
`timestampMillis` (non-negative integer epoch ms), `actor` (a typed reference — actor kind:
"human"|"agent"|"system" + an opaque id string, NOT inline credentials), `capability` (well-formed
capability name), `operation` ("apply"|"read"), `outcome` ("committed"|"rejected"|"rolled_back"|"failed"),
and optional `reason` (short string). `validateAuditEvent(input)` uses `safeNormalize`, then validates on
the trusted value.
- **Validate fail-closed**: integers finite + non-negative; actor kind from the closed set + non-empty id;
  capability name well-formed; operation + outcome from their closed sets; `reason` (if present) a bounded
  plain string. Absent required field ⇒ reject. **§13.1**: reject any field carrying inline key material
  (PEM/`data:`/long base64) — an audit event must never embed secrets. Also expose
  `isMonotonic(events)` — true iff `sequence` strictly increases across an ordered list (reject equal/
  decreasing), so a log can be checked for gaps/replays.

## User value
The typed, validated provenance record the agent emits + the controller renders (spec §17/FR-008) — every
privileged change is attributable, with a monotonic sequence so tampering/replay (out-of-order or repeated
sequence) is detectable; secrets can never be smuggled into the trail.

## Non-goals
- No real audit-log storage, no agent, no I/O. Types + pure validators only. No shared-index edits.
