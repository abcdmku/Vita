## Objective
Headless, deterministic **view-model** for the flagship desktop's `Settings` screen (`ui_kits/desktop/Settings.html` / index.html),
built ONLY on `@vita/desktop-sdk` public ports (the settings port + theme tokens (PSD-023 when present, else theme port)) — injected ports, NO platform internals, NO DOM/rendering (the view-model
is the pure interaction logic the rendered design binds to later).
- State: sidebar sections, active section, Appearance values (theme: light/dark/graphite, accent color, layout density/tiling). Actions: setTheme(t), setAccent(c), setLayout(l), select(section) — each writes via the settings port and reflects the new value; reads initial values from the port. Fail-closed without the settings grant; reject unknown enum values.
- Put the code under `ui_kits/desktop/viewmodels/Settings.ts` and tests under `sdk/typescript/test/ui-kits/Settings.test.ts`.
- Import the SDK exactly as `ui_kits/desktop/package.ts` does; use ONLY public exports.

## User value
Turns the static `Settings` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design (the HTML is the design of record). Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the state transitions + fail-closed paths described above against fake SDK ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/Settings.ts` + `sdk/typescript/test/ui-kits/Settings.test.ts`, deterministic, typecheck clean. R1.
