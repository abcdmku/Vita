## Objective
Harden the P1-045 fetch path per its cross-review (which APPROVED the load-bearing SRI-before-extract + traversal +
nothing-staged properties but flagged three follow-ons that MUST land together):
1. **Real zstd decode.** P1-045's `extractTar` reads the `.tar.zst` artifact as a PLAIN uncompressed tar (the committed
   test bundle begins with a ustar header, not the zstd magic `28 b5 2f fd`). Implement genuine zstd decompression
   (klauspost/compress/zstd — vendored, offline) wrapping the tar reader; re-bake the test bundle as a REAL
   zstd-compressed tar with a recomputed SRI. SRI is still verified over the FULL compressed artifact bytes BEFORE
   decompression/extraction (unchanged trust order).
2. **Extraction resource caps (CRITICAL once decompression exists).** Add an `io.LimitReader` / per-entry size cap, a
   total-uncompressed-bytes cap, and an entry-count cap to `extractTar`/`writeTarFile`. A decompression bomb or an
   integrity-valid-but-adversarial bundle must be REFUSED (fail-closed, nothing staged) — not allowed to exhaust
   disk/RAM. Caps are constants/manifest-bounded and documented.
3. **Traversal test completeness.** P1-045's test only covers the `../` relative vector. Add table cases for an
   ABSOLUTE-path entry and for `TypeSymlink`/`TypeLink` entries with an escaping `Linkname`, asserting each is
   rejected and NOTHING is staged. (The impl is already safe via `safeArchiveName`/`safeExtractPath` + the
   `default: return error` arm — these tests pin that behavior against future refactors.)

Minor (fold in): replace deprecated `tar.TypeRegA` (SA1019) with `tar.TypeReg`; consider rm-then-rename self-heal when
the cache target exists but is incomplete (`existingComplete`==false currently errors permanently).

## User value
The node can fetch REAL compressed capsule bundles, and a maliciously-crafted (but integrity-valid) or
decompression-bomb artifact cannot exhaust the node — the supply-chain path is both functional and DoS-resistant.

## Non-goals
NO network registry/auth yet (still local artifact). NO OCI format. Keep SRI-over-full-compressed-bytes-before-decode
trust order. Don't regress P1-045's verified properties.

## Dependencies

## Acceptance tests
`acceptance_command` — Go tests: a REAL zstd bundle decodes+extracts+verifies (SRI over compressed bytes); a
decompression bomb / oversized total / too-many-entries is REFUSED fail-closed (nothing staged); absolute-path entry
rejected; symlink/hardlink escape rejected; existing P1-045 cases stay green. vet/staticcheck-clean (no TypeRegA).
Orchestrator host-verifies: boot, `VITA-CAPSULE-FETCH … verified=OK` for the re-baked REAL zstd bundle + a tampered
artifact → `VITA-CAPSULE-FETCH-REJECT reason=sri_mismatch`, nothing staged.

## Performance & security constraints
SRI over full compressed bytes BEFORE decode. Bounded decompression (size/entry/total caps) — fail-closed on exceed.
Traversal-safe (abs/symlink/hardlink). No network, no keys. R3 (supply-chain + DoS surface) → parallel-candidate +
reviewer gate.
