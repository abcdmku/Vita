## Objective
A standalone, fully unit-testable mapping from Linux **evdev** key codes to a CEF key event:
`windows_key_code` (VK code), DOM `key`/`code` strings, and a modifier bitmask, plus
**shift/caps state tracking** for the US (QWERTY) layout. This is the gnarly lookup table the CEF
OSR host (`spikes/cef-osr/osr_host.cc`, ADR-0014) will need once it injects keyboard input via
`CefBrowserHost::SendKeyEvent` — extracted NOW so the later routing/host wiring slices stay thin and
this table is independently verified before any CEF link exists.
- Ships as a small **vendored C++ header** `spikes/cef-osr/input/evdev_keymap.h` (the form
  `osr_host` will `#include` — pure constexpr/`switch`, no CEF symbols, no I/O, no allocation), AND a
  **mirrored TS fixture** `sdk/typescript/src/ui-kits/cef-keymap.ts` that encodes the SAME matrix so
  it can be cross-checked headlessly under Node (CEF cannot be linked in CI). The TS module is the
  source of record for the test; a comment in each file points at the other so they stay in lockstep.
- Coverage (US layout): letters a–z, digits 0–9, Enter, Backspace, Tab, Escape, Space, the four
  arrows (Up/Down/Left/Right), and the modifier keys (LeftShift/RightShift, LeftCtrl, LeftAlt,
  CapsLock). Each entry yields the CEF `windows_key_code` (VK_*), the DOM `code` (e.g. `KeyA`,
  `Digit1`, `Enter`, `ArrowUp`), and the modifier bit it contributes (if any).
- **Modifier composition + state**: a small pure state tracker folds keydown/keyup of the modifier
  keys into a current modifier bitmask, and tracks CapsLock toggle. The produced DOM `key` for a
  printable key reflects shift/caps: `a` -> `a`, `Shift+a` -> `A`, `CapsLock` then `a` -> `A`,
  `Shift+1` -> `!` (US shift map for the number row), CapsLock has NO effect on digits/symbols.
- **Unknown / out-of-range evdev codes are dropped** (mapping returns null/has-no-entry; the tracker
  ignores them) — fail-closed, never a bogus key event.
- Pure and deterministic: same (evdev code, modifier state) in -> byte-identical event out. No DOM,
  no rendering, no CEF, no ambient I/O.

## User value
The hardest, most error-prone part of CEF keyboard input — the evdev->VK->DOM table and the
shift/caps composition rules — lands as a verified unit, so the subsequent host/routing slices that
feed real key events into the live-rendered desktop are thin wiring over a table that is already
proven correct.

## Non-goals
- NO `CefBrowserHost::SendKeyEvent` call / no CEF link / no edit to `osr_host.cc` itself (a later
  routing slice consumes the header). NO mouse/pointer/touch mapping. NO non-US layouts, no IME, no
  dead keys, no key repeat policy. NO reading `/dev/input` or any device I/O. NO DOM/CSS/rendering.

## Acceptance
`acceptance_command` passes: `npm run typecheck` is clean and the Node test
`sdk/typescript/test/ui-kits/cef-keymap.test.ts` asserts the full key matrix against the TS fixture —
letters/digits/Enter/Backspace/Tab/Escape/Space/arrows resolve to the expected
`windows_key_code` + DOM `code`; modifier composition (`Shift+a` -> `A`, `Shift+1` -> `!`, CapsLock
toggle affects letters but not digits) is correct; modifier keydown/keyup updates the bitmask;
unknown/out-of-range evdev codes are dropped. The test must reference exact mapped entries (no
vacuous glob) so an empty branch fails. The vendored C++ header parses as a self-contained
constexpr/switch translation unit (it `#include`s nothing CEF) — a comment in the header documents
the build-time check; the authoritative automated check is the TS mirror.

## Security/constraints
- Pure/deterministic, no ambient I/O, no device access, no network. No remote imports; lockfile
  unchanged; no package lifecycle scripts; no FFI/native addons in the TS module. The C++ header is a
  leaf with zero dependencies (no CEF includes) so it cannot widen the spike's attack surface.

## Definition of done
- `spikes/cef-osr/input/evdev_keymap.h` (vendored, CEF-free, constexpr/switch) +
  `sdk/typescript/src/ui-kits/cef-keymap.ts` (mirror) + `sdk/typescript/test/ui-kits/cef-keymap.test.ts`,
  the two encodings agreeing on the documented matrix, deterministic, typecheck clean. R1.
