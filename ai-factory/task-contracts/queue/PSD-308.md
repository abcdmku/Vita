## Objective
Give the production daemon a **stable, reconnectable command transport** so CEF (and later the WM/shell) can attach and
detach without tearing down the compositor. Today the only command path is the process's **stdin**: the
`CommandDrivenSession` (`packages/compositor-core/src/main.rs:283`) reads `registerSurface`/`registerBufferSurface`/
`updateBufferSurface`/`updatePlacement`/`removeSurface`/`present` lines via `run`/`run_continuous` from `stdin.lock()`
(main.rs:106, main.rs:118). stdin is fine for selftest/M1 (one producer, dies with the pipe), but a powered-on desktop
needs a producer that can crash/restart/re-attach while the compositor keeps its scene and KMS scanout alive.
- Add a **unix-socket command listener** selected by a new flag `--command-socket=<path>` to `--commands`/
  `--command-stream` mode. When absent, behave EXACTLY as today (stdin path, byte-identical; zero behavioral change to
  the existing present/marker flow). The socket and stdin paths must drive the SAME `CommandDrivenSession` so behavior is
  identical regardless of transport.
- The socket is created **root-owned, mode `0660`, group-gated** (same posture as `agentd.sock`): bind the listener,
  `chmod` to `0660`, set the owning group so only the compositor's peer group can connect. Refuse to run if the path
  exists and is not a socket we own (no clobbering arbitrary files). Remove the socket on clean exit.
- Speak the **SAME bounded line protocol** already implemented in `CommandDrivenSession::handle_line` (main.rs:360) —
  the exact `registerBufferSurface`/`updateBufferSurface`/`updatePlacement`/`present` grammar, the
  `MAX_COMMAND_RGBA_BYTES` (16 MiB) cap (main.rs:19, `checked_command_rgba_len` main.rs:664, `parse_buffer_payload`
  main.rs:674), and the present/no-repaint invariant. Do NOT fork a second protocol dialect.
- **Reconnectable + fail-closed framing:** accept ONE client at a time; on client disconnect (EOF/EPIPE) the compositor
  KEEPS its current scene + last present and goes back to `accept()` waiting for the next client (no scene teardown, no
  panic). A malformed or oversize command line is rejected fail-closed (the existing `CompositorError::Protocol` /
  `InvalidBufferLength` / "rgba payload exceeds maximum command size" errors); a per-line/per-connection error must
  drop/close THAT connection without crashing the daemon or corrupting the scene. NEVER `panic!`/`unwrap` on attacker-
  controlled input.
- Keep emitting the existing `VITA-COMPOSITOR: ...` OK/FAILSAFE marker on **stdout** (the verification channel,
  `SelfTestReport::marker_line`, lib.rs:705) once after the first successful present — unchanged.
- Put the integration test at `packages/compositor-core/tests/command_socket_ipc.rs` (a `--test` target so it builds in
  linux `rust-in-docker` AND fails closed on an empty branch — an empty crate has no such test target, so the exact-path
  `cargo test --test command_socket_ipc` cannot pass vacuously).

## User value
Replaces the brittle stdin/baked-file command feed with a real, reconnectable daemon socket: the CEF host (and later the
window manager / shell) can restart or re-attach without killing the live desktop, which is the prerequisite for a
durable powered-on Vita desktop rather than a one-shot pipe that dies with its first producer.

## Non-goals
- NO new command verbs and NO change to the existing bounded text grammar or the present/no-repaint invariant (the socket
  carries the SAME protocol as stdin; `--command-socket` absent ⇒ byte-identical behavior). NO binary/RPC framing — plain
  bounded text lines only. NO multi-client fan-in (one attached client at a time is sufficient for this slice). NO CEF
  code, NO TS/DOM, NO networking beyond a local AF_UNIX socket (`allowed_network: false`). Keep the production KMS path
  and the stdin selftest/M1 path untouched.

## Acceptance
`acceptance_command` passes: `npm run typecheck` clean; `cargo test --test command_socket_ipc -- --exact` passes
deterministic integration tests over a `RecordingBackend` (the in-crate test backend, lib.rs:1636 / main.rs:1027 style)
that cover: (1) **bounded RGBA reject** — a `registerBufferSurface`/`updateBufferSurface` payload exceeding
`MAX_COMMAND_RGBA_BYTES` is rejected with the exact `Protocol("rgba payload exceeds maximum command size")` /
`InvalidBufferLength` error and the daemon stays up; (2) **malformed-command reject, no panic** — a garbage/short line is
rejected fail-closed and the process does not panic; (3) **reconnect after client disconnect** — a client connects, sends
valid commands + `present`, disconnects; a SECOND client then connects to the SAME socket and successfully drives another
`present` (scene preserved, no teardown); (4) **present after updateBufferSurface** — a socket session that
`registerBufferSurface` → `updatePlacement` → `present` → `updateBufferSurface` → `present` succeeds; (5) **socket
round-trip == stdin round-trip** — a headless socket session and the equivalent stdin command list produce the SAME
output readback (`output_readback_rgba`, lib.rs:654) and the SAME `marker_line()`. INDEPENDENT (orchestrator): compositor
builds for linux via `rust-in-docker` (`cargo build --release --locked` in the pinned `rust:1.88.0-bookworm` container)
and `cargo test --test command_socket_ipc` is clean there. State honestly whether the linux build/test passed.

## Security/constraints
- Socket is **root-owned, `0660`, group-gated** (agentd.sock posture); refuse to bind over a non-owned existing path; unlink
  on clean exit. Transport is **fail-closed and reconnectable**: per-connection/per-line errors drop/close that connection
  without crashing the daemon or mutating the scene into an inconsistent state; client disconnect preserves the scene and
  returns to `accept()`. Reuse the existing bounded caps (`MAX_COMMAND_RGBA_BYTES`, cap line length / payload length as in
  `parse_buffer_payload`); never `panic!`/`unwrap` on socket-supplied bytes. No ambient I/O beyond the explicitly-passed
  `--command-socket` path; `allowed_network: false` (AF_UNIX only, no TCP/remote). No remote imports; `--locked` crates;
  lockfile; no package lifecycle scripts; no FFI/native addons beyond the crate's existing deps. Keep the compositor crate
  SELF-CONSISTENT (every called fn must exist/compile in linux `rust-in-docker` — the Windows-host `npm run typecheck` does
  NOT catch Rust errors; the `rust-in-docker` floor is authoritative).
