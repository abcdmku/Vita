## Objective (read fully — REFOCUSED: foundation + node.config; timesync DEFERRED)
The `/apply` operation `request` IS the capability's full `ApplyRequest` (`{"desired":{…}}`), so manifests
that are in the EVALUATOR'S DEFAULT REGISTRY must model the full request AND prove manifest≡agent at the
agent's real `DecodeJSONRequest` entrypoint. node.config (closed enums, no IP) can do this cleanly. **timesync
CANNOT yet** — the agent's `timesync.ApplyRequest` accepts IP-literal servers (netip), but the manifest
`format` set only has hostname formats (parity-safe IP is the deferred hard work from P9-002), so
manifest≢agent on IP vectors. Therefore timesync's migration is DEFERRED and it is EXCLUDED from the default
registry until a parity-safe IP format exists.
1. **Object-type dialect primitive (governed, TS + Go):** `FieldSchema` `{ type:"object", required, fields:
   Record<string,FieldSchema> }` — validator recurses, rejecting unknown keys + duplicate JSON keys at this
   level + validating nested fields. Documented in the closed type set. (Authorized here.)
2. **Migrate `node.config` (full request):** `node.config.json` = top-level `desired` object with `mode`
   (enum normal/maintenance) + `remoteAccess` (enum disabled/enabled), required. Conformance ≡ the agent via
   `transport.DecodeJSONRequest[nodeconfig.ApplyRequest]` (full `{"desired":{…}}` vectors, raw strings for
   dup-key). Harden the node.config request decode to reject duplicate JSON keys (envelope + inner) BUT keep
   `validateConfig` in `Validate()` (not eager in `UnmarshalJSON`). Regenerate ⇒ `NODE_CONFIG_MANIFEST`.
3. **Default-registry inclusion flag.** A manifest JSON may set `"defaultRegistry": false` to be EXCLUDED
   from the codegen-emitted `DEFAULT_CAPABILITY_MANIFESTS` (a PoC / not-yet-faithful manifest). Set
   `"defaultRegistry": false` on `timesync.json` (it stays for the P9-006 TS≡Go conformance, but is NOT in
   the evaluator's default registry). node.config + hostname have no flag ⇒ included. The default registry =
   { hostname.set, node.config }.
4. **REVERT any timesync re-model** from prior rounds: `timesync.json` + its conformance + `TIMESYNC_MANIFEST`
   return to their merged (P9-006) state, plus only the `"defaultRegistry": false` flag.
5. **Evaluator + apply-node** use the default registry (hostname + node.config). Update
   `runtime/evaluator/test/evaluate.test.ts` + `controller/apply-node/test/apply-node-config.test.ts`
   fixtures to use a node.config (or hostname) full-request config — NOT timesync. Same assertions.

## Performance & security constraints

default registry. Strict TS / clean `go vet`. R3 → reviewer-gated.
**BOUNDED dup-key scan (DoS — R3 trust boundary).** The recursive duplicate-JSON-key pre-scan in the
node.config decode MUST have a bounded depth + node/total budget — an untrusted deeply-nested `/apply`
request (`{"extra":[[[[…]]]]}`) must FAIL CLOSED (a typed rejection), never force unbounded recursion / stack
or CPU exhaustion. Reuse the bounded scanner pattern from `agent/internal/capmanifest` (the manifest JSON
scanner is bounded) rather than an unbounded recursive walk. Add a regression: a request nested past the
bound is rejected (no panic / no runaway). Apply the SAME bound to the inner-config scan.
