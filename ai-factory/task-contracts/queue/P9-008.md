## Objective (FOUNDATIONAL — read fully; this supersedes any inner-config assumption)
The `/apply` operation `request` IS the capability's full `ApplyRequest`, decoded by `DecodeJSONRequest
[<cap>.ApplyRequest]` — e.g. node.config receives `{"desired":{"mode":"maintenance","remoteAccess":
"enabled"}}` and timesync receives `{"desired":{"enabled":true,"servers":[...]}}`. So for the evaluator's
plan to be SUBMITTABLE and for conformance to test the agent's REAL entrypoint, **every manifest must model
the full `{desired: …}` request**, not the inner config. `hostname.json` already does (`{desired:<string>}`).
This task makes the foundation correct and migrates `node.config`:
1. **Object-type dialect primitive (GOVERNED extension, TS + Go).** Add `FieldSchema` `{ type:"object",
   required, fields: Record<string,FieldSchema> }`; the validator recurses — reject unknown keys + duplicate
   JSON keys at THIS level, validate each nested field's presence/type/constraints. Document it in the closed
   `FieldSchema` type set. (This is the intended way to express nested requests; it is authorized here.)
2. **`node.config.json` = the full request:** one top-level field `desired` of `type:"object"`, whose
   `fields` are `mode` (string, `enum:["normal","maintenance"]`, required) + `remoteAccess` (string,
   `enum:["disabled","enabled"]`, required). Regenerate (`npm run gen:manifests` ⇒ `NODE_CONFIG_MANIFEST`,
   auto-joins the default registry).
3. **Re-model `timesync.json` to the full request** (it currently wrongly models the inner config — a latent
   non-submittable bug): one top-level `desired` object with `enabled` + `servers` (keep their constraints
   incl. `hostnameRFC1123` servers + `enabled`⟺`servers` cross-field rule, now under the object). Regenerate.
4. **Conformance against the agent's REAL decode** (node.config + timesync): vectors are full requests
   `{"desired":{…}}` (raw JSON strings for dup-key cases); BOTH the manifest validator AND `transport.
   DecodeJSONRequest[<cap>.ApplyRequest]` (+ `ApplyRequest.Validate`) run each vector and MUST agree. Harden
   the node.config request decode for duplicate JSON keys (envelope + inner) so it matches the manifest —
   BUT keep `validateConfig` in `Validate()` (do NOT validate eagerly inside `UnmarshalJSON`; that breaks
   the pre-transaction gate + the transport tests).
5. **Evaluator + apply-node:** `config[capability]` is the full `{desired:{…}}` request; the plan operation
   `request` = the validated full request (submittable). Update the evaluator tests AND
   `controller/apply-node/test/apply-node-config.test.ts` fixtures to the full-request shape (same
   assertions). hostname stays as-is.

## User value
The migration foundation made correct + consistent: every manifest = the agent's real request, every
conformance = the real entrypoint, the evaluator emits directly-submittable plans. node.config migrated;
timesync's latent inner-config bug fixed.
