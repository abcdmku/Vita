## Objective
Migrate the `node.config` capability onto the shared manifest (ADR 0007 migration pattern, following P9-007).
The cap's rules (`agent/capabilities/nodeconfig/nodeconfig.go` `validateConfig`) are two CLOSED ENUMS — no
new format needed (existing dialect: `string` + `enum` + `required`).
- **`schema/capabilities/node.config.json`** (capability key `"node.config"`, matching the agent op name +
  the registry convention): fields `mode` (string, `enum:["normal","maintenance"]`, required) and
  `remoteAccess` (string, `enum:["disabled","enabled"]`, required). Reject unknown keys. Regenerate the const
  (`npm run gen:manifests` ⇒ `NODE_CONFIG_MANIFEST`) — it auto-joins `DEFAULT_CAPABILITY_MANIFESTS`.
- **`schema/capabilities/conformance/node.config.json`**: ≥ 12 accept/reject vectors — valid {normal,
  disabled}/{maintenance,enabled} combos; invalid mode/remoteAccess value; absent mode or remoteAccess;
  unknown key; duplicate JSON key (valid final value); non-object.
- **TS + Go conformance tests** (like P9-007): the TS manifest validator AND the Go manifest validator each
  match every vector, AND the Go manifest validator agrees with the AGENT's actual `node.config` validator
  on every vector (drive it through the cap's validate/decode entrypoint). Any disagreement FAILS.
- **Dup-key parity:** if the agent `node.config` decode does NOT already reject duplicate JSON keys (the
  manifest validator does), HARDEN it with `rejectDuplicateObjectKeys` (matching the other caps — a latent
  smuggling gap, as P9-007 found for hostname) so manifest≡agent; include an effective dup-key vector.
- The evaluator's default registry now covers node.config (auto via codegen) — extend the evaluator test to
  evaluate a node.config request.

## User value
Whole-node apply coverage extends to node.config (mode + remote-access), proven to match the agent — the
third capability on the shared schema, exercising the enum path of the migration pattern.

## Non-goals
- No new dialect format (enums suffice), no transport/wiring changes beyond a possible dup-key hardening,
  no other caps. Additive manifest + conformance + registry (auto).

## Dependencies
P9-007 (the migration pattern + default registry + conformance harness). Merged.

## Acceptance tests
`acceptance_command` runs the TS conformance. The ORCHESTRATOR runs the Go conformance in the container
(manifest≡corpus AND manifest≡agent-validator) + `npm run typecheck` + the evaluator tests (now covering
node.config). A wrong corpus expectation must fail both planes.

## Performance & security constraints
Deterministic; enums via the existing dialect (no new format); manifest faithfully matches the agent (proven,
incl. dup-key parity). Strict TS / clean `go vet`. R3 (may touch the TCB cap for dup-key) → reviewer-gated.
