## Objective
The Go counterpart to the TS `compileCapabilityValidator` (P9-002/P9-003): a generic, audited package
`agent/internal/capmanifest/` that loads a capability manifest (the shared dialect) and validates a JSON
request against it, fail-closed, with semantics IDENTICAL to the TS validator so a cross-language conformance
corpus (P9-006) passes. This is the single Go validation engine that will replace per-cap hand-written
validators.
- `LoadManifest(raw []byte) (Manifest, error)`: parse + validate the manifest STRUCTURE itself fail-closed
  (mirror `loadCapabilityManifest`): require `capability`, supported `version`, `fields` (each a valid
  `FieldSchema` of the dialect — `string` with optional `pattern`/`maxLength`/`enum`/`lowercase`/
  `noInlineSecrets`, `integer` with `minimum`/`maximum`, `boolean`, `array` with `items`/`minItems`/
  `maxItems`/`uniqueItems`; each field `required` bool), `crossFieldRules` (closed set:
  `requireNonEmptyArrayWhenTrue`, `requireEmptyArrayWhenFalse`, referencing existing fields of the right
  types). Reject unknown manifest/field-schema keys, bad refs, unsupported version.
- `Validate(manifest Manifest, requestJSON []byte) error` (or a compiled validator): reject duplicate JSON
  object keys; reject unknown request keys; enforce per-field presence (required-absent ⇒ reject; absent ≠
  present-zero/empty), type, and constraints (pattern via Go `regexp` with the SAME pattern string; `enum`;
  `minimum`/`maximum`; `maxLength`; `minItems`/`maxItems`; `uniqueItems` AFTER applying `lowercase`
  canonicalization; `noInlineSecrets` = reject PEM `-----BEGIN` / `data:` anywhere (case-insensitive) /
  long base64-or-base64url); then the cross-field rules. Fail-closed; never panic on hostile input.
- **Semantic parity is the contract.** The accept/reject decision for any request MUST match the TS
  `compileCapabilityValidator` for the same manifest + request. Embed `schema/capabilities/timesync.json`
  (via `go:embed` or a test fixture copy) and validate against it in tests.

## User value
The privileged plane gains ONE audited manifest-driven validator (ADR 0007) — replacing 13 hand-written
per-cap validators with a single conformance-tested engine — and the foundation the config→plan evaluator
(P9-001) + whole-node apply require, with the TS plane validating identically from the SAME manifest.

## Non-goals
- No migration of existing caps yet (P9-005 is the engine; wiring caps to it is later), no transport changes,
  no IP-literal format (timesync is hostname-only), no `os/exec`. Additive new package.

## Dependencies
P9-003 (the shared JSON manifest + the TS validator semantics to mirror — read
`sdk/typescript/src/capability-manifest.ts` for the exact dialect behavior). Merged. Follow AGENTS.md
dup-JSON-key + fail-closed + absent≠zero rules.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Cover: `LoadManifest` accepts
`timesync.json` and rejects malformed manifests (unknown field type, bad cross-field ref, unsupported
version, unknown key); `Validate` against the timesync manifest accepts a valid enabled-with-hostnames
request; rejects enabled-with-empty-servers, disabled-with-non-empty-servers, malformed hostname, IP literal
(out of scope ⇒ reject), case-insensitive duplicate, absent `enabled`, unknown key, duplicate JSON keys,
inline secret material; hostile/truncated JSON fails closed (no panic). The accept/reject set MUST match the
TS validator's (the corpus is shared in P9-006).
