## Objective
Build the Phase-2 **Developer CLI** (`vita`) — the local developer's command-line front-end to the SAME control
plane the on-device runtime already drives (the EVAL→PREVIEW→EXPLAIN→APPLY chain proven on-device by P1-033..P1-043).
The CLI is a host-side, UNPRIVILEGED TypeScript program that COMPOSES the existing, already-merged building blocks and
adds only argument parsing, a Node unix-socket `AgentTransport`, and human-readable output. It must NOT re-implement
the evaluator, the diff, the apply flow, or the capsule preview — it WIRES them.

A new `cli/` package with these subcommands (all read-only/preview by DEFAULT; mutation requires an explicit flag):

- **`vita evaluate <config.json> [--json]`** — load a node-config JSON document from a file path, run it through
  `evaluateNodeConfig` (import `runtime/evaluator/src/evaluate.ts`) against `DEFAULT_CAPABILITY_MANIFESTS`
  (import `sdk/typescript/src/generated/capability-manifests.generated.ts`), and print the resulting
  `TransactionPlan` (operation count + per-capability summary; `--json` prints the canonical plan JSON). On an
  invalid config, print the structured `EvaluationRejection`s and exit NON-ZERO (fail-closed). This is pure/offline —
  no agentd contact. (v1 input is a JSON config document, NOT a `.ts` module — see Non-goals.)
- **`vita preview <config.json> [--socket <path>]`** — evaluate the config to a plan, then DIFF it against the node's
  CURRENT live state read from agentd (`AgentClient.getState` per capability over the unix socket), reusing the
  existing transaction-plan diff (`sdk/typescript/src/transaction-plan-diff.ts`, the same one `main.ts` uses). Print
  the added/removed/changed summary. NEVER mutates. This is the DEFAULT posture: a developer previews before applying.
- **`vita apply <config.json> --commit [--socket <path>]`** — evaluate→apply via the EXISTING
  `applyNodeConfig` (import `controller/apply-node/src/apply-node-config.ts`) over a POST `/apply` transport. **Apply
  is GATED behind an explicit `--commit` flag**; without it the command behaves like `preview` and prints
  "dry-run (pass --commit to apply)" then exits zero WITHOUT contacting `/apply`. Print the `ApplyNodeApplyResult`
  outcome (committed / rolledBack / rejected) and exit non-zero on any non-`committed` outcome (fail-closed).
- **`vita capsule list|preview [--socket <path>]`** and **`vita capsule install <capsule.json> --commit`** — `list`
  reads the current capsule registry from agentd and prints installed capsules; `preview` reuses
  `readCapsuleRegistryPreview` (`controller/capsule/src/capsule-preview.ts`) to show install/remove/upgrade counts
  for a desired registry vs. current; `install` is GATED behind `--commit` and submits a `capsule.registry` apply via
  the same apply transport (default = preview/dry-run). Reuse the existing capsule preview/diff — do not re-derive it.
- **`vita state [<capability>] [--socket <path>]`** — query node state: with no arg, list capability names + health
  (`AgentClient.getOperations` / `getHealth`); with a capability arg, print that capability's state
  (`AgentClient.getState`). Read-only.

New code the CLI OWNS (the only non-trivial new logic):
- **`cli/src/agentd-transport.ts`** — a host `AgentTransport` (the interface from `controller/agent-client/src/agent-client.ts`)
  implemented over a **Node `node:net` `net.connect({ path })` unix-socket** HTTP/1.1 client (the host analogue of the
  on-device Deno transport at `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/unix-socket-transport.ts` — same wire
  behavior: Connection: close, bounded response size, chunked decode). Default socket path = `/run/vita-agent/agentd.sock`
  (overridable by `--socket`). It must enforce the SAME guard the on-device apply transport enforces: GET is always
  allowed; POST is allowed ONLY for `/apply` (a `createApplyTransport()` variant), so a read-only command can never be
  tricked into a mutation path. Bound the response body (reuse the 64 KiB cap convention).
- **`cli/src/args.ts`** — a tiny, dependency-free argument parser (no remote/3rd-party CLI lib): subcommand routing,
  `--commit` / `--socket <path>` / `--json` flags, positional file path. Unknown flag / missing required arg ⇒ usage
  error + non-zero exit (fail-closed, do not "best-effort" guess).
- **`cli/src/format.ts`** — pure human-readable formatting of plans / diffs / apply results / rejections (clear errors
  are an explicit goal). Pure, no I/O, unit-testable.
- **`cli/src/vita.ts`** — the entry point: parse args, read the input file (the ONLY filesystem read; via `node:fs`),
  dispatch to a command, set the process exit code. Commands return a typed result; `vita.ts` is the only place that
  touches `process`/stdout/stderr so the commands stay pure and testable.

**Add `"cli/**/*.ts"` to the `include` array in `tsconfig.json`** so `npm run typecheck` (strict TS 7) covers the new
package (the existing include list does not cover `cli/`).

## User value
Closes the Phase-2 "Developer CLI" deliverable (spec §21, Phase 2). A developer can drive the node's declarative
control plane from a terminal — evaluate a config to a plan, preview the diff against live state, apply it, manage
capsules, and inspect node state — over the SAME untrusted-proposes / agentd-validates boundary the OS uses, with no
shell access to the host (spec §21 exit gate: "A TypeScript plan can configure a service without shell access"). It
also gives the orchestrator + future tests a scriptable surface over the control plane.

## Non-goals
- **NO new privilege and NO new agentd endpoints.** The CLI is unprivileged; it ONLY talks to the EXISTING agentd
  read/`/apply`/`/read/{cap}`/`/operations`/`/healthz` surface. If something the CLI needs is missing from agentd, STOP
  and report it — do not add a privileged handler in this slice.
- **NO `.ts` config module evaluation / no Deno embed.** v1 input is a JSON node-config document (and a JSON capsule
  registry); compiling/sandbox-executing a developer's `system.ts` is a later slice. (The deterministic evaluator
  already operates on the normalized config object; feeding it JSON is the thin, safe first increment.)
- **NO re-implementation** of the evaluator, the transaction-plan diff, `applyNodeConfig`, or the capsule preview —
  import and compose the already-merged modules. Do not fork the plan/diff model.
- **NO 3rd-party CLI / arg-parsing dependency** (no commander/yargs); no remote imports; no new runtime deps. No
  package lifecycle scripts. Keep `cli/` dependency-free beyond `node:*` + first-party imports.
- NO interactive prompts, NO config-file discovery/globbing, NO daemonization, NO writing to the host filesystem
  (only READS the input config file). NO secrets handling — the CLI never reads, generates, or transmits keys.

## Acceptance tests
`acceptance_command`: `node --experimental-strip-types --test "cli/test/*.test.ts"` MUST pass on a clean run, AND the
worker MUST run `npm run typecheck` (strict TS 7) clean for files it touched (the strip-types acceptance erases types;
typecheck is the real type gate — per AGENTS.md §2). The tests (no hidden cases here) must cover, against an INJECTED
in-memory `AgentTransport` mock and the real evaluator/diff/apply modules — NO real socket, NO real agentd:
- **evaluate**: a valid config produces the expected `TransactionPlan` (operation count + capabilities); an invalid
  config (unknown capability / bad request shape / empty config / non-object) yields `EvaluationRejection`s and the
  command returns a non-zero exit code. Deterministic: same input ⇒ same plan output (spec §21 exit gate).
- **preview**: evaluate + diff against a mocked `getState` current-state response; assert the added/removed/changed
  summary; assert preview makes NO `/apply` call (the mock transport records calls; assert zero POSTs).
- **apply gating (fail-closed, security-critical)**: WITHOUT `--commit`, the command performs NO POST `/apply`
  (assert the mock saw zero POSTs) and exits zero as a dry-run; WITH `--commit`, it POSTs `/apply` once and on a
  mocked `rejected`/`rolledBack` outcome (or a transport/malformed response) it exits NON-zero and prints the reason
  (never crashes/throws past the boundary).
- **agentd-transport**: the Node unix transport (driven against a throwaway `node:net` `net.createServer` listening on
  a temp unix socket that speaks one canned HTTP/1.1 response) builds a correct request and parses status+body incl. a
  chunked response; and its guard REJECTS a POST to any path other than `/apply` (read transport rejects ALL POSTs) —
  proving a read command cannot be steered into a mutation.
- **capsule**: `preview` reuses the existing capsule preview to produce install/remove/upgrade counts against a mocked
  registry read; `install` without `--commit` makes no apply call.
- **format**: plan/diff/apply-result/rejection formatting is pure and stable (snapshot the strings).

Orchestrator independent verification (no Borg51 boot needed — this is an off-device host tool): re-run the acceptance
command + `npm run typecheck`; read the diff to confirm the CLI composes the existing modules (no forked evaluator/
diff/apply), that apply is genuinely gated behind `--commit`, and that the only privileged-ish surface (the transport)
fail-closes POSTs to non-`/apply` paths.

## Performance & security constraints
- **Security model (encode it):** the CLI is UNPRIVILEGED and only PROPOSES; ALL privileged host mutation stays in the
  narrow Go agentd, which RE-VALIDATES every plan from the re-decoded manifest/input and FAILS CLOSED — the CLI's
  output is never trusted by agentd. The CLI's transport may POST only to `/apply` (read variant: no POST at all);
  read commands cannot reach a mutation path. Mutation requires an explicit `--commit` flag (dry-run/preview default).
- **Fail-closed everywhere:** invalid config ⇒ rejections + non-zero exit (never a partial/best-effort apply);
  malformed/oversized agentd responses ⇒ a typed error result, never an unhandled throw escaping a command; bounded
  response body (64 KiB). Use the existing `safeNormalize`-based parsing in the reused modules; do not hand-roll a
  looser parser at the boundary.
- **No secrets / no keys** (spec §13.1, §16): the CLI never reads, embeds, generates, or transmits key material;
  signing/TPM/recovery keys are OWNER-HELD and out of scope. No secrets in code, tests, or fixtures.
- **No remote imports; no new dependencies; no lockfile change** (the package adds no third-party deps). Deterministic
  evaluate output (same JSON in ⇒ same plan out).
- R1: an isolated, non-privileged TS module/tool — no TCB change, no new agentd surface.
