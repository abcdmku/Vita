## Objective
Headless, deterministic **view-model** for the flagship desktop's application/window switcher
(Cmd/Alt-Tab), built ONLY on `@vita/desktop-sdk` public ports (the window model + WM types used by
`ui_kits/desktop/viewmodels/stage.ts`). No DOM/rendering/CEF, no platform internals — this is the
pure interaction logic the rendered overlay binds to later.
- Maintain a **most-recently-used (MRU) window order** derived from window-manager focus. The MRU is
  rebuilt deterministically from the SDK `WindowModel` (`windows` + `focusStack`): the focused
  window is most-recent, then the remainder of `focusStack` in order, then any windows not in the
  focus stack ordered by a stable key (`window.id`). Track focus changes over time so the switcher
  reflects real WM focus history, not just a single snapshot.
- Actions form one cycle session: `begin()` opens the switcher and pre-selects the next MRU entry
  (the second most-recent window, so a single begin+commit swaps the two most-recent apps);
  `cycleForward()` / `cycleBack()` move the highlight through the MRU list (wrapping); `commit()`
  closes the switcher and emits a **focus intent** (`{ type: "focus", windowId }`, matching the
  stage WM intent shape) for the highlighted window; `cancel()` closes the switcher and restores the
  prior focus (emits no focus intent, or a focus intent for the originally-focused window — pick one
  and make it consistent + tested).
- Read the WM model through an injected port (same fail-closed pattern as `stage.ts`'s
  `StageWindowManagerPort.readWindowModel()` / `applyWindowManagerIntents()`); never touch ambient
  I/O. All committed focus changes go through the injected WM port and fail-closed if the port
  rejects/throws.
- Edge cases fail-closed: **zero windows** — `begin()` is a no-op rejection (no session, no
  intents); **one window** — `begin()` either no-ops or selects the sole window with no swap, and
  `commit()` emits no spurious focus change; cycle/commit/cancel called with **no active session**
  reject deterministically.
- Put the code under `ui_kits/desktop/viewmodels/app-switcher.ts` and tests under
  `sdk/typescript/test/ui-kits/app-switcher.test.ts`.
- Import the SDK exactly as `ui_kits/desktop/viewmodels/stage.ts` does (relative import of
  `../../../sdk/typescript/src/desktop-sdk/index.ts`); use ONLY public exports
  (`WindowModel`, `WindowState`, `WindowId`, `WindowManagerEvent`, `createWindowModel`,
  `focusWindow`, etc.). Mirror the `ok/error/intents/state` result shape and `Object.freeze`
  discipline of `stage.ts`.

## User value
The core multi-app switching primitive: turns Cmd/Alt-Tab into real, testable desktop behavior on
the SDK so the user can flip between running apps by most-recent use — the logic the CEF-rendered
switcher overlay hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF; NO keybinding/global-shortcut registration (the chord layer is separate
  — this VM only exposes begin/cycle/commit/cancel actions). NO platform internals. NO new visual
  design. Don't re-implement SDK window-model functions — consume them.

## Acceptance
`acceptance_command` passes against fake injected WM ports: deterministic unit tests prove
(1) MRU order builds from `windows` + `focusStack` (focused first) and updates as focus changes;
(2) `begin()` -> `commit()` emits exactly one `{ type: "focus", windowId }` intent for the chosen
window and that window becomes focused via the WM port; (3) `cycleForward`/`cycleBack` wrap and move
the highlight deterministically; (4) `cancel()` restores prior focus and emits no spurious focus
change; (5) empty (zero-window) and single-window edge cases fail-closed as described; (6) WM port
throw/reject is surfaced as an `ok:false` error, not a crash. Typecheck clean. Pure, headless.
The exact (non-glob) test path means an empty branch fails.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic (same
  inputs -> same MRU order + same intents). No remote imports; lockfile; no lifecycle scripts.
  `allowed_network: false`.

## Hardware profiles
- Portable-first; pure TS, no native addons / FFI. Runs in any Node with
  `--experimental-strip-types` (the SDK test runner profile).
