## Objective
S1 (P1-035) opened the unix-socket channel (`VITA-CONNECT`). This slice has the unprivileged TS runtime READ host
state THROUGH agentd over that socket — proving the boundary works for real data before any mutation (S3). At boot,
after `VITA-CONNECT`, `main.ts` reads agentd's state/read endpoint and prints `VITA-STATE: caps=<N> hostname=<x>
status=OK` (fields per what agentd actually reports), plus `VITA-STATE-ERROR: status=FAILSAFE` on any failure
(never crash the oneshot). PURE READ — the runtime gains NO new mutation authority and NO direct host-FS access; it
only learns to *talk* to agentd (which already exists and re-validates everything).

Concretely:
- **Find agentd's read endpoint.** Read `agent/transport/server.go` (routes) + `agent/cmd/agentd/main.go` — agentd
  already serves read handlers (the frontier map noted `/healthz` (S1) + capability read handlers; look for a state
  / `/read/{cap}` / `/state` route). Use the EXISTING read endpoint that exposes node state (capabilities and/or
  hostname). If genuinely none exists, add a MINIMAL read-only `GET /state` handler to agentd that returns the
  registered capability names (+ hostname if cheap) as JSON — read-only, no mutation, no new privilege.
- **Vendor the agent client** into `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/agent-client.ts` from
  `controller/agent-client/src/agent-client.ts` (the typed client + its `AgentTransport` interface, ~line 20) —
  byte-identical except a `// Vendored from …` header + import-path adjustments. Provide a Deno **unix-socket
  transport** implementing `AgentTransport` by REUSING the HTTP-over-unix helper S1 added to `main.ts` (refactor
  S1's hand-rolled `Deno.connect({transport:"unix"})` + HTTP/1.1 request/response code into a small reusable
  transport module under `ts/vita/` if cleaner — don't duplicate it).
- **`main.ts`**: after `VITA-CONNECT`, construct the client over the unix transport, call the read/state method, and
  print `VITA-STATE: caps=<N> hostname=<x> status=OK` (use the real fields agentd returns). On error →
  `VITA-STATE-ERROR: status=FAILSAFE`. Keep ALL prior markers (VITA-TS/EVAL/EVAL-REJECT/PREVIEW/PREVIEW-NOOP/
  EXPLAIN/CONNECT). Pure read; no FS/network beyond the unix socket; AF_UNIX-only kept.

## User value
The unprivileged runtime can OBSERVE host state through the privileged boundary — the read half that de-risks the
apply keystone (S3): a bug here is observable + harmless (a GET), nothing to roll back.

## Non-goals
NO mutation/apply (S3). NO PDS write. NO new Deno permission beyond S1's socket-scoped read/write. NO AF_INET. Vendor
exact client source. If you add a `/state` handler to agentd, it MUST be read-only (no mutation, no new caps).

## Dependencies
P1-035 (S1, the unix transport + the `VITA-CONNECT` client helper in main.ts) merged + host-verified. Read S1's
main.ts transport code, `controller/agent-client/src/agent-client.ts`, and agentd's routes first.

## Acceptance tests
`acceptance_command` — `agent-client.test.ts` (node --experimental-strip-types --test) MUST: drive the vendored
agent-client against a MOCK `AgentTransport` and assert it builds the right request + parses a representative
state response into the `VITA-STATE` fields; assert upstream parity (vendored client ≡ `controller/agent-client`
on the mock); assert fail-closed (a transport error / malformed response → a safe error result, not a throw that
escapes). If you add a Go `/state` handler, also add a Go test for it (`cd agent && go test ./transport/...`) and
include that in the acceptance. Orchestrator host-verifies on Borg51: boot (plain + verity), confirm `VITA-STATE:
... status=OK` on the serial after `VITA-CONNECT` (the runtime actually read agentd's state on-device).

## Performance & security constraints

endpoint is read-only. Fail-closed marker on error. Pure parsing (reuse safeNormalize if parsing untrusted JSON from
agentd). No keys. R1.
