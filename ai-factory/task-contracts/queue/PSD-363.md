## Objective
Ship **Terminal** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), on the app-package SDK foundation
(PSD-361). Three artifacts, mirroring the flagship-package pattern:
1. **App package** under `apps/terminal/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` —
   `id: "vita.app.terminal"`, `version`, `sdkVersion: SDK_VERSION`, `entry: "index.html"`, and the MINIMAL
   `capabilityGrants` Terminal needs (NONE of the privileged host grants — Terminal does NOT get `files.write` or
   raw host access; declare an empty/minimal grant set so it fails closed) and a `WebAppDescriptor`
   (`surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-terminal" }`, `title:"Terminal"`,
   `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/terminal/index.html` — a static HTML/CSS terminal surface (monospace output area +
   prompt input), CSS-var tokens, no inline JS (behavior via the view-model / binder convention). Minimal; NOT the
   acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/terminal-app.ts` — a PURE, in-memory terminal
   session model (no real shell, no host process execution in this slice; command execution against a real capsule/agentd
   is explicitly deferred): injected-port style, frozen `snapshot()`, discriminated-union results. State: scrollback lines
   (`{ kind:"input"|"output"|"error"; text }`), current input buffer, command history with cursor, working-prompt label.
   Actions: `type(text)`, `submit()` (echoes the input line + appends a deterministic output from an injected pure
   command-resolver port — e.g. a `help`/`echo`/`clear` built-in table, UNKNOWN command -> a deterministic error line,
   fail-closed), `historyPrev()`/`historyNext()`, `clear()`. NO real process spawning, NO DOM/CSS, NO ambient I/O, NO
   network.

## User value
Terminal becomes a swappable first-party package the dock/launcher lists + launches into its own WM window, with a real
testable in-memory session model — proving the app-package pattern for an interactive app, with the privileged
command-execution backend cleanly deferred behind an injected port.

## Non-goals
- NO real shell / process spawn / host execution / FFI in this slice (deferred to a later capsule-backed slice). NO DOM/
  CSS/CEF logic in the view-model. NO platform internals; NO new SDK ports beyond PSD-361 + existing. OFFLINE only.
- Do NOT grant Terminal privileged capabilities; it fails closed on anything not explicitly granted.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at `sdk/typescript/test/ui-kits/terminal-app.test.ts`
cover the manifest (`defineAppPackage` accepts it; minimal grants; descriptor url === entry) and the view-model state
transitions (type/submit echoes input + appends resolver output; built-in commands; UNKNOWN command -> deterministic
error/fail-closed; history prev/next cursor; clear empties scrollback; deterministic snapshot). `npm run typecheck` is
clean. Pure, headless. (The exact test path exists only when the work lands — an empty branch fails.)

## Security/constraints
- MINIMAL/empty capabilityGrants; the command-resolver is an INJECTED pure port (no ambient process execution);
  fail-closed on unknown commands and absent ports; pure/deterministic. OFFLINE. No remote imports; lockfile; no
  lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).

## Allowed tools + network
Local filesystem + Node test runner + `npm run typecheck` only. `allowed_network: false`.

## Compute/time budget
`budget_minutes: 120`, single worker.
