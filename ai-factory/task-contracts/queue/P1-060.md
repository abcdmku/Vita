## Objective
W6-S3 (ADR-0011 slice 3 — controlled egress, DEFAULT-DENY): a capsule whose validated manifest declares egress CIDR
grants gets REAL outbound reachability to ONLY those CIDRs (+ ports), and NOTHING else. This is the first slice where a
capsule can reach off-namespace. Build on S2's per-capsule netns (P1-059): switch granted capsules from
`PrivateNetwork=yes` to the NAMED netns (the dormant `netns.go` Create/withCapsuleNetns machinery — agentd enters the
netns to program it), add a veth pair (capsule end inside the netns, host end on the host), and install nftables rules
that **default-deny all egress** and **allow ONLY the manifest's egress CIDRs/ports**. Capsules with NO egress grant
stay loopback-only (S2). Capsules with no network at all stay AF_UNIX-mute.

Concretely:
- **veth + routing:** agentd creates a veth pair; moves one end into the capsule netns (the netns from S2's machinery),
  assigns a link-local /30 (or host-routed) addressing host↔capsule, brings both ends up, sets the capsule's default
  route via the host end. NO bridge to the wider LAN; the host end is a dedicated per-capsule link (no promiscuous
  forwarding). IP forwarding enabled ONLY for the specific allowed flows.
- **nftables DEFAULT-DENY:** in the capsule netns (and/or the host forward path for that veth), a per-capsule nft table
  with policy DROP; ACCEPT rules ONLY for the manifest's egress CIDRs (+ ports if specified) and established/related
  return traffic; DROP everything else (incl. all other CIDRs, link-local-only by default). NO NAT/masquerade beyond
  what's needed to reach the granted CIDRs (document the choice). DNS is NOT resolved for the capsule this slice (egress
  is CIDR-only per ADR-0011 v1 — the capsule connects to IPs within granted CIDRs).
- **MANIFEST-ONLY nft composition (CRITICAL):** agentd builds the nft rule set IN CODE from the re-validated egress CIDR
  grants (reuse the P1-057 validators: NormalizeCIDR/SourceCoversAll/PortAll) — NEVER from raw runtime-supplied rule
  text/strings. The capsule proposes only `{cidr,port}` which is validated; agentd emits the nft bytes. No shelling out
  to user-controlled strings; if nft is invoked, args are agentd-constructed + validated.
- **Teardown:** remove the nft table, the veth (both ends auto-removed with the netns), the netns — NO leak across churn
  (extend the S2 transaction-undo).
- **MEASURED marker (the P1-055 lesson):** the baked test capsule (egress grant to a TEST CIDR that maps to a host-side
  listener) REALLY connects to an in-grant addr (succeeds) AND REALLY fails to reach an out-of-grant addr (dropped). The
  marker is gated on BOTH (in-grant reach OK + out-of-grant DENY enforced), plus agentd confirming the nft policy is DROP
  with only the granted ACCEPTs. NEVER synthesized.
Markers: `VITA-CAPSULE-NET-EGRESS: id=<id> allowed=<cidr> reach=OK denied=<other> drop=enforced status=OK`;
`VITA-CAPSULE-NET-EGRESS-REJECT: reason=<specific step+errno> status=OK`; `…-ERROR: status=FAILSAFE`. Keep ALL prior
markers (incl. NET-NS, NET-PARSE). Diagnosability: specific step+errno on failure (the S2 rev2 pattern).

## User value
A capsule can serve its purpose by reaching exactly the network endpoints its manifest grants — and provably NOTHING
else (default-deny). The kernel + nftables enforce the egress allowlist; a compromised capsule cannot exfiltrate to an
un-granted destination. The core of capsule networking.

## Non-goals
NO ingress/DNAT/port-publish (S4). NO DNS resolution service (CIDR-only egress v1). NO LAN bridge / promiscuous
forwarding. NO NAT beyond reaching granted CIDRs. agentd composes nft ONLY from the validated manifest (never raw text).
Non-granted-egress capsules stay loopback-only (S2 behavior unchanged).

## Performance & security constraints
Default-deny egress (policy DROP); ACCEPT only validated manifest CIDRs/ports + established/related; manifest-only nft
composition (no raw runtime text, no user-controlled shell args); per-capsule veth (no LAN bridge/promiscuous); minimal
forwarding; all S2/ADR-0009 hardening intact (AF widening still granted-only); teardown no-leak; setns thread-safety;
fail-closed (any setup error → DROP-all + FAILSAFE, never fail-open to allow-all). No keys. R3 → reviewer gate.
