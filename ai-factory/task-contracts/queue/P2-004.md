## Objective
Flesh out the controller's UniFi-style overview (spec §7, FR-008) with typed, SDK/stub-backed
read-only endpoints (R2 → reviewer-gated):
- `getStorageOverview(): StorageOverviewResponse` — pools/volumes, encryption state, snapshot
  cadence, capacity/health summary, and the **protection-state model** (spec §10.3: clearly
  distinguish snapshot vs mirror vs local-backup vs off-site backup — "a mirror is never displayed
  as a backup").
- `getBackupStatus(): BackupStatusResponse` — backup targets, last/next run, last restore-test result
  (FR-014/015), each tagged with its protection level (not conflating mirror with backup).
- `getIdentitySummary(): IdentitySummaryResponse` — roles present (owner/admin/member/…), passkey
  enrollment status, audit-log availability (FR-016). No secrets/PII beyond non-sensitive summary.

Types must be real and precise; data may be stubbed. Route through the existing in-memory dispatcher;
unknown methods still fail closed; malformed params return typed errors, never throw.

## User value
The overview is the product's first screen (spec §28, FR-008). Crucially it must encode the
protection-state distinction (§10.3, §16 "user perceives mirror as backup" risk) so the UI can never
present a mirror as a backup.

## Non-goals
- No mutation/apply; no real host probing; no transport. Read-only typed endpoints over stub data.
- No identity secrets/credential material in responses.

## Dependencies
P2-001 (controller dispatcher + patterns).
