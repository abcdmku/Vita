## Objective
W5-S6 (ADR-0010 approach C — the strong-isolation `microvm-service` class, owner-greenlit "do them all"): run a baked
first-party OCI rootfs in a STRONGLY-ISOLATED container via **systemd-nspawn** — its OWN PID/mount/IPC/UTS namespaces +
private users (`--private-users=pick -U`) + an ephemeral overlay, started as a hardened systemd unit so the
ADR-0009-class resource caps + sandboxing still apply. This is heavier isolation than the `RootDirectory=` path
(P1-052): nspawn gives the workload its own PID1/namespaces (a fuller container boundary), the natural home for
untrusted/stronger-isolation workloads. (NOT a separate-kernel microVM/firecracker — that needs nested virt + is a
later slice; nspawn is the shared-kernel strong-isolation first step, per ADR-0010.)

Concretely:
- Add `systemd-container` (provides systemd-nspawn) to the image — `os/x86_64/mkosi.conf` Packages. Confirm nspawn is
  present on the booted node.
- `agent/capabilities/capsule/microvm.go` (new): a `packageClass=microvm-service` (or a runtime flag) launch path —
  agentd composes a hardened unit that runs `systemd-nspawn --directory=<rootfs> --private-users=pick -U
  --as-pid2 --ephemeral` (or `machinectl`/a transient `.nspawn`), with no ambient caps, DynamicUser-equivalent (nspawn
  private-users), and the manifest cgroup caps. Re-validate the manifest; compose ONLY from validated fields (no raw
  runtime text). Reuse the baked OCI rootfs assembly.
- Markers: `VITA-CAPSULE-MICROVM: id=<id> isolation=nspawn pid1=own health=OK status=OK`;
  `VITA-CAPSULE-MICROVM-REJECT: reason=<specific> status=OK`; `VITA-CAPSULE-MICROVM-ERROR: status=FAILSAFE`. The baked
  capsule prints a readiness line proving it runs inside its own PID namespace (e.g. it sees itself as PID 1/2). Keep
  all prior markers.

## User value
A stronger-isolation runtime class for untrusted/risky workloads: own PID/mount namespaces + private user mapping +
ephemeral root, so a compromised workload is contained beyond the shared-root `RootDirectory=` model.

## Non-goals
NO separate-kernel microVM (firecracker/qemu) — nspawn shared-kernel only (true microVM is a later slice). NO network
(nspawn `--private-network` / no veth). NO untrusted-image fetch (baked first-party rootfs). Reuse the OCI rootfs
assembly; don't reinvent it.

## REVISION REQUIRED (cross-review verdict: REJECT — 2026-06-23) — two BLOCKING defects
1. **The hardening profile is applied to the nspawn JAILER unit, which will prevent nspawn from EVER starting.** In
   `microvm.go` the systemd-run `--property` values are set on the unit whose ExecStart is `/usr/bin/systemd-nspawn`.
   So `ProtectSystem=strict` (no ReadWritePaths) blocks nspawn writing `/run/systemd/nspawn`, `/run/machines`, and the
   `--ephemeral` scratch/overlay; `PrivateDevices=yes` drops CAP_MKNOD + DevicePolicy so nspawn cannot mknod the
   container `/dev`; `NoNewPrivileges=yes` blocks nspawn's userns uid/gid-map setup. The unit fails to activate →
   `microvm_start_failed`. FIX: express ISOLATION via nspawn's OWN flags (it creates the namespaces) — `--private-users=pick -U`,
   `--drop-capability=all`, `--ephemeral`, no network — and grant the OUTER unit what nspawn NEEDS (drop
   PrivateDevices / ProtectSystem=strict / NoNewPrivileges from the jailer unit; provide writable scratch). Containment
   = nspawn namespaces + private-users (no host-root mapping) + drop-all-caps + the cgroup caps. Re-validate
   RestrictAddressFamilies/RestrictNamespaces against a REAL nspawn run.
2. **The own-PID-namespace proof is FAKED (gamed evidence — CLAUDE.md §5 / spec §24).** `main.ts`
   `formatMicroVMCapsuleMarker` HARDCODES `isolation=nspawn pid1=own` and derives health from `status.health`, which
   `execute.go` sets to "OK" the instant the unit is is-active (= "systemd spawned nspawn", NOT "the workload reached
   PID 1/2"). The top-line `VITA-CAPSULE-MICROVM` marker asserts a property the control plane NEVER measured. FIX:
   DERIVE `pid1=own` + readiness from the WORKLOAD's own `VITA-CAPSULE-MICROVM-WORKLOAD` line (the baked init prints it
   only when `getpid()==1||2`); the top-line marker must reflect MEASURED reality, and the orchestrator host-verify
   PASS gates on the WORKLOAD serial line, never the synthesized marker. NEVER hardcode evidence of an unmeasured property.
3. The nspawn path is unproven (tests mock the launcher; no real exec). After the fixes, it MUST host-verify on a real
   nspawn boot. Verify via go-in-docker (linux). Re-review re-runs the gate.

## REVISION 2 (host-verify: nspawn doesn't reach readiness — 2026-06-23)
The gamed-evidence fix WORKED (it now FAILS HONESTLY): boot showed `VITA-CAPSULE-MICROVM-REJECT: reason=microvm_readiness_failed`
(+ `rootfs_absent` for the forced-invalid). But nspawn never produced the `VITA-CAPSULE-MICROVM-WORKLOAD: … pid1=own`
line within the 10s readiness window, and the SPECIFIC systemd/nspawn reason is journal-only (not on the serial), so
`microvm_readiness_failed` is undebuggable. Extend THIS branch (task/P1-055):
1. **DIAGNOSABILITY FIRST.** On readiness failure, agentd MUST capture + emit the SPECIFIC cause — `systemctl status`
   / the unit's Result+ExecMainStatus, AND whether the `VITA-CAPSULE-MICROVM-WORKLOAD:` line appeared in the unit's
   journal AT ALL. Emit `reason=<specific>` (e.g. `nspawn_absent`, `nspawn_exec_failed`, `workload_line_absent`,
   `workload_pid1_not_own`, `journal_read_failed`) — NOT generic `microvm_readiness_failed`.
2. **Fix the nspawn execution so the workload reaches readiness.** Check, in order: (a) is `systemd-nspawn` actually
   in the booted image + on PATH (the `systemd-container` mkosi add — verify the binary exists at boot)? (b) does the
   minimal baked rootfs satisfy nspawn's container checks — nspawn may reject a rootfs lacking `/etc/os-release` /
   `/etc/machine-id` / a valid `/sbin/init`; with `--as-pid2` the entrypoint binary must exist at the expected path and
   handle being pid2 — verify the static /init runs under nspawn; add the minimal rootfs files nspawn requires. (c)
   does the container's stdout (the init's WORKLOAD print) reach the HOST unit's journal that agentd reads (`journalctl
   -u <unit>`)? nspawn may need `--console=pipe`/its output routed so the host journal captures it. (d) `--ephemeral`
   needs a writable scratch — confirm the outer unit provides it (the REVISION-1 jailer fix).
3. After the fix → host-verify: the WORKLOAD line appears, `pid1=own` is MEASURED, the top-line marker reflects it.
Verify via go-in-docker (linux). Re-review re-runs the gate.
