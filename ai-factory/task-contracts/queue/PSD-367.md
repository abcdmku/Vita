## Objective
Ship **Text-Editor** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), on the app-package SDK foundation
(PSD-361). Three artifacts, mirroring the flagship-package pattern:
1. **App package** under `apps/editor/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` —
   `id: "vita.app.editor"`, `version`, `sdkVersion: SDK_VERSION`, `entry: "index.html"`, MINIMAL `capabilityGrants`
   (`files.read`, `files.write` from the `DesktopCapability` union, `ui-package.ts:25-34` — open + save) and a
   `WebAppDescriptor` (`surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-editor" }`,
   `title:"Text Editor"`, `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/editor/index.html` — a static HTML/CSS editor surface (toolbar + document area +
   status bar), CSS-var tokens, no inline JS (behavior via the view-model / binder convention). Minimal; NOT the
   acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/editor-app.ts` — a PURE document/editing model
   over the injected SDK files port (open/save through the `files.read`/`files.write` ports; **fail-closed if the grant is
   missing/denied**). Injected-port style, frozen `snapshot()`, discriminated-union results. State: open document
   (path/content/language), dirty flag, cursor/selection (line/col), undo/redo stacks. Actions: `open(path)` (reads via
   files port), `edit(replacement)` (mutates buffer + sets dirty + pushes undo), `undo()`/`redo()`, `save()` (writes via
   files port; clears dirty; fail-closed on denied write), `moveCursor(pos)`. Deterministic. NO DOM/CSS/rendering, NO
   platform internals, NO ambient I/O.

## User value
Text-Editor becomes a swappable first-party package the dock/launcher lists + launches into its own WM window (not a shell
built-in), with a real testable open/edit/undo/save model on the SDK files port — proving the app-package pattern for an
editing app with persistence through the capability-gated files port.

## Non-goals
- NO DOM/CSS/rendering/CEF logic in the view-model; NO platform internals; NO new SDK ports (consume PSD-361 + existing).
- Do NOT add capabilities beyond `files.read`/`files.write`. NO syntax-highlighting engine / language servers (deferred).
  OFFLINE only.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at `sdk/typescript/test/ui-kits/editor-app.test.ts`
cover the manifest (`defineAppPackage` accepts it; `hasAppCapabilityGrant` true for `files.read`/`files.write`; descriptor
url === entry) and the view-model state transitions (open reads content via the files port; edit sets dirty + pushes undo;
undo/redo restores buffer; save writes via the files port + clears dirty; missing/denied files grant fails closed on
open AND save; cursor/selection; deterministic snapshot). `npm run typecheck` is clean. Pure, headless. (The exact test
path exists only when the work lands — an empty branch fails.)

## Security/constraints
- MINIMAL capabilityGrants (`files.read`/`files.write` only); injected ports only; capability-mediated + fail-closed
  (open AND save); pure/deterministic. OFFLINE. No remote imports; lockfile; no lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).

## Allowed tools + network
Local filesystem + Node test runner + `npm run typecheck` only. `allowed_network: false`.
