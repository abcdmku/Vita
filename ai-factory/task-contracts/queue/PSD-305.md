## Objective
Add **bounded frame pacing + backpressure** to the compositor command path (`packages/compositor-core/src/main.rs`)
so a fast `OnPaint` producer cannot grow the command buffer without bound. The M4 live-render path
(`osr_host` -> `updateBufferSurface ... present`) closes stdout after a fixed N frames; a *daily* desktop
streams `updateBufferSurface` indefinitely, so the serial `run()` loop must not accumulate work faster
than it presents. Pure protocol/buffer logic; NO GPU/platform changes.
- **Coalesce per-surface:** multiple queued `updateBufferSurface` for the *same* `SurfaceId` collapse to the
  latest payload before the next `present` (an older frame for a surface is never composited once a newer one
  has arrived in the same present interval). Different surfaces are kept independently.
- **Cap in-flight bytes:** track total buffered (pending, not-yet-presented) RGBA bytes; extend the existing
  `MAX_COMMAND_RGBA_BYTES` (`packages/compositor-core/src/main.rs:19`) into an aggregate in-flight cap. When the
  cap would be exceeded, drop the *oldest superseded* pending update (it would be coalesced away anyway) and
  count it; never OOM, never block unbounded. The per-command size guard stays as-is.
- **Steady present cadence:** under a flood of updates between presents, the latest coalesced state per surface
  is presented exactly once per `present`; counters (`coalesced`, `dropped`) are reported.
- Keep the production behavior identical when updates arrive 1:1 with `present` (no coalescing/dropping then).
- Emit a marker line on a self-test/pacing run: `VITA-COMPOSITOR: coalesced=<n> dropped=<m> status=OK`.

## User value
Lets the live CEF desktop stream OnPaint frames forever without the compositor's serial command loop growing
the buffer unbounded — bounded memory + steady cadence is the difference between an M4 demo (N frames) and a
daily-driver desktop.

## Non-goals
- NO GPU/KMS/Ozone/platform changes (`platform/linux.rs`, `lib.rs` compositing core untouched except where the
  pending-update queue must call existing `update_buffer_surface`). NO new wire commands. NO threading/async
  runtime — the loop stays single-threaded and deterministic. Don't change the KMS present path or damage math.

## Acceptance
`acceptance_command` passes: new `cargo test`s (filter `pacing`) prove, headlessly and deterministically:
(1) N queued `updateBufferSurface` for one surface collapse to the last before `present` (only the final
payload composites; `coalesced` counts the rest); (2) total buffered bytes never exceed the aggregate cap
under a flood (excess superseded updates dropped + counted, no OOM); (3) under a flood between two presents,
each surface presents its latest state exactly once (steady cadence); (4) the 1:1 update/present case is
byte-identical to current behavior. Build clean in `rust:1.79` docker (no host Rust on Borg51).

## Security/constraints
- Pure protocol/buffer logic; no I/O beyond the existing stdin/stdout stream; deterministic (same input stream
  -> same coalesced/dropped counts and same composited frames). No network (`allowed_network: false`); no new
  deps; no `unsafe`. Bounded memory is the security property — the cap must hold under adversarial flood input.
