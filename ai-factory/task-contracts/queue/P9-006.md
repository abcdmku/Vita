## Objective
The drift-detecting gate of ADR 0007 (step 4): a SHARED conformance corpus that BOTH the TS validator
(P9-002/003 `compileCapabilityValidator(TIMESYNC_MANIFEST)`) AND the Go validator (P9-005
`capmanifest.Validate` over the same `timesync.json`) run, each asserting its accept/reject decision matches
the corpus's declared expectation — so the two planes provably agree on the shared manifest, and any future
divergence FAILS CI.
- **`schema/capabilities/conformance/timesync.json`**: a list of vectors `{ name, request (a JSON value),
  expect: "accept" | "reject", rejectCode? }` covering the timesync rules end to end — valid enabled+
  hostnames; enabled+empty-servers (reject); disabled+non-empty (reject); disabled+empty (accept); malformed
  hostname (reject); IP literal (reject — out of manifest scope); case-insensitive duplicate (reject); absent
  `enabled` (reject); unknown key (reject); duplicate JSON key (reject — the request is given as a raw string
  for that case); inline secret (reject). ≥ 15 vectors.
- **`sdk/typescript/test/timesync-conformance.test.ts`**: load the corpus (fs in test), run each vector
  through the TS validator, assert the outcome matches `expect` (and `rejectCode` when given).
- **`agent/internal/capmanifest/conformance_test.go`**: load the SAME corpus + `timesync.json` (fixture/
  embed), run each vector through the Go validator, assert the outcome matches `expect`.
Both tests reference the SAME corpus file, so passing both proves TS-validator ≡ Go-validator ≡ corpus.

## User value
The mechanism (ADR 0007) that keeps the two planes honest: one shared corpus, both validators must agree
with it, drift breaks CI. This is what makes "preview == apply" trustworthy on the shared schema and is the
template every migrated capability will follow.

## Non-goals
- No new validation logic (reuse P9-002/003 TS + P9-005 Go), no agent/cap migration yet, no IP-literal
  support. Just the corpus + the two conformance tests. Do NOT modify the validators.

## Dependencies
P9-003 (TS validator + `timesync.json`), P9-005 (Go `capmanifest.Validate`). Both merged.

## Acceptance tests
`acceptance_command` runs the TS conformance test (must pass: TS validator matches every corpus vector). The
ORCHESTRATOR additionally runs the Go conformance test in the container
(`node tools/build/go-in-docker.mjs --dir agent test ./internal/capmanifest/...`) and confirms it passes —
i.e. BOTH planes agree with the corpus. A deliberately wrong `expect` in a scratch vector must make BOTH
tests fail (sanity: the corpus actually drives the assertions). Orchestrator runs `npm run typecheck`.

## Performance & security constraints
Deterministic; corpus read via fs/embed in TESTS only. The corpus is the shared contract — any validator
that disagrees fails. Strict TS / clean `go vet`. R2 → reviewer-gated.
