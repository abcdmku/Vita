## Objective
Implement the user-facing authoring API from spec §8.3 on top of the plan model (P0-001):
- `defineSystem(fn)` where `fn` receives an **immutable typed snapshot** `{ device, data }` and
  returns a `DesiredState`. The function must be evaluated deterministically (no I/O) and its result
  fed through `normalize` from P0-001.
- `app(id, opts)` and `backup.usb(opts)` helper builders that produce typed fragments of the
  desired state, matching the shapes used in the spec §8.3 example.
- An example at `sdk/examples/system.ts` that reproduces the spec §8.3 example faithfully.

## User value
This is the TypeScript surface users actually write (spec §3.1). It must be ergonomic and type-safe.

## Non-goals
- No accelerator selection logic here (that's P0-003); accept a placeholder/typed value.
- No host mutation, no Go agent, no signing.

## Dependencies
P0-001 (uses `DesiredState`, `normalize`, `planHash`).

## Acceptance tests
`acceptance_command` above. `sdk/typescript/test/define-system.test.ts` must prove:
1. Evaluating `defineSystem(...)` with a fixed `device`/`data` snapshot returns a `DesiredState`
   that normalizes successfully.
2. The same fixed snapshot yields a byte-identical normalized plan across two evaluations
   (determinism, spec §8.4).
3. The §8.3-style example produces a plan containing the declared apps and backup.

## Performance & security constraints
Deterministic, no I/O (spec §8.2). The snapshot passed to the user function must be deeply readonly
(no mutation of discovered capabilities).

## Hardware profiles
n/a (architecture-neutral TS).
