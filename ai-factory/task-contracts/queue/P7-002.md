## Objective
A transactional capability `agent/capabilities/timesync/` that stores the node's **NTP time-sync
configuration** (distinct from the `time` capability which SETS the clock — this configures the time
SOURCE) to a FIXED agent state path, applied atomically with rollback — the proven nodeconfig (P1-007)
pattern. A typed `Config` = enabled (bool) + servers (list of NTP server hostnames/IPs, 1-8 when enabled).
`Handle` reads current; `Apply` validates a desired config and writes via a single atomic commit point
(temp + rename — nothing fallible after the rename), returning a restoring `Undo`; commit + rollback
proven. Implements `Validate()` (with duplicate-JSON-key rejection + canonical persisted bytes, per
AGENTS.md). Injected FS facade.
- **Validate fail-closed**: each server is a valid hostname (RFC-1123) or IP literal — reject URLs/
  schemes/inline content; when `enabled` is true, require 1-8 servers (reject 0); when disabled, servers
  must be empty. Reject duplicate servers. `enabled` uses an explicit presence model (absent ⇒ reject).
  No `os/exec`, no real NTP/chrony.

## User value
The on-host time-source config (NTP) the controller manages — distinct from setting the clock; the node's
time integrity depends on a trusted, validated NTP source set. Real chrony/timesyncd apply is a later contract.

## Non-goals
- No real NTP daemon/chrony/timesyncd, no network. Store + validate the config only. No `os/exec`. No
  `cmd/agentd/main.go` edits (wiring is a follow-up).

## Dependencies
P1-006 (engine), P1-007 (atomic-file pattern). Both merged. Follow the AGENTS.md dup-key + canonical-bytes + absent≠zero rules.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Cover: Handle reads (canonical
bytes); Apply writes + restoring Undo; transaction commit; rollback (later op fails ⇒ prior restored);
malformed server (URL/scheme/bad host) rejected; enabled-with-zero-servers rejected; disabled-with-servers
rejected; duplicate servers rejected; absent `enabled` rejected (typed + JSON path); duplicate JSON keys
rejected; atomic-write-failure leaves the live file unchanged (single commit point). Injected FS.
