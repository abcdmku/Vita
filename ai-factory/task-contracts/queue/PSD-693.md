## Objective
Scaffold a new **`controller-ui` rendered-shell package** at `controller/shell-ui/` — the shell that
composes the EXISTING headless controller modules (`controller/overview`, `controller/dashboard`,
`controller/state`, `controller/audit`, `controller/node-config`, and the `*-preview` modules) into the
operator console enumerated by spec §17.2. SCAFFOLD ONLY — no live agentd calls, deterministic, offline,
strict TS.
- A typed `AppShell` contract enumerating the spec §17.2 views with EXACTLY these view ids:
  `dashboard`, `node`, `storage`, `identity`, `app`, `backup`, `ai`.
- A pure router / view-registry: each view id resolves to a pure view-model **factory** (no I/O at
  resolution time); an unknown view id **fails closed** (throws/returns a typed error — never a default view).
- A single **read-only data port** that wraps `controller/agent-client` (`Pick<AgentClient, "getHealth" |
  "getOperations" | "getState">` shape, as `controller/shell/src/controller-shell.ts` already does) — the
  port is injected, NOT constructed here, and the scaffold makes NO network/agentd call.
- Put sources under `controller/shell-ui/src/app-shell.ts` and the test under
  `controller/shell-ui/test/app-shell.test.ts`.

NOTE: `controller/shell/` already exists and is the headless REQUEST HANDLER
(`handleControllerShellRequest`). Do NOT modify or collide with it — this is the new rendered-shell
composition layer at `controller/shell-ui/`, consuming the headless modules + SDK ports only.

## User value
Gives the flagship desktop a single typed entry point that wires the already-built headless controller
views (§17.2) into one navigable shell — the seam the CEF-rendered console hydrates against — without
pulling any live transport into the offline test surface.

## Non-goals
- NO live agentd / `node:net` / fetch / DOM / CSS / CEF / rendering. NO new headless module logic
  (consume the existing modules — do not re-implement overview/dashboard/state/etc). NO transport
  construction in the shell sources.

## Acceptance
`acceptance_command` passes. `controller/shell-ui/test/app-shell.test.ts` asserts, deterministically and
offline: (1) the view registry exposes EXACTLY the §17.2 view ids `{dashboard, node, storage, identity,
app, backup, ai}` — no more, no fewer; (2) the router resolves each id to a pure view-model factory;
(3) an unknown view id fails closed; (4) typecheck clean under strict `tsc` (TS 7); (5) the shell sources
import neither `node:net` nor any remote module.

## Security/constraints
- Injected read-only port only (no ambient I/O); fail-closed routing; pure/deterministic; offline. No
  remote imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons.

## Hardware profiles

## Allowed tools / network
