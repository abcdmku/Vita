## Objective
Headless, deterministic **view-model** for the flagship desktop's `Tiling` screen (`ui_kits/desktop/Tiling.html` / index.html),
built ONLY on `@vita/desktop-sdk` public ports (the WM intents + layouts/workspaces ports (PSD-004/014)) — injected ports, NO platform internals, NO DOM/rendering (the view-model
is the pure interaction logic the rendered design binds to later).
- State: panes (editor/explorer/system) as tiled windows, active workspace, status-bar fields. Actions: focusPane(id), cycleLayout(), moveWindow(intent), splitFocus(dir) — emitted as SDK WM intents; the resulting layout is read back from the WM port. Deterministic tiling math; fail-closed on invalid intents.
- Put the code under `ui_kits/desktop/viewmodels/Tiling.ts` and tests under `sdk/typescript/test/ui-kits/Tiling.test.ts`.
- Import the SDK exactly as `ui_kits/desktop/package.ts` does; use ONLY public exports.

## User value
Turns the static `Tiling` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design (the HTML is the design of record). Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the state transitions + fail-closed paths described above against fake SDK ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/Tiling.ts` + `sdk/typescript/test/ui-kits/Tiling.test.ts`, deterministic, typecheck clean. R1.
