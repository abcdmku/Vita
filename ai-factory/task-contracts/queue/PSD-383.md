## Objective
Bind the flagship lock screen's static DOM (`ui_kits/desktop/Lock.html`) to the existing lock view-model
(`ui_kits/desktop/viewmodels/Lock.ts`) **through the screen manifest + hydrate runtime**, and make that
binding **fail-closed inert** when the host bridge exposes no auth port — proving the full DOM hydration path
end-to-end, not just the view-model in isolation.
- `ui_kits/desktop/screens/lock.ts` already declares the manifest (`actions` lock.submit/lock.cancel/lock.tick,
  `binds` lock.time/date/user/initials/error/remainingAttempts/state, `selectPorts` reading `lockAuth`/`auth`
  + `lockUser` via `optionalHostPort`). `Lock.html` already carries `data-vita-screen="desktop/lock"`,
  `data-vita-action="lock.submit"`, `data-vita-credential`, and the `data-vita-bind-text` anchors. The GAP is
  that (a) there is no hydrate-level test exercising this through `hydrateScreen` against a DOM stub, and
  (b) `createSurfaceHost` (`ui_kits/desktop/runtime/host-bridge.ts`) never surfaces a `lockAuth`/`auth` port,
  so on the real host the lock view-model's auth path is unreachable and the inert/static fallback is unverified.
- Wire `createSurfaceHost` to expose an optional `lockAuth` port that forwards `authenticate` over the transport
  (a `authenticateOwner`-style bridge method), present ONLY when the transport advertises it; keep the existing
  `optionalHostPort(host, "lockAuth"|"auth")` lookup in `screens/lock.ts` as the single source of truth — do NOT
  change the protected view-model error taxonomy.
- Confirm/normalize `Lock.html` `data-vita-*` anchors so the rendered design hydrates: the passkey/submit button
  (`lock.submit` + `data-vita-credential`), the clock (`lock.date`/`lock.time`), the attempt/error sink
  (`lock.error`, `lock.remainingAttempts`), and the unlocked/authenticating class binds — add only missing
  anchors, never new visual design.
- Add `sdk/typescript/test/ui-kits/screen-lock.test.ts` modeled on
  `sdk/typescript/test/ui-kits/screen-settings.test.ts` (reuse its `StubElement`/`createSurfaceHost` fixture style):
  build the Lock DOM stub, `hydrateScreen(root, lockScreen, host)`, and assert the hydrate path.

## User value
Turns the static `Lock.html` mockup into a live, testable sign-in surface that hydrates against the SDK host bridge
when an auth port is present and **safely shows the static lock screen (inert, never throws) when it is absent** —
the behavior the CEF-rendered HTML depends on at boot.

## Non-goals
- NO new visual design (the HTML is the design of record) — add only missing `data-vita-*` anchors.
- NO change to the lock view-model's frozen error taxonomy / behavior (PSD-046 view-model is the source of record;
  don't re-implement or weaken it). NO platform internals, NO ambient I/O, NO credential echo.
- Do NOT broaden the host bridge beyond an optional, transport-advertised `lockAuth` forward.

## Acceptance
`acceptance_command` passes. The new `screen-lock.test.ts` deterministically covers, via `hydrateScreen` against a
DOM stub + `createSurfaceHost` transport:
1. **Hydrates active when an auth port is present** — typing a credential then dispatching the `lock.submit` action
   forwards through the bridged auth port (request carries the credential + attempt number) and, on `ok`, the
   snapshot transitions to `unlocked` (and the manifest's unlocked class bind reflects it).
2. **Failed auth writes the error sink** — a rejecting auth port leaves the screen locked, increments
   `remainingAttempts`, surfaces the message on the `lock.error` anchor, and the raw credential is NEVER echoed
   into the DOM or any snapshot (`JSON.stringify` excludes it).
3. **Inert without a bridge** — `hydrateScreen` against a `createSurfaceHost` with NO auth port still returns a
   screen whose root renders the static lock content (clock/user binds resolve from defaults) and a `lock.submit`
   click never throws (fails closed via the view-model `AUTH_PORT_UNAVAILABLE` path).
Typecheck clean. Pure/headless (no real network, no real DOM).

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; credentials never logged/echoed/serialized.
- Inert-on-missing-bridge must never throw out of hydration (matches `hydrateScreen`/inert-screen contract).
- No remote imports; lockfile mandatory; no package lifecycle scripts; deterministic (fixed injected clock/user).
