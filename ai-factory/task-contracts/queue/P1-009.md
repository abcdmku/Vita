## Objective
Second transactional capability (after nodeconfig, P1-007), exercising the engine end-to-end:
`agent/capabilities/time/`. A `TxCapability` named `time.set`: `Handle` reads the current node time;
`Apply(ctx, req)` validates a desired absolute time and sets it via a NARROW injected `Clock` facade,
returning an `Undo` that restores the prior time; rollback proven through `transaction.Apply`.
- The Linux impl (`set_linux.go`, `//go:build linux`) sets the clock via the `clock_settime` syscall
  (golang.org/x/sys/unix) — **no `os/exec`, no shelling to timedatectl**. A `set_stub.go`
  (`//go:build !linux`) returns an unsupported error. Tests inject an in-memory `Clock` (no real time
  change), like nodeconfig's in-memory FS.
- **Constrain the request**: reject a desired time more than ±7200s from the current reading (prevent
  wild skew); reject zero/garbage. Request data never becomes a path or command.

## User value
Unblocks time-dependent features (backup schedules, cert validity, NTP). Proves the transactional
pattern generalizes past nodeconfig.

## Non-goals
- Do NOT modify `agent/cmd/agentd/main.go` — P1-008 owns it concurrently; capability **registration**
  is a separate follow-up after P1-008 merges. Deliver the package + a `NewCapability()` constructor only.
- No NTP daemon management; no timezone DB changes (just the absolute clock).

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + the orchestrator runs `go vet`. Cover: Handle reads
time; Apply sets + returns a working Undo (mock clock observes set→restore); transaction commit;
transaction rollback (a later op fails ⇒ time restored); ±7200s bound rejects out-of-range; stub path
returns unsupported. No real clock mutation in tests.

(with a restoring Undo) or returns an error having changed nothing — no error path after the set point.
`go vet` clean. R3 → reviewer-gated.
