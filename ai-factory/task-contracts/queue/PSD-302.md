## Objective
Add the **reverse input-event channel** the CEF host process is missing. Today the command stream is one-directional:
CEF (or a producer) writes `registerSurface`/`updatePlacement`/`present` lines on the compositor's **stdin** (the
`CommandDrivenSession` in `packages/compositor-core/src/main.rs:283`), but the compositor has NO way to push routed
input back to the client. The only input path (`stream_input_events` / `poll-input`, main.rs:511, main.rs:263) is bound
to the `--serve` mode and writes to **stdout**, which `--commands` already uses for marker lines — so a CEF host running
`--commands` cannot receive routed input without corrupting the marker channel.
- Extend `--commands` mode with a **separate, line-oriented output sink** for routed input, selected by a new flag
  `--input-out=<path>` (a writable FIFO/file/unix-socket path the host opens). When absent, behave exactly as today (no
  reverse channel; zero behavioral change to the existing present path).
- On each `present` (or an explicit `routeInput` tick), drain `compositor.poll_input_events()` and emit **one plain-text
  line per routed event** to the `--input-out` sink, reusing the EXACT field grammar already defined by
  `format_input_event` (main.rs:813) prefixed with a stable record tag, e.g.
  `inputEvent surface=<id|none> kind=key key-code=<n> pressed=<bool>` /
  `inputEvent surface=<id|none> kind=pointer-button button=<n> state=<pressed|released>` /
  `inputEvent surface=<id|none> kind=pointer-motion dx-micropixels=<n> dy-micropixels=<n>`.
  `surface=` carries the focused/hit-tested surface id (or `none`).
- **Bounded + fail-closed + non-blocking:** the reverse channel must NEVER block compositing. Use a bounded queue; on a
  full queue or a closed/broken sink (EPIPE), **drop** events and keep presenting (mirror the `emit_marker_best_effort`
  hot-path discipline at main.rs:158). Track `routed`/`dropped` counters.
- Emit a one-line summary marker to **stdout** (the existing marker channel) at end-of-stream:
  `VITA-INPUT: routed=<n> dropped=<m> status=OK` (or `status=FAILSAFE reason=...` on a real error).
- Put the integration test at `packages/compositor-core/tests/reverse_input_channel.rs` (a `--test` target so it builds
  in linux rust-in-docker AND fails closed on an empty branch).

## User value
Closes the last missing seam between the compositor and the CEF host: the desktop shell can finally RECEIVE keyboard/
pointer input routed by the compositor (text, debuggable, bounded) without polluting the marker stream — the prerequisite
for any interactive CEF-rendered desktop (clicks/keys reaching the live shell) rather than a static live-rendered image.

## Non-goals
- NO change to the existing CEF-stdout→compositor-stdin command grammar or the present/no-repaint invariant (the forward
  path is untouched; `--input-out` absent ⇒ byte-identical behavior). NO binary/RPC framing — plain text line protocol
  only. NO new input *sources* (consume `poll_input_events`; do not add evdev/libinput here). NO CEF code, NO TS/DOM, NO
  hit-testing policy beyond reporting the already-known focused surface. Keep the production KMS path untouched.

## Acceptance
`acceptance_command` passes: `npm run typecheck` clean; `cargo test --test reverse_input_channel -- --exact` passes
deterministic integration tests that (1) drive synthetic `InputEvent`s through a `RecordingBackend` whose
`poll_input_events` returns scripted events, run a `--commands` session with `--input-out` pointed at an in-memory/temp
sink, and assert the EXACT `inputEvent ...` lines appear **in order**, one per event, with the right `surface=` and field
grammar; (2) the **backpressure/closed-sink** path drops events (asserts `dropped>0`) and STILL presents successfully
(final `VITA-INPUT: ... status=OK` + the present succeeds); (3) `--input-out` absent ⇒ no reverse output and unchanged
present behavior. INDEPENDENT (orchestrator): compositor builds for linux via `rust-in-docker`; `cargo build --release
--locked` + `cargo test` clean in the pinned container. State honestly whether the linux build/test passed.

## Security/constraints
- Reverse channel is **fail-closed and non-blocking**: bounded queue, drop-on-backpressure, drop-on-EPIPE, never block
  or panic the compositing loop; a broken `--input-out` sink must NOT tear down the live desktop. No ambient I/O beyond
  the explicitly-passed `--input-out` path. Plain bounded text (cap line length / per-tick event count). No remote
  imports; `--locked` crates; lockfile; no package lifecycle scripts; no FFI/native addons beyond the crate's existing
  deps. Keep the compositor crate SELF-CONSISTENT (every called fn must exist/compile in linux rust-in-docker — the
  Windows-host `npm run typecheck` does NOT catch Rust errors; the rust-in-docker floor is authoritative).

The reverse-input sink write is SYNCHRONOUS on the compositor thread (drain_best_effort -> writer.write), and O_NONBLOCK does NOT make regular-file writes nonblocking; unix stream-socket short writes also corrupt the line protocol.
