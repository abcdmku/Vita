## Objective
A transactional capability `agent/capabilities/services/` that stores the node's **enabled system-services
configuration** (the declared desired set of services to enable/disable — e.g. systemd unit names) to a
FIXED agent state path, applied atomically with rollback — the proven nodeconfig (P1-007) pattern. A typed
`Config` = a list of `ServiceEntry { name: string; enabled: bool }`. `Handle` reads current; `Apply`
validates a desired config and writes via a SINGLE atomic commit point (the proven `os.CreateTemp`+O_EXCL →
write → Sync → Close → Rename pattern from `agent/capabilities/nodeconfig/apply_linux.go` — NOT a predictable
temp name), returning a restoring `Undo`; commit + rollback proven. Implements `Validate()` with
duplicate-JSON-key rejection + canonical persisted bytes (AGENTS.md).
- **Validate fail-closed**: each `name` is a valid systemd unit name (RFC-ish: non-empty, bounded length,
  charset `[A-Za-z0-9:._@-]`, must NOT contain path separators / `..` / whitespace / inline content — reject
  unit names that look like inline material §13.1); the `enabled` field uses EXPLICIT presence (pointer
  `*bool` — absent ⇒ reject, per the absent≠zero rule); reject duplicate service names; reject an empty
  desired set ONLY if you choose to require ≥1 (document the choice; an explicit empty list = "disable all
  managed services" is acceptable IF distinguishable from absent — use a pointer slice `*[]ServiceEntry`).
- No `os/exec`, no real `systemctl` — this stores the DESIRED config; the real enable/disable apply is a
  later host contract.

## User value
The declared service-management state the controller manages (FR-007) — which services the node should run
— stored transactionally + validated, so a malformed/ambiguous request is rejected. Real systemctl apply
is a later contract.

## Non-goals
- No real `systemctl`/systemd/`os/exec`, no network. Store + validate the desired config only. No
  `cmd/agentd/main.go` wiring (a follow-up).

## Dependencies

+ canonical-bytes + absent≠zero rules.

## Acceptance tests

Apply writes + restoring Undo; transaction commit; rollback (later op fails ⇒ prior restored); malformed
unit name (path sep / `..` / whitespace / bad charset / inline content) rejected; absent `enabled` (typed +
JSON) rejected; absent vs explicit-empty service list distinguished (pointer slice); duplicate service name
rejected; duplicate JSON keys rejected; atomic-write-failure (and a pre-existing temp/symlink) leaves the
live file UNCHANGED (exclusive temp). Injected FS.
