## Objective
Evolve the on-device TypeScript runtime (P1-030 — today `main.ts` prints a `VITA-TS` hello marker) to run the
**real config→plan evaluator** (P9-001, `runtime/evaluator/src/evaluate.ts`) ON-DEVICE under the pinned Deno. At
boot, `main.ts` evaluates a representative node config against the default capability-manifest registry, producing a
**deterministic** `TransactionPlan`, and prints grep-able proof markers to the serial:
- valid config →  `VITA-EVAL: caps=<N> ops=<M> planHash=<hex> status=OK`
- invalid config → `VITA-EVAL-REJECT: code=<rejectionCode> status=OK` (the evaluator correctly fails closed)

This makes the device run the ACTUAL control-plane brain (the §8.2 deterministic evaluator), not a stub.

Concretely:
- **Vendor the evaluator + its pure deps** into `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/`, Deno-compatible
  (loads under `deno run --no-remote --cached-only`, relative imports only, NO npm, NO Node builtins). The modules
  (ALL pure/deterministic — no I/O, spec §8.2):
  - `runtime/evaluator/src/evaluate.ts`  (`evaluateNodeConfig`)
  - `sdk/typescript/src/capability-manifest.ts` (`compileCapabilityValidator`) + the generated registry
    `sdk/typescript/src/generated/capability-manifests.generated.ts` (`DEFAULT_CAPABILITY_MANIFESTS`)
  - `sdk/typescript/src/safe-normalize.ts` — the ONLY non-trivial Deno gap: it `import`s `node:util` `types` for an
    `isTypedArray` check. **Replace that with an INLINE, dependency-free check** (e.g. `ArrayBuffer.isView(x) &&
    !(x instanceof DataView)`) so the file needs no `node:` import and runs identically under BOTH Deno and
    `node --experimental-strip-types`. This swap MUST be proven byte-equivalent (see acceptance).
- **VENDOR THE EXACT SOURCE — do NOT fork or rewrite the logic.** Copy the upstream files; the ONLY permitted change
  is the `node:util`→inline-check swap in safe-normalize. Keep a short header comment in each vendored file pointing
  at its upstream path so drift is auditable. (If you must adjust import paths for the vendored layout, that's fine;
  logic stays identical.)
- **`main.ts`**: import the vendored evaluator; evaluate a representative VALID config (e.g. a `node.config` /
  `hostname.set` / `time.sync` request) against `DEFAULT_CAPABILITY_MANIFESTS` → deterministic plan → print the
  `VITA-EVAL` marker (operation count + a stable hash over the canonical plan JSON). Then evaluate an INVALID config
  → print `VITA-EVAL-REJECT` with the rejection code. Keep the existing `VITA-TS` hello line too (proof the runtime
  itself still runs). PURE: no FS, no network — the evaluator needs none.

## User value
The device now runs the REAL deterministic config→plan control-plane logic locally — the foundation for on-device
reconfiguration without a cloud roundtrip, and concrete proof that "Vita is a TypeScript OS" beyond a hello-world.

## Acceptance tests
`acceptance_command` — `eval.test.ts` (runnable by the worker under `node --experimental-strip-types --test`, no Deno
needed) MUST assert:
1. **Determinism** — the vendored evaluator returns a byte-identical plan for the same input across repeated calls.
2. **Upstream parity (no drift)** — for a corpus of configs (valid + invalid), the vendored evaluator's output
   EQUALS the upstream `runtime/evaluator/src/evaluate.ts` output (import BOTH and deep-compare). This proves
   vendoring + the safe-normalize swap introduced zero behavioral change.
3. **Fail-closed** — invalid/unknown-capability configs are rejected with the same rejection codes as upstream.
Orchestrator host-verifies on Borg51: build smoke (the ts-overlay ships via `--extra-tree`), boot, and confirm
`VITA-EVAL: ... status=OK` AND `VITA-EVAL-REJECT: ...` on the serial; also `deno check` of the vendored tree passes.

## Performance & security constraints
Pure/deterministic (§8.2): same inputs → identical plan + hash. The runtime is UNPRIVILEGED (no caps; the evaluator
needs no FS/network/privilege). No keys/secrets. R1 (non-privileged TS module on-device; evaluator is frozen/pure).
