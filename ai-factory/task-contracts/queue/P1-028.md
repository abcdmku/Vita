## Objective
Step 2 of trusted boot: make the smoke root **dm-verity-protected** so the kernel verifies every root-fs block
against a signed/known hash tree at boot and refuses a tampered root. `--verity` alone is a NO-OP (proven in
STATE) — mkosi needs explicit partition defs: add `os/x86_64/repart-verity/` (esp + root `Verity=data` +
root-verity `Verity=hash`, matched `VerityMatchKey=root`) and pass it via `--repart-directory` **only when
`VITA_VERITY=1`** (the default smoke/SB layout is untouched). mkosi builds the hash tree and bakes `roothash=`
onto the UKI cmdline; the root is read-only so `systemd.volatile=overlay` gives a writable `/`.

## User value
The root filesystem is now tamper-evident + tamper-resistant: a single flipped byte is detected by dm-verity and
the root is refused. Combined with Secure Boot (P1-027), the boot chain is firmware→signed-UKI→verified-root.

## Non-goals
- Smoke single-root verity (mkosi-native). The full-mode A/B per-slot verity (planVerity, `verity.conf`) is the
  separate deterministic spec; not executed here. No signed verity (`--verity-key`) yet — hash-only (unsigned),
  which is sufficient because the roothash rides inside the (Secure-Boot-signed at 4b) UKI. No RAUC (step 3).

## Dependencies
P1-026 (agentd smoke base) merged. Host (Borg51 WSL): mkosi 26 with `--repart-directory` + `--verity`, qemu, KVM,
OVMF `_4M`. The smoke image already boots to multi-user with the agent.

## Acceptance tests
`acceptance_command` (`node --check`) is the Windows-runnable syntax gate; the **real** acceptance is the host
verity matrix `bash tools/wsl-verify.sh verity` on Borg51 (orchestrator-run, independent verification). VERIFIED
GREEN:
```
static gate: root-verity partition present (type 2C7357ED…2BF5); roothash= on the UKI cmdline.
POS   PASS   VITA_VERITY=1 image boots; root on /dev/mapper/root; "device-mapper: verity" active; multi-user.
VNEG  PASS   one byte flipped in the root DATA partition -> "device-mapper: verity: 253:2: data block 0 is
             corrupted" -> root does NOT reach userspace.
RESULT: PASS (verity root boots verified; tampered root rejected by dm-verity)
```
Enforcement is proven by the POS-boots-verified / VNEG-rejected contrast; a static gate first asserts the verity
partition exists (else `--verity` was a no-op).

## Performance & security constraints

verification + reviewer-gated. No production keys (hash-only verity; signing is a later hardening).
