## Objective
Remove the **baked-HTML placeholder** behavior of first-party app launch and replace it with REAL,
port-backed hydration. Today the app viewmodels under `ui_kits/desktop/viewmodels/apps/` (created by
`createTerminalAppViewModel`/`createMailAppViewModel`/`createBrowserAppViewModel`/`createEditorAppViewModel`/
`createFilesAppViewModel`/`createActivityMonitorAppViewModel`/`createSettingsAppViewModel`) are **orphaned**:
a grep for those factories outside `viewmodels/apps` and `sdk/typescript/test/ui-kits` returns nothing.
`createAppRegistryViewModel` (`ui_kits/desktop/viewmodels/app-registry.ts:55`) calls
`host.launchApp(app.descriptor)` (line 112) which mounts the static `index.html` and **never instantiates a
viewmodel or runs the binder** â€” so every first-party app renders its baked sample HTML and the port-backed
viewmodel layer is dead in the running OS. `bootstrap.ts` `DEFAULT_SCREEN_MODULES` (`ui_kits/desktop/runtime/bootstrap.ts:57-66`)
mounts none of the app viewmodels.

Add a **per-app hydration step** at launch:
- After `host.launchApp(...)` returns a launch (with its web/tsx surface), the registry (or a new
  `ui_kits/desktop/runtime/app-hydrate.ts` it delegates to) must, for each first-party app id, instantiate
  the app's viewmodel with its **injected host-bridge ports** and run the existing binder
  (`createBinder` in `ui_kits/desktop/runtime/binder.ts`, which already supports
  `data-vita-bind-text`/`data-vita-bind-list`/`data-vita-action`) over the launched surface's DOM.
- Wire a first-party `AppPackage` registry whose entries carry: the launchable descriptor, the viewmodel
  factory, and the host-bridge ports each viewmodel needs (injected â€” NO ambient I/O, NO platform internals).
- The hydrated state MUST come from the **injected real ports**, not from any hardcoded sample/baked literal.
  Removing the placeholder means: the bound text/list nodes reflect values pulled through the port, and when
  a port is absent the viewmodel/hydration **fails closed honestly** (returns an error result / leaves the
  surface unhydrated with a signal) rather than silently showing baked content.
- Import the SDK exactly as the existing `viewmodels/apps/*.ts` files do; use ONLY public `@vita/desktop-sdk`
  exports.

## User value
First-party apps (terminal/mail/browser/editor/files/activity-monitor/settings) become **live** in the running
desktop OS: launching one shows real, port-driven content instead of a frozen mockup. Closes the dead-layer gap
where built viewmodels were never instantiated or rendered.

## Non-goals
- NO new visual design / CSS â€” the app `index.html` files remain the design of record; this wires logic to them.
- NO new SDK ports and NO re-implementation of existing viewmodels â€” consume them.
- NO CEF/compositor changes; NO platform internals; NO DOM engine â€” bind against the existing
  `VitaElement`/binder abstraction used by the headless tests.
