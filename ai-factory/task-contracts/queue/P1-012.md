## Objective
Build the **Unified Kernel Image (UKI) + Secure Boot signing PLAN** on top of the merged root-image
scaffold (P1-011): a deterministic `planUKI()` that assembles the UKI inputs (kernel image ref + `cmdline`
+ initrd + `os-release` + the systemd `ukify`/stub, all pinned) and the sign step. As with P1-011, this
is a pure, offline PLAN + determinism harness — NOT a real kernel build/sign.
- `os/x86_64/uki.conf`: pinned UKI inputs (kernel/initrd refs by digest, fixed cmdline, os-release).
- `os/x86_64/uki.mjs`: `planUKI()` (pure) returning the normalized, byte-deterministic UKI+sign plan;
  the `ukify`/sign tool container is **digest-pinned**; SOURCE_DATE_EPOCH set; no eval-time network.
- **Signing uses a DEV/TEST key reference only.** Real Secure Boot keys are R4 / owner-only and MUST
  NOT appear in the repo or plan — reference a clearly-labelled `test` key id; the plan records that
  production signing is a separate owner-only step (spec §16, §11). NEVER embed key material (§13.1).
- `os/x86_64/test/uki-determinism.test.ts`: asserts `planUKI()` is byte-identical across runs, pins the
  kernel/initrd/tool by digest, sets SOURCE_DATE_EPOCH, references only the TEST key, declares no network.

## User value
Next step toward a bootable signed image (FR-001 QEMU boot): the UKI is what UEFI verifies + boots.
Establishes the signing contract with the production keys held back (owner-only).

## Non-goals
- No real kernel/initrd build, no real `ukify` run, no real signing. No production keys. No RAUC/
  dm-verity yet (later). Do not modify P1-011's root-image files beyond referencing their outputs.

## Reviewer revision (round 2 — BLOCKING, from P1-012.review.md)
1) **Inputs the plan references must actually exist for the build to consume** (same class as P1-011 r1).
   Round 1 recorded `inputs.osRelease.text` but the command passed `--os-release /work/os/x86_64/
   uki.os-release` to a read-only `/work` with no such file ever produced/mounted. Fix: either commit a
   real `os/x86_64/uki.os-release` artifact and reference THAT path, or have the plan emit it
   deterministically as a declared produced-input the run mounts. The test must assert every path the
   command references corresponds to a real committed/produced artifact (no dangling input paths).
2) **Model TEST signing coherently — do not fake it.** Round 1 modeled an inline `docker ukify sign`
   passing abstract `test:` refs as key/cert args with no way to resolve them. Replace with EITHER:
   (a) a separate, explicitly non-executable "sign" step the plan DECLARES (key/cert resolved by a
   dev/owner-provided TEST-key PATH given at run time, clearly labelled non-production, material NEVER
   in the repo), OR (b) a deterministic TEST-artifact path flow. The plan must never pretend to execute
   signing with non-resolvable refs. Keep the digest pins / SOURCE_DATE_EPOCH / no-network / production-
   keys-absent guarantees (reviewer approved those). Assert the signing model in the test.

## Reviewer revision (round 3 — BLOCKING, from P1-012.review.md round 2)
1) **Be honest about external inputs.** `vmlinuz`/`initrd.img`/`linuxx64.efi.stub` come from the upstream
   kernel/image build — they are NOT produced by this contract. Stop modeling them as self-declared
   `producedInputs` (the test currently treats self-declaration as proof). Model them as **external,
   digest-pinned PRECONDITIONS**: the plan declares each as a required external input with a digest, and
   an explicit precondition step that must VERIFY each input (by digest) before the assembly step may
   run. The test must assert: (a) each kernel input is declared external-with-digest (not "produced"),
   and (b) assembly is gated on the precondition — a missing/unverified input blocks assembly. Do not
   claim to produce what an upstream step provides.
2) **Lock the TEST signing env names.** Round 2 validated the `test:` key/cert IDs but not
   `TestKeyPathEnv`/`TestCertPathEnv`, then emitted those env names as runtime key/cert refs — a config
   could keep the `test:` IDs but point the path env at a production signing variable. Enforce a strict
   TEST-only allowlist for the key/cert path env NAMES (only the committed `VITA_TEST_*` names accepted);
   reject any non-TEST env name. Add rejection tests for a production-looking env name.

## Reviewer revision (round 4 — BLOCKING, from P1-012.review.md round 3)
The kernel/initrd/stub digests in `uki.conf` are placeholders (`sha256:111…`, `222…`, `333…`) that only
satisfy the test regex — not real pins. Fix honestly:
- The pin validator must enforce a REAL `sha256:` value (exactly 64 lowercase hex) AND **reject
  sentinel/placeholder digests** (all-same-char, short repeated patterns, obvious fakes). A fake pin must
  fail validation, not pass.
- Do NOT ship fake pins. Either (a) the committed config references REAL sha256 digests of small
  committed fixture artifacts, and the test computes those real digests and asserts the plan pins exactly
  them; or (b) model the kernel inputs as **unresolved** (`resolved: false`) when no real digest is
  supplied — a valid first-class state meaning "the upstream image build must supply real digests before
  this plan can run" — and the assembly precondition blocks on unresolved.
- Add regressions: a sentinel/placeholder digest ⇒ rejected (or unresolved, never "pinned"); a real
  fixture digest ⇒ resolved/pinned. (Round-3 signing-env + os-release fixes are approved — keep them.)

## Reviewer revision (round 5 — BLOCKING, from P1-012.review.md round 4)
`assertContainerPath()` is only a string-prefix check, so `Kernel.Path=/external/../plan/x` or
`UKI.Output=/out/../work/x` passes and can escape the mount root after normalization (path traversal).
Fix COMPREHENSIVELY: route EVERY container/host path in the plan (kernel/initrd/stub paths, UKI output,
os-release, mounts, signing paths) through ONE canonical-POSIX-path validator that requires: absolute,
NO `.`/`..` segments, no empty/duplicate-slash segments, no control chars, and — after canonicalization
— containment WITHIN the exact declared mount root (string-prefix alone is insufficient: canonicalize
THEN check containment). Reject everything else. Add path-traversal regressions: `/external/../plan/x`,
`/out/../work/x`, `//x`, `/a/./b`, a control-char path, and a path outside the mount root ⇒ all rejected.
(Round-4 unresolved-digest model + signing + os-release are approved — keep them.)
