## Objective
Build the **Unified Kernel Image (UKI) + Secure Boot signing PLAN** on top of the merged root-image
scaffold (P1-011): a deterministic `planUKI()` that assembles the UKI inputs (kernel image ref + `cmdline`
+ initrd + `os-release` + the systemd `ukify`/stub, all pinned) and the sign step. As with P1-011, this
is a pure, offline PLAN + determinism harness — NOT a real kernel build/sign.
- `os/x86_64/uki.conf`: pinned UKI inputs (kernel/initrd refs by digest, fixed cmdline, os-release).
- `os/x86_64/uki.mjs`: `planUKI()` (pure) returning the normalized, byte-deterministic UKI+sign plan;
  the `ukify`/sign tool container is **digest-pinned**; SOURCE_DATE_EPOCH set; no eval-time network.
- **Signing uses a DEV/TEST key reference only.** Real Secure Boot keys are R4 / owner-only and MUST
  NOT appear in the repo or plan — reference a clearly-labelled `test` key id; the plan records that
  production signing is a separate owner-only step (spec §16, §11). NEVER embed key material (§13.1).
- `os/x86_64/test/uki-determinism.test.ts`: asserts `planUKI()` is byte-identical across runs, pins the
  kernel/initrd/tool by digest, sets SOURCE_DATE_EPOCH, references only the TEST key, declares no network.

## User value
Next step toward a bootable signed image (FR-001 QEMU boot): the UKI is what UEFI verifies + boots.
Establishes the signing contract with the production keys held back (owner-only).

## Non-goals
- No real kernel/initrd build, no real `ukify` run, no real signing. No production keys. No RAUC/
  dm-verity yet (later). Do not modify P1-011's root-image files beyond referencing their outputs.
