## Objective
W6-S5 (ADR-0011 slice 5 — THE GATE; the FR-011 Phase-4 exit, mirroring the OCI cgroup gate P1-054): prove on a real
boot that a HOSTILE capsule — one that actively tries to violate its network grants — is BLOCKED AT THE KERNEL on EVERY
axis, and the NODE SURVIVES (agentd + the benign capsules keep working). This is the BLOCKING precondition before any
UNTRUSTED capsule may receive network grants: widening RestrictAddressFamilies removed a coarse backstop, so containment
now rests on netns + nft holding — and that MUST be re-verified against an adversary.

Build a HOSTILE test capsule (granted a SPECIFIC egress CIDR + a SPECIFIC ingress port, like the benign one) that then
ATTEMPTS to break out, and confirm each attempt is DENIED by the kernel (not by cooperation):
- **Egress violation:** connect to a NON-granted CIDR/host (e.g. the host's real addr, another capsule's veth, an
  arbitrary public-range addr) → MUST be DROPPED by the egress nft default-deny (P1-060).
- **Ingress violation:** attempt to be reachable on / bind-and-serve a NON-granted port, and from a non-host-veth source
  → MUST NOT be reachable (the input policy DROP from P1-059/060 holds; no DNAT for un-granted ports, P1-061).
- **Isolation violation:** try to see host interfaces / reach the host beyond its own veth /32 / reach a SECOND capsule's
  netns / raw-socket or netlink-escape → MUST be contained by the netns + the empty CapabilityBoundingSet + seccomp
  (the AF widening did NOT grant CAP_NET_RAW/ADMIN to the workload).
- **DoS attempt:** a burst of connections/packets → the per-capsule netns + nft + cgroup contain it; agentd + the node
  do NOT degrade.
agentd CONFIRMS enforcement (independent of the workload's self-report): re-read the nft policy is DROP with only the
granted accepts, the netns has only its veth+lo, the host is not reachable — and the NODE SURVIVES (agentd healthz OK,
the benign capsule's NET-EGRESS/NET-INGRESS/NET-NS markers STILL emit OK after the hostile capsule ran).

## User value
The security guarantee that makes network grants safe for UNTRUSTED apps: a malicious capsule provably gets ONLY its
declared network and nothing else — the kernel (netns + nftables), not good behavior, enforces it, and one hostile
capsule cannot reach the host, other capsules, or un-granted destinations, nor take the node down. The Phase-4 exit.

## Non-goals
NO new enforcement mechanism (this VERIFIES the S2–S4 netns/nft/DNAT enforcement against an adversary — it does not add
new privileged surface). NO public exposure. NO weakening of any S2–S4 control to make the test pass. The hostile
capsule is a TEST artifact (first-party, baked) — not a real untrusted package.
