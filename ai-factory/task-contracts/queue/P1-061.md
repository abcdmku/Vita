## Objective
W6-S4 (ADR-0011 slice 4 — controlled INGRESS, DEFAULT-DENY, HOST-LOCAL ONLY): a capsule whose validated manifest declares
ingress PORT grants becomes reachable ON ITS GRANTED PORTS — but ONLY from the HOST (via the per-capsule veth host end),
NOT from the LAN/public (which stays OWNER-GATED, deferred — see Non-goals). Build on S3's persistent named netns + veth
+ nft (P1-060): add a DNAT rule on the host so a connection to the host-side per-capsule veth address on a granted port
is forwarded to the capsule's listener inside its netns, and an nft ACCEPT for that specific port (default-deny ingress
otherwise). A capsule with NO ingress grant is NOT reachable inbound at all (the S3 default-deny already drops it).

Concretely (build on egress.go's named-netns/veth/nft; new ingress.go):
- **DNAT (host-local):** on the host, a per-capsule nft `nat`/`prerouting`-or-`output` DNAT that maps
  `<host-veth-addr>:<granted-port>` → `<capsule-netns-addr>:<granted-port>` for EACH validated ingress port grant. The
  match is scoped to the per-capsule host veth address (NOT the host's external/LAN interface — no public exposure).
- **nft ingress ACCEPT (default-deny):** in the capsule netns's input chain (policy DROP from S3), ACCEPT new inbound
  ONLY on the granted ports (+ established/related already allowed); everything else stays DROPPED. NO ingress on
  un-granted ports.
- **MANIFEST-ONLY composition:** ports come from the re-validated manifest ingress grants (reuse P1-057 PortAll/port
  validators); agentd emits the DNAT + nft in code (no raw runtime text, no user-controlled shell args). A capsule
  proposing a port outside its grant, or raw text, is rejected.
- **Teardown:** remove the DNAT + the ingress ACCEPT with the rest of the per-capsule nft/veth/netns (S3 undo) — no leak.
- **MEASURED marker (the P1-055 lesson):** the baked test capsule LISTENS on a granted port inside its netns; agentd (or
  a host-side probe) connects to `<host-veth-addr>:<granted-port>` and REALLY reaches the capsule listener (in-grant
  reach OK), AND a connect to a NON-granted port REALLY fails (default-deny enforced). The marker is gated on BOTH +
  agentd confirming the DNAT/ACCEPT exist only for granted ports. NEVER synthesized.
Markers: `VITA-CAPSULE-NET-INGRESS: id=<id> port=<p> reach=OK denied_port=<q> drop=enforced status=OK`;
`VITA-CAPSULE-NET-INGRESS-REJECT: reason=<specific step+errno> status=OK`; `…-ERROR: status=FAILSAFE`. Keep ALL prior
markers (NET-EGRESS, NET-NS, NET-PARSE, …). Diagnosability: specific step+errno (the S2/S3 pattern).

## User value
A capsule can SERVE — be reached on the ports it declares — while default-deny still blocks every un-granted port. This
slice keeps it HOST-LOCAL (the node can reach its own capsules' services; e.g. a local reverse-proxy/sidecar pattern)
without yet exposing anything to the LAN/internet, which remains an explicit owner-gated decision.

## Non-goals
**NO public/LAN exposure** (binding a capsule port on the host's external interface / routing from the LAN) — that is
OWNER-GATED and DEFERRED to a later slice with explicit owner sign-off. NO DNS. NO load-balancing. NO NAT beyond the
host-local DNAT to the per-capsule veth. agentd composes DNAT/nft ONLY from the validated manifest (never raw text).
Capsules without ingress grants stay non-reachable inbound (S3 default-deny unchanged).

## Performance & security constraints

addr, NEVER the external/LAN iface); manifest-only composition (no raw text/shell); all S3/S2/ADR-0009 hardening intact;
teardown no-leak; fail-closed (setup error → no ingress, never open-all). NO public/LAN exposure (owner-gated, deferred).
No keys. R3 → reviewer gate.
