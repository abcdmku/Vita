## Objective
**Storage durability, Phase-3 slice (spec §10.2 "Btrfs … subvolumes, quotas, and read-only snapshots"; §10.1 "snapshots"
live on the data plane).** Today the persistent `vita-data` `/var` volume (P1-029's `repart-verity/40-data.conf` +
`verity-overlay/.../var.mount`) is a flat **ext4** filesystem — no snapshots, no quotas, no rollback target. Make the
authoritative mutable data volume a **Btrfs filesystem with a `data` subvolume mounted at `/var`**, and give the narrow
privileged Go `agentd` a NEW capability that **creates / lists / rolls back read-only snapshots of the data subvolume
and enforces a per-subvolume quota** — driven ONLY from a re-validated typed request, fail-CLOSED. The keystone proof:
agentd takes a read-only snapshot BEFORE an apply (the rollback target), and a rollback restores the prior on-disk
state. This is the data-durability counterpart to the trusted-boot work: the OS root is dm-verity-immutable; the data
plane gains snapshot/rollback so a bad change is recoverable.

This is a THIN vertical slice composed of two coherent halves, both gated/additive so the plain-smoke and existing
verity/LUKS images stay byte-compatible:

1. **OS: Btrfs `data` subvolume on the data volume (gated behind `VITA_BTRFS=1`).** In the VITA_VERITY build path
   (`os/x86_64/build-and-boot.mjs`, behind a `VITA_BTRFS=1` env gate — mirroring the existing `VITA_LUKS=1` gate so
   plain smoke + non-Btrfs verity images are UNAFFECTED): after repart lays down the `vita-data` partition (or, when
   composed with `VITA_LUKS=1`, after the LUKS mapper is opened — Btrfs lives INSIDE the decrypted volume, never on the
   bare ciphertext), format it `mkfs.btrfs -L vita-data` and create a top-level subvolume `@data` plus the snapshots
   home subvolume `@snapshots` (a sibling, NOT nested under `@data`, so a snapshot of `@data` never recurses into the
   snapshot store). `/var` mounts the `@data` subvolume (`Options=subvol=@data,compress=zstd:1`, keep the existing
   `nofail`/`x-systemd.device-timeout=5s` skip-semantics so a non-Btrfs disk falls back exactly as P1-029 — condition
   unmet = success-skip, NEVER a hard fail that cascades to vita-agentd's `StateDirectory`, the P1-029 lesson).
   Enable Btrfs quota groups (`btrfs quota enable`) on the filesystem so a quota can be set on `@data`. The build emits a
   gate marker file (e.g. `/usr/lib/vita/btrfs/enabled`) the way `VITA_LUKS=1` emits `/usr/lib/vita/luks/enabled`, so
   the marker service is condition-gated. **Compose, don't fight, P1-068/LUKS**: when both gates are on, the ext4
   `mkfs` of the mapper is REPLACED by the btrfs format of the mapper; `var.mount`'s `Type=` becomes `btrfs` + the
   `subvol=` option; keep the `BindsTo=vita-data-luks.service` hard-dependency intact (no plaintext fallback). When
   `VITA_BTRFS=0` nothing changes.

2. **Agent: a NEW privileged `storage.snapshot` capability** (a SEPARATE package `agent/capabilities/storagesnap` —
   do NOT modify the existing declarative `storage.layout` capability in `agent/capabilities/storage`, which is the
   plan-level subvolume MODEL, not the runtime mutator). It exposes a CLOSED typed op set via the existing
   typed-request pattern (`jsonsafe.DecodeStrict` + `RejectDuplicateObjectKeys`, the `transaction.Undo` contract for the
   mutating ops, the AGENTS.md single-commit-point R3 discipline):
   - **create** — take a READ-ONLY btrfs snapshot of the `@data` subvolume into `@snapshots/<name>` where `<name>` is a
     validated label (timestamp/monotonic id + an optional caller tag; agentd OWNS the name, the runtime never supplies a
     raw path). Read-only (`btrfs subvolume snapshot -r`) so a snapshot is an immutable rollback point.
   - **list** — enumerate snapshots under `@snapshots` (name, id, creation time, read-only flag, referenced/exclusive
     size from `btrfs subvolume list`/`qgroup show`), sorted deterministically.
   - **rollback** — restore the data subvolume to a named snapshot as a SINGLE COMMIT POINT: snapshot the rollback
     TARGET first (so rollback is itself reversible), then atomically swap `@data` → the chosen snapshot (the
     subvolume-set-default + the documented atomic swap; the live `@data` is replaced as one commit point with a
     working `Undo` that restores the prior `@data`). If any precondition fails (unknown snapshot, snapshot not
     read-only, target busy), REFUSE and mutate nothing (fail-CLOSED). Document the reboot requirement if the swap of a
     mounted `/var` needs a remount/next-boot to take effect, and make the marker MEASURE the real post-state.
   - **quota-set / quota-enforce** — set a btrfs qgroup limit on `@data` (from a validated `quotaGiB > 0`, reusing the
     `storage.layout` `QuotaGiB` integer-literal discipline — reject float/exponent tokens per AGENTS.md trap 9), and
     prove enforcement: a write that EXCEEDS the quota fails (`EDQUOT`/`ENOSPC`) while a write within it succeeds.
   - **snapshot-before-apply (the keystone wiring)** — expose a `SnapshotBeforeApply(tag)` entry agentd calls to take
     the read-only rollback snapshot immediately BEFORE a mutating apply, returning the snapshot id so a failed apply
     can roll back to it. (This slice WIRES the helper + proves it on-device; it does NOT have to retrofit every
     existing capability's Apply — demonstrate it once around a representative mutation, and document the seam.)
   The capability is REGISTERED in `registry.go` under the closed name `storage.snapshot`; an unknown op is rejected.
   It composes ONLY from the re-validated typed request — every `btrfs`/`mount` invocation is built from FIXED,
   code-controlled args + validated fields, NEVER from raw runtime-supplied text. The real btrfs syscalls are isolated
   behind a build-tagged `btrfs_linux.go` (a `btrfs_stub.go` for non-linux `go build`), and the privileged real-op
   tests `t.Skip` on `EPERM`/missing-`btrfs`/no-loop-device under go-in-docker (the AGENTS.md idiom); the PURE logic
   (name/label validation, quota integer parsing, request decode, list sort/format, fail-closed rejects, the
   single-commit-point Undo state machine) runs ALWAYS and a no-op/always-ok impl MUST fail the suite.

**Markers (emitted on-device, MEASURED — never synthesized; the boot is the real floor).** A `vita-btrfs-marker.service`
(mirroring `vita-luks-marker.service`, condition-gated by `/usr/lib/vita/btrfs/enabled`) runs `vita-btrfs-marker.sh`,
which emits the OK marker ONLY after REAL checks: `/var` is mounted from a **btrfs** filesystem on the `@data` subvolume
(`findmnt -n -o FSTYPE,SOURCE /var` ⇒ btrfs + `subvol=/@data`); a read-only snapshot of `@data` was taken and appears in
`btrfs subvolume list` with the read-only flag; the qgroup limit on `@data` is set and an over-quota write FAILS while an
under-quota write SUCCEEDS; and a rollback round-trip restores prior content (write sentinel A → snapshot → write
sentinel B → rollback → A present, B gone). Marker:
`VITA-BTRFS: subvol=@data snapshot=OK rollback=OK quota=enforced status=OK`;
fail path `VITA-BTRFS-ERROR: reason=<specific step+errno, e.g. var_not_btrfs | snapshot_create_EPERM | quota_not_enforced
| rollback_mismatch> status=FAILSAFE`. Keep ALL prior markers (VITA-TS → EVAL → PREVIEW → EXPLAIN → CONNECT → STATE →
APPLY → CAPSULE-* → PDS → FILES → …) intact on the same boot.

## User value
The authoritative data plane gains the Btrfs durability primitives the spec requires (§10.1/§10.2): platform-controlled
read-only snapshots, per-subvolume quotas, and rollback. A bad configuration apply, a runaway app, or a corrupted write
is RECOVERABLE — agentd snapshots `@data` before a mutation (a rollback target) and can restore it, and a quota stops a
single subvolume from exhausting the disk. Combined with the immutable dm-verity root and (P1-068) LUKS encryption, the
node now has a recoverable, bounded, encryptable data plane — the foundation for the Phase-3 storage exit gates and for
the backup/restore (P1-066) and disk-full-handling work that builds on snapshots.

- NO LUKS work here (P1-068 owns encryption; this slice COMPOSES with it but does not implement it). NO TPM/recovery
  keys — owner-held §16; generate/commit NO production key material.
- NO automatic snapshot SCHEDULER / retention-pruning policy / GC timer (explicit create/list/rollback ops only; a
  retention policy is a later slice — though `list` exposes enough for one to be built).
- NO send/receive, NO incremental/differential snapshot streaming, NO cross-disk replication, NO backup target (P1-066).
- NO btrfs RAID/multi-device, NO defrag/balance/scrub scheduling, NO compression-policy UX, NO per-app/per-capsule
  subvolume carve-out (this slice is the single `@data` subvolume + its snapshots/quota; per-role subvolumes from the
  `storage.layout` model are a later wiring).
- NO controller/web UI. NO ARM/Pi image (x86_64 only). NO migration of an EXISTING ext4 `/var` in place (the Btrfs
  format is a fresh-image build concern; do NOT write an in-place ext4→btrfs converter).
- Do NOT modify the `storage.layout` capability's on-disk format/behavior, the dm-verity RO root, or the Secure Boot
  chain. agentd composes every btrfs/mount command from code-controlled args, NEVER from raw runtime text.

## Performance & security constraints
- **Security model (encode it):** the TS runtime is UNPRIVILEGED; ALL privileged mutation (mkfs/mount/btrfs
  snapshot/qgroup/rollback) belongs ONLY to the narrow Go `agentd`, which acts ONLY from a re-validated typed request
  (validated label, `quotaGiB>0` integer, known op) — NEVER from raw runtime text; every `btrfs`/`mount` invocation is
  composed from FIXED code-controlled args. Unknown/invalid ⇒ fail-CLOSED reject. The capability is a CLOSED typed op
  set; arbitrary commands rejected.
- **Fail-CLOSED everywhere:** wrong-state/unknown-snapshot/quota-unset/non-readonly-snapshot/busy-target ⇒ refuse +
  mutate nothing; `VITA_BTRFS=1` with a non-btrfs `/var` ⇒ marker FAILSAFE (no silent ext4 fallback). The marker is
  MEASURED, never synthesized; failures carry a specific step+errno (diagnosability — the P1-066/P1-068 lesson).
- **Single commit point (R3, AGENTS.md §2):** rollback snapshots the target first, then swaps `@data` as the ONE
  irreversible step, with no fallible work after it and a working `Undo`; never mutated-but-reported-failed.
- **Read-only snapshots:** snapshots are `-r` (immutable rollback points); `@snapshots` is a sibling subvolume so a
  snapshot of `@data` never recurses into the snapshot store.
- **NO real keys / TPM / recovery / signing material** — owner-held (§16); TEST/throwaway loopback images only; never
  generate or commit production key material. No remote imports; vendored deps only (no new vendored dep needed — btrfs
  is driven via the in-image `btrfs-progs` CLI from code-controlled args, OR `unix` ioctls already vendored); no package
  lifecycle scripts; offline. Determinism: `list` output is canonical; the agent capability logic is pure given inputs.
- The plain smoke image and non-Btrfs verity/LUKS images stay byte-compatible (everything gated behind `VITA_BTRFS=1`).
- R3 (boot/storage — privileged TCB FS mutation of authoritative data) → **reviewer gate** (`npm run review -- P1-074`)
  `VERDICT: approve` AND independent orchestrator host-verify before merge.
