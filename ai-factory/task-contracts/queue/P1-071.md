## Objective
Phase 4 supply-chain join: given a VERIFIED signed catalog (P1-063 `verifyCatalog`) + an app id + version, resolve a
complete, fail-closed INSTALL PLAN — the capsule package ref + its mirror-resolved dependency closure (P1-064
`resolveFromMirror`, byte-verified SRI) + the capability grants — reusing the existing `resolveInstallPlan`
(packages/install/src/resolve.ts). This is the pure TS resolver that turns "install app X" into a verified, deterministic
plan an agentd slice can later apply. NO host mutation, NO download side effects (pure over caller-supplied catalog +
mirror store).

Concretely: a pure `resolveFromCatalog({catalog, appId, version, mirrorStore})`:
1. `verifyCatalog(catalog)` FIRST — if the catalog signature/integrity doesn't verify, REJECT (no resolution from an
   unverified catalog). 2. Locate the app+version entry (fail-closed if absent/ambiguous). 3. `resolveFromMirror` the
   entry's package + dep closure against the mirror store, byte-verifying every SRI (reject NOT_IN_MIRROR /
   INTEGRITY_MISMATCH). 4. Build the ordered install plan + capability grants via the existing `resolveInstallPlan`.
   Output is deterministic (byte-identical for the same inputs) + never throws at the boundary (safeNormalize the inputs).
Errors: CATALOG_UNVERIFIED, APP_NOT_FOUND, VERSION_NOT_FOUND, MIRROR_* (from P1-064), POLICY_REJECTED. No remote fetch.

## User value
The supply chain end-to-end as pure logic: a signed catalog + a mirror yield a verified install plan for a named app —
the foundation for `vita install <app>` (CLI P1-070) + a future agentd install slice. A tampered catalog, a missing/
bad-integrity dependency, or an unknown app all fail closed before any plan is produced.

## Non-goals
NO actual install/host mutation (a later agentd R3 slice applies the plan). NO network/downloader (the mirror store is
caller-supplied/in-memory, per P1-064). NO loosening of verifyCatalog or resolveFromMirror or validateLockfilePolicy
(reuse, don't re-implement/weaken). NO on-device marker (pure host-side module — SDK/unit-level floor).

## Dependencies

Read those before coding; match the package-platform test style (node --experimental-strip-types --test).

## Acceptance tests
`acceptance_command` — node TS tests: resolveFromCatalog produces the correct ordered plan + grants for a valid
verified-catalog app; REJECTS an unverified/tampered catalog (CATALOG_UNVERIFIED) before any resolution; REJECTS an
unknown app/version; REJECTS when a dependency is NOT_IN_MIRROR or fails SRI (INTEGRITY_MISMATCH); is deterministic
(byte-identical output under input key reorder); never throws on hostile input (cyclic/accessor/__proto__). `npm run
typecheck` clean on touched files.

deterministic; fail-CLOSED on every invalid/ambiguous input; never throws at the trust boundary; no remote imports/fetch;
no lifecycle scripts; no keys/secrets. R2 → reviewer gate.

## REVISION 2 (Codex R2 review: REVISE — 2 blocking — 2026-06-24)
1. **packageRef must reference the capsule ARTIFACT, not a metadata envelope.** resolve-from-catalog.ts (:124/:141/:162/
   :166) treats `packageRef` as a mirror key for a `{entry, lockfile}` JSON envelope and signs/verifies THAT envelope —
   but the catalog contract defines `packageRef` as the capsule/package artifact reference that downstream install
   fetches + integrity-verifies. FIX: resolve + verify the actual capsule ARTIFACT (its bytes/digest), and return the
   artifact's ref + integrity so the produced plan is a valid install plan for the real capsule package (not the metadata
   envelope).
2. **Fail-closed on artifact/catalog id+version mismatch.** (:159-174) the resolver never checks that the package
   contract embedded in the resolved artifact MATCHES the verified catalog selection. A signed catalog entry for
   appId=com.vita.notes@1.2.3 pointing at an artifact whose contract is com.other.app@9.9.9 currently returns ok=true with
   the catalog's appId/version but the artifact's package/grants. FIX: after resolving the artifact, verify its embedded
   package contract's appId + version EQUAL the verified catalog selection; REJECT fail-closed on any mismatch (never
   return an install plan where "install app X version Y" yields a different app/version).
