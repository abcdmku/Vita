## Objective
The keystone. The unprivileged TS runtime EVALUATES a config → sends the resulting plan to agentd over the unix
socket → **agentd re-validates and APPLIES it** through its transaction engine. This is the first end-to-end crossing
of the unprivileged→privileged MUTATION boundary. Markers:
- benign apply → `VITA-APPLY: outcome=committed applied=<N> rolledBack=0 audit=recorded status=OK`
- a deliberately INVALID plan → `VITA-APPLY: outcome=rejected reason=<code> status=OK` (proves agentd FAILS CLOSED on
  untrusted input — the runtime cannot force an invalid mutation)
- transport/unexpected error → `VITA-APPLY-ERROR: status=FAILSAFE` (never crash the oneshot)

**BENIGN BY CONSTRUCTION:** the boot apply MUST be a no-op-equivalent — evaluate `hostname.set` to the CURRENT
hostname (read it first via the S2 read path / `getState("hostname.set").current`), so applying commits but changes
nothing destructive on a real boot. Do NOT apply anything that alters the running node's real state.

Concretely:
- **Vendor** `controller/apply-node/src/apply-node-config.ts` (the `applyNodeConfig` wrapper + its `ApplyNodeTransport`
  type, ~line 13) into `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/apply-node-config.ts` — byte-identical except a
  `// Vendored from …` header + import-path adjustments. It composes evaluate (vendored `evaluate.ts`) → transport
  POST `/apply` → result. Reuse the vendored `agent-client.ts` (S2) for the POST if that's the upstream path.
- **Apply-capable transport.** S2's `unix-socket-transport.ts` is READ-ONLY (rejects non-GET). Add a NARROW
  apply-capable path: allow EXACTLY `POST /apply` (plus the existing GETs) — nothing else. Prefer a distinct
  `createApplyTransport()` (or an explicit `{ allowApply: true }` flag) so the read-only default stays the default and
  the apply capability is opt-in + obvious. NO new Deno permission needed (S1's socket-scoped `--allow-read/write`
  already covers the socket; the read-only-ness was a TS-layer guard, not a Deno perm). Document that agentd
  RE-VALIDATES every plan (`server.go buildPlan`) before executing — the TS side is NOT trusted.
- **`main.ts`**: after `VITA-STATE`, (1) read the current hostname, build a `hostname.set`→current config, evaluate
  it, POST the plan via the apply transport, print `VITA-APPLY` from agentd's outcome; (2) attempt a deliberately
  invalid plan (e.g. an unknown capability or a malformed request) and confirm agentd REJECTS it →
  `VITA-APPLY: outcome=rejected …`. `VITA-APPLY-ERROR: FAILSAFE` on transport error. Keep ALL prior markers. The
  oneshot still exits 0.

## User value
The node can RECONFIGURE ITSELF on-device, end-to-end, with the unprivileged runtime proposing and the narrow
privileged agent validating+executing — the payoff of the whole control-plane-on-device arc, and the basis for real
config management without a cloud roundtrip.

## Non-goals
NO destructive mutation on boot (benign idempotent op ONLY). NO PDS write (S5). NO capsule install (S6). NO AF_INET.
NO new agentd capability (it already has /apply + the transaction engine). The apply transport allows ONLY `/apply`
(+ GETs) — no broader write surface. Do NOT bypass agentd's re-validation.

## Performance & security constraints
The runtime PROPOSES; agentd (the sole privileged mutator) RE-VALIDATES + executes — the TS plan is untrusted at the
boundary. Apply transport surface = exactly `/apply` + GETs (no broader write). Benign idempotent boot op. Fail-closed
markers. No keys/secrets (ADR-0008: the channel is unauthenticated, guarded by socket perms; SO_PEERCRED is a noted
future slice). R3 (crosses the privileged mutation boundary) → parallel-candidate + reviewer gate.
