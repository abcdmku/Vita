## Objective
Remove the **baked fake directory listing** from the standalone Files app package and replace it
with a real, port-backed surface. Today `apps/files/index.html:243-256` hardcodes two seed rows
(`apps` Folder; `readme.md` 2 KB) under `data-vita-bind-list="files.entries"` at a fixed path `/`,
and `createFilesAppViewModel` (`ui_kits/desktop/viewmodels/apps/files-app.ts:64`) — which already
wires a `FilesCapabilityPort` + grant and fails closed without one — is **never instantiated for
this surface** and **no runtime bootstrap hydrates the binder over the HTML**. The user therefore
sees baked rows, not their real disk.

The fix is the surface wiring layer (the view-model itself already exists and is tested by
PSD-024 / files-app.test.ts — do NOT re-implement it):
1. Add `apps/files/runtime/bootstrap.ts`: on Files-app launch, construct `createFilesAppViewModel`
   with the injected `FilesCapabilityPort` + capability grant, routing `requestFile` through the
   host bridge to the on-device VFS/agentd file API (the same `host.requestFile` path used by
   `ui_kits/desktop/screens/files.ts:233-250`). Select the grant from the host's
   `files.read`/`files.write` capability resources; fail closed (no port / no grant → the surface
   shows the honest fail-closed status, NOT seed rows).
2. Hydrate `apps/files/index.html` through the existing binder (`ui_kits/desktop/runtime/binder.ts`)
   so `files.path` and `files.entries` reflect real disk: an initial `refresh()` populates the list
   from the port, and `files.select` / `files.open` actions drive the view-model.
3. **Delete** the two static seed `<button class="row" …>apps/readme.md</button>` entries
   (`apps/files/index.html:243-256`); replace them with a keyed binder list template (the header row
   stays static; entry rows are produced from `files.entries` via `data-vita-key`, matching the
   keyed-template convention already used by the flagship `desktop/files` surface).
- Import the SDK + binder + host bridge exactly as the existing desktop surfaces do; use ONLY
  public exports. NO platform internals.

## User value
The Files app shows the user's **actual** files (read live through the capability-gated VFS/agentd
API), instead of a misleading hardcoded `apps` + `readme.md` sample at a fake `/` path. This closes
a place where the desktop lies about the real filesystem.

## Non-goals
- Do NOT re-implement `createFilesAppViewModel` / the files view-model (PSD-024 owns it) — consume it.
- NO new file-mutation features (copy/cut/paste/trash are out of scope here; this is the read/list
  surface only).
- NO new visual design — the HTML layout/CSS is the design of record; only the data source and the
  seed rows change.
- NO direct disk I/O in the bootstrap — all reads go through the injected port / host bridge.

## Acceptance
`acceptance_command` passes. Add `sdk/typescript/test/ui-kits/files-app-surface.test.ts` with
deterministic, headless tests (fake `FilesCapabilityPort` + fake host bridge; no real I/O, no DOM
beyond the binder's own surface API) that assert, concretely, the placeholder is GONE and real
behavior is present:
- **Seed rows removed (placeholder gone):** read `apps/files/index.html` as text and assert it no
  longer contains the hardcoded entry markup — i.e. NO `data-vita-entry-name="apps"` /
  `data-vita-entry-name="readme.md"` seed rows, and no hardcoded `2 KB` / `Folder` sample cells in
  the `files.entries` list body. Assert the list container still carries
  `data-vita-bind-list="files.entries"` and now uses a `data-vita-key` template row (not literal
  fixed entries).
- **Data comes from the injected real port:** after bootstrap + initial refresh, the hydrated
  `files.entries` exactly match what the injected `FilesCapabilityPort` returns (e.g. distinct
  fixture entries that do NOT include `apps`/`readme.md`), and `files.path` reflects the port's
  real path — NOT the old hardcoded `/`.
- **Fail-closed is honest (stub now errors honestly):** with no grant (or no port) injected, the
  bootstrap does NOT render any rows; the surface exposes the fail-closed status/error from the
  view-model (`MissingFilesGrant` / `MissingFilesPort`) rather than falling back to sample rows.
- **Selection/open route through the port:** a `files.select` / `files.open` action updates the
  view-model state (selection / navigation issues a `list` request to the port with the grant), not
  a static no-op.
- `npm run typecheck` is clean. Pure/deterministic; folders-first ordering preserved.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed (missing grant/port →
  honest error, never seed rows). Grant routed through the host bridge to the VFS/agentd file API.
- Deterministic: same port responses → byte-identical hydrated list. Folders first, then name.
- No remote imports in production artifacts; lockfile mandatory; no package lifecycle scripts; no
  FFI/native addons.
