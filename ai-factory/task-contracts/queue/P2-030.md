## Objective
`applyNodeConfig(config, registry, transport)` (controller/apply-node): the END-TO-END whole-node apply path
the previews complement — turn an authored node desired-state config into a validated plan and submit it,
fail-closed at every stage. The genuine goal of ADR 0007 + P9-001, demonstrated through the manifest registry.
- `registry`: the `CapabilityManifestRegistry` (the closed vocabulary; currently `{ timesync: TIMESYNC_MANIFEST }`).
- `transport`: an injected async `(method, path, body) => Promise<{ status, body }>` (no real socket — tests
  inject a fake), mirroring the existing controller client pattern.
- Flow: (1) `evaluateNodeConfig(config, registry)` (P9-001) ⇒ if it rejects, return `{ ok:false,
  stage:"evaluate", rejections }` (NO submission — a config that doesn't evaluate is never sent). (2) On a
  valid plan, submit it via `transport("POST","/apply", plan)`; map a non-2xx / a rejected apply result to
  `{ ok:false, stage:"apply", … }`; a transport throw ⇒ `{ ok:false, stage:"transport" }`. (3) On success
  return `{ ok:true, plan, applyResult }`. NEVER throws.

## User value
Whole-node apply (FR-005/007): the operator authors a config, it is validated into a CLOSED deterministic
plan by the evaluator (the SAME manifest rules the agent enforces — preview == evaluate == apply), and only
a fully-valid plan is submitted. The write counterpart to the whole-node change PREVIEW (P2-028).

## Non-goals
- No real HTTP/socket/network (inject the transport). No new validation (reuse the evaluator + manifests).
  No multi-step orchestration/rollback beyond the single /apply submission. Do NOT modify P9-001/P2-006.

## Dependencies
P9-001 (evaluateNodeConfig), P2-006 (the injected-transport client pattern), the manifest registry
(P9-003). All merged.

## Acceptance tests
`acceptance_command` — `apply-node-config.test.ts`: a valid timesync config + a fake transport returning a
committed apply result ⇒ `ok:true` with the plan + applyResult; a config that FAILS evaluation (unknown cap
/ invalid request) ⇒ `ok:false, stage:"evaluate"` and the transport is NEVER called (assert with a spy); a
non-2xx / rejected apply ⇒ `ok:false, stage:"apply"`; a transport that throws ⇒ `ok:false,
stage:"transport"`; hostile config ⇒ fail-closed (no throw, accessor not invoked). Orchestrator runs
`npm run typecheck`.

## Performance & security constraints
Deterministic; no real I/O. Fail-closed: an un-evaluable config is NEVER submitted; never throws; named-stage
errors. Strict TS (no `any`). R2 → reviewer-gated.
