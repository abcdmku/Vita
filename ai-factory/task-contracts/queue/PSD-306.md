## Objective
Net-new GL plumbing that is the **compositor-only foundation for the M3 zero-copy DMABUF path**
(`packages/compositor-core/src/platform/linux.rs`): bind the EGLImage import entry points into the
existing `dlopen`/`eglGetProcAddress` `Egl`/`Gl` structs, probe the required EGL/GL extensions at
backend-open time, and **failsafe** (no zero-copy, current CPU/texture path unchanged) when any
extension is absent. This slice imports nothing into the present/composite hot path yet — it lands
the bindings + capability detection that the later M3 import slice consumes.
- **Bindings (additive to the existing function-pointer structs):** add
  `eglCreateImageKHR` / `eglDestroyImageKHR` to `struct Egl` (loaded via the existing
  `get_proc_address` path used for `eglGetPlatformDisplayEXT` at `linux.rs:1922`, NOT `lib.symbol`,
  because these are extension entry points), and `glEGLImageTargetTexture2DOES` to `struct Gl`
  (loaded via the existing `gl_symbol(&lib, egl, ...)` helper at `linux.rs:2067`). Match the
  surrounding `unsafe extern "C" fn(...)` style and the `EglDisplay`/`GlEnum`/`GlUInt` type aliases
  already defined at `linux.rs:90-101`. Define the new EGL/GL constants (`EGL_LINUX_DMA_BUF_EXT`,
  the `EGL_DMA_BUF_PLANE0_*` attrib names, `GL_TEXTURE_EXTERNAL_OES` / `GL_TEXTURE_2D` target)
  alongside the existing `const EGL_*` / `const GL_*` block (`linux.rs:20-65`).
- **Extension detect:** add a `DmabufCaps` probe (queried from `eglQueryString(display, EGL_EXTENSIONS)`
  + the GL extension string) that detects `EGL_EXT_image_dma_buf_import`,
  `EGL_EXT_image_dma_buf_import_modifiers`, and `GL_OES_EGL_image`. Store the result on
  `PlatformGpuBackend` (a `dmabuf: DmabufCaps` field) and compute it during `open_with_input_policy`
  for the KMS path; the surfaceless software fallback (`open_surfaceless`, `linux.rs:482`) sets caps
  to the **disabled default** (`DmabufCaps::none()`) because llvmpipe has no DMABUF import.
- **Failsafe:** when `import` is unavailable (any required extension missing, or surfaceless),
  `DmabufCaps::can_import()` returns `false` and the backend continues on the merged KMS/buffer-surface
  texture path with **zero behavior change** — no new import is attempted, no error is raised. The
  bindings being absent must never abort backend open.
- **Fix the two PSD-020 review bugs (carried on the merged branch this dispatches onto):**
  (1) `GBM_BO_USE_WRITE` misuse — a DMABUF/scanout buffer must NOT be allocated with the CPU-write
  usage flag; the scanout allocation at `linux.rs:339-347` must stay `GBM_BO_USE_SCANOUT |
  GBM_BO_USE_RENDERING` (no `GBM_BO_USE_WRITE`), and any import-buffer allocation introduced by
  PSD-020 must likewise drop `GBM_BO_USE_WRITE`. (2) `TextureHandleKind::DrmPrimeFd` (the public enum
  at `lib.rs:99-103`) must carry a **real dma-buf file descriptor** in `GpuTextureHandle.value`
  (`lib.rs:106-112`), NOT a GL texture name — `export_handle` (`linux.rs:927`) currently returns
  `OpaqueNativeTexture` with the GL `texture.id`; the DrmPrimeFd variant, when emitted by the M3
  path, must be a `dup`'d prime fd, never `texture.id`.
- **TS source-of-record mirror (the automated check):** because CEF/EGL cannot be linked in CI,
  encode the exact extension-name set, the required-extensions list for `can_import()`, and the
  `DmabufCaps::none()` failsafe truth table in a small pure TS module
  `sdk/typescript/src/ui-kits/cef-dmabuf-bindings.ts` (no DOM, no I/O, no FFI). A comment in
  `linux.rs` and in the TS module each points at the other so the Rust constants and the TS fixture
  stay in lockstep. The Node test asserts against this mirror.

## User value
Lands the hardest, link-blocked piece of the zero-copy CEF render arc (M3) — the EGLImage import
bindings and the capability gate — as an independently verified unit with a fail-closed default, so
the subsequent M3 import slice is thin wiring over a foundation already proven correct, and the two
known PSD-020 correctness bugs (GBM usage flag; prime-fd vs texture-name) cannot reach the GPU path.

## Non-goals
- NO actual zero-copy import in `composite`/present yet (no `eglCreateImageKHR` call on a live CEF
  buffer, no `glEGLImageTargetTexture2DOES` bind in the draw loop) — bindings + detect ONLY. NO change
  to the merged KMS/GBM scanout or surfaceless buffer-surface readback behavior. NO modifier-aware
  import plane wiring (the `_modifiers` extension is detected but not yet used). NO CEF link, no
  `osr_host.cc` edit. NO DOM/CSS/rendering. Do not weaken or remove the surfaceless fallback.

## Acceptance
`acceptance_command` passes: `npm run typecheck` is clean and the Node test
`sdk/typescript/test/ui-kits/cef-dmabuf-bindings.test.ts` asserts, against the TS mirror with exact
named entries (no vacuous glob, so an empty branch fails): the required-extension set is exactly
{`EGL_EXT_image_dma_buf_import`, `GL_OES_EGL_image`} for `can_import()` to be true (with
`EGL_EXT_image_dma_buf_import_modifiers` detected separately and NOT required); that
`DmabufCaps::none()` (the surfaceless/failsafe default) yields `can_import() === false`; and that a
caps set missing any required extension yields `can_import() === false`. Independent Rust verification
(the reviewer/orchestrator re-runs): `rust-in-docker` builds the `compositor-core` crate clean
(`cargo build` / `cargo test -p compositor-core`), the new `eglCreateImageKHR` /
`eglDestroyImageKHR` / `glEGLImageTargetTexture2DOES` symbols load through the existing
`get_proc_address`/`gl_symbol` paths (a binding-load unit test or a self-test probe), the
extension-probe + failsafe-default-on-surfaceless behavior is covered, and a diff read confirms the
two PSD-020 fixes (no `GBM_BO_USE_WRITE` on scanout/import buffers; `DrmPrimeFd.value` is a dup'd fd,
never `texture.id`) with **no behavior change** to the merged KMS/buffer-surface path.

## Security/constraints
- Compositor is a privileged graphics component — keep the fail-closed posture: missing extensions
  disable import, never abort open and never silently attempt an unsupported import. The TS mirror is
  pure/deterministic, no ambient I/O, no FFI/native addons, no DOM. No remote imports; lockfile
  unchanged; no package lifecycle scripts. No new `unsafe` beyond the existing function-pointer
  transmute pattern already used in `Egl::open`/`gl_symbol`. Performance: detection runs once at
  backend open (no per-frame cost); the present/composite hot path is untouched in this slice.

## Hardware profiles
- KMS/GBM path: VMware `vmwgfx` GPU (the M4 live-render target) and any Mesa EGL/GLES2 backend
  exposing the dma_buf_import extensions. Surfaceless software (llvmpipe) path: no-GPU hosts (WSL /
  Borg51 headless) — must take the `DmabufCaps::none()` failsafe and behave exactly as today.
