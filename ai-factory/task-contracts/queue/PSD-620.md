## Objective
Author an ADR (`architecture/adr/0017-catalog-artifact-integrity.md`, status **ACCEPTED**) that
resolves the circular-design question that deferred **P1-071**: a catalog entry's artifact
integrity is `sri(capsule bundle)`, but the `ExecutionManifest` lives *inside* that bundle, so the
manifest's `integrity` field can never equal `sri(the-bundle-that-contains-it)` (self-reference).
The ADR MUST decide and document the canonical integrity model and name, for each verifier, the
exact field it checks. Adopt this model:

- **(a) Bundle gate.** The catalog entry's artifact integrity `= sri(bundle)` is the ONLY
  artifact-hash gate the fetch/resolver layer enforces. This is what
  `agent/storage/capsules/fetch.go` already does: `ParseIntegrity` → `verifiedArtifact` streams the
  bundle through `sha256/384/512` and `subtle.ConstantTimeCompare`s it against the SRI, returning
  `ErrSRIMismatch` (`VITA-CAPSULE-FETCH-REJECT: reason=sri_mismatch`) on any mismatch. The manifest
  `integrity` field is NOT a second hash of the bundle and MUST NOT be interpreted as one.
- **(b) Manifest integrity = declared content digest.** The `manifest.integrity` (and the catalog
  entry's `Integrity`) field declares the package's signed **content digest** — the publisher's
  canonical identity for `(id, version, packageClass)` — set by a two-pass publisher build so it
  equals the catalog's signed `contentDigest`/`ImmutableDigest`. It is an identity/cross-check
  token, not the bundle SRI.
- **(c) Resolver cross-check.** Execution cross-checks `id + version + packageClass + integrity`
  agreement across the three sources — request, in-bundle manifest, and registry entry — exactly as
  `validateManifestMatchesRequest` in `agent/capabilities/capsule/execute.go:1890` already does:
  it rejects when `manifest.{ID,Version,Integrity}` disagree with `desired.{ID,Version,Integrity}`
  OR with `entry.{ID,Version,Integrity}`/`entry.State != StateInstalled`. The ADR documents that
  this triple-agreement (NOT a manifest-self-hash) is the integrity invariant.

Cite the real code in the ADR body: `packages/catalog/src/catalog-entry.ts` (the `CatalogEntry`
shape: `digest: ImmutableDigest`, `signingPublisher`, `signatures`, `sbom`; `validateDigest`
restricts `algorithm` to `sha256|sha384|sha512`), `agent/capabilities/capsule/execute.go`
(`validateManifestMatchesRequest`, lines ~1890-1901), and `agent/storage/capsules/fetch.go`
(`Integrity`, `ParseIntegrity`, `verifiedArtifact`, `ErrSRIMismatch`). Use `path:line` references.

## User value
Unblocks the deferred P1-071 catalog supply-chain slice by removing the circular-design ambiguity:
implementers get one canonical, code-grounded answer for what each verifier hashes and checks, so
the publisher build, catalog schema, and on-device resolver can be implemented without contradicting
each other. No more "manifest.integrity == sri(its-own-bundle)" impossibility.
