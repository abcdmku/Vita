## Objective
Ship **Activity-Monitor** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), on the app-package SDK
foundation (PSD-361). Three artifacts, mirroring the flagship-package pattern + the existing
`ui_kits/desktop/viewmodels/Activity.ts`:
1. **App package** under `apps/activity-monitor/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` —
   `id: "vita.app.activity-monitor"`, `version`, `sdkVersion: SDK_VERSION`, `entry: "index.html"`, MINIMAL
   `capabilityGrants` (NO privileged host grants — Activity-Monitor READS metrics through an injected pure stats port, NOT
   raw host/process access; declare an empty/minimal grant set so anything else fails closed) and a `WebAppDescriptor`
   (`surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-activity-monitor" }`, `title:"Activity Monitor"`,
   `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/activity-monitor/index.html` — a static HTML/CSS activity surface (process/app
   table + CPU/mem summary header), CSS-var tokens, no inline JS (behavior via the view-model / binder convention), in the
   design-of-record style of `ui_kits/desktop/Activity.html`. Minimal; NOT the acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/activity-monitor-app.ts` — a PURE metrics model
   over an injected **stats port** (NO raw host/process introspection; the port supplies a deterministic snapshot of
   running entries `{ id, name, kind, cpuPercent, memBytes, status }` + totals; reading is pull-based via `refresh()`).
   Injected-port style, frozen `snapshot()`, discriminated-union results. State: entries (sorted by the active sort key,
   default cpu desc then id), totals (cpu/mem), selected entry, sort key/direction. Actions: `refresh()` (pulls via the
   stats port; fail-closed if absent/denied), `setSort(key, dir)`, `select(id)`. Deterministic ordering. NO DOM/CSS/
   rendering, NO platform internals, NO ambient I/O.

## User value
Activity-Monitor becomes a swappable first-party package the dock/launcher lists + launches into its own WM window (not a
shell built-in), with a real testable metrics/sort/select model on an injected stats port — proving the app-package
pattern for an observability app while keeping host introspection cleanly behind a capability-gated port (no raw access).

## Non-goals
- NO raw host/process introspection / privileged access in the view-model (metrics come from an injected pure stats port;
  the real host-metrics backend is deferred). NO DOM/CSS/CEF logic in the view-model; NO platform internals; NO new SDK
  ports beyond PSD-361 + existing.
- Do NOT grant Activity-Monitor any privileged capability; it fails closed on anything not explicitly granted. OFFLINE only.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at
`sdk/typescript/test/ui-kits/activity-monitor-app.test.ts` cover the manifest (`defineAppPackage` accepts it; minimal/no
privileged grant; descriptor url === entry) and the view-model state transitions (refresh pulls entries + totals via the
stats port; deterministic default sort (cpu desc then id); setSort re-sorts deterministically; select; absent/denied stats
port fails closed; deterministic snapshot). `npm run typecheck` is clean. Pure, headless, no network. (The exact test path
exists only when the work lands — an empty branch fails.)

## Security/constraints
- MINIMAL/empty capabilityGrants; metrics via an INJECTED pure stats port (no raw host/process access); fail-closed on
  absent/denied port; pure/deterministic. OFFLINE. No remote imports; lockfile; no lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).
