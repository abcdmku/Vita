## Objective
Provide the path from a built image to real hardware. A SAFE, self-contained `tools/install-vita.sh` that writes
the Vita GPT image (ESP + dm-verity root + data partition) to a target block device: write the image, repair the
GPT backup header, grow the data partition to fill the disk (or rely on systemd-repart first-boot growth —
documented). MUST have strong safety (refuse the running system disk; require the explicit target + `--yes`; show
the target model/size + confirm), a `--dry-run` mode, robust bash (`set -euo pipefail`), and post-write
verification (`sfdisk -l`). Plus `docs/install.md`: the end-to-end user flow incl. enrolling the owner's Secure
Boot cert (`vita-db.crt`) in the TARGET machine's UEFI firmware (a manual step). Built by an Opus worker (P1-032);
to be **reviewed by Codex**.

## User value
Turns the QEMU `.raw` into something you can put on a spare PC / Pi-class disk and boot — the install half of
"install and use Vita."

## Non-goals
- Thin first slice: a dd/repart-style whole-image installer + docs. NOT a graphical/guided installer; NOT
  network/PXE install; NOT automated firmware key enrollment (that's a manual UEFI step — documented). Do NOT edit
  build-and-boot.mjs.

## Dependencies
P1-028 (the verity image layout). The image artifact is `os/x86_64/out/*.raw`.

## Acceptance tests
`acceptance_command` (`bash -n`) is the syntax gate. The worker also validates a `--dry-run` and (ideally) a real
write against a LOOPBACK image file (truncate + losetup) then `sfdisk -l` the result. REAL acceptance is
orchestrator-run: dry-run + a loopback install on Borg51. Reviewer (Codex) judges: SAFETY (cannot nuke the system
disk; explicit confirm; dry-run honored), correctness of the GPT-backup repair + data-partition growth, robust
quoting, and that docs/install.md covers the firmware SB-enrollment step honestly.

## Performance & security constraints
DESTRUCTIVE (writes a disk) → safety-first: explicit target + `--yes`, refuse the system disk, dry-run. R3 → reviewer-gated.
