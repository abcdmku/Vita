## Objective
A single, headless **AppHost** view-model that owns app lifecycle for the flagship desktop so the
⌘K command palette and the dock drive ONE source of truth — launch, focus-existing, and close —
instead of each keeping its own private launch map.

Today the dock keeps lifecycle in a private `#launches` Map inside `IndexDockModel`
(`ui_kits/desktop/viewmodels/dock.ts:105`) and exposes `launchOrFocus(appId)`
(`ui_kits/desktop/viewmodels/dock.ts:123`), while the ⌘K palette (`createSearchViewModel`,
`ui_kits/desktop/viewmodels/search.ts:260`) executes app results via its own `launchApp` port and
command results via `emitLauncherIntent` (`search.ts:140`, `search.ts:463`, `search.ts:498`) with no
shared running-state — so ⌘K "Run terminal" cannot focus a terminal the dock already launched, nor
can the palette close it. Build a pure, deterministic host in `ui_kits/desktop/viewmodels/app-host.ts`:

- **Ports (injected, no ambient I/O).** `AppHostPorts = Pick<DesktopHost, "package" | "launchApp" | "stopApp">`
  — the public SDK host surface (`sdk/typescript/src/desktop-sdk/ui-package.ts:130-131`). Construct
  with `createAppHost(ports, apps)` where `apps: readonly DesktopRegistryApp[]` comes from the
  PSD-347 app registry (`createAppRegistry(...).list()`) — a single authoritative catalog for both
  consumers, NOT a re-hardcoded id list.
- **Lifecycle state.** Track per-app status `{ appId, title, running, focused, launch?: DesktopAppLaunch }`,
  exactly one `focusedAppId` at a time. `snapshot(): AppHostState` returns the frozen running/focused
  view both the dock and palette bind to. Deterministic order (registry `list()` order).
- **launchOrFocus(appId).** If the id is already running → set focus, return `{ ok: true, dispatch: "focus", appId, state }`
  (no re-launch, no port call). If not running → check `apps.launch` grant via
  `hasDesktopCapabilityGrant(ports.package, "apps.launch", app.id)`
  (`sdk/typescript/src/desktop-sdk/index.ts:88`); on miss return `{ ok: false, error.code: "MISSING_CAPABILITY", state }`.
  On grant present, call `ports.launchApp(app)`; map a thrown/rejected port to
  `{ ok: false, error.code: "APP_LAUNCH_PORT_FAILED" }`, a `{ ok:false }` host result to the host
  error, and a returned `value.app.id !== appId` mismatch to `APP_LAUNCH_MISMATCH` — mirroring the
  existing dock semantics (`dock.ts:146-188`). On success store the `DesktopAppLaunch` (surfaceId /
  windowId / textureId), set running+focused, return `{ ok: true, dispatch: "launchApp", appId, value, state }`.
- **close(appId).** Only valid for a running id; call `ports.stopApp(appId)`
  (`ui-package.ts:131`), and on `{ ok: true }` drop the lifecycle entry + its surface/window state
  (clear `focusedAppId` if it was focused), returning `{ ok: true, dispatch: "stop", appId, value: DesktopAppStop, state }`.
  An unknown/not-running id → `{ ok: false, error.code: "APP_NOT_RUNNING", state }`; a port
  throw → `APP_STOP_PORT_FAILED`; a `{ ok:false }` host result → the host error. Fail-closed
  (state unchanged on any failure).
- **applyLauncherIntent(intent: DesktopLauncherIntent).** Resolve a `"launcher.launch"` intent's
  `appId` through `launchOrFocus`, a `"launcher.close"` intent through `close`, and treat
  `"launcher.open"`/missing-or-unlisted `appId` as a no-op reject (`UNKNOWN_LAUNCHER_INTENT`) — so the
  palette's command path and the dock both flow through this one host.
- `isRunning(appId)` / `focusedAppId` accessors. Import the SDK exactly as
  `ui_kits/desktop/viewmodels/dock.ts` does (public `@vita/desktop-sdk` surface only) and re-export
  the host from `ui_kits/desktop/viewmodels/index.ts`. Pure, deterministic, frozen outputs — no
  DOM/CSS/CEF, no platform internals, no re-implementing the SDK loader/ports/registry (consume them).

## User value
⌘K and the dock become two faces of one lifecycle: "Run terminal" from the palette focuses the
already-open terminal the dock launched, the dock shows running/focused state the palette changed,
and closing from either cleans up the surface/window — one auditable, grant-checked launch path
instead of two divergent ones.

## Non-goals
- NO new app catalog / hardcoded id list — consume the PSD-347 registry. NO changes to `dock.ts`
  or `search.ts` in this slice (rewiring those consumers to delegate to AppHost is a follow-up);
  only build + export the host.
- NO DOM/CSS/CEF/rendering, no compositor/window-manager calls beyond the injected `launchApp`/
  `stopApp` ports, no platform internals, no ambient filesystem/network I/O.
- No new `DesktopCapability` values, no changes to the loader's enforcement gate, the SRI module,
  or the `DesktopLaunchableApp` / `DesktopAppLaunch` / `DesktopAppStop` shapes.

## Acceptance
`acceptance_command` passes. Author `sdk/typescript/test/ui-kits/app-host.test.ts` (imports the SDK
exactly as `dock.ts` does — public `@vita/desktop-sdk` exports only: `createAppHost`,
`hasDesktopCapabilityGrant`, and registry/host types) with deterministic `node:test` cases against
fake `launchApp`/`stopApp` ports and a stub package manifest:
1. **Palette launch via AppHost.** `applyLauncherIntent({ type: "launcher.launch", appId: terminal })`
   (or `launchOrFocus(terminal)`) calls `launchApp` once and the snapshot marks terminal
   running+focused with the returned `surfaceId`/`windowId`.
2. **Focus, not relaunch.** A second `launchOrFocus(terminal)` returns `dispatch: "focus"` and does
   NOT call `launchApp` again; `focusedAppId === terminal`.
3. **Dock/palette parity.** Launching app A then app B leaves exactly one `focused` item (B) and both
   `running` in the deterministic `snapshot()` the dock and palette share.
4. **Close cleans up.** `close(terminal)` (and `applyLauncherIntent({ type: "launcher.close", appId })`)
   calls `stopApp` once, drops the entry (running=false, surface/window state gone, focus cleared),
   returns `dispatch: "stop"`; closing a not-running id → `error.code: "APP_NOT_RUNNING"` with state
   unchanged.
5. **Grant fail-closed.** With a manifest missing `apps.launch` for the id, `launchOrFocus` returns
   `error.code: "MISSING_CAPABILITY"` and never calls `launchApp`; a thrown `launchApp` port →
   `APP_LAUNCH_PORT_FAILED`, a `value.app.id` mismatch → `APP_LAUNCH_MISMATCH`, both leaving state
   unchanged.
`npm run typecheck` is clean. Pure/headless.

## Security/constraints
- Injected ports only (no ambient I/O); launch authorization capability-mediated via
  `hasDesktopCapabilityGrant` (`apps.launch`) and fail-closed (`MISSING_CAPABILITY`); every port
  failure (throw, `{ok:false}`, id mismatch) fails closed with state unchanged. Pure/deterministic
  given ports + registry seeds; frozen, byte-stable outputs. No remote imports; lockfile mandatory;
  no package lifecycle scripts; no FFI/native addons.

## Definition of done
- A pure AppHost view-model launches an app through the SDK `launchApp` port (grant-checked,
  fail-closed), focuses an already-running app without relaunch, closes via `stopApp` cleaning up
  surface/window/focus, resolves `launcher.launch`/`launcher.close` intents to that same lifecycle,
  exposes a deterministic running/focused snapshot for dock+palette parity, and is exported from the
  desktop view-models; the new deterministic test and `npm run typecheck` pass. R1.
