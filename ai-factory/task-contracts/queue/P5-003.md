## Objective
A pure, standalone SDK type model + fail-closed validators for the personal data server's record + sync
state (AT Protocol, FR-018): `pds-model.ts` exports the types (`RecordKey`, `RecordRef` (collection +
rkey + CID), `RepoCommit` (rev + CID + prev), `SyncState` (cursor + repo head)) and validators
(`validateRecordRef`, `validateRepoCommit`, `validateSyncState`). Builds on the identity model (P5-001
DID). NEW validator ⇒ use `safeNormalize` for the boundary, then validate on the trusted plain value.
- **Syntax validation**: collection = a reverse-DNS NSID; rkey = a valid record key (tid/literal);
  CIDs = well-formed CIDv1 strings; cursor monotonic shape. Reject malformed fail-closed.
- **Secrets-as-references (§13.1)**: no embedded key material (records reference, never inline, keys).
- Standalone module — import from `identity-model.ts`/`safe-normalize.ts` only; no shared-index edits.

## User value
The typed contract for PDS records + repo sync (FR-018) the PDS server, controller, and federation will
share — lets record/sync state be authored + validated deterministically before any network sync.

## Non-goals
- No real PDS server, no network/repo sync, no MST/merkle implementation, no crypto. Types + pure
  validators only. Do NOT modify identity-model; import it. No shared-index edits.

## Dependencies
P5-001 (identity/DID model), P0-015 (safeNormalize). Both merged.

## Acceptance tests
`acceptance_command` — `pds-model.test.ts`: a valid record ref (NSID collection + rkey + CIDv1) +
repo commit + sync state validate; malformed NSID/rkey/CID rejected with clear paths; non-monotonic /
malformed sync cursor rejected; embedded key material rejected (§13.1); fail-closed on hostile input via
safeNormalize. Orchestrator also runs `npm run typecheck`.
