## Objective
Tie the two merged layers together: when the unified app model (PSD-008 `AppHost`) launches an app, a window surface
should flow through the WM into the compositor driving seam (PSD-009 `CompositorDriver`) — so "launch app" becomes
"window on the GPU". Pure, deterministic, headless TypeScript over INJECTED ports (the real AppHost + CompositorDriver
are injected; tests use fakes). NO GPU/FFI.
- An `AppWindowHost` that observes `AppHost` launch/stop events (via an injected subscription/port) and maintains the
  shell+WM window model the `CompositorDriver` reconciles: launch → add a window surface (default placement from the
  app's window hints + WM policy), stop → remove it, with the surfaceKind (tsx/wasm/container/web) carried through.
- **Consistency:** a launch whose window registration fails rolls back the app launch (or records pending cleanup) —
  reuse PSD-008's fail-closed lifecycle invariants; never leave an app running with no window or a window with no app.
- Deterministic ordering + idempotent reconcile (reuse PSD-009's driver semantics; don't fork them).

## User value
The missing glue: the app platform (PSD-008) and the GPU pipeline (PSD-009/010) become one flow — launching a TSX/web/
wasm/container app yields a managed window driven onto the GPU. The spine of the actual desktop UX.

## Non-goals
- NO real content/textures (the window surface is a placeholder until the content rasterizer/CEF lands) — this wires
  the LIFECYCLE (app↔window), not pixels. NO GPU/compositor/AppHost/driver changes (compose them via injected ports).

## Acceptance
`acceptance_command` passes: launch→window-add, stop→window-remove, surfaceKind carried, failed window-registration
rolls back the launch fail-closed, idempotent reconcile; comprehensive unit tests with fake AppHost + fake
CompositorDriver. Pure, headless.

## Security/constraints
- Compose via INJECTED ports only; fail-closed on registration/teardown failure (no app-without-window or
  window-without-app); pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `AppWindowHost` composing PSD-008 AppHost + PSD-009 CompositorDriver (launch↔window lifecycle, fail-closed,
  idempotent) over injected ports; comprehensive unit tests incl. rollback; typecheck clean. R1 review + integrate.

## REVISION 1 (Codex R1: real event subscription + fail-closed maybe-landed rollback — 2026-06-25)
1. The AppHost port is only launch/stop/snapshot with a manual `observe()` — the contract requires AppWindowHost to
   OBSERVE AppHost launch/stop via an INJECTED subscription. Define an injected `AppHostEvents`-style port
   (`subscribe(listener) -> unsubscribe`, delivering launch/stop events) that AppWindowHost uses to AUTO-produce/remove
   windows; an app launched through the real AppHost must automatically yield/withdraw a compositor window. Tests: a fake
   AppHost emits launch/stop through the port → windows appear/disappear without a manual call.
2. Fail-closed rollback (index.ts ~257): a failed window `registerSurface` MAY have partially landed in the injected
   compositor port, but the code reconciles from the CompositorDriver's (uncommitted) snapshot + records no pending
   cleanup → can leave a native window with no app. Treat a failed registerSurface as "surface MAY be live": attempt
   removeSurface and/or record a pending-cleanup retry; NEVER leave app-without-window or window-without-app. Test:
   registerSurface throws → end state has no untracked live window (removed or pending-cleanup).
