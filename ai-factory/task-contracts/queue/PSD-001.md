## Objective
Establish the desktop as a **separable, first-class package** and PROVE the **OS-headless boundary**, per spec §6.0:
1. Define a stable **compositor-substrate interface** — the documented seam a desktop package consumes from the OS
   (capability surface + lifecycle: discover/launch/stop a desktop session). No GPU/rendering yet — just the contract
   of the seam, with a typed schema (`sdk/typescript/src/desktop-substrate.ts`).
2. Ship a **stub desktop package** (`packageClass: "desktop"`, a no-op session that registers against the substrate
   interface, emits a heartbeat, and exits cleanly) installed via the EXISTING package/capsule mechanism — NOT baked
   into the OS image.
3. PROVE the OS is fully functional **headless with no desktop installed**: the existing 21-feature control-plane boot
   still passes, and the desktop package is demonstrably a SEPARATE, optional unit (install → launch → stop; absence
   leaves the OS boot unchanged).

## User value
The OS is never desktop-coupled: multiple desktop packages (flagship PSD, lighter variants) or NONE (headless) are
supported without changing the OS. The desktop is the default UX, not the foundation.

## Non-goals (explicit)
- NO actual rendering, compositor, GPU, DRM/KMS, or CEF (those are PSD-002/003 + the PSD-000 spike, verified on the
  VMware Workstation Pro GPU target). The stub session does no drawing.
- NO window manager / shell / TSX rendering (PSD-004/005).
- Do NOT modify OS boot/recovery/update/storage code to ACCOMMODATE the desktop — the seam is consumed BY the package;
  the OS stays headless-first.

## Dependencies (all merged)
- Capsule/package mechanism (P1-045 capsule.fetch, capsule runtimes, lifecycle P1-084).
- Control plane (eval→preview→apply) for install/launch as a managed transaction.
- The unprivileged-TS / narrow-agentd model (the desktop session is an UNPRIVILEGED capsule like any app).

## Acceptance
`acceptance_command` (typecheck + the substrate-interface/stub unit tests) MUST pass. INDEPENDENT host verification:
the boot (`tools/wsl-verify.sh ts` on Borg51) still PASSES all existing 21 markers WITH the desktop NOT installed,
PLUS a new MEASURED marker when the stub is installed+launched:
`VITA-DESKTOP-PKG: class=desktop installed=OK launched=OK heartbeat=OK headless-boundary=OK status=OK`
— gated on the stub actually installing via the package mechanism, its no-op session launching + emitting a real
heartbeat read back through the substrate interface, and a proof the OS control-plane markers are unaffected (the
boundary holds). `status=FAILSAFE` on any inconsistency. Never synthesized.

## Perf / security constraints
- The desktop session is an UNPRIVILEGED capsule (DynamicUser, empty caps, seccomp allow-list) like any app — NO
  privileged host access. The substrate interface exposes only what a desktop legitimately needs, capability-gated.
- Fail-closed: an absent/broken desktop package must NOT affect OS boot/recovery/update/data — prove it.
- No remote imports; lockfile mandatory; no package lifecycle scripts (spec §9.3).

## Hardware profiles
- Verifiable on the existing headless x86_64 smoke image (no GPU needed for this slice).

## Rollback plan
- Additive (a new package + interface + marker). If boot regresses, revert the merge; the OS (no desktop) is
  unaffected by design.

## Definition of done
- Substrate interface defined + typed + unit-tested; stub desktop package installs+launches+stops via the package
  mechanism; the existing 21-feature headless boot still PASSES with no desktop; the `VITA-DESKTOP-PKG` marker is
  MEASURED on the live boot when the stub is installed; the OS-headless boundary is demonstrated. R2 reviewer gate
  (Codex) + independent boot-verify.
