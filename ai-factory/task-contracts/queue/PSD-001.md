# PSD-001 — Separable desktop package + OS-headless boundary

- **id:** PSD-001
- **status:** ready
- **risk class:** R2 (defines a stable OS interface seam + the desktop package mechanism; no privileged host mutation
  beyond the existing capsule/package install path)
- **phase:** 6 (desktop environment) — the FOUNDATION slice (see [PHASE6-PLAN.md](../../PHASE6-PLAN.md))

## Objective
Establish the desktop as a **separable, first-class package** and PROVE the **OS-headless boundary**, per spec §6.0:
1. Define a stable **compositor-substrate interface** — the documented seam a desktop package consumes from the OS
   (capability surface + lifecycle: discover/launch/stop a desktop session). No GPU/rendering yet — just the contract
   of the seam, with a typed schema.
2. Ship a **stub desktop package** (`packageClass: "desktop"`, a no-op session that registers against the substrate
   interface, emits a heartbeat, and exits cleanly) installed via the EXISTING package/capsule mechanism — NOT baked
   into the OS image.
3. PROVE the OS is fully functional **headless with no desktop installed**: the existing 21-feature control-plane boot
   still passes, and the desktop package is demonstrably a SEPARATE, optional unit (install → launch → stop, and
   uninstall leaves the OS boot unchanged).

## User value
The OS is never desktop-coupled: multiple desktop packages (flagship PSD, lighter variants) or NONE (headless) are
supported without changing the OS. The desktop is the default UX, not the foundation.

## Non-goals (explicit)
- NO actual rendering, compositor, GPU, DRM/KMS, or CEF (those are PSD-002/003 + the PSD-000 spike — they need GPU
  test infra). The stub session does no drawing.
- NO window manager / shell / TSX rendering (PSD-004/005).
- Do NOT modify the OS boot/recovery/update/storage code to ACCOMMODATE the desktop — the seam is consumed BY the
  package, the OS stays headless-first.

## Dependencies (all merged)
- Capsule/package mechanism (P1-045 capsule.fetch, capsule runtimes, lifecycle P1-084).
- Control plane (eval→preview→apply) for install/launch as a managed transaction.
- The unprivileged-TS / narrow-agentd model (the desktop session is an UNPRIVILEGED capsule like any app).

## Target component paths
- `os/x86_64/ts-overlay/usr/lib/vita/ts/` — the substrate-interface types + the boot driver wiring that proves the
  boundary + emits the marker.
- `sdk/typescript/src/desktop-substrate.ts` (new) — the typed compositor-substrate interface (the seam schema).
- `packages/desktop-stub/` (new) — the stub desktop package manifest + no-op session (packageClass desktop).
- `agent/` ONLY if the substrate interface needs an agentd-mediated session lifecycle op — keep it within the existing
  validated manifest/capsule surface; NO new privileged authority.

## Acceptance command
`npm test` (TS unit tests for the substrate interface + stub package manifest validation) AND the host boot
(`tools/wsl-verify.sh ts` on Borg51) still PASSES all existing 21 markers WITH the desktop NOT installed, PLUS a new
measured marker when the stub is installed+launched:
`VITA-DESKTOP-PKG: class=desktop installed=OK launched=OK heartbeat=OK headless-boundary=OK status=OK`
— MEASURED: the marker is gated on the stub package actually installing via the package mechanism, its no-op session
launching + emitting a real heartbeat read back through the substrate interface, and a proof that the OS control-plane
markers are unaffected (the boundary holds). `VITA-DESKTOP-PKG: ... status=FAILSAFE` on any inconsistency. Never
synthesized.

## Perf / security constraints
- The desktop session is an UNPRIVILEGED capsule (DynamicUser, empty caps, seccomp allow-list) like any app — it gets
  NO privileged host access. The substrate interface exposes only what a desktop legitimately needs, capability-gated.
- Fail-closed: an absent/broken desktop package must NOT affect OS boot/recovery/update/data — prove it.
- No remote imports; lockfile; no package lifecycle scripts (spec §9.3).

## Hardware profiles
- Verifiable on the existing headless x86_64 smoke image (no GPU needed for this slice).

## Allowed tools + network
- Standard build/test; no network beyond the local package mechanism. No production keys (TEST keys only if signing
  the stub package — build-only, never shipped).

## Compute/time budget
- One worker pass + revs; native build/vet/typecheck + the single Borg51 boot.

## Required artifacts
- The substrate-interface schema (`desktop-substrate.ts`), the stub package, the boot-driver wiring + the marker, unit
  tests. A short ADR note on the seam (what the OS exposes vs what a desktop package provides).

## Rollback plan
- The slice is additive (a new package + an interface + a marker). If the boot regresses, revert the merge; the OS
  (no desktop) is unaffected by design.

## Definition of done
- Substrate interface defined + typed + unit-tested; stub desktop package installs+launches+stops via the package
  mechanism; the existing 21-feature headless boot still PASSES with no desktop; the `VITA-DESKTOP-PKG` marker is
  MEASURED on the live boot when the stub is installed; the OS-headless boundary is demonstrated (OS unaffected by the
  desktop package's presence/absence). R2 reviewer gate (Codex) + independent boot-verify.
