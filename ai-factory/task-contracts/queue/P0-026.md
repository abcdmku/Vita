## Objective
A small, explicit, fail-closed version-compatibility utility `sdk/typescript/src/semver-range.ts` built on
P0-025 (`parseSemver`/`compareSemver`). NO npm-style range grammar (no `^`/`~`/`||`/`*`) — only an
explicit, auditable bounded range so capsule/update compatibility checks are unambiguous.
- `SemverRange` = `{ readonly min?: string; readonly minInclusive?: boolean; readonly max?: string;
  readonly maxInclusive?: boolean }` (at least one bound required).
- `parseRange(input): { ok: true, value: NormalizedRange } | { ok: false, reason }` — validate the input
  object (use `safeNormalize` on the OBJECT first — it IS an object so safeNormalize applies; reject
  accessors/unknown keys/exotic), each present bound must `parseSemver`-validate, default inclusivity
  (minInclusive default true, maxInclusive default false — typical `>=min, <max`), and reject an empty/
  contradictory range (min > max, or min == max with both exclusive).
- `satisfies(version, range): boolean` — parse `version` (P0-025) and the range fail-closed; return true
  iff version is within the bounds honoring inclusivity, using `compareSemver`. By policy a PRERELEASE
  version satisfies ONLY when a bound with the SAME major.minor.patch is present (prereleases are opt-in,
  never matched by a plain stable range) — document this and test it.
- `maxSatisfying(versions, range): string | null` — the highest input version that satisfies, by
  `compareSemver`; null if none; fail-closed on any invalid input.

## User value
Auditable, explicit version-compatibility checks (FR-012) for capsule upgrades / update bundles — `>=1.2.0
<2.0.0` style, with prereleases opt-in — without the footguns of npm range grammar.

## Non-goals
- No `^`/`~`/`||`/wildcard/hyphen ranges. No network/I/O. Pure functions. Do NOT modify `semver.ts` (P0-025)
  — import it. New files only.

## Dependencies
P0-025 (semver: parseSemver/compareSemver), P0-015 (safeNormalize). Merged.

## Acceptance tests
`acceptance_command` — `semver-range.test.ts`: a valid range parses; range with no bounds rejected;
contradictory range (min>max, equal-and-both-exclusive) rejected; `satisfies` honors inclusive/exclusive
bounds at the boundaries; a prerelease version is NOT matched by a plain stable range but IS when a
same-core bound is present; `maxSatisfying` returns the highest match (and null when none); invalid
version/range/hostile input fails closed (no throw, accessor not invoked — external-counter probe).
Orchestrator also runs `npm run typecheck`.

## Performance & security constraints

explicit bounds only; prerelease opt-in. Strict TS (no `any`). R1 → orchestrator-reviewed.
