## Objective
The vendored on-device `safe-normalize.ts` (P1-033) replaced the upstream direct `import { types } from "node:util"`
with an indirect `globalThis.process.getBuiltinModule(...)` resolver whose Proxy check **fails OPEN** if the resolver
ever returns undefined (`nodeIsProxy?.(value) ?? false` → a Proxy would be ACCEPTED). It works on the pinned Deno
(host-verified), but it is structurally fail-open and it FORKS the vendored copy from upstream. Fix both: make the
vendored copy use the **direct `import { types } from "node:util"`** — which is host-verified to work under the
pinned Deno (`--no-remote` allows node: built-ins; `util.types.isProxy` returns true for a Proxy) AND under Node — so
the guardian is structurally fail-CLOSED (isProxy always available) and the vendored file becomes byte-identical to
upstream (modulo the vendored header).

Concretely:
- FIRST confirm the upstream `sdk/typescript/src/safe-normalize.ts` already uses the direct `import { types } from
  "node:util"` and rejects Proxy/accessor/exotic inputs. (It should — the P1-033 fork was only in the vendored copy.)
  If upstream ALSO uses an indirect/fail-open form, fix upstream too (direct import, fail-closed).
- Rewrite the vendored `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/safe-normalize.ts` to be the EXACT upstream source
  with ONLY a `// Vendored from sdk/typescript/src/safe-normalize.ts` header line different — i.e. remove the
  `resolveNodeIsProxy`/`getBuiltinModule` resolver and use `import { types } from "node:util"` + `types.isProxy`
  directly. No behavioral change on the pinned Deno; the difference is structural fail-closed + zero fork.
- Do NOT change any other vendored file or `main.ts`. Do NOT weaken any guardian check.

## User value
The security guardian that gates ALL untrusted input into the on-device evaluator/preview is now structurally
fail-closed (a Proxy can never be silently accepted) and the vendored copy no longer drifts from upstream — removing
a latent fail-open and an audit-trail divergence.
