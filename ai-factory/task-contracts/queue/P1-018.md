## Objective
A transactional capability `agent/capabilities/storage/` that stores a validated **storage layout
desired-state** (Btrfs subvolume set, §10) to a FIXED agent state path, applied atomically with rollback
— the proven nodeconfig (P1-007) pattern. A typed `Layout` is the set of subvolumes (role + path +
optional appId + quota). `Handle` reads the current layout; `Apply` validates a desired layout and writes
it via a single atomic commit point (temp + rename — nothing fallible after the rename), returning an
`Undo` that restores prior bytes. Integrate with the transaction engine (commit + rollback proven).
Implements `Validate()` for the transport pre-transaction gate (P1-008). Injected FS facade for tests.
- **Validate fail-closed** (mirror the §10 invariants the SDK P0-019 model enforces): require the full
  set of required storage roles (system-state, user-data, app-state, snapshots, local-backup-cache);
  an `app-state` subvolume MUST carry an appId, non-app roles MUST NOT; paths canonical+absolute; reject
  a layout missing `subvolumes` (absent ⇒ reject, not empty-default). No `os/exec`/real Btrfs.

## User value
The on-host storage desired-state (FR-014, §10) the controller manages — completes the storage stack
(SDK model P0-019 + this agent capability). Proves the pattern generalizes to storage.

## Non-goals
- No real Btrfs/mkfs/subvolume creation/LUKS (needs a privileged host — a later enforcement contract).
  Store + validate the typed layout only. No `os/exec`. No `cmd/agentd/main.go` edits (wiring is a follow-up).

## Dependencies

## Reviewer revision (round 2 — BLOCKING, from P1-018.review.md)
`quotaGiB` is a non-pointer `int64` with `omitempty` and validation allows `0`, so an explicit
`"quotaGiB":0` is accepted and normalized away as if absent. Quota is OPTIONAL, but when PRESENT it must
be a valid positive value. Use a pointer (`*int64`) to distinguish absent (nil ⇒ ok, no quota) from
present; reject an explicit `0` (and any ≤ 0). Add a regression: `"quotaGiB":0` ⇒ rejected; absent ⇒ ok;
positive ⇒ ok.
