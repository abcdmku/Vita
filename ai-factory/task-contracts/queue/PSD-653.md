## Objective
Implement the spec §10.3 **independent target backends** behind the existing `backup.policy` capability
(`agent/capabilities/backup/backup.go`). Today a `TargetRef` is opaque-ID-only — `normalizeTargets`
keeps just `target.ID` (`backup.go:361-380`) and nothing ever *writes* a backup to an independent
target. This contract adds fail-closed, deterministic **target writers** for the two independent target
kinds the spec calls out:
1. **attached-disk** — a local block/dir target the customer attaches to the node, and
2. **customer-selected object/SFTP** — a vendor-managed object-store / SFTP endpoint.

A write produces a **measured result**: the artifact bytes are written, then read back and
**integrity-verified by sha256 (readback digest == written digest)**, and the result is tagged with a
`protectionState` of `backup` (a true independent copy) vs `mirror` (a replica that is explicitly NOT a
backup). A mirror MUST NEVER be reported as a backup. Targets keep carrying their opaque `TargetRef.ID`
in the persisted policy; the new backend logic is keyed off a `kind` discriminator added to the target
ref and validated through the existing reference/secret rules — declarations stay secret-free.

Concretely:
- Add a `kind` discriminator to `TargetRef` (e.g. `attached-disk`, `object`, `sftp`, `mirror`) plus the
  minimal opaque descriptor fields each kind needs (all routed through `validateRef` so they are opaque,
  syntactically bounded, and reject inline key material — reuse `containsInlineSecretMaterial` /
  `validReferenceSyntax`; mirror the `backupRef` `format` in `schema/capabilities/backup.json` if a field
  is added there). Unknown `kind` REJECTS (fail-closed).
- Implement a deterministic `TargetBackend` interface with a `Write(ctx, artifact) (Result, error)` that
  for **attached-disk** writes the artifact atomically (reuse `internal/atomicfile`) under the
  target-described directory and verifies sha256 readback; for **object/SFTP** writes through an injected
  transport seam (NO real network — `allowed_network: false`; the seam is faked in tests) and verifies the
  returned digest equals the written digest, failing closed on mismatch/partial/short write.
- `Result` records `{ targetID, kind, protectionState (backup|mirror), bytesWritten, sha256, verified }`.
  A `mirror` target ALWAYS yields `protectionState: mirror` and is never counted toward backup coverage.
- Keep secrets out of declarations: any target ref/descriptor bearing inline key material, a private-key
  marker, a secret assignment, a seed phrase, or long hex/base64 (the existing `backup.json` SECRET
  scanner surface) is REJECTED before any write.
- **No key handling for vendor-managed targets.** Per spec §16, signing/recovery/TPM keys are
  **owner-held** and unavailable to dev agents; object/SFTP credentials are referenced by opaque handle
  only and resolved outside this code — this contract MUST NOT read, embed, marshal, or log key material,
  and MUST NOT touch `RecoveryKeyRef` semantics beyond what already exists.

Determinism: same inputs → byte-identical artifact + identical `Result` (no wall-clock, no RNG, no
ambient I/O beyond the injected fs/transport seams). Pure validation path stays I/O-free.

## User value
The node can write the customer's data to a **real independent copy** (an attached disk or a
customer-chosen object/SFTP target) and *prove* it landed via sha256 readback — the first end-to-end
"my data is actually backed up somewhere I control" guarantee of the §10.3 personal-data product —
while structurally refusing to pass a mirror off as a backup and keeping all secrets out of declarations.

## Non-goals
- NO real network I/O (`allowed_network: false`) — object/SFTP goes through a faked transport seam in
  tests; the live transport binding is a later slice.
- NO scheduler/retention execution, NO restore path, NO encryption/key derivation, NO `RecoveryKeyRef`
  changes — those stay owner-held (§16) and out of scope.
- Do NOT weaken or bypass the existing reference/secret validation; do NOT add remote imports, package
  lifecycle scripts, FFI, or new third-party deps.
- Do NOT introduce non-determinism (clocks, randomness, map-iteration-order in outputs).

## Acceptance
`acceptance_command` runs and PASSES:

```
go test ./agent/capabilities/backup/ -run 'TestTargetBackend|TestNormalizeTargets|TestTargetSecretRejected|TestMirrorNotReportedAsBackup' -count=1
```

The new/extended tests in `agent/capabilities/backup/` MUST cover, deterministically:
- **attached-disk write + integrity**: writing an artifact to an attached-disk target produces a
  verifiable artifact whose **sha256 readback == written digest** (`Result.verified == true`,
  `protectionState == backup`); a forced readback/digest mismatch (corrupt/short write via the fake fs)
  FAILS CLOSED (error, `verified == false`).
- **object/SFTP write + integrity** over the faked transport seam: digest-match verifies; a
  digest/partial-write mismatch FAILS CLOSED.
- **malformed / secret-bearing target ref REJECTS**: an unknown `kind`, a malformed opaque descriptor,
  and a descriptor carrying inline key material / secret assignment / long hex|base64 are each rejected
  before any write (no artifact produced).
- **mirror is never a backup**: a `mirror`-kind target yields `protectionState == mirror`, is excluded
  from backup coverage, and is never reported as a backup.

Verify independently: re-run the exact command above and read the diff — confirm writes go through
`internal/atomicfile`, all refs/descriptors route through `validateRef`, no key material is read/embedded,
and `protectionState` cannot be `backup` for a `mirror` target.

## Security/constraints
- **Fail-closed** everywhere: unknown kind, secret-bearing ref, unverifiable readback, short/partial
  write → reject/error, never a silent success. Capability-mediated; no ambient I/O (injected fs +
  transport seams only).
- **§16 owner-held keys**: signing/recovery/TPM keys and vendor credentials are owner-held and absent
  from dev agents; reference by opaque handle only — never read/embed/log key material.
- Secrets stay out of declarations (reuse the `backup.json` SECRET scanner surface;
  `containsInlineSecretMaterial`).
- Determinism: pure config/validation path no-I/O; same inputs → byte-identical artifact + `Result`.
- No remote imports; lockfile/go.sum unchanged-or-tidy; no package lifecycle scripts; no FFI/native deps.
