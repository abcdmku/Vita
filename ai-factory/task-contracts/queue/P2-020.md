## Objective
`previewNodeConfigChange(current, desired)` (controller/node-config): the TOP-LEVEL operator view that
validates current + desired `NodeConfig` (the P0-022 aggregate) and composes the EXISTING per-section
change-previews — `previewStorageChange` (P2-011), `previewNetworkChange` (P2-012), `previewBackupChange`
(P2-014) — into ONE unified `{ ok: true, sections: { storage?, network?, backup?, identity? }, summary } |
{ ok: false, rejections }`. For each section present in EITHER config, run that section's change-preview
(passing the section value or a typed "absent" sentinel). `summary` rolls up: sections added/removed/
changed, plus the security flags the section previews surface (`wideningInbound` from network,
`weakensRetention` from backup). Fail-closed: invalid either config ⇒ typed rejection (no diff, no throw);
a section without a dedicated preview (identity) is diffed structurally (present/added/removed).

## User value
The single "what does this whole-node config change do" view (FR-005/006) — composes every section diff +
surfaces the security-relevant flags (inbound widening, weakened backup retention) in one operator action.

## Non-goals
- No real apply, no agent call, no network. Compose the existing aggregate + section previews. Do NOT
  modify P0-022 or the section previews — import + compose them.

## Dependencies
P0-022 (node config aggregate), P2-011 (storage preview), P2-012 (network preview), P2-014 (backup preview). Merged.

## Acceptance tests
`acceptance_command` — `node-config-preview.test.ts`: two valid configs ⇒ a unified diff with the correct
per-section sub-diffs; an added/removed section ⇒ reflected in `summary`; a network change adding an
allow rule ⇒ `wideningInbound` surfaced; a backup change shortening retention ⇒ `weakensRetention`
surfaced; invalid current OR desired ⇒ typed rejection (no throw); hostile input ⇒ fail-closed. Orchestrator
also runs `npm run typecheck`.

## Performance & security constraints
Deterministic, no I/O/network. Fail-closed (compose validated previews; never throw). Surfaces the
section security flags faithfully. Strict TS (no `any`). R2 → reviewer-gated.
