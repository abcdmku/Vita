## Objective
Phase 5 (spec §21, data product arc "Export center"), export arc slice 1: let the node OWNER take their data
elsewhere as a **verifiable, content-addressed EXPORT BUNDLE**. The bundle aggregates the three authoritative
owner-data sources the node already exposes — granted **files** (P1-065 `/files` list+read), the **PDS
sync-state** (P1-042 / `pds.sync-state` via the read surface), and the **node config** (the `/state` capability
snapshot) — into one self-describing, integrity-checked archive that a third party can re-verify offline. The
bundle is produced through the SAME unprivileged-proposes / agentd-mediates boundary as every other on-device
operation: the UNPRIVILEGED TypeScript runtime composes the bundle bytes from data it can already read, but the
privileged Go `agentd` is the SOLE writer of the output file (via the existing `/files` write surface) AND the
sole authority that RE-VALIDATES the export request and RE-COMPUTES the bundle's content-address before
acknowledging it. The runtime never gets raw filesystem access and agentd never trusts runtime-supplied digests.

Concretely:

- **Deterministic, content-addressed bundle format (the data-product core), in `sdk/typescript/src/export-bundle.ts`.**
  A PURE (no-I/O) builder takes the three already-read inputs and emits the canonical bundle:
  - **Entries**: each included file (relPath, byte length, `sha256-<base64>` SRI-style digest of the CONTENT — reuse
    the SRI shape proven in `agent/capabilities/capsule` + `sriIntegrity`, NOT a bespoke hash string), plus a config
    entry (the `/state` snapshot, canonicalized) and a PDS entry (the sync-state record). Entries are SORTED by
    relPath with a fixed total order so the SAME inputs → BYTE-IDENTICAL manifest (determinism, spec §8.2 discipline).
  - **Bundle manifest** (`export-manifest.json`): `{ formatVersion, createdMarker?, entries: [{ path, kind, bytes,
    integrity }], rootDigest }` where `rootDigest = sha256-<base64>` over the canonical-JSON of the SORTED entry list
    (a Merkle-style root: changing ANY entry's content or path changes `rootDigest`). NO timestamps / no host-entropy
    in the hashed region (determinism); any non-deterministic provenance (a wall-clock createdAt) lives OUTSIDE the
    hashed `entries`+`rootDigest` region or is omitted this slice.
  - **NO SECRETS IN PLAINTEXT METADATA (security core):** the manifest carries only paths + sizes + digests + the
    config/PDS PUBLIC fields. It MUST NOT embed inline secret material — run the manifest's string fields through the
    agent's existing secret screen (`containsInlineSecretMaterial` family, reused via the manifest dialect / the
    `noInlineMaterial` substrate) and any field that would carry a key/seed/token is REJECTED (fail-closed), not
    silently included. File CONTENT bytes are exported as-is (the owner's own data), but the METADATA index stays
    secret-free. TEST data only — never commit/generate production key material (§16).

- **agentd export RE-VALIDATION + content-address verify, in `agent/capabilities/export/`.** agentd does NOT
  re-read every source itself this slice (the runtime composes the bytes from surfaces it is already granted), but it
  IS the trust boundary on the WRITE + the integrity claim:
  - `manifest.go` — a STRICT decoder (`decodeStrictJSON`/`DecodeJSONRequest`, reject duplicate keys per the AGENTS.md
    TCB-parser rule) + validator for the export-manifest shape: every entry's `integrity` is a well-formed
    `sha256-<base64>` (reuse `sriIntegrity`), `rootDigest` is well-formed, `path`s pass the SAME scope/segment
    rejection used by files (`ResolveWithinScope`-equivalent: no absolute/`..`/NUL/empty/`.`/`..` segments), and the
    manifest string fields pass the secret screen. A malformed/oversized/cyclic-shape/dup-key manifest → REJECTED
    before use (fail-closed, NEVER a panic/throw at the trust boundary).
  - `export.go` — `VerifyBundle(manifestBytes, lookup func(path)->bytes)`: RE-COMPUTES each entry digest from the
    actual content the bundle claims, RE-COMPUTES `rootDigest` from the sorted entries, and confirms they match the
    manifest's claimed digests. A bundle whose claimed digest does NOT match the recomputed content → REJECTED
    (`integrity_mismatch`). agentd acts ONLY from the re-validated manifest + recomputed bytes — never from a
    runtime-supplied digest taken on faith. A no-op/always-accept verifier MUST fail the suite.
  - The bundle OUTPUT file(s) are written ONLY through the EXISTING agentd `/files` write surface (P1-065) under a
    dedicated **export grant** (a read-write files grant scoped to `/var/lib/vita/files/<scope>/export` — agentd owns
    + provisions the dir, the runtime never mkdirs). NO new privileged write path is introduced: export reuses the
    files mediator. (If a thin `/export` route is needed to expose `VerifyBundle` as an RPC, add it to
    `server.go` alongside `/files`/`/state`; otherwise the verify runs inside the files write acknowledgement — the
    worker picks the minimal surface and DOCUMENTS the choice. Either way the privileged surface stays narrow and
    composes only from the re-validated manifest.)

- **Unprivileged on-device wiring** (`os/.../ts/vita/export-client.ts` + `main.ts`). Add a thin client that: (1) reads
  the inputs via the EXISTING surfaces — `readAgentStateSummary` (`/state`), the PDS read (`pds-read.ts` /
  `pds.sync-state`), and the files client `list`+`read` over a granted source folder; (2) builds the bundle with the
  pure `export-bundle.ts` builder; (3) WRITES `export-manifest.json` + the content blobs back through the files client
  `write` (agentd-mediated) into the export grant; (4) RE-READS the just-written manifest + at least one blob via the
  files client and RE-VERIFIES the `rootDigest`/entry digest against what was written (the round-trip integrity
  proof). The runtime keeps its AF_UNIX-only Deno sandbox (socket-path-scoped allow only, P1-035) — NO `--allow-read`
  /`--allow-write` for the data root. Then FORCE a fail-closed case (a manifest with a tampered/mismatched digest, OR
  a metadata field carrying inline secret material) and prove it is REJECTED.
  Markers (MEASURED — built from the real recomputed digests, NEVER synthesized):
  `VITA-EXPORT: entries=<n> bytes=<total> root=sha256-<short> verify=OK status=OK` (gated on the write→re-read→
  re-hash match — the recomputed rootDigest equals the written one); `VITA-EXPORT-REJECT: reason=<sanitized, e.g.
  integrity_mismatch | inline_secret_metadata | path_traversal | unknown_grant> status=OK`;
  `VITA-EXPORT-ERROR: status=FAILSAFE`. Keep ALL prior markers (VITA-TS → … → FILES → PDS → …).

## User value
The owner can take their data elsewhere — a core sovereignty promise of a PERSONAL node (spec §21 data product,
FR-015 portability). The export is a single, self-describing, content-addressed bundle that ANY third party can
re-verify offline (recompute the digests → confirm `rootDigest`), so the data's integrity is provable without
trusting the node that produced it. Because the bundle is produced through the unprivileged-proposes / agentd-verifies
boundary and carries NO secrets in its plaintext metadata, exporting cannot leak key material and cannot be forged by
a compromised runtime claiming a digest it did not actually produce. Deterministic output means two exports of the
same data are byte-identical — diffable, cacheable, reproducible.

## Non-goals
NO encryption / signing of the bundle (that rides the owner-held signing keys §16 + a later slice — this slice is
integrity/content-addressing, NOT confidentiality or authenticity-by-owner-key). NO IMPORT / restore-from-bundle
(a separate arc; P1-066 covers backup/restore of /var state). NO streaming/incremental or delta export, NO
compression (whole-file, within the size cap; a `.tar`/zstd container is a later slice — emit the manifest + blobs
as files in the export grant). NO selective/redacted export UI, NO scheduling, NO remote/network upload (local
agentd-mediated write only). NO controller UI. NO multi-user/household scoping. NO new transactional capability and
NO new privileged write path beyond reusing the P1-065 `/files` mediator. The runtime never receives a raw FS path or
`--allow-read`/`--allow-write` for the data root; agentd composes/verifies ONLY from the re-validated manifest +
recomputed bytes, never from a runtime-supplied digest on faith.

## Performance & security constraints
- **Unprivileged runtime, mediated FS + verified integrity (spec §3.4, §7.1):** the runtime composes bundle bytes
  from data it can already read, but agentd is the SOLE writer (via the P1-065 `/files` mediator) AND the sole
  authority that RE-COMPUTES + verifies the content-address. agentd acts ONLY from the re-validated manifest +
  recomputed bytes, NEVER from a runtime-supplied digest taken on faith.
- **No secrets in plaintext metadata:** the manifest index (paths/sizes/digests/config-PDS public fields) is screened
  by the agent secret scanner; any field that would carry inline key/seed/token material → REJECTED, not included.
  No keys/secrets — TEST data only; never commit/generate production key material (§16: signing/TPM/recovery/mesh
  keys are owner-held and unavailable to dev agents).
- **Deterministic (spec §8.2 discipline):** same inputs → byte-identical manifest + rootDigest; entries fixed-sorted;
  NO timestamps/host-entropy inside the hashed region. Prove with a build-twice equality test.
- **Content-addressed integrity:** `sha256-<base64>` per entry (reuse `sriIntegrity`) + a Merkle-style `rootDigest`
  over the sorted entries; tamper ANY content/path → rootDigest changes → REJECT on verify. A no-op verifier FAILS.
- **Fail-CLOSED everywhere:** integrity mismatch / inline-secret metadata / path traversal / unknown grant / oversize
  / malformed / dup-key → reject with a sanitized reason; default-deny. A guard over untrusted input MUST NOT throw
  (a throw at the trust boundary is a DoS — return a rejection); prove with a malformed/cyclic regression.
- **Size cap:** total bundle bytes + per-entry bytes bounded (reuse the P1-065 `MaxFileBytes`/`MaxRequestBodyBytes`
  constants; fix a total-bundle cap constant and reject over it with a typed error) so a single export cannot OOM
  agentd or fill /var unbounded.
- **Strict decode:** reject duplicate JSON keys before decoding; validate the FULL required manifest shape (absent ≠
  empty for optional fields). No remote imports in the TS builder/client; lockfiles mandatory; no package lifecycle
  scripts. R2 → reviewer gate (`npm run review` must APPROVE before merge, per the standing R2/R3/R4 gate).
