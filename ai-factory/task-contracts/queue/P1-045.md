## Objective
W4-S2 (per ADR-0009 + the wave-4 map): agentd FETCHES + verifies a capsule artifact by its SRI integrity before it
can be executed — so capsules need not be baked into the image. Implement `agent/storage/capsules/fetch.go`:
`FetchCapsule(ctx, ref, integrity) (localPath, error)` that (1) reads the artifact (a `file://` path OR a tar.zst
bundle from a LOCAL staging area — NO network registry auth yet, that's a later slice; the source is a local/loopback
artifact for this slice), (2) computes its hash and verifies it MATCHES the SRI `integrity` (sha256/384/512) BEFORE
extraction, (3) extracts atomically (temp dir → verify completeness → rename) into the capsule cache
`/var/lib/vita-agent/capsule-storage/<id>/<version>/`, root-owned. On SRI mismatch: log an audit event, return an
error, stage NOTHING (fail-closed). Wire it as a read-ish agentd op or a step the capsule path calls; emit
`VITA-CAPSULE-FETCH: id=<id> sri=<algo>-<short> verified=OK status=OK` (and `VITA-CAPSULE-FETCH-REJECT: reason=sri_mismatch`
on a tampered artifact; `VITA-CAPSULE-FETCH-ERROR: FAILSAFE`).

Concretely:
- **No network registry / no OCI** (deferred). Source = a local file/tar.zst artifact baked or staged into the image
  (a test bundle) — prove the FETCH + SRI-VERIFY + atomic-extract path, not remote pull.
- **SRI is the trust anchor**: verify the bytes match the CapsuleEntry `integrity` BEFORE extraction; tampered → reject,
  nothing staged. Reuse the SRI/integrity validation already in `agent/capabilities/capsule/capsule.go` if present.
- **TS side** (`main.ts`): propose a fetch of a baked test bundle (with a known-good SRI) → `VITA-CAPSULE-FETCH`; a
  forced-bad SRI → reject. Keep all prior markers.

## User value
The node can obtain capsule code by content-addressed integrity (not just baked) — the storage half of running real
capsules, with SRI as the supply-chain trust anchor (tampered artifacts refused).

## Non-goals
NO network registry pull / auth (later). NO OCI/WASM artifact formats (later — tar.zst/file only). NO execution change
(that's capsule.execute, done — this stages the artifact it would run). Fail-closed on any SRI/extract failure.

## Acceptance tests
`acceptance_command` — Go tests: SRI match → stages + returns the path; SRI MISMATCH → error, NOTHING staged
(fail-closed, audit logged); atomic extract (no partial dir on failure); path-traversal-safe extraction (a malicious
tar entry `../` is rejected). vet/build clean. Orchestrator host-verifies: boot, `VITA-CAPSULE-FETCH: … verified=OK`
on the serial + a `VITA-CAPSULE-FETCH-REJECT` for a tampered SRI; agentd up.

## Performance & security constraints
SRI verified BEFORE extraction; tampered → fail-closed, nothing staged. Path-traversal-safe tar extraction. Atomic
(temp→rename). Root-owned cache. No network. No keys. R3 (supply-chain trust anchor) → parallel-candidate + reviewer gate.
