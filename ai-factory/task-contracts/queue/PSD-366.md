## Objective
Ship **Mail (offline/local)** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), on the app-package SDK
foundation (PSD-361). Three artifacts, mirroring the flagship-package pattern:
1. **App package** under `apps/mail/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` —
   `id: "vita.app.mail"`, `version`, `sdkVersion: SDK_VERSION`, `entry: "index.html"`, MINIMAL `capabilityGrants`
   (NO network capability — offline/local mailbox only; declare an empty/minimal grant set so any send/sync attempt fails
   closed) and a `WebAppDescriptor` (`surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-mail" }`,
   `title:"Mail"`, `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/mail/index.html` — a static HTML/CSS mail surface (folder list + message list +
   reading pane), CSS-var tokens, no inline JS (behavior via the view-model / binder convention). Minimal; NOT the
   acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/mail-app.ts` — a PURE mailbox model over an
   injected **local mailbox port** (NO real network/IMAP/SMTP; the port supplies a deterministic in-tree mailbox of
   folders + messages; composing/sending is QUEUED to a local Outbox only — actual send is explicitly deferred and any
   network send attempt fails closed). Injected-port style, frozen `snapshot()`, discriminated-union results. State:
   folder list with active folder + unread counts, message list (sorted deterministically by date desc then id), selected
   message + body, compose draft. Actions: `selectFolder(id)`, `selectMessage(id)`, `markRead(id)`,
   `composeDraft(fields)`, `queueDraft()` (-> Outbox). All reads go through the injected mailbox port, **fail-closed if it
   is absent/denied**. NO real network/send, NO DOM/CSS, NO ambient I/O.

## User value
Mail becomes a swappable first-party package the dock/launcher lists + launches into its own WM window, with a real
testable mailbox model — proving the app-package pattern for a content+compose app while staying strictly OFFLINE +
fail-closed (compose queues to a local Outbox; no egress).

## Non-goals
- NO real network / IMAP / SMTP / send / sync (offline/local only — sends queue to Outbox; network send fails closed). NO
  DOM/CSS/CEF logic in the view-model; NO platform internals; NO new SDK ports beyond PSD-361 + existing.
- Do NOT grant Mail any network/privileged capability; it fails closed on anything not explicitly granted.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at `sdk/typescript/test/ui-kits/mail-app.test.ts`
cover the manifest (`defineAppPackage` accepts it; NO network grant; descriptor url === entry) and the view-model state
transitions (selectFolder updates active + list; deterministic message ordering; selectMessage loads body; markRead
decrements unread; composeDraft + queueDraft moves to Outbox; absent mailbox port fails closed; deterministic snapshot).
`npm run typecheck` is clean. Pure, headless, no network. (The exact test path exists only when the work lands — an empty
branch fails.)

## Security/constraints
- OFFLINE/LOCAL by construction: NO network capability granted; the mailbox is an injected pure port; compose queues
  locally; any network send/sync fails CLOSED. Pure/deterministic. `allowed_network:false`. No remote imports; lockfile;
  no lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).

## Allowed tools + network
Local filesystem + Node test runner + `npm run typecheck` only. `allowed_network: false`.
