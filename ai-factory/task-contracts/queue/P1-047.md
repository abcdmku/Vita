## Objective
W4-S4 (wave-4 map): after a capsule is running (capsule.execute, P1-044), agentd MONITORS its health per the
manifest `healthChecks` (http / tcp / lifecycle) and exposes the workload status in `/state`. Implement
`agent/internal/capsule-runtime/health.go`: `PollHealth(ctx, check) (status, error)` — http: GET/HEAD the target +
check the status code; tcp: dial the port; lifecycle: inspect the unit's active/exit state (`systemctl is-active` /
the unit substate). A background poller (per running capsule, with interval + jitter from the check spec) updates a
workload-status struct; extend `/state` to include `capsuleWorkloads: [{id, unit, status, health, restarts}]`.
Marker: `VITA-CAPSULE-HEALTH: id=<id> check=<type> status=OK` (+ `…-ERROR: FAILSAFE`). NO restart logic yet (detect +
report only; restart policy is a later slice).

Concretely:
- **Read-side mostly** (R2): polling + reporting; no new mutation beyond the existing capsule.execute. The poller is
  a background goroutine in agentd keyed to the running unit.
- **/state extension**: add the capsule-workload status array (alongside services/network/etc.), so the TS runtime
  (and operators) can read live capsule health via the existing `/state` read path.
- **TS side**: after capsule.execute, the runtime reads `/state` and emits `VITA-CAPSULE-HEALTH: … status=OK` for the
  running test capsule. Keep all prior markers.

## User value
The node knows whether its running apps are HEALTHY — the observability half of capsule execution, the basis for
restart policy + operator dashboards. Detect crashes/unhealthy workloads.

## Non-goals
NO restart/backoff logic yet (detect + report only — a later slice). NO new privileged mutation. NO OCI/WASM. Reuse
the existing /state read path + the running unit from capsule.execute.

error → unknown, not a crash). No keys. R2 (read + an existing-capability state extension) → reviewer-gated.
