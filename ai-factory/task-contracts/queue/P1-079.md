## Objective
Phase 4 (spec §21 app platform), multi-arch OCI slice: extend the P1-053 OCI image fetch so the pinned
`runtime.ociImageIndexes[].digest` may be a **multi-arch OCI image index (manifest list)** — agentd RESOLVES the
single child manifest that matches the NODE's platform (`linux/amd64` today; `arm64` is the forward case), VERIFIES the
selected child manifest's digest against the index descriptor before decoding it, then runs the EXISTING two-level
digest-verify + rootfs-assembly graph on the selected manifest unchanged. If the index contains NO child compatible
with the node platform, FAIL CLOSED (nothing staged). A pin that already points directly at a single image manifest
(the current P1-053 behavior) MUST keep working byte-for-byte — this slice only adds the index→child resolution step in
front of the proven path.

Concretely, in `agent/storage/capsules/oci_fetch.go` (REUSE the existing types/graph — do not fork them):

- **Distinguish index vs. image manifest at the pinned digest.** Today `verifyOCILayout` looks the pinned
  `imageDigest` up in `index.json` via `findManifestDescriptor` and expects it to BE an image-manifest descriptor.
  Generalize: the `oci-layout` `index.json` is the top descriptor list; the pinned digest now identifies EITHER (a) a
  child image-manifest descriptor in `index.json` (current single-arch path) OR (b) a separate **image-index blob**
  (`application/vnd.oci.image.index.v1+json` / `application/vnd.docker.distribution.manifest.list.v2+json`) stored in
  `blobs/sha256/<digest>` whose own `manifests[]` are the per-platform image manifests. Detect the index case by the
  descriptor/blob `mediaType` (image-index/manifest-list media types) — NOT by guessing; an unknown/ambiguous mediaType
  fails closed. The `ociIndex`, `ociDescriptor`, and `ociPlatform` structs already model exactly this (`oci_fetch.go`
  ~63-97); reuse them.

- **Platform selection (the new logic) — `selectOCIPlatformManifest(index ociIndex, node nodePlatform)`.** Pure
  function. The node platform is `os=linux` + arch from `runtime.GOARCH` (`amd64` today; `arm64` accepted for the
  forward path) — define a small `nodeOCIPlatform()` that maps `runtime.GOARCH`→the OCI arch token (`amd64`/`arm64`)
  and pins `os=linux`; do NOT hardcode `amd64` as a literal in the selection logic (the slice must already be correct
  on an arm64 build). Iterate the index `manifests[]`, SKIP any descriptor whose `mediaType` is not an image-manifest
  media type (e.g. attestation/SBOM referrers carry a non-manifest `artifactType`/`mediaType` — they MUST NOT be
  selectable), and pick the FIRST whose `Platform.OS == node.os && Platform.Architecture == node.arch` (variant, when
  present on BOTH, must also match; a node with no required variant accepts a child with no variant). EXACTLY-zero
  matches → `ErrOCIArchUnsupported`, fail closed. Selection is deterministic (first match in index order); a malformed
  child descriptor (missing/empty digest, missing platform, negative size) is REJECTED, not silently skipped past a
  later match in a way that could be gamed — a child with a manifest mediaType but absent/garbage platform fails closed.

- **Verify the selected child, THEN reuse the existing graph.** Read the selected child via `readVerifiedBlob` (its
  sha256 content digest MUST equal the index descriptor's pinned digest — same constant-time compare already used) and
  feed that verified manifest into the SAME `verifyOCImanifest`/layer-and-config digest-verify + `applyOCILayer`
  assembly P1-053 already proves. Do NOT weaken or re-roll the digest checks. The selected child's digest becomes the
  resolved image digest reported in `OCIFetchResult.ImageDigest` and the metadata (so idempotent re-fetch still keys on
  the concrete resolved manifest, not the index).

- **Markers.** Extend the success marker with the resolved arch:
  `VITA-CAPSULE-OCI-FETCH: id=<id> image-digest=<algo>-<short> arch=<os>/<arch> layers=<N> verified=OK status=OK`
  (the existing tokens preserved; `arch=` ADDED). New fail-closed reject reason:
  `VITA-CAPSULE-OCI-FETCH-REJECT: reason=arch_unsupported status=OK` (the pinned index has no node-compatible child).
  Keep every existing reason (`sri_mismatch|digest_mismatch|whiteout|bomb|traversal`) and the
  `…-FETCH-ERROR: status=FAILSAFE` path. ALL prior markers in `main.ts` stay.

- **Bake a multi-arch test image for the boot.** Add an OCI-layout artifact whose pinned digest is an image INDEX with
  (at least) a `linux/amd64` child and a `linux/arm64` child (only the amd64 child's blobs need a real tiny rootfs;
  the arm64 child may reference its own minimal manifest/blobs) plus its SRI, under `capsule-bundles/`. Wire a
  `CAPSULE_OCI_ARCH_FETCH_PLAN` in `main.ts` that pins the INDEX digest and proves agentd resolves the amd64 child on
  the x86_64 node, emitting `arch=linux/amd64 verified=OK`. Also bake a digest-valid index with ONLY a non-amd64 child
  to force the `arch_unsupported` reject on boot.

## User value
The node can consume the SAME multi-arch container images the rest of the ecosystem ships (a single pinned image-index
ref that resolves to amd64 today and arm64 on future hardware) instead of requiring a per-arch hand-pinned manifest —
the realistic shape of `runtime.ociImageIndexes[]` (`storage/capsules/src/capsule.ts:72` already models
`platforms?: RuntimePlatform[]` with `architecture: "x86_64" | "arm64"`). It does so without loosening the supply-chain
trust graph: the index is just one more digest-verified hop in front of the proven P1-053 manifest→config→layer verify,
and an image with no compatible architecture fails closed rather than running the wrong binary.

## Non-goals
- NO registry/network pull (still local `oci-layout` artifact only, P1-053 contract; resolution is over the LOCAL
  index blob). NO crun/runc, NO running the rootfs (that is the launcher path).
- NO `arm64` HOST build/CI in this slice — the selection logic must be arch-correct (driven by `runtime.GOARCH`, arm64
  accepted) but the boot proof + acceptance run on the x86_64 host (Borg51); an actual arm64 boot is future hardware.
- NO platform `variant` fuzzy/closest-match or feature-list negotiation, NO `os.version`/`os.features` matching, NO
  "best fit" ranking — exact `os`+`arch` (+ exact variant when both present), first match, else fail closed. NO fallback
  to an incompatible arch ever.
- NO change to the layer-assembly, whiteout, caps, or SRI logic from P1-053 (the index hop sits IN FRONT of it). NO new
  manifest/TS-schema field (the `OciImageIndexDescriptor.digest` + `platforms` already exist).
- NO selecting attestation/SBOM/referrer descriptors as a runnable image (mediaType-gated out).

## Acceptance tests

per the verification-pipeline lesson) — Go tests prove:
- **Selection (pure-function tests):** `selectOCIPlatformManifest` returns the `linux/amd64` child from an index that
  has amd64 + arm64 + a non-manifest (attestation) descriptor; returns `ErrOCIArchUnsupported` when the only children
  are non-amd64 (e.g. arm64-only on an amd64 node — drive it by injecting the node platform, not the real GOARCH, so
  the test is host-independent); REJECTS a child with a manifest mediaType but missing/empty platform; never selects a
  non-image-manifest mediaType (attestation/SBOM referrer) even if its `platform` happens to match; first-match is
  deterministic. A no-op resolver that returns the first descriptor regardless of platform MUST FAIL these.
- **End-to-end via `FetchOCIImageFor`:** a multi-arch image-INDEX artifact (pinned digest = the index blob) → resolves
  the amd64 child, assembles its rootfs, `OCIFetchResult.ImageDigest` == the SELECTED child manifest digest, the
  marker carries `arch=linux/amd64`; the index→child digest hop is content-verified (a TAMPERED child manifest whose
  bytes don't match the index-pinned digest → `digest_mismatch`, nothing staged); an index with ONLY an arm64 child on
  an amd64 node → `arch_unsupported`, nothing staged.
- **No regression:** the EXISTING single-image-manifest pin (P1-053's `newOCILayoutFixture` direct-manifest case) still
  assembles unchanged and its marker still reports `arch=linux/amd64` (resolved from the child's own platform or the
  config arch). All P1-053 fail-closed tests (tampered blob, digest-mismatch, bomb, traversal, whiteout) stay green.
- `node tools/build/go-in-docker.mjs --dir agent vet ./...` clean; build clean.

## Performance & security constraints
- **Security model (encode it):** the TypeScript runtime is UNPRIVILEGED and only PROPOSES the fetch (it passes the
  manifest-pinned index digest, never an image it picks); ALL privileged resolution + staging happens in the narrow Go
  agentd, RE-VALIDATED from the re-decoded local index/manifest/config blobs — never from raw runtime text. agentd
  composes the selection from the verified index + its OWN node platform (`runtime.GOARCH`), never from a
  runtime-supplied platform.
- **Fail-CLOSED everywhere:** no compatible arch / ambiguous-or-unknown index mediaType / malformed child descriptor /
  child digest mismatch / any decode error → reject with a sanitized reason, stage NOTHING. A guard over the untrusted
  index MUST NOT throw/panic at the trust boundary (return a rejection) — prove with a malformed/duplicate-key index
  regression. NEVER fall back to an incompatible architecture.
- **Digest graph unchanged & not weakened:** the index→child hop is a full constant-time sha256 content-digest verify
  (reuse `readVerifiedBlob`); the selected manifest then runs the unchanged P1-053 two-level verify + capped/
  traversal-safe/whiteout-safe assembly. The index adds a hop, it does not relax a check.
- **Determinism:** same index + same node platform ⇒ same selected child (first-match in index order). Strict decode
  (dup-key rejection via the existing `decodeOCIJSON`), absent≠empty for optional `platform`/`variant`.
- **No keys/secrets** (§16): TEST OCI artifacts only; never commit/generate production signing/TPM/recovery/mesh key
  material. No remote imports in any prod artifact; lockfiles mandatory; no package lifecycle scripts. R2 → reviewer
  gate (`npm run review` must APPROVE before merge, per the standing R2/R3/R4 gate).
