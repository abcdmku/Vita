## Objective
Add a **sanitized-diagnostics** capability (spec Phase-5 "Sanitized diagnostics" personal-data-product
surface) under a NEW Go package `agent/capabilities/diagnostics`. It assembles a deterministic
diagnostics bundle from already-available, non-privileged signals — storage health
(`agent/capabilities/storage/storage.go`), audit/lifecycle summary fields, and node config summary —
and runs the established inline-secret SCANNER over **every field of the assembled bundle** before
emitting it, so NO secret, key-reference value, owner credential, seed/recovery phrase, or inline key
material can leak into a diagnostics export.

- Build the bundle as a pure function: `Build(in Inputs) (Bundle, error)` — no I/O, no clock, no
  randomness; same inputs → byte-identical JSON (sort keys, stable ordering of any slices/maps).
- Port the secret scanner exactly as the export package already does it
  (`agent/capabilities/export/manifest.go:571` `containsInlineSecretMaterial` + the regex set at
  `manifest.go:563-568`: control chars, `-----BEGIN`, private-key/age-secret-key/xprv/seed/mnemonic/
  recovery-phrase, secret-assignment `key:`/`=`, 12–24 seed words, long hex, long base64). Copy the
  predicate into this package as an unexported func (each capability keeps its own copy — backup,
  identity, and export each have one; do NOT add a new shared export or cross-import another
  capability's internals).
- **Fail-closed redaction:** walk every string field (and string map keys/values) of the assembled
  bundle; if `containsInlineSecretMaterial` matches a field, that field is replaced with a fixed
  redaction sentinel (e.g. `"[REDACTED]"`) rather than emitted — the bundle is ALWAYS emittable, but
  a leaking field never survives. The scan runs over the *final* serialized bundle so nothing slips
  past via a field added later.
- Put the code under `agent/capabilities/diagnostics/diagnostics.go` and tests under
  `agent/capabilities/diagnostics/diagnostics_test.go` (package `diagnostics`, table-driven).

## User value
Lets the owner (and on-device control plane) produce a shareable diagnostics bundle for
troubleshooting — health/audit/config at a glance — with a hard guarantee, enforced by the same
scanner that gates the backup/identity/export paths, that it carries ZERO secret material. This is
the safe-to-export complement to the privileged data surfaces.

## Non-goals
- NO new transport/agentd wiring, RPC op, or registry entry (this slice is the pure bundle builder +
  scanner only; wiring is a follow-up). NO real I/O — health/audit/config arrive as injected `Inputs`.
- Do NOT export a shared scanner or import another capability package's unexported helpers — copy the
  predicate locally (matches the established per-capability pattern).
- NO new regexes / weakening of the ported scanner. NO networking. NO secrets in fixtures committed
  in clear beyond the adversarial test corpus (which is the point of the test).

## Acceptance
`acceptance_command` passes. Tests named `TestDiagnostics*` must, deterministically and offline,
prove:
1. A happy-path bundle includes the health, audit-summary, and config-summary sections.
2. `Build` is deterministic: building twice from identical `Inputs` yields byte-identical JSON.
3. **Adversarial corpus, ZERO leaks:** seed every scannable field in turn with hostile values — an
   age secret key (`AGE-SECRET-KEY-1…`), an OpenSSH private key header (`-----BEGIN OPENSSH PRIVATE
   KEY-----`), a 12+/24-word seed/recovery phrase, an `api_key=…` / `password:` assignment, a long
   hex blob, a long base64 blob, and an owner-credential-looking string — then scan the final
   serialized bundle and assert `containsInlineSecretMaterial` finds ZERO matches across the whole
   emitted bundle, and that each seeded field came out as the redaction sentinel rather than the raw
   secret.

## Security/constraints
- Pure/deterministic, no ambient I/O (spec §8.2). Fail-closed: redact rather than emit on any scanner
  hit. The scanner is the release-blocking control here — do not weaken it. No remote imports;
  lockfile/go.mod unchanged structurally; no lifecycle scripts.
- This bundle is explicitly the NON-privileged surface: it must never read identity/backup/owner key
  material directly — only the injected health/audit/config summaries, all of which pass through the
  scanner before emission.

## Definition of done
- `agent/capabilities/diagnostics/diagnostics.go` (pure `Build` + local secret scanner + redaction
  walk) and `agent/capabilities/diagnostics/diagnostics_test.go` (`TestDiagnostics*`, adversarial
  corpus, determinism), `go test ./agent/capabilities/diagnostics/ -run 'TestDiagnostics' -count=1`
  green. R1.
