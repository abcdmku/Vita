## Objective
Wire the headless application-switcher view-model (PSD-389, `ui_kits/desktop/viewmodels/app-switcher.ts`:
`begin()`/`cycleForward()`/`cycleBack()`/`commit()`/`cancel()`) to a **hydrated overlay** and to the
existing **global keyboard runtime** so a single reserved chord (default `Super+Tab`, i.e. `Meta+Tab`)
drives a whole switch session end to end. This is the *anchors/runtime* layer — the same per-screen
hydration binding pattern as `ui_kits/desktop/runtime/shortcuts-binding.ts` and the hydrate/dispose
lifecycle of `ui_kits/desktop/runtime/hydrate.ts` — NOT new VM logic and NOT new visual design.
- Add `ui_kits/desktop/runtime/app-switcher-binding.ts` that attaches a delegated keyboard listener
  pair (`keydown` + `keyup`) to an injected overlay root and translates raw key events into switcher
  VM actions, mirroring the single-delegated-listener + idempotent-`dispose()` discipline of
  `createShortcutsBinding` (one `addEventListener` per type on the root; `removeEventListener` on
  dispose; inert if `addEventListener` throws).
- **Chord semantics (key-down):** when the activation chord matches (canonicalized exactly like
  `viewmodels/shortcuts.ts` `normalizeShortcutChord` — so `Super+Tab`, `Meta+Tab`, and `meta + tab`
  collapse to one form; default activation chord is configurable via options, default `Meta+Tab`):
  the FIRST matching keydown with no active session calls `begin()` and shows the overlay; each
  REPEAT of the chord while the session is live calls `cycleForward()` (and the shift-variant, e.g.
  `Meta+Shift+Tab`, calls `cycleBack()`) to advance the highlight. `Escape` while a session is live
  calls `cancel()` and hides the overlay.
- **Commit semantics (key-release):** when the held modifier that anchors the chord is released
  (i.e. a `keyup` of the activation modifier — `Meta`/`Super` for the default chord) AND a session is
  live, call `commit()`, hide the overlay, and surface the switcher VM's focus intent through the same
  injected sink the VM emits to. Releasing with no active session is a no-op.
- **Overlay rendering binding:** the binding owns NO CSS/DOM rendering itself — it reflects switcher
  VM state to the overlay through an injected, pure **overlay presenter** port (e.g.
  `show(entries, highlightedId)`, `update(highlightedId)`, `hide()`), exactly the way
  `shortcuts-binding.ts` reflects the active binding through `onActiveBinding` rather than mutating the
  DOM. The presenter receives the deterministic window list + highlighted window id from the switcher
  VM snapshot so the rendered overlay (the design of record) lists windows with the candidate
  highlighted.
- **Inert without a bridge (fail-closed):** with no granted WM/host bridge the switcher VM fails
  closed (per PSD-389) and `begin()`/`commit()` produce an `ok:false` that is routed to an injected
  error sink (never thrown, never swallowed), the overlay is never shown, and NO focus intent is
  emitted — same posture as `shortcuts-binding.ts` routing a fail-closed dispatch result to `onError`.
- Construct the switcher VM exactly as PSD-389 exposes it (inject its WM port; do not re-implement it)
  and import the SDK exactly as the other runtime modules do
  (`../../../sdk/typescript/src/desktop-sdk/index.ts`), using ONLY public exports + the existing
  runtime/view-model modules (`viewmodels/app-switcher.ts`, `viewmodels/shortcuts.ts`'s
  `normalizeShortcutChord`, the `VitaElement`/`VitaEventLike` DOM-stub surface from `runtime/binder.ts`).
  Mirror the `Object.freeze` + ok/error discipline of the surrounding runtime.

## User value
Turns the headless Cmd/Alt-Tab switcher (PSD-389) into a working desktop gesture: pressing and holding
`Super+Tab` pops the app-switcher overlay, repeating it cycles the highlight, and releasing the
modifier commits focus to the highlighted window — the runtime glue that makes the rendered switcher
overlay (hydrated like every other screen) come alive on real keyboard input.

## Non-goals
- NO new VM logic (consume PSD-389's `begin/cycle/commit/cancel`; do not re-implement MRU/focus).
- NO DOM/CSS/rendering/CEF and NO new visual design — the overlay HTML and its presenter are the
  design of record; this binding only drives a pure injected presenter port.
- NO ambient I/O: no real `window`/`document`, no `Date.now`, no global registration of the chord
  beyond the injected root's delegated listeners (the reserved-chord *policy* lives in
  `viewmodels/reserved-chords.ts` and is out of scope here).
- Do NOT modify `shortcuts-binding.ts` or the production `bootstrapDesktop` boot path — this module is
  additive/composable.

## Acceptance
`acceptance_command` passes. Deterministic unit tests against a fake switcher VM (or PSD-389's real VM
fed fake WM ports), a fake overlay-presenter port, a fake error sink, and a `VitaElement`/`VitaEventLike`
keyboard stub prove:
(1) activation-chord keydown with no live session calls `begin()` and the presenter's `show(...)` is
invoked with the VM's window list + highlighted id;
(2) repeat activation-chord keydown advances the highlight via `cycleForward()` and the presenter is
`update(...)`d; the shift-variant calls `cycleBack()`;
(3) releasing the anchor modifier (`keyup`) while a session is live calls `commit()`, hides the overlay,
and emits exactly one focus intent through the injected sink for the highlighted window;
(4) `Escape` during a live session calls `cancel()` and hides the overlay with NO focus intent;
(5) inert-without-bridge: a fail-closed VM result routes to the error sink, the overlay is never shown,
and no focus intent is emitted;
(6) `dispose()` is idempotent and removes both delegated listeners (second call no-ops); a root whose
`addEventListener` throws yields an inert, disposed binding.
Typecheck clean; pure and headless. The exact (non-glob) test path means an empty branch fails.

## Security/constraints
- Injected ports/roots only (no ambient I/O, no real DOM, no document scan); capability-mediated,
  fail-closed (no bridge -> no overlay, no intent); pure/deterministic (same key sequence + VM ->
  same presenter calls + same intents). Intrinsic-safe event reads (one read per field) as in
  `shortcuts-binding.ts`. No remote imports; lockfile mandatory; no package lifecycle scripts; no
  FFI/native addons. `allowed_network: false`.
