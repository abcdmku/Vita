## Objective
A compositor-managed, visible software pointer for the flagship desktop: a small RGBA **cursor surface** the
routing core (PSD-300) keeps positioned at the accumulated pointer coordinate, composited **top-most every frame**
WITHOUT a per-move full re-upload of the desktop/wallpaper surface. This reuses the existing surface machinery in
`packages/compositor-core/src/lib.rs` — it does NOT invent a new texture path.
1. **Cursor as a buffer surface.** Register the cursor exactly once via the existing
   `Compositor::register_buffer_surface` (lib.rs:461) from a **baked offline RGBA asset** (a small bitmap, e.g.
   24x24, compiled-in `const`/`include_bytes!` — NO runtime decode, NO network, NO file I/O). Give it a stable id
   (e.g. `cursor.pointer`) and a z_index strictly greater than every desktop/window/panel placement so it is
   always top-most (mirror the z ordering in `desktop_demo_surfaces` lib.rs:1032 where the max is 41).
2. **Move = reposition only, no re-upload.** Moving the cursor MUST go through `Compositor::update_placements`
   (lib.rs:521) changing only the cursor `Placement`'s x/y — it MUST NOT call `update_buffer_surface` on the
   wallpaper/desktop or re-create any texture. Verify via `source_repaint_count()` (lib.rs:664): a cursor move
   leaves the repaint count unchanged (the existing `reposition_no_repaint` invariant). The damage report MUST
   cover the old and new cursor rects only (same shape as the move damage in `run_reposition_self_test`).
3. **Clamp to output.** The routed pointer coordinate is clamped so the cursor hotspot stays within
   `[0, output_width) x [0, output_height)` before becoming the placement x/y (the recording backend already
   clips off-output pixels in `draw_recording_placement` lib.rs:1863 — clamp the placement origin too so the
   glyph never fully leaves the visible output). Off-output inputs fail-closed to the clamped edge, never panic.
4. **Boot marker.** Add a small self-test entry point (mirror `run_reposition_self_test` lib.rs:780, exposed the
   same way the other self-tests are) that registers the cursor top-most, routes a pointer move, composites, and
   reads back the output to confirm the cursor glyph landed at the injected (clamped) position. Emit to serial:
   `VITA-CURSOR: present=ok status=OK` on success, `VITA-CURSOR: present=ok status=FAILSAFE reason=...` otherwise,
   so the orchestrator can confirm it on the VMware GPU readback.

## User value
The desktop gets a real, visible pointer that tracks input — the missing piece between PSD-300's pointer routing
and a usable on-screen cursor — built on the proven buffer-surface + placement paths so it costs no extra
per-frame upload of the desktop.

## Non-goals
- NO new cursor THEMES/animation/blinking, NO hardware-cursor plane (software composite only here), NO CEF/web
  engine, NO DOM/CSS. Do NOT add runtime image decoding or asset loading — the bitmap is baked in. Do NOT touch
  the production KMS present path beyond adding the top-most cursor placement. Do NOT re-implement pointer
  accumulation (that is PSD-300) — consume the routed coordinate.

## Acceptance
`acceptance_command` passes: `npm run typecheck` clean AND the compositor crate's cursor unit tests pass in the
pinned rust container (`cargo test --manifest-path packages/compositor-core/Cargo.toml --locked cursor` selects
the new `cursor*` tests by name — an empty branch with no such tests fails, since `cargo test <filter>` with a
missing module errors / runs zero of the required cases). Tests MUST cover, deterministically against the existing
`RecordingBackend`: (a) cursor registered top-most (highest z_index, composited above all desktop surfaces);
(b) a routed move repositions the cursor with `source_repaint_count()` unchanged and damage = old∪new cursor
rects; (c) the cursor glyph is present in the output readback at the injected coordinate; (d) an off-output
coordinate is clamped to the edge fail-closed (no panic). INDEPENDENT (orchestrator): rust-in-docker `cargo
build --release` + `cargo test` clean, then GPU-boot the cursor self-test on the VMware 3D target and confirm
`VITA-CURSOR: present=ok status=OK` plus the cursor glyph visible in the readback PNG.

## Security/constraints
- Baked-in asset only (no ambient I/O, no network, no runtime decode). Fail-closed on out-of-range coordinates
  (clamp, never panic) and on missing/invalid surface (reuse the existing `CompositorError` variants). Keep the
  compositor crate SELF-CONSISTENT — every called fn must exist/compile (the worker is on Windows so
  `npm run typecheck` does NOT catch Rust errors; the rust-in-docker floor is authoritative). No remote imports;
  `--locked` crates; lockfile mandatory; no lifecycle scripts. Verification/desktop substrate, deterministic.

## Definition of done
- A baked cursor buffer surface registered top-most + a routed-move reposition path (no desktop re-upload) +
  output-clamping, with deterministic cursor unit tests (a–d above) green in rust-in-docker, plus a boot
  self-test emitting `VITA-CURSOR: present=ok status=OK|FAILSAFE reason=...`. Orchestrator GPU-boots it on
  VMware and confirms the marker + visible glyph honestly. R1 — orchestrator reviews + integrates.
