## Objective
Author the `services` capability manifest (the cap is `agent/capabilities/services`, op name `services.set` —
verify the exact `Name`), proven manifest≡agent. Uses EXISTING dialect primitives only (object + array +
`systemdUnitName` (P9-012) + boolean) — NO dialect change.
- **`schema/capabilities/services.json` = the full request** `{ desired: { object: { services: array of
  object { name: string `systemdUnitName`; enabled: boolean (required) } } } }`. Match the agent
  `services` validator EXACTLY (read `agent/capabilities/services/services.go`): the `services` pointer-slice
  presence (absent ⇒ reject; explicit empty `[]` ⇒ accept — model with the array's required/min rules as the
  agent does), `enabled` explicit presence. **Match EXACTLY — neither stricter nor looser** (AGENTS.md): do
  NOT add `noInlineSecrets`/length/charset the agent's `validServiceName` doesn't have; `systemdUnitName`
  already encodes its rule.
- **CRITICAL — duplicate handling (round-1 BLOCKING, confirmed): the agent dedups by `name` ONLY.**
  `normalizeConfig` builds `seen := map[string]int` keyed on `entry.Name` and REJECTS any repeated name
  REGARDLESS of `enabled` (pinned by `services_test.go` "duplicate service name": `ssh.service,true` +
  `ssh.service,false` ⇒ reject). The array `uniqueItems:true` does NOT express this — `uniqueValueKey` hashes
  the WHOLE object `{name,enabled}`, so `{ssh.service,true}` and `{ssh.service,false}` hash DISTINCT ⇒ the
  manifest ACCEPTS while the agent REJECTS = preview≠apply. **FIX (AUTHORIZED dialect extension):** add a
  per-array `uniqueBy: ["name"]` option to the array FieldSchema in BOTH planes (`validateArrayField` in
  `sdk/typescript/src/capability-manifest.ts` ~:1150 + `agent/internal/capmanifest/capmanifest.go` ~:820 —
  key `seen` on `uniqueValueKey` of ONLY the listed sub-field(s)), use it on `services` (dedup by `name`),
  and add the REVEALING corpus vector `{"desired":{"services":[{"name":"ssh.service","enabled":true},
  {"name":"ssh.service","enabled":false}]}}` ⇒ EXPECT REJECT (it will fail the Go parity assertion until
  manifest≡agent). Do NOT loosen the agent.
- **Conformance ≡ the agent via the real entrypoint**: `schema/capabilities/conformance/services.json` (≥ 15
  full-request `{"desired":{…}}` vectors) run by BOTH the TS manifest validator AND `transport.DecodeJSONRequest
  [services.ApplyRequest]` + `Validate()`; they MUST agree (valid; bad unit name; absent enabled; duplicate
  name; absent vs empty services; unknown field; dup JSON key). The corpus encodes the AGENT's accept/reject.
- **Do NOT** edit the codegen/registry/evaluator or `agent/capabilities` here — the orchestrator regenerates
  the registry + wires evaluator coverage after merge (so this migration is disjoint + parallel-safe).
