## Objective
Build the **skeleton of the privileged Go system agent** (spec §7.1 trusted computing base, §19
`agent/`, §25 Week 2 "Go agent health endpoint", §21 Phase 1 "Local status endpoint"). This is the
narrow privileged core — R3, the highest-scrutiny component. Establish the SHAPE correctly; real
host operations come later behind `//go:build linux` build tags.

Provide:
1. `agent/go.mod` — `module github.com/vita/agent`, `go 1.26`. Standard library only (no deps).
2. **Capability registry** (`agent/capabilities/registry.go`): a `Capability` interface with a typed
   `Name() string` and `Handle(ctx, req TypedRequest) (TypedResponse, error)` over **typed** request/
   response values (NOT arbitrary strings/commands). A `Registry` holds a CLOSED set of registered
   capabilities and a `Dispatch(name, req)` that routes to the named capability and **rejects unknown/
   unregistered names with a typed error (fail-closed)**. There is NO path that runs a shell,
   `os/exec`, or evaluates arbitrary/caller-controlled commands — adding one is a hard failure
   (spec §3.4, §7.1: "rejects arbitrary commands").
3. **Status/health** (`agent/status/status.go`): a `Status` struct (agent version, start time / uptime,
   list of registered capability names, healthy bool) and an `http.Handler` serving `GET /healthz` →
   JSON status (read-only; no mutation; no secrets). Bind logic is testable without opening a socket
   (construct the handler + use `httptest`).
4. `agent/cmd/agentd/main.go` — minimal daemon entry that builds a `Registry` (with zero or a couple
   of inert example capabilities), wires the status handler, and would listen on a LOCAL endpoint
   (loopback/unix socket). Keep `main` thin; logic lives in the tested packages.

## User value
The agent is the only component allowed to perform host operations; its narrowness IS the security
model (spec §3.4, §4, §7.1). A correct skeleton (closed capability set, fail-closed dispatch, no
arbitrary execution, read-only health) anchors everything built on top.

## Non-goals
- No real privileged operations (storage/network/update/identity impls) — interfaces/stubs only.
- No RPC/Connect transport yet; no auth; no actual socket server in tests.
- No `os/exec`, no shell, no FFI, no arbitrary command surface — ever.

## Dependencies
None (first Go contract).

## Acceptance tests
`acceptance_command` runs `go test ./...` in the `golang:1.26` Linux container. Also run
`node tools/build/go-in-docker.mjs --dir agent vet ./...` clean. Tests must prove:
1. `Registry.Dispatch` routes to a registered capability and returns its typed response.
2. Dispatching an **unknown/unregistered** capability name returns a typed error (fail-closed) — no
   panic, no execution.
3. `GET /healthz` returns 200 + JSON status listing the registered capability names and `healthy:true`,
   via `httptest` (no real socket). No secrets in the response.

## Performance & security constraints
TCB component. NO shell / `os/exec` of arbitrary input / eval / FFI. Closed typed capability set;
unknown ⇒ reject. `go vet` clean. Deterministic tests. R3 → reviewer-gated, extra scrutiny on the
privileged surface (the reviewer must find no arbitrary-execution path).

## Hardware profiles

later behind build tags).
