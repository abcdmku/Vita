## Objective
Fix two findings the independent reviewer raised against the merged SDK (see
`ai-factory/task-contracts/P0-003.review.md`). The SDK currently has **two divergent accelerator
models**: `capabilities.ts` (the real one — typed refusal + mandatory CPU fallback) and
`define-system.ts` (P0-002's looser `AcceleratorKind`/`AcceleratorSelection`). Unify them:

1. **Wire the real model into the authoring surface.** `define-system.ts` must consume the
   `AcceleratorCapability`, `DeviceSnapshot`, `bestAvailable`, `AcceleratorSelection`, and
   `AcceleratorRefusal` from `capabilities.ts` (single source of truth). `device.ai.bestAvailable`
   used in `defineSystem` authors (spec §8.3) must support `requireFallback: "cpu" | false` and be
   able to return the typed refusal. `AppOptions.accelerator` must accept the unified selection
   type. Remove the duplicate `AcceleratorKind`/`AcceleratorSelection` island in `define-system.ts`.
2. **Close the readonly leak.** `AcceleratorSelection.selected` and `AcceleratorRefusal.available`
   must be typed read-only (e.g. `DeepReadonly<AcceleratorCapability>`), and the returned values must
   not allow mutating the source snapshot (return frozen/cloned values as needed). The immutable
   snapshot (spec §8.2) must stay immutable through the selection result.

## User value
Capability-based placement with guaranteed CPU fallback (spec §3.9, §14, FR-022) must be enforced at
the surface users actually author, not in a parallel island. Type safety and snapshot immutability
are core to the deterministic plan model.

## Non-goals
- No new accelerator kinds; no runtime hardware probing; no Go-agent work.
- Don't change the spec §8.3 example's authored shape (it must still evaluate).

## Dependencies
P0-002 (`define-system.ts`), P0-003 (`capabilities.ts`). Both merged.

## Acceptance tests
`acceptance_command` — `sdk/typescript/test/accelerators.test.ts` must prove:
1. A `defineSystem` author calling `device.ai.bestAvailable({ prefer:[...], requireFallback:false })`
   with no satisfying accelerator yields the **typed refusal** (not an invalid device).
2. With `requireFallback:"cpu"`, the CPU fallback is selected.
3. The selection result is read-only: attempting to mutate `result.selected` does not alter the
   source snapshot (frozen → throws, or type-level readonly enforced and value cloned).
Additionally, the pre-existing `capabilities.test.ts` and `define-system.test.ts` must STILL pass
(verified at integration) — do not weaken them.

## Performance & security constraints
