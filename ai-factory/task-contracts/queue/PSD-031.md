## Objective
Headless, deterministic **view-model** for the flagship desktop's `Shell` screen, built ONLY on `@vita/desktop-sdk` public ports
(an injected ShellSessionPort (run command -> output lines/exit)) — injected ports, NO platform internals, NO DOM/rendering (pure interaction logic the rendered design binds to later).
- State: tabs (each a session with cwd, history, output buffer, running flag), active tab. Actions: newTab(), closeTab(id), submit(input) -> sends to the session port + appends output, historyPrev/Next(), clear(). Deterministic buffering + history; no ambient I/O (the port is injected). Fail-closed if the session port denies. Mirrors the design Shell.html REPL.
- Code under `ui_kits/desktop/viewmodels/Shell.ts`, tests under `sdk/typescript/test/ui-kits/Shell.test.ts`. Import the SDK exactly as `ui_kits/desktop/package.ts` does; ONLY public exports.
- If the SDK lacks the exact port, define a MINIMAL injected port interface in the view-model module (typed, fail-closed) that a later slice implements — the view-model must be fully testable against a fake of that port now.

## User value
Turns the static `Shell` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design. Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the described state transitions + fail-closed paths against fake ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/Shell.ts` + `sdk/typescript/test/ui-kits/Shell.test.ts`, deterministic, typecheck clean. R1.
