## Objective
Implement two first-party windowed TSX apps as composite components on the MERGED shell (PSD-005) + WM policy (PSD-004),
pure/headless-testable (no GPU paint — VMware later):
- **Settings app**: a windowed TSX app whose state is a managed configuration edited through the control-plane
  preview/apply model (reuse the existing eval→preview→apply discipline). Categories → setting widgets (pure render);
  changing a setting emits a control-plane preview/apply INTENT — it does NOT mutate the host directly. Deterministic.
- **File-manager app**: a windowed TSX app over the MERGED files capability (P1-065 — the unprivileged files API). Lists
  a directory's entries, navigates, and issues read/list/stat through the files capability port (INJECTED, not raw FS).
  All access goes through the capability (fail-closed on AccessForbidden); the app gets NO ambient FS access. Pure
  render of the listing state; the capability port is faked in tests.

## User value
The two apps every desktop needs (settings + files), as windowed TSX surfaces on the shell — proving the app model
(TSX app = windowed surface) and that apps act only through capabilities/the control plane, never ambient host access.

## Non-goals
- NO GPU/compositor (PSD-002/003). Apps compose to element trees + emit intents; tests use fakes.
- NO webview/web/WASM app class (PSD-008). NO panel/launcher (PSD-006).
- Do NOT import PSD-001's `desktop-substrate.ts` directly — build on PSD-005's shell + PSD-004 WM + the P1-065 files
  capability port.

## Dependencies (merged)
- PSD-005 shell + PSD-004 WM (on main). The files capability (P1-065, merged) for the file-manager — use its existing
  port/types.

## Acceptance
`acceptance_command` passes: settings app emits control-plane preview/apply intents (never direct host mutation);
file-manager lists/navigates ONLY through the injected files capability and fails closed on forbidden paths; both
compose deterministically. Unit-tested with fake capability/control-plane ports. Headless-verifiable; no boot marker.

## Security/constraints
- Apps act ONLY through capabilities (files) + the control plane (settings) — NO ambient host/FS access; fail-closed on
  forbidden. Pure/deterministic render; injected ports. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- Settings app (control-plane-mediated edits) + file-manager (files-capability-mediated, fail-closed) as windowed TSX
  components on the shell; comprehensive unit tests (incl. forbidden-path fail-closed + settings preview/apply intent);
  typecheck clean. R1.
