## Objective
**Phase 3 storage durability, slice "Disk-full and power-loss handling" (spec §21 Phase 3 deliverable; the exit
gate "1,000 forced power cycles without unrecoverable system state").** The authoritative node state lives on the
persistent `vita-data` `/var` partition (P1-029). Today every agentd state write uses the temp + `Sync()` + `Close()`
+ `Rename()` atomic-write pattern — but it **never fsyncs the parent directory after the rename**, so under an abrupt
power loss the *file data* is durable while the *directory entry* (the rename = the commit) may NOT be: the latest
committed state can silently revert to the prior version, or the directory can land in a partial state. Close that gap
end-to-end and PROVE survival with a power-cut test.

Concretely:

1. **Shared durable-rename helper — `agent/internal/atomicfile/atomicfile.go`.** Factor the (currently duplicated)
   atomic-write discipline into ONE reusable function and ADD the missing step: after the `Rename` commit, **open the
   target's PARENT DIRECTORY and `fsync` it** so the rename itself is durable (POSIX: a rename is only crash-safe once
   the containing directory's metadata is synced). Exact ordering, no fallible step skipped:
   `CreateTemp(dir, ".name-*.tmp")` (O_CREATE|O_EXCL — random, never a predictable `path+".tmp"`, the AGENTS.md TCB
   rule) → `Chmod(0600)` → `Write` (assert full length, else `io.ErrShortWrite`) → `f.Sync()` (data durable) →
   `f.Close()` → **`Rename(tmp, path)` (the single commit point — no fallible work before the dir-sync)** →
   **open the parent dir + `dirf.Sync()` + `dirf.Close()` (rename durable)**. On ANY earlier error: remove the temp
   (best-effort) and leave the live file BYTE-IDENTICAL to before (the existing two-outcomes guarantee, preserved).
   Keep the `FileSystem`/`TempFile` seam so tests inject a fake — but ADD a `SyncDir(dir string) error` (or
   `OpenDir`/`Dir.Sync`) method to the interface so the directory fsync is observable and a no-op impl FAILS the suite.
   Signature shape (adapt to fit both callers): `atomicfile.Write(fsys FileSystem, path string, data []byte, mode
   fs.FileMode) error`. Pure stdlib (`os`/`filepath`), no privileged syscalls, no new vendored deps.

2. **Migrate BOTH existing state writers onto it (no behavior change except the added durability).**
   - `agent/internal/auditlog/auditlog.go` — its `persist()` (`auditlog.go:289`, temp `.auditlog-*.tmp`,
     `tmp.Sync()`/`Rename` at `:326`/`:336`) currently has NO parent-dir fsync. Route it through `atomicfile` (or
     inline the dir-sync after the rename using the same helper). Preserve the existing `FileSystem`/`TempFile`
     abstraction, the canonical-bytes + max-events + symlink/hardlink-safe-temp semantics, and the
     "live log unchanged on error" guarantee.
   - `agent/capabilities/pdsrepo/pdsrepo.go` — its `AtomicWrite()` (`pdsrepo.go:501`, temp `.pds-repo-*.tmp`,
     `tmp.Sync()`/`Rename` at `:538`/`:551`) likewise has NO parent-dir fsync. Same migration. Preserve the
     `context.Err()` cancellation checks, `stateRootMode`/`repoStateFileMode`, and the undo-only-after-nil-error
     contract.
   Do NOT change the on-disk formats, paths, or modes — this is a DURABILITY hardening, byte-compatible with existing
   state files. (Search for any other agentd `os.Rename`-after-`Sync` writer; if a third exists, migrate it too and
   note it in the result — but the audit log + PDS repo are the two AUTHORITATIVE-state writers and are the required
   scope.)

3. **Power-cut harness — `os/x86_64/test/powercut.test.sh` (worker-runnable, host-side).** A self-contained
   bash test that proves crash-consistency of the durable-rename WITHOUT needing a full QEMU boot (the boot is the
   orchestrator floor; the worker test exercises the code path directly). It MUST:
   - Build the agentd (or a tiny in-repo Go test harness binary that imports `atomicfile` + drives `auditlog.Store`
     and the pdsrepo writer) via `go-in-docker`, then run an **N-cycle loop (N=20 in the harness; the 1000-cycle soak
     is a SEPARATE long run, not this acceptance)**: each cycle (a) starts a writer doing repeated atomic commits of a
     monotonically-increasing sentinel to a loopback-backed ext4 `/var`-like image, (b) **HARD-CUTs** it
     (`kill -9` the writer process AND drop the page cache / `echo 3 > /proc/sys/vm/drop_caches`, or detach+reattach
     the loop device, to simulate the volatile-cache loss of a power cut — pick the strongest available simulation and
     document it; if neither loop devices nor root are available, **skip with a clear message** — the QEMU boot is the
     real floor), (c) remounts and asserts the state is RECOVERABLE: the committed log/repo parses as canonical, the
     sentinel is either the last-fully-committed value or the prior one (NEVER a torn/half value, NEVER unparseable),
     and a fresh `Store.Read()`/repo load succeeds.
   - Include a NEGATIVE: a deliberately torn/truncated state file (simulate a crash MID-rename by planting a partial
     temp and a zero-length or half-written target) MUST be detected as corrupt and the loader FAILS CLOSED (returns a
     `CorruptLogError`-class error, never silently accepts garbage) — proving recovery is fail-closed, not fail-open.
   - Emit, on success, `VITA-POWERCUT: cycles=20 intact=OK status=OK` (MEASURED from the real cycle results, never
     hard-coded) and on any cycle failure `VITA-POWERCUT-ERROR: cycle=<n> reason=<step> status=FAILSAFE`.

4. **On-device MEASURED marker (the real floor) — `vita-powercut-marker.sh` + its unit.** Add a verity-overlay marker
   service (mirror the P1-068 `vita-luks-marker.service` + `multi-user.target.d/10-vita-luks-marker.conf` enablement
   pattern EXACTLY) that, on EACH boot: writes a monotonically-increasing counter into the audit log / a sentinel under
   `/var/lib/vita-agent` via the SAME durable-rename code path (so the marker exercises the real writer), then on a
   SUBSEQUENT boot verifies the counter persisted and the state parses. The marker is **MEASURED, never synthesized**:
   it emits `VITA-POWERCUT: cycles=<n> intact=OK status=OK` ONLY after it confirms the persisted counter from a PRIOR
   boot is intact and the state file parses canonically; the pending/first-boot state emits a `*-PENDING` line and the
   failure path emits `VITA-POWERCUT-ERROR: reason=<step+errno> status=FAILSAFE`. (The orchestrator drives the actual
   hard-reset via QEMU between boots — see Acceptance; the on-device script only MEASURES persistence, it does not
   reset itself.) Keep ALL prior markers. The marker runs only on the verity/persistent-/var image; on plain-smoke
   (no `vita-data`) it must skip cleanly (condition unmet = success-skip, the P1-029 no-cascade lesson) and never
   hard-fail into the dependency graph.

## User value
The node's authoritative state — the audit trail (every privileged mutation, spec §11) and the PDS repository — must
survive the single most common real-world fault: someone yanks the power. Without a durable rename, a power cut can
silently roll the node's recorded state back to a stale commit or leave it in a partial directory state, which for an
audit log is a tamper-equivalent loss and for the PDS is data loss. This slice makes every authoritative `/var` write
crash-consistent (atomic AND durable) and proves it by abruptly killing the node mid-write across N cycles and showing
the state always recovers to a valid, fully-committed point — the foundation for the Phase-3 exit gate "1,000 forced
power cycles without unrecoverable system state" (spec §21 Phase 3; the 1000-cycle soak is a separate long run built on
this mechanism).

## Performance & security constraints
- **Crash-consistency (the deliverable):** every authoritative `/var` write is ATOMIC (exclusive-temp + rename single
  commit point, no fallible step after the rename before the dir-sync) AND DURABLE (data `fsync` before rename; parent
  directory `fsync` after rename). After an abrupt power loss the state is EITHER the last fully-committed value OR the
  immediately-prior committed value — NEVER a torn/partial/unparseable file. No fail-open: a corrupt/non-canonical
  state file is detected and rejected (`CorruptLogError`-class), never silently accepted.
- **Unprivileged runtime, privileged agentd (spec §3.4, §7.1):** the durable-rename runs INSIDE the narrow privileged
  agentd writing its own validated state; the TS runtime never touches raw `/var`. agentd composes its write target
  from FIXED, code-controlled paths + re-validated content — NEVER from raw runtime-supplied text used as a path.
- **Fail-CLOSED everywhere:** any write-step error → live state byte-identical to before (two outcomes only); any load
  of a torn/non-canonical/duplicate-key state → reject, never accept. A guard over untrusted input MUST NOT throw/panic
  at the trust boundary (return an error); prove with a torn-file + malformed-input regression.
- **Byte-compatible:** no change to on-disk formats, paths, or modes; the migration is observable ONLY as the added
  fsync(dir). The plain-smoke + non-verity images stay byte-unchanged (the marker overlay lives in `verity-overlay/`
  and skips cleanly when `vita-data` is absent — the P1-029 no-cascade rule).
- **No keys/secrets:** TEST data only; never commit/generate production key material (§16). No remote imports;
  lockfiles mandatory; no package lifecycle scripts; no new vendored deps; pure stdlib `os`/`filepath` (+ `fsync` on a
  dir fd). R3 (boot/storage/agent-state — privileged TCB) → **reviewer gate** (`npm run review -- P1-088`) +
  independent host-verify before merge.
