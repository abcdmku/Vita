## Objective
Implement the core desktop CHROME as composite TSX/CSS **shell components** registered through the MERGED PSD-005
component registry (`sdk/typescript/src/shell/index.ts`) and placed by the MERGED PSD-004 WM policy
(`sdk/typescript/src/wm/policy.ts`). All pure/headless-testable logic (no GPU paint — that's the compositor on VMware):
- **Panel**: a top/bottom bar shell component — clock, focused-window title, a system tray/status area (pure state →
  composed TSX element tree).
- **Launcher**: an app-launcher component — given a list of installed apps (injected, not fetched here), filter/search +
  emit a "launch app X" INTENT against the shell's port (the same intent model PSD-004/005 use). Pure + deterministic.
- **Notifications**: a notification-center component — a pure reducer over notification events (add/dismiss/expire by a
  passed-in clock) → composed element tree; no real timers/I-O in the logic.

## User value
The desktop's default chrome — the visible shell the owner interacts with — as customizable, testable TSX components on
the merged shell+WM foundation.

## Non-goals
- NO GPU/compositor/paint (PSD-002/003 on VMware). Components compose to element/surface trees via the shell; tests use
  fakes/injected clocks + app lists.
- NO settings/file-manager apps (PSD-007) or webview class (PSD-008).
- Do NOT import PSD-001's `desktop-substrate.ts` directly — build on PSD-005's shell registry + port types (PSD-001's
  substrate reconciles separately).

## Dependencies (merged)
- PSD-005 shell component registry + composition (on main). PSD-004 WM policy (on main, for placement intents).

## Acceptance
`acceptance_command` passes: panel/launcher/notifications register as shell components, compose deterministically, and
emit the correct intents (launch/focus) + notification reducer transitions — all unit-tested with injected clock/app-
list/fake ports. Headless-verifiable; no boot marker (pure component logic). A later VMware integration paints them.

## Security/constraints
- Pure/deterministic composition; injected time/data (no ambient clock/I-O in logic). No remote imports; lockfile; no
  lifecycle scripts. Launcher emits intents only — it does not itself install/execute (that's the control plane).

## Definition of done
- Panel + launcher + notifications shell components registered via PSD-005, composing deterministically, intent-correct,
  comprehensively unit-tested (incl. notification expiry by injected clock, launcher search/intent); typecheck clean. R1.
