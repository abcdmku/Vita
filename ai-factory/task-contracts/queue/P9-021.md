## ROUND-2 (Opus gate findings, GROUND-TRUTH adjudicated — resume from the existing `task/P9-021` branch and
apply ONLY these two fixes; keep everything else from round 1, which is correct):
- **FINDING 2 — REAL (CONFIRMED via real Go): explicit JSON `null` on the agent's OPTIONAL POINTER fields must
  be treated as ABSENT, not type-checked.** The agent's `Schedule.Cron *string` / `Schedule.IntervalSeconds
  *int64` / `RecoveryKeyRef.KeyStoreRef *string` are omitempty pointers — `encoding/json` decodes `null`→nil→
  absent, so VERIFIED: `{"schedule":{"cron":null,"intervalSeconds":3600},…}` ⇒ agent ACCEPT, and
  `{…,"recoveryKeyRef":{…,"keyStoreRef":null}}` ⇒ agent ACCEPT. The manifest currently keeps the null key
  present and type-checks it ⇒ rejects ⇒ manifest STRICTER. **FIX:** add a per-field option (e.g.
  `nullAsAbsent: true`) in BOTH planes' `validateObjectField` — when a field's raw value is JSON `null` AND
  the field is OPTIONAL with this flag, treat it as ABSENT (skip validation), AND make the `exactlyOneOf`
  cross-field count a null-valued key as NOT-present (so `{cron:null,intervalSeconds:3600}` satisfies
  exactly-one). Set the flag ONLY on `schedule.cron`, `schedule.intervalSeconds`, `recoveryKeyRef.keyStoreRef`
  (the agent's pointer-optional fields). Do NOT apply it to non-pointer optional fields (a `bool`+omitempty
  like network's unsafeWideOpen, where the agent json-decode of `null` ERRORS ⇒ both must reject). Add null
  conformance vectors: `cron:null`+interval ⇒ ACCEPT; `intervalSeconds:null`+cron ⇒ ACCEPT; `keyStoreRef:null`
  ⇒ ACCEPT (they fail the current `backup_conformance_test.go` oracle until fixed).
- **FINDING 1 — FALSE POSITIVE (do NOT change the scanner): the ASCII-lowercase scanner is CORRECT.**
  Ground-truth via REAL Go: `containsInlineSecretMaterial("ſecret=x")` (U+017F long-s) ⇒ **false** — Go RE2
  `(?i)` does NOT fold the long-s into `s` (the gate's claim used JS `/iu`, which DOES fold it — a JS-vs-Go-RE2
  difference; AGENTS trap 5b: a `(?i)` scanner is correctly mirrored by ASCII-lowercase). The agent ACCEPTS
  `s3://x/ſecret=y` and so does the manifest ⇒ manifest≡agent. **ONLY ADD a lock-in vector** targets id
  `"s3://x/ſecret=y"` ⇒ ACCEPT (proving both accept), so the oracle records the parity. Do NOT touch the
  scanner code.
