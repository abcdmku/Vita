## Objective
Headless, deterministic **view-model** for the flagship desktop's `Activity` screen, built ONLY on `@vita/desktop-sdk` public ports
(the SDK metrics/telemetry port if present, else a minimal injected MetricsPort) — injected ports, NO platform internals, NO DOM/rendering (pure interaction logic the rendered design binds to later).
- State: live samples for CPU%, memory, processes (pid/name/cpu/mem), per the design Activity screen. Actions: refresh(), selectProcess(pid), sortBy(col). Sampling via the injected metrics port; deterministic sorting + rolling-window aggregation (pure, with an injected clock — no Date.now()). Fail-closed without the metrics grant.
- Code under `ui_kits/desktop/viewmodels/Activity.ts`, tests under `sdk/typescript/test/ui-kits/Activity.test.ts`. Import the SDK exactly as `ui_kits/desktop/package.ts` does; ONLY public exports.
- If the SDK lacks the exact port, define a MINIMAL injected port interface in the view-model module (typed, fail-closed) that a later slice implements — the view-model must be fully testable against a fake of that port now.

## User value
Turns the static `Activity` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design. Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the described state transitions + fail-closed paths against fake ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/Activity.ts` + `sdk/typescript/test/ui-kits/Activity.test.ts`, deterministic, typecheck clean. R1.
