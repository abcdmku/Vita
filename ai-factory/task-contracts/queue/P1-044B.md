## Objective
First wave-4 slice (per **ADR-0009**): the node RUNS a capsule. agentd gains a `capsule.execute` capability (R3) that
launches an installed `ts-service` capsule as a HARDENED systemd **transient unit**, reusing the host-verified
`vita-ts.service` hardening profile (systemd is the jailer). The unprivileged TS runtime only PROPOSES execution over
the ADR-0008 unix socket; agentd re-validates the manifest, composes the unit ONLY from validated fields, starts it,
and records start + undo + audit in the transaction engine. Markers:
- `VITA-CAPSULE-EXECUTED: id=<id> unit=<unit> uid=<dynuid> health=OK status=OK`
- `VITA-CAPSULE-EXECUTE-REJECT: reason=<code> status=OK` (a deliberately invalid/unknown capsule → agentd fails closed)
- `VITA-CAPSULE-EXECUTE-ERROR: status=FAILSAFE` (transport/unexpected — never crash the oneshot)

ADR-0009 ACCEPTANCE CONDITIONS this slice MUST honor:
- **ts-service ONLY.** No OCI/WASM runtime (deferred to separate slices). The capsule runs under the PINNED Deno
  (`/usr/lib/vita/deno`) already staged + hardened.
- **No fetch/storage yet** (that's a later slice). Use a TEST capsule BAKED into the image: a trivial Deno entrypoint
  at `os/x86_64/ts-overlay/usr/lib/vita/capsules/<id>/main.ts` (e.g. prints a marker + exits 0, or a tiny readiness
  loop) + a registry entry for it (reuse the P1-041 capsule-registry path / a fixed installed entry).
- **Manifest-only unit composition.** agentd composes the transient unit's properties from the VALIDATED capsule
  manifest + the `vita-ts.service` hardening template — NEVER from raw runtime-supplied unit text. Hardening MUST
  include: DynamicUser, empty CapabilityBoundingSet/AmbientCapabilities, NoNewPrivileges, ProtectSystem=strict,
  RestrictAddressFamilies=AF_UNIX (or none if the capsule needs no socket), SystemCallFilter=@system-service +pkey
  family, and cgroup caps (MemoryMax/CPUQuota/TasksMax) from the manifest `resourceLimits`.
- **Fail-closed + transactional undo.** Mirror `agent/capabilities/services/services.go`: validate → act → record
  undo (stop + unlink the transient unit) → audit. An unknown/invalid capsule is REJECTED, no unit started.

Concretely:
- **agentd `capsule.execute`** (`agent/capabilities/capsule/execute.go` + register in `cmd/agentd/main.go`): the
  capability handler. Launch mechanism — `systemd-run --unit ... --property=...` OR the D-Bus `StartTransientUnit`
  (the worker PICKS + justifies; ADR-0009 leans D-Bus but systemd-run is acceptable for the first slice). Confirm
  the unit started (`systemctl is-active`/the bus job result) + capture the DynamicUser uid for the marker.
- **TS side** (`main.ts`): propose `capsule.execute` for the baked test capsule over the existing apply/transport
  path; print `VITA-CAPSULE-EXECUTED` from agentd's outcome; forced-invalid → `VITA-CAPSULE-EXECUTE-REJECT`;
  transport error → `VITA-CAPSULE-EXECUTE-ERROR: FAILSAFE`. Keep ALL prior markers.

## User value
The node can RUN apps (capsules) on-device — the foundation of Vita as a personal app node — with each workload in a
hardened, resource-capped, unprivileged systemd jail composed by the privileged agent from a validated manifest.

## Non-goals

yet (S3 — the test capsule is stateless). NO new transport surface beyond the existing apply path. NO raw unit-text
from the runtime. Benign test capsule only.

## Performance & security constraints
Runtime PROPOSES; agentd (sole privileged spawner) VALIDATES the manifest + composes the hardened unit + applies
resource caps + fails closed. NEW ATTACK SURFACE (ADR-0009): agentd now spawns a workload — it MUST run under the
full hardening profile (unprivileged DynamicUser, no caps, seccomp, ProtectSystem=strict, cgroup-capped) so the
workload cannot escalate. No raw unit text from the runtime. No keys/secrets. R3 → parallel-candidate + reviewer gate.
