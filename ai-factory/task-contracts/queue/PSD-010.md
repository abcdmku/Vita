## Objective
Close the render→composite loop end-to-end on the GPU: let the merged TS `CompositorDriver` (PSD-009) drive the REAL
native compositor (PSD-002) over a small command protocol, so the actual shell/WM window LAYOUT renders on the vmwgfx
GPU — replacing the compositor's hardcoded `--demo`. This is the first increment: SOLID-COLOR surfaces (placeholder
content) driven from a TS-side window model; real web/TSX texture content is the follow-up (PSD-003).
1. **Command-driven compositor session (Rust, packages/compositor-core):** add a mode that reads a line-delimited
   command stream (stdin or a unix socket) and applies `registerSurface(id, w, h, rgba)` / `updatePlacement(id, x, y, w,
   h, z, visible)` / `removeSurface(id)` / `present` against the SAME DRM/KMS+GBM path as the demo (VT takeover, no-repaint
   reposition, page-flip present). Fail-closed/FAILSAFE on GPU/protocol errors; keep emitting a VITA-COMPOSITOR marker.
   Keep `--screenshot` readback working (capture the command-driven frame).
2. **`CompositorPort` native binding (TS, compositor-bridge):** an implementation of the PSD-009 `CompositorPort` that
   serializes the driver's commands to that protocol (over an INJECTED transport/writer port — no ambient I/O; tests use
   a fake writer asserting the exact wire commands). Deterministic encoding.
3. **Verification wiring (os/x86_64 smoke overlay):** a boot path that feeds a fixed sample window layout (a panel + 2-3
   solid-color windows, derived from the shell/WM model shape) through the driver→port→compositor and presents it, so a
   VMware boot renders REAL driver-produced windows (not `--demo`) and the readback PNG shows them.

## User value
The actual TS desktop model (shell surfaces + WM placement) now drives pixels on the GPU through the no-repaint
compositor — the architecture's core promise, end to end. After this, swapping solid colors for real web/TSX textures
(PSD-003) yields the full desktop.

## Non-goals
- NO web engine / real texture content yet (solid colors only — PSD-003 brings content). NO new WM policy (consume
  PSD-004/PSD-009). Keep the production OS headless — this is the desktop-package substrate, baked only in the
  smoke/verification overlay.

## Acceptance
`acceptance_command` passes (the TS port unit-tested against a fake writer for exact wire commands + deterministic
encoding; compositor builds for linux via rust-in-docker). INDEPENDENT verification (orchestrator): boot on the 3D-accel
VMware target; the compositor renders the DRIVER-PRODUCED layout (solid-color panel + windows) — `VITA-COMPOSITOR
present=kms`, and the readback PNG (`/run/...png`, copied out via `--guest-file`) shows the driver-produced windows, not
the old hardcoded demo. State honestly which result occurred.

## Security/constraints
- Verification/desktop-substrate only (smoke overlay), NOT the production OS. Compositor stays fail-closed (VT/DRM/GPU
  unavailable → FAILSAFE). TS port uses an INJECTED transport (no ambient I/O). No remote imports; --locked crates;
  lockfile; no lifecycle scripts. Snapshot/validate any externally-supplied command input.

## Definition of done
- Command-driven compositor (register/update/remove/present over a protocol, same GPU path, no-repaint, fail-closed) +
  TS `CompositorPort` native binding (injected transport, unit-tested wire encoding) + a smoke-overlay boot that renders
  the driver-produced solid-color window layout on the VMware GPU (readback PNG shows it, present=kms). R2 reviewer gate
  + orchestrator GPU-boot verification.

## REVISION 1 (Codex R2: dirty-since-present + Rust command-stream tests — 2026-06-25)
GPU-verified (driver-produced layout renders on vmwgfx, present=kms, readback PNG). Blocking + coverage findings:
1. **Dirty-since-present (main.rs:278-284, :377-378; mutators :304-356):** command mode treats ANY prior `present` as
   success, but mutating commands (register/update/remove) AFTER a present do NOT mark the frame dirty or reset
   `presented`. So `present\nremoveSurface X\n` returns status=OK and writes a screenshot of the STALE pre-remove frame.
   FIX: track "dirty since last present" — any mutator after a present marks the frame dirty; a screenshot/success
   requires a present that reflects the FINAL command state (auto-present before readback, OR FAILSAFE/reject if a
   mutation is left un-presented). The captured PNG MUST reflect post-mutation state.
2. **Rust unit coverage (NOTE→required):** add recording-backend tests for the command-stream session/parser:
   register/update/remove/present happy path, protocol/parse errors (FAILSAFE), and the dirty-after-present case above.
3. **Exact smoke-layout output:** the OS smoke test (compositor-selftest.test.ts:148-158) only substring-checks; make it
   EXECUTE the layout generator and assert exact equality with the baked `vita-compositor-smoke.commands` (no TS-model↔
   baked-commands drift).
(Non-blocking follow-up noted: remove_surface has no explicit texture-destroy path — fine for this short-lived demo.)
Verify: acceptance (typecheck + compositor-bridge tests) + cargo test + orchestrator GPU boot: a present-then-remove
