## Objective
An internal append-only provenance store `agent/internal/auditlog/` (NOT a client-applicable capability —
audit events are SYSTEM-generated, not user-submitted). A typed `Event` mirroring the SDK P0-024 shape:
`Sequence uint64`, `TimestampMillis int64` (caller-supplied; validated ≥ 0), `ActorKind` (closed:
human|agent|system), `ActorID string`, `Capability string`, `Operation` (closed: apply|read), `Outcome`
(closed: committed|rejected|rolled_back|failed), optional `Reason string`. A `Store` over an injected FS +
a FIXED path with:
- `Append(e Event) (Event, error)`: ASSIGNS the next sequence (current max + 1, starting at 1 — caller does
  NOT supply Sequence; ignore/reject a caller-supplied one), validates the event fail-closed, and persists
  the WHOLE log atomically via a single commit point (temp + rename; nothing fallible after the rename),
  returning the stored event. Enforce a bounded capacity `MaxEvents`: when full, FAIL CLOSED with a typed
  "log full; rotation required" error — NEVER silently drop audit history.
- `Read() ([]Event, error)`: returns the events in sequence order, as canonical bytes (stable field order).
- On load, REJECT a persisted log that is not strictly monotonic by Sequence, has duplicate JSON keys, or
  decodes non-canonically (tamper/corruption ⇒ fail closed, do not append onto a bad log).

## User value
The on-host, tamper-evident provenance store (spec §17/FR-008) every privileged action will be recorded to —
append-only, strictly monotonic, atomic, and bounded so it fails closed rather than losing or corrupting
history.

## Non-goals
- No transport emission / `/apply` wiring (a follow-up), no client capability, no network, no `os/exec`.
  Store + validation only.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Cover: Append assigns 1,2,3… and is
strictly monotonic; Read returns canonical sequence-ordered bytes; a caller-supplied Sequence is ignored/
rejected (store assigns); invalid event (bad actor kind/operation/outcome closed sets, negative timestamp,
empty actor id) rejected WITHOUT writing; `MaxEvents` reached ⇒ typed "log full" error, log unchanged;
atomic-write failure leaves the live log unchanged (single commit point); loading a non-monotonic / dup-key
/ non-canonical log fails closed (no append onto it); §13.1 — an event field carrying inline key material
(PEM/`data:`/long base64) rejected. Injected FS.
