## Objective
Wire the append-only audit-log store (`agent/internal/auditlog`, P7-005) into the transport so EVERY
`POST /apply` records an audit event, and expose the trail read-only at `GET /audit`.
- Construct an `auditlog.Store` in `agent/cmd/agentd/main.go` (fixed state path) and inject it into the
  handler (a new optional dependency in the transport `Config`; if absent, /apply still works but /audit
  reports unavailable — fail-closed, never panic on a nil store).
- On `POST /apply`: AFTER the transaction resolves, append ONE audit event = `{ actor: {kind:"system",
  id:"agentd"}, capability: <the applied capability name>, operation:"apply", outcome: <committed |
  rolled_back | failed>, timestampMillis: now }` (sequence is store-ASSIGNED — never client-supplied). The
  apply's HTTP result MUST reflect the transaction outcome regardless of whether the audit append itself
  errors; if the audit append fails, log/surface it but do NOT change a committed transaction's result
  (record-keeping failure must not roll back a real change — but DO include an "audit_unrecorded" flag in
  the response so the gap is visible). Appending happens OUTSIDE/after the transaction commit point.
- `GET /audit`: read-only, GET-only (reject other methods), returns the events from the store (the same
  canonical shape the store persists), loopback-only. No mutation.

## User value
The agent now produces the tamper-evident provenance trail (spec §17/FR-008) — every privileged /apply is
recorded with its outcome and a monotonic sequence, readable for audit; the controller audit viewer
(P2-021) can consume it.

## Non-goals
- No real user authentication/identity yet (actor is system:agentd until an auth layer exists). No new
  capability. No `os/exec`. Do NOT alter the transactional semantics of /apply or the existing endpoints
  beyond adding the post-commit audit append + the /audit route.

## Dependencies
P7-005 (auditlog.Store: Append/Read), P7-003 (the wired transport with all 11 caps). Both merged.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Cover: a successful /apply appends
exactly ONE committed audit event (capability + outcome correct, sequence assigned); a rolled_back/failed
apply records the corresponding outcome; `GET /audit` returns the recorded events in order (byte-stable);
an injected audit-append failure does NOT change a committed apply's success result but sets the
`audit_unrecorded` flag; a nil/absent store ⇒ /apply still works and /audit reports unavailable (no panic);
/audit rejects non-GET; no audit event is recorded for a request REJECTED pre-transaction by Validate
(or, if you do record rejected, outcome must be "rejected" — pick one and test it). Use httptest + the
injected store/facades.
