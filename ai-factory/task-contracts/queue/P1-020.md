## Objective
Register the two newest capabilities — `storage` (P1-018) and `update` (P1-019) — into `agentd`, exactly
like P1-016 wired identity + network. Construct each with its production facade in
`agent/cmd/agentd/main.go` and add them to the registry; add their request decoders to
`DefaultRequestDecoders()` in `agent/transport/server.go` (without a decoder, /apply rejects them with
"no registered request decoder"). After this, all SEVEN capabilities (nodeconfig, time, hostname,
identity, network, storage, update) are discoverable via `GET /operations` and applicable via `POST /apply`.

## User value
Completes the agent's exposed operation set — storage + update become managed operations the controller
can discover + apply (FR-004/007/014/023).

## Non-goals
- No new capabilities, no transport behavior changes beyond registration + decoder wiring. No real
  Btrfs/RAUC enforcement (those stay in their capabilities / later host contracts).

## Dependencies
P1-016 (wiring pattern + the existing 5-cap registration), P1-018 (storage), P1-019 (update). All merged.

## Acceptance tests

test: `GET /operations` returns all SEVEN registered names (sorted); `POST /apply` routes a plan to a
storage op and an update op and commits (injected facades, no real host mutation). Both must have a
registered decoder. No real disk/RAUC mutation in tests.
