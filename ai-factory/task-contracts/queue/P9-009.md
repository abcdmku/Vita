## Objective
Add two GOVERNED named string formats to the shared dialect (closed `StringFormat` set), implemented so TS
and Go agree, with the parity GUARANTEED by an extensive cross-language conformance corpus (the test is the
contract — this is how ADR 0007 makes a canonicalizing format safe). These unblock timesync + network.
- **Go side = `net/netip` (authoritative, matches the agent's own validators).** In `capmanifest`, the
  `ipLiteral` format parses with `netip.ParseAddr(value)` and canonicalizes via `.String()`; reject on
  parse error or if the value is not already canonical-INPUT-agnostic (accept any valid spelling, dedupe/
  return the canonical `.String()`). Reject zones (`%`) unless a later contract needs them.
- **TS side = a structured RFC-5952 canonicalizer** (NO regex engine reliance for the structure): parse IPv4
  (dotted quad, octets 0–255, no leading zeros) and IPv6 (exactly one `::`, 8 groups incl. trailing embedded
  IPv4 `…:a.b.c.d`, IPv4-mapped `::ffff:a.b.c.d`); reject malformed (wrong group count, >1 `::`, out-of-range).
  Canonical IPv6 (RFC 5952): lowercase hex, strip per-group leading zeros, compress the LONGEST run of ≥2
  zero groups to `::` (leftmost on a tie, never a single zero group), render IPv4-mapped with the dotted tail;
  canonical IPv4 = plain dotted decimal. Return/dedupe on the canonical form so canonical-equivalents
  (`2001:0db8::1` ≡ `2001:db8::1`, `::ffff:192.0.2.1` ≡ itself) match.
- **`hostnameOrIp`** = accept a value that is EITHER a valid `hostnameRFC1123` hostname OR a valid
  `ipLiteral`; canonicalize the IP branch. (timesync's `servers` will use this.)
- `noInlineSecrets` + `maxLength` still compose. Both formats are structured checks (no JS regex for the IP
  structure). Document both in the closed `StringFormat` set + a header note that the corpus is the parity
  guarantee.

## User value
The parity-safe IP foundation (the deferred hard problem from P9-002) — unblocking the faithful migration of
timesync (`hostnameOrIp` servers) and network (`ipLiteral`/CIDR later), with TS↔Go agreement PROVEN on a
large corpus rather than assumed.

## Non-goals
- No CIDR/range format yet (a follow-up for network), no zone-id support, no cap migration in THIS contract
  (timesync migration is the next contract). Additive dialect formats + conformance only.

## Acceptance tests
`acceptance_command` (native `go test ./internal/capmanifest/...` + the TS IP tests + the manifest suite) —
all green; orchestrator ALSO runs the full container `go test ./...` + `npm run typecheck`. The CORPUS
`schema/capabilities/formats/ip-conformance.json` (≥ 40 vectors) is run by BOTH the TS `ipLiteral`/
`hostnameOrIp` validators AND the Go ones; they MUST agree on every vector AND, for accepted IPs, on the
CANONICAL output. Cover: IPv4 (valid, leading-zero reject, octet>255 reject), IPv6 (compressed, full,
`::`, `::1`, IPv4-mapped, trailing embedded IPv4), canonical-equivalent duplicates (zero-padded, compression
variants) must canonicalize identically, malformed (two `::`, too many groups, bad chars), hostnameOrIp
accepts both branches, inline secret rejected. A wrong expectation fails both planes.

## Performance & security constraints
Deterministic; Go uses `netip` (authoritative), TS RFC-5952 structured (no regex engine for structure); the
corpus is the TS↔Go parity guarantee (drift fails CI). Fail-closed; no panic on hostile input. Strict TS /
clean `go vet`. R3 → reviewer-gated.
