## Objective
Mirror the P1-034 preview pattern for capsules: BEFORE applying a capsule.registry change, the runtime READS the
current registry via agentd, DIFFS it against the desired registry, and prints the change set — so the operator sees
what will change without mutating. Marker: `VITA-CAPSULE-PREVIEW: installed=<i> removed=<r> upgraded=<u> status=OK`
(or `VITA-CAPSULE-PREVIEW-ERROR: status=FAILSAFE`). Read-only + pure diff; NO mutation.

Concretely:
- **Read the current registry** via agentd (`GET /read/capsule.registry`, the existing read handler — confirm the
  route/shape in `agent/transport/server.go` + `agent/capabilities/capsule/capsule.go`) using the vendored
  agent-client over the READ-ONLY transport (not the apply transport). Validate the untrusted response via
  safeNormalize + the capsule model.
- **Diff** current vs the DESIRED registry (the same fixed entry S6/P1-041 installs) → a change set
  {installed/removed/upgraded}. Reuse `controller/capsule/src/capsule-preview.ts` if it exists (vendor it
  byte-identical + header); else a small pure diff over the capsule-registry-model (reuse the vendored
  `capsule-registry-model.ts` from P1-041). NO apply, NO mutation.
- **New module** `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/capsule-preview.ts` (the read+diff helper). **`main.ts`**:
  BEFORE (or alongside) the S6 `VITA-CAPSULE` apply, emit `VITA-CAPSULE-PREVIEW` from the read+diff. Keep ALL prior
  markers. Read-only; AF_UNIX; no new privilege/transport surface.

## User value
The operator can see exactly which capsules a change would install/remove/upgrade BEFORE it's applied — the capsule
analogue of the config preview, closing the capsule lifecycle's "look before you leap" half. Pure read; nothing to
roll back.

## Non-goals
NO capsule apply (that's S6, done). NO capsule storage/execution (wave 4). NO mutation. NO new agentd capability
(capsule.registry read exists). Read-only transport only.

## Dependencies
P1-041 (S6 — the vendored capsule-registry-model + the apply path) + P1-040 (S4 — the read transport pattern) merged.
Read agentd's `capsule.registry` read route, `controller/capsule/src/capsule-preview.ts` (if present), and the
vendored `capsule-registry-model.ts`/`agent-client.ts`/`pds-read.ts` (the read pattern) first.

## Acceptance tests
`acceptance_command` — `capsule-preview.test.ts` (node --experimental-strip-types --test): drive the read+diff helper
against a MOCK transport — assert it reads the current registry, diffs vs desired correctly (a known
install/remove/upgrade → exact counts; current==desired → all-zero), parses into the `VITA-CAPSULE-PREVIEW` fields,
and is fail-closed (transport error / malformed → safe result, no throw). Upstream parity if `capsule-preview.ts` is
vendored. Orchestrator host-verifies on Borg51: boot, confirm `VITA-CAPSULE-PREVIEW: installed=.. status=OK` on the
serial (before the `VITA-CAPSULE` apply).

## Performance & security constraints
Read-only over the unix socket; UNPRIVILEGED (no new authority, no apply surface). Pure deterministic diff. Untrusted
response via safeNormalize. Fail-closed marker. No keys. R2 (read + pure diff) → reviewer-gated.
