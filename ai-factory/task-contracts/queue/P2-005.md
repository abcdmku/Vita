## Objective
Add a controller endpoint `previewCapsuleImport({ capsule, targetArch, policy })` that ties together
the capsule, simulation, and broker layers (R2 → reviewer-gated). It returns a typed
`CapsuleImportPreviewResponse` reporting:
1. **Validity** — `validateCapsule` (P6-001); invalid ⇒ typed error.
2. **Architecture-migration readiness** (FR-020) — whether the capsule's state is architecture-neutral
   or has artifacts for `targetArch` (x86_64↔arm64); report `migratable` + reasons.
3. **Required-simulation coverage** (FR-021) — `coversRequiredProfiles` (P6-002) over the capsule's
   declared `simulation.profiles`; report missing required profiles.
4. **Grant safety** — run `decideGrants` (P2-002) for the capsule's `policy` against the destination
   `policy`; surface granted vs denied, enforcing spec §13.1 "import never grants more than the
   destination policy permits" (over-grant ⇒ denied/flagged).

Fail-closed at the boundary: malformed/exotic input (incl. method-shadowing, hostile iterators,
throwing proxies, exotic prototype-bearing objects) ⇒ typed error, never throws (wrap the whole
method).

## User value
Capsule import/migration is FR-020 + a definition-of-success item (move an app + state to another
architecture, §28.7). Previewing validity + migration + sim coverage + grant safety before import is
the safe control-surface for it.

## Non-goals
- No actual import/unpack/migration execution; no crypto. Read-only preview over the SDK/validators.

## Dependencies
P2-001 (dispatcher), P6-001 (validateCapsule), P6-002 (sim profiles), P2-002 (decideGrants).

## Acceptance tests
`acceptance_command` (controller suite — existing tests pass, no weakening). Add:
1. A valid, architecture-neutral capsule with full sim coverage + within-policy grants ⇒
   `ok:true, migratable:true, missingProfiles:[], denied:[]`.
2. A capsule missing a required sim profile / requesting over-policy grants ⇒ those surfaced (not
   silently ok); an arch-specific capsule for the wrong `targetArch` ⇒ `migratable:false` + reason.
3. Malformed/exotic capsule or policy ⇒ typed error, never throws.

## Performance & security constraints
No network. Reuse capsule/sim/broker (no duplication). Fail-closed; over-grant on import is denied
(§13.1). R2 → reviewer-gated.

## Hardware profiles
x86_64↔arm64 migration; no-accelerator-aware via sim profiles.

## Reviewer revision (round 2 — BLOCKING, from P2-005.review.md)
1. **Fail-closed at the TOP-LEVEL params object, and avoid TOCTOU.** `readCapsuleImportPreviewParams`
   checks keys then returns the ORIGINAL object and reads `params.targetArch` directly, so a plain
   object with **accessor (getter) properties** is accepted — a caller's getter can return DIFFERENT
   `capsule`/`policy` values across the validation read vs the grant-decision read. **Snapshot the
   entire untrusted input to plain trusted data ONCE** before any field access: reject any property
   that is an accessor (use `Object.getOwnPropertyDescriptor` — require data properties, no get/set)
   at every level including the top-level `{ capsule, targetArch, policy }`; then pass the trusted
   snapshot to validate/migration/sim/grant. Never re-read an untrusted field across decisions.
   Add a regression test: params (and nested capsule/policy) with getter/flipping accessor properties
   ⇒ typed error (or consistent single-read), never a TOCTOU bypass.
2. (Clarify migration readiness — was a non-blocking note) `migratable:true` for architecture-neutral
   state must ALSO require that the needed runtime artifacts are available for `targetArch` (or the
   runtime is genuinely architecture-neutral, e.g. WASM/TS). An x86-only OCI capsule with neutral
   state targeting arm64 is NOT migratable — report `migratable:false` + reason.
