## Objective
Ship **Browser (offline/local)** as a separable FIRST-PARTY app package (per ADR-0016 / PSD-360), on the app-package SDK
foundation (PSD-361). Three artifacts, mirroring the flagship-package pattern:
1. **App package** under `apps/browser/`: `manifest.ts` exporting an `AppPackage` via `defineAppPackage(...)` —
   `id: "vita.app.browser"`, `version`, `sdkVersion: SDK_VERSION`, `entry: "index.html"`, MINIMAL `capabilityGrants`
   (NO network capability — this is the OFFLINE/LOCAL browser; declare an empty/minimal grant set so any network attempt
   fails closed) and a `WebAppDescriptor` (`surfaceKind:"web"`, `runtime:{ url:"index.html", partition:"vita-app-browser" }`,
   `title:"Browser"`, `defaultWindow`).
2. **CEF-rendered web-app entry** `apps/browser/index.html` — a static HTML/CSS browser chrome surface (address bar + back/
   forward + viewport area), CSS-var tokens, no inline JS (behavior via the view-model / binder convention). Minimal; NOT
   the acceptance target.
3. **Headless deterministic view-model** `ui_kits/desktop/viewmodels/apps/browser-app.ts` — a PURE navigation/history model
   over an injected **local content resolver port** (NO real network; the resolver maps a small allow-listed set of
   `vita://`/local in-tree pages to deterministic content; any non-allow-listed/`http(s)` URL fails closed with a
   deterministic "blocked: offline browser" error). Injected-port style, frozen `snapshot()`, discriminated-union results.
   State: current url, page title/content (from the resolver), back/forward stacks, loading/blocked status. Actions:
   `navigate(url)`, `back()`, `forward()`, `reload()`. NO real network/fetch, NO DOM/CSS, NO ambient I/O.

## User value
Browser becomes a swappable first-party package the dock/launcher lists + launches into its own WM window, with a real
testable navigation/history model — proving the app-package pattern for a content app while staying strictly OFFLINE +
fail-closed (no egress), the security floor for the desktop.

## Non-goals
- NO real network / fetch / egress / remote URL loading (explicitly OFFLINE/LOCAL only — non-local URLs fail closed). NO
  DOM/CSS/CEF logic in the view-model; NO platform internals; NO new SDK ports beyond PSD-361 + existing.
- Do NOT grant the Browser any network/privileged capability; it fails closed on anything not explicitly granted.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at `sdk/typescript/test/ui-kits/browser-app.test.ts`
cover the manifest (`defineAppPackage` accepts it; NO network grant; descriptor url === entry) and the view-model state
transitions (navigate to an allow-listed local page loads deterministic content + pushes history; back/forward/reload
cursor; a non-local/`http(s)` URL is BLOCKED fail-closed with the deterministic error; loading/blocked status; absent
resolver port fails closed; deterministic snapshot). `npm run typecheck` is clean. Pure, headless, no network. (The exact
test path exists only when the work lands — an empty branch fails.)

## Security/constraints
- OFFLINE/LOCAL by construction: NO network capability granted; the content resolver is an injected pure port over an
  allow-listed local page set; any non-allow-listed/remote URL fails CLOSED. Pure/deterministic. `allowed_network:false`.
  No remote imports; lockfile; no lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).

## Allowed tools + network
Local filesystem + Node test runner + `npm run typecheck` only. `allowed_network: false`.

## Compute/time budget
`budget_minutes: 120`, single worker.
