## Objective
Headless, deterministic **view-model** for the flagship desktop's `files` screen (`ui_kits/desktop/files.html` / index.html),
built ONLY on `@vita/desktop-sdk` public ports (the files capability port (PSD-007) + surface model) — injected ports, NO platform internals, NO DOM/rendering (the view-model
is the pure interaction logic the rendered design binds to later).
- State: current path, breadcrumb segments, favorites list, directory entries (name/kind/size/modified), selection. Actions: navigate(path), up(), openFavorite(id), select(entry), refresh(). All directory reads go through the SDK files port (fail-closed if the grant is missing). Deterministic ordering (folders first, then name).
- Put the code under `ui_kits/desktop/viewmodels/files.ts` and tests under `sdk/typescript/test/ui-kits/files.test.ts`.
- Import the SDK exactly as `ui_kits/desktop/package.ts` does; use ONLY public exports.

## User value
Turns the static `files` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design (the HTML is the design of record). Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the state transitions + fail-closed paths described above against fake SDK ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/files.ts` + `sdk/typescript/test/ui-kits/files.test.ts`, deterministic, typecheck clean. R1.
