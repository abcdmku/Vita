## Objective
Drive agentd's ALREADY-BUILT, transactional `capsule.registry` Apply (`agent/capabilities/capsule/capsule.go:272`,
persists `installed-capsule-registry.json` with SRI + secret-rejection validation) from the on-device runtime through
the proven S3 apply path. At boot, after `VITA-PDS`, `main.ts` sets the desired capsule registry to a SINGLE installed
`CapsuleEntry` (a synthetic, fixed test id — IDEMPOTENT: the same desired entry every boot, so agentd's transactional
apply is a no-op once converged), evaluates → POST `/apply` → and prints `VITA-CAPSULE: id=<rdns> ver=<x>
state=installed outcome=committed status=OK`, or `VITA-CAPSULE: outcome=rejected reason=<code>` on a deliberately
invalid entry (proves agentd's capsule validation fails closed), or `VITA-CAPSULE-ERROR: status=FAILSAFE`.

Concretely:
- **Vendor/define the capsule registry model.** Read `agent/capabilities/capsule/capsule.go` for the EXACT
  `CapsuleEntry{id,version,integrity,state}` shape + the `capsule.registry` request shape agentd's Apply expects.
  Add a small UPSTREAM `sdk/typescript/src/capsule-registry-model.ts` (the `CapsuleEntry` + registry-request types +
  a validator/builder, pure) matching that shape, with a test; vendor it into
  `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/capsule-registry-model.ts` (byte-identical + header). (If a suitable
  model already exists in `storage/capsules/` or `sdk/`, reuse/extend it instead of duplicating — confirm first.)
- **`main.ts`**: build a `capsule.registry` config with one installed `CapsuleEntry` (a fixed synthetic id like
  `local.test.capsule`, a pinned version, a valid integrity/SRI value, state `installed`), evaluate it (the evaluator
  must accept `capsule.registry` — confirm it's in the manifest registry; if not, that's a gap to note), POST via the
  S3 apply transport, print `VITA-CAPSULE` from agentd's outcome. Also attempt a deliberately INVALID entry (bad SRI
  / embedded secret / unknown field) → confirm agentd REJECTS → `VITA-CAPSULE: outcome=rejected …`. Keep ALL prior
  markers. agentd RE-VALIDATES (it owns the registry); the TS side is untrusted.

## User value
The node can install/track capsules (apps) on-device via the same proposed-by-runtime / validated-by-agent boundary —
the first step of the capsule lifecycle, reusing agentd's existing, well-validated registry handler.
