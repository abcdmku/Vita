## Objective
Make Vita actually run TypeScript on the device (today the image is Debian + the Go agent; the TS control plane is
dev-side only). Add a PINNED Deno runtime to the rootfs + a systemd service (`vita-ts.service`, enabled via a
committed `multi-user.target.wants` 120000 symlink, mirroring agent-overlay) that runs a TS entrypoint
`/usr/lib/vita/ts/main.ts` on boot, printing a grep-able `VITA-TS: hello from Deno <version>` marker — and, if
feasible, invoking a trivial piece of the existing control-plane TS to prove the real TS layer runs on-device.
Shipped via a new `os/x86_64/ts-overlay/` (`--extra-tree`). Deterministic (pinned deno version + sha256); no
remote imports in the production entrypoint. Built by an Opus worker (P1-030); to be **reviewed by Codex**.

## User value
The foundation of "Vita as a TS OS": a TypeScript runtime on the node, on which the control plane, capsules, and
the config→plan→apply loop will run (wave 2).

## Non-goals
- Thin first slice: the runtime + a TS entrypoint that runs on boot. NOT the full control plane / capsules / PDS
  (wave 2). Do NOT edit build-and-boot.mjs (orchestrator wires `--extra-tree=os/x86_64/ts-overlay` post-merge —
  the result must state the exact wiring). If a package is added to the allowlist, os/x86_64/test/root-determinism
  .test.ts MUST be updated in lockstep.

## Dependencies
P1-026 (agentd smoke base). Overlay + enablement-symlink pattern from agent-overlay; build-and-boot `--extra-tree`.

## Acceptance tests
`acceptance_command` is the Windows/sandbox-runnable gate (root-determinism test — catches an unsynced package
allowlist). REAL acceptance is orchestrator-run on Borg51: build smoke with `--extra-tree=ts-overlay`, boot, and
confirm `VITA-TS: hello from Deno …` on the serial (the TS runtime ran on-device). Reviewer (Codex) judges: pinned
+ deterministic deno; the unit is correct + enabled (the 120000 wants-symlink present); no remote imports in the
production entrypoint; no large binary committed (fetch/stage pattern instead); diff within `os/`.

## Performance & security constraints
Deterministic (pinned version + sha256). No remote imports in production artifacts. R3 (node runtime) → reviewer-gated.
