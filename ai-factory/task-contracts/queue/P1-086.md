## Objective
Build the **read-only model** behind the spec's Phase-5 deliverable **"UniFi-style overview for data protection and
exposure"** (§21 Phase-5 deliverables) and its exit gate **"Dashboard accurately distinguishes snapshots, mirrors,
local backup, and off-site backup"** (§21 Phase-5 exit gates). This is a thin vertical slice: a **pure, deterministic,
read-only** SDK model that ingests the node's already-existing capability read-states and produces a single
operator-facing overview that (a) classifies the node's **data-protection tiers** and (b) classifies **network
exposure** per capsule. No mutation, no new agent capability, no UI rendering — the *model* the later web/controller
UI will render, plus an on-device driver that reads real agentd state and emits a MEASURED marker.

Two coherent halves, both pure functions over normalized JSON (no I/O, no Date.now, no randomness — same inputs ⇒
byte-identical output):

1. **Protection-tier model — `summarizeProtection(input)` in `sdk/typescript/src/protection-dashboard-model.ts`.**
   It ACCURATELY DISTINGUISHES the four protection tiers the exit gate names, sourced from the existing merged
   capability read-states (the shapes the agent already returns from `/read/{cap}` — REUSE the SDK models, do not
   invent new wire shapes):
   - **`snapshots`** — btrfs read-only snapshots of the data subvolume. Source: the `storage.layout` read-state
     (`sdk/typescript/src/storage-model.ts` — the `snapshots` subvolume role + `snapshotPolicy.cadence`/`retentionCount`
     /`readOnlySnapshots`). A tier is **`active`** only when a `snapshots` storage area EXISTS **and** `snapshotPolicy.
     cadence !== "disabled"` **and** `retentionCount >= 1`; **`configured-inactive`** when the area exists but cadence is
     `disabled` (or retention 0); **`absent`** when neither. (P1-074, the runtime btrfs snapshot capability, is NOT a
     dependency and may not be merged — this model reads the DECLARED storage layout, which already exists; if a future
     runtime snapshot-count read-state is wired, the model accepts an optional measured count but NEVER requires it.)
   - **`mirror`** — multi-disk redundancy (RAID/mirror of the data volume). Source: `storage.layout` `diskHealth` +
     (optionally) a mirror indicator. Today `storage-model.ts` models a single `dataVolume` with no mirror field, so the
     HONEST classification is **`absent`** unless a mirror indicator is present; the model must NOT fabricate a mirror
     tier from a single-disk layout. Encode the tier as a first-class field whose default is `absent`, with a clearly
     documented optional input (`mirrorDevices >= 2`) that flips it to `active` — so the dashboard never *claims* mirror
     protection the node does not have (the accuracy that the exit gate demands).
   - **`localBackup`** — an on-node / attached-disk backup that lives on the node. Source: `backup.policy`
     (`sdk/typescript/src/backup-model.ts` `BackupTarget.kind`) — `local-snapshot` and `attached-disk` are LOCAL tiers —
     COMBINED with the **measured** `backup.archive` last-result read-state (`os/.../ts/vita/backup.ts` already reads the
     `backup.archive` capability via `getState`). Tier = **`verified`** when a `local`/`attached-disk` backup target is
     configured AND the measured last archive round-trip `verified=OK`; **`configured`** when a local target is declared
     but no successful verified round-trip is observed; **`absent`** otherwise.
   - **`offSite`** — an INDEPENDENT, OFF-NODE backup target. Source: `backup.policy` `BackupTarget.kind` — `peer-node`,
     `remote-object`, `sftp`, `vendor-managed` are OFF-SITE tiers. Tier = **`configured`** when such a target is declared;
     **`absent`** otherwise. (No off-site EXECUTION exists yet — P1-066 is local-only by design — so the honest value is
     `configured`/`absent`, never `verified`; do NOT claim a verified off-site backup the node cannot perform.)
   The result is a frozen object `{ snapshots, mirror, localBackup, offSite }` where each tier carries a discrete
   `status` enum (the values above) + the supporting evidence it was derived from (e.g. snapshot cadence, backup target
   kind) so the UI can explain WHY, plus a top-level `overall` summary (`protectedTiers: number`, the count of tiers not
   `absent`) — the four-tier distinction the exit gate requires, computed deterministically.

2. **Exposure model — `summarizeExposure(input)` (same module).** It classifies **network exposure** so the operator
   sees, UniFi-style, which capsules can talk to/from the network and which are network-mute:
   - **Host ingress surface** — from the `network.policy` read-state (`sdk/typescript/src/network-model.ts` host firewall
     `allow` rules: proto/port/sourceCidr/unsafeWideOpen). Summarize the open ingress ports and flag any rule with
     `unsafeWideOpen === true` or a `0.0.0.0/0`/`::/0` source as **wide-open** (a prominent exposure flag — the
     accuracy-critical case).
   - **Per-capsule exposure** — from the capsule set (the `capsule.registry` read-state: id/version/state) JOINED with
     each capsule's declared network grants (an `egress`/`ingress` grant list per capsule, the `ExecutionNetwork`
     declaration the capsule runtime already consumes — supplied to the model as a normalized
     `{ capsuleId, egressGrants: number, ingressGrants: number }[]`). Each capsule classifies as:
     - **`exposed-ingress`** when it has ≥1 ingress grant (reachable from outside its netns),
     - **`egress-only`** when it has ≥1 egress grant and 0 ingress grants,
     - **`network-mute`** when it has 0 egress AND 0 ingress grants (the default-deny baseline — the node's networking
       arc S1–S3 makes capsules network-mute by default; this tier MUST be reported accurately, not assumed).
   - The result is a frozen object `{ host: { openIngressPorts, wideOpen: boolean, rules }, capsules: [{ capsuleId,
     exposure, egressGrants, ingressGrants }], counts: { exposedIngress, egressOnly, networkMute } }`, deterministically
     sorted (capsules by `capsuleId`; rules by proto/port/sourceCidr) for byte-stable output.

The two halves compose into one `summarizeDashboard(input)` returning `{ protection, exposure }`. **Every input is
untrusted JSON** (it ultimately comes from the agent's `/read` over the wire), so the model MUST run each input through
`safeNormalize` (`sdk/typescript/src/safe-normalize.ts`) and **fail CLOSED**: malformed/cyclic/partial/lying-Proxy
input ⇒ a typed `{ ok: false, errors }` rejection (NEVER a throw at the trust boundary, NEVER a fabricated "protected"
status from garbage). Mirror the validator discipline already used in `storage-model.ts`/`backup-model.ts`
(`safeNormalize` → `reject(...)` on unknown fields / wrong types / out-of-range; `Object.freeze` the result; collect
`{ path, message }` errors). A missing capability read-state (e.g. the node has no `backup.policy` yet) is NOT an error
— it deterministically yields the `absent` tier (graceful degradation), but a STRUCTURALLY INVALID state that IS
present (wrong type, unknown enum) IS a rejection.

**On-device marker (MEASURED — never synthesized; the QEMU boot is the real floor).** Add
`os/x86_64/ts-overlay/usr/lib/vita/ts/vita/protection-dashboard.ts`: read the REAL agentd states via the existing
`AgentClient.getState` for `storage.layout`, `backup.policy`, `backup.archive`, `network.policy`, `capsule.registry`
(the capsules' egress/ingress grant counts derived from the registry + the capsule states the node actually has),
build the dashboard with `summarizeDashboard`, and emit on the serial:
`VITA-PROTECT-DASH: snapshots=<active|configured-inactive|absent> mirror=<active|absent> localBackup=<verified|configured|absent> offSite=<configured|absent> exposed=<N> mute=<M> wideOpen=<yes|no> status=OK`
ONLY when the dashboard was computed from real read-states (the counts MEASURED from the node's actual state, not
hardcoded). On a read/transport failure emit `VITA-PROTECT-DASH-ERROR: reason=<sanitized-step> status=FAILSAFE`, and on
a fail-closed model rejection (a deliberately malformed state) emit
`VITA-PROTECT-DASH-REJECT: reason=<sanitized> status=OK` (markerToken-sanitize the reason — mirror `backup.ts`). Wire
the emit into `main.ts` AFTER the existing VITA-BACKUP marker; keep ALL prior markers
(VITA-TS→EVAL→PREVIEW→EXPLAIN→CONNECT→STATE→APPLY→CAPSULE-*→PDS→FILES→DRIFT→BACKUP) intact on the same boot.

## User value
Phase-5 ships the "UniFi-style overview for data protection and exposure" so the household operator can see, at a
glance and ACCURATELY, how protected their data is (snapshots vs mirror vs local backup vs off-site — the exact
four-way distinction the exit gate audits) and what is exposed to the network (which apps can reach out, which can be
reached, which are network-mute, and whether anything is dangerously wide-open). Accuracy is the whole point: a
dashboard that claims a backup tier or a closed network the node does not actually have is worse than none. This model
is the deterministic, fail-closed core the controller/web UI renders; building it as a pure SDK model (UI-agnostic,
fully unit-testable, boot-verified) lets the eventual UI be a thin presentation layer.

## Non-goals
- **No UI rendering / no web component / no controller HTTP endpoint** — this is the data MODEL + an on-device driver
  only. Visual layout, colors, and the controller wiring are a later slice.
- **No new agent capability, no mutation, no /apply** — strictly read-only over EXISTING `/read` states. The model does
  not call agentd to change anything; it only summarizes.
- **No dependency on P1-074 (runtime btrfs snapshots) being merged** — the snapshot tier is derived from the DECLARED
  `storage.layout` (already merged). If/when a measured snapshot-count read-state exists, the model accepts it as an
  OPTIONAL input but never requires it. Do not block on or import P1-074 artifacts.
- **No off-site backup EXECUTION** — P1-066 is local-only; off-site is classified as `configured`/`absent` from the
  declared policy, never `verified`.
- No mirror/RAID IMPLEMENTATION (the model reports `absent` honestly when no mirror indicator is present; it does not
  build RAID).
- No historical/time-series data, no alerting/notifications, no PII/diagnostics export (separate Phase-5 deliverables).
- No changes to `storage.layout`, `backup.policy`, `backup.archive`, `network.policy`, or `capsule.registry` behavior or
  wire shapes — REUSE them.

Protection tiers (`protection-dashboard-model.test.ts`):
- **snapshots distinction:** a `storage.layout` with a `snapshots` area + `cadence:"daily"` + `retentionCount:7` ⇒
  `snapshots.status === "active"`; the SAME area with `cadence:"disabled"` (retention 0) ⇒ `"configured-inactive"`;
  a layout with NO `snapshots` area ⇒ `"absent"`. (Assert the model reads the DECLARED layout, not a runtime count.)
- **mirror honesty:** a single-`dataVolume` layout ⇒ `mirror.status === "absent"` (NOT fabricated); with the optional
  `mirrorDevices: 2` input ⇒ `"active"`. A garbage `mirrorDevices` value REJECTS (not silently treated as a mirror).
- **localBackup distinction:** `backup.policy` target `attached-disk` + a measured `backup.archive` `verified=OK`
  last-result ⇒ `"verified"`; same target with NO verified round-trip ⇒ `"configured"`; no local target ⇒ `"absent"`.
- **offSite distinction:** `backup.policy` target `remote-object` (or `peer-node`/`sftp`/`vendor-managed`) ⇒
  `offSite.status === "configured"`; a `local-snapshot`-only policy ⇒ `offSite "absent"` AND `localBackup` non-absent
  (the two tiers are independent and not conflated — the exit-gate accuracy case). `offSite` is NEVER `"verified"`.
- **overall:** `protectedTiers` equals the count of non-`absent` tiers; a fully-bare node ⇒ all four `absent`,
  `protectedTiers === 0`.
- **fail-closed:** a non-object / cyclic / lying-Proxy / unknown-field / wrong-type / unknown-enum input ⇒
  `{ ok: false, errors: [...] }` (never throws, never returns a fabricated protected status). A MISSING (absent)
  capability state ⇒ deterministic `absent` tier (NOT an error). Determinism: the same input twice ⇒
  `JSON.stringify`-identical output.

Exposure (`protection-dashboard-model.exposure.test.ts`):
- **per-capsule classification:** a capsule with ingress grants ⇒ `"exposed-ingress"`; egress-only ⇒ `"egress-only"`;
  zero/zero ⇒ `"network-mute"`; `counts` tallies all three correctly; output sorted by `capsuleId` (byte-stable).
- **host wide-open flag:** a `network.policy` allow rule with `unsafeWideOpen:true` or a `0.0.0.0/0`/`::/0` source ⇒
  `host.wideOpen === true` and the rule surfaced; a scoped rule (e.g. `192.168.1.0/24`) ⇒ `wideOpen === false`.
  `openIngressPorts` lists the allowed ports deterministically.
- **fail-closed exposure:** malformed `network.policy`/capsule input ⇒ rejection (no throw); an absent `network.policy`
  ⇒ empty host surface + `wideOpen:false` (deterministic, not an error). A capsule with a non-integer grant count
  REJECTS (no silent coercion).
- A trivial/no-op model (always `network-mute`, or always `absent`) MUST FAIL these suites.

Orchestrator host-verify (Borg51 QEMU boot, MEASURED — added by the orchestrator, NOT the worker): boot the verity

## Performance & security constraints
- **Security model (encode it):** the TS runtime is UNPRIVILEGED and this model is **read-only** — it performs NO
  mutation and defines NO new agent capability. ALL privileged state lives behind the narrow Go `agentd`; the model only
  consumes agentd's `/read` responses (already validated server-side) and re-validates them at the TS trust boundary via
  `safeNormalize` before use. There is no path from this model to a privileged mutation. (Privileged mutation remains
  ONLY in agentd from a re-validated typed request — unchanged by this slice.)
- **Fail-CLOSED at the trust boundary:** every public entry runs `safeNormalize` first; malformed/cyclic/partial/
  accessor-getter/lying-Proxy input ⇒ a typed rejection, NEVER a throw and NEVER a fabricated "protected"/"mute" status
  derived from garbage (a dashboard that lies about protection or exposure is a security failure, per the exit gate's
  "accurately distinguishes" requirement). Reject unknown fields, wrong types, and unknown enum values.
- **No secrets surfaced:** the dashboard reports tier STATUS + opaque target KINDS + grant COUNTS only — it MUST NOT
  echo backup credential/bucket/endpoint refs, recovery-key handles, or any opaque secret ref into its output or the
  marker. If a read-state carries such fields, they are dropped, not propagated. (Reuse the secret-field awareness from
  `backup-model.ts`; do not re-emit `credentialRef`/`bucketRef`/etc.)
- **NO real keys / TPM / recovery / signing material** — owner-held (§16). Use TEST/fixture read-states only; never
  generate or commit production key material.
- **Determinism (spec §8.2 spirit):** the model is a PURE function — no `Date.now`, no randomness, no I/O, no ambient
  state; same inputs ⇒ byte-identical output (sorted arrays, frozen objects). The on-device driver's I/O is confined to
  `protection-dashboard.ts` (the `getState` reads); the model in `protection-dashboard-model.ts` stays pure.
- **No remote imports; vendored/first-party only; lockfiles mandatory; no package lifecycle scripts; no FFI/native**
  (spec §9.3). The SDK model imports only existing first-party SDK modules; the on-device copy follows the existing
  vendoring convention (relative `./vita/…` imports under the ts-overlay).
- R-class: R2 (UI/SDK read-only model touching the cross-cutting data-protection + exposure surface; no TCB mutation) →
  **reviewer gate** (`npm run review -- P1-086`) `VERDICT: approve` AND independent orchestrator verification before merge.
