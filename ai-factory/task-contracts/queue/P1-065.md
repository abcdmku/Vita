## Objective
Phase 5 (spec §21 "Files and shared folders"), files arc slice 1: give the UNPRIVILEGED TypeScript runtime a **files
capability** — `list` / `read` / `write` / `stat` confined to a capability-SCOPED folder root — without ever handing the
runtime raw filesystem access. The narrow privileged Go agent (`agentd`) MEDIATES every file operation: the runtime
proposes only `{op, relPath, [data]}` over the existing `/run/vita-agent/agentd.sock` unix transport (ADR-0008,
P1-035), and agentd resolves it under the granted root, enforces the scope, and acts. The runtime gets NO `--allow-read`
/ `--allow-write` for the data root — agentd is the only process that touches it (mirroring how the runtime proposes
config/capsule operations and agentd validates+applies, never the reverse).

Concretely:

- **Grant shape (re-validated, manifest-driven).** A files grant declares a single scoped folder root + access mode:
  `{ name, root, access: "read-only" | "read-write" }` where `root` is an agentd-resolved key (NOT a runtime-supplied
  absolute path) — agentd maps the grant `name` → an absolute base under the per-capsule/per-owner data area
  (`/var/lib/vita/files/<scope-id>/<name>`, on the persistent /var from P1-029; reuse the StateDirectory-style
  ownership discipline proven in P1-046 — agentd owns + creates the dir, the runtime never does). Define the grant
  TS type in `sdk/typescript/src/files-grant.ts` (shared, no duplication) and the Go decode/validate in
  `agent/capabilities/files/files.go`. The runtime CANNOT widen its own grant: agentd reads the granted set from its
  own validated config, never from the request.

- **New agentd `/files` RPC handler (NOT a transactional capability).** Files ops are an interactive request/response
  surface, not a plan→apply transaction, so add a dedicated handler routed in `agent/transport/server.go` alongside
  the existing `/state` `/apply` `/read/{cap}` cases. One JSON envelope: `{ "op": "list"|"read"|"write"|"stat",
  "grant": "<grant-name>", "path": "<rel/path>", "data"?: "<base64 for write>" }`. agentd decodes STRICTLY
  (`decodeStrictJSON` / `DecodeJSONRequest`, reject duplicate keys per the AGENTS.md TCB-parser rule), then:
    - `list` → entries (name, kind ∈ {file,dir,symlink-skipped}, size, mtime) under the scoped subdir.
    - `read` → file bytes (size-capped, see constraints) — read-only AND read-write grants may read.
    - `write` → create/replace a file via the **atomic exclusive-temp + rename** pattern (the AGENTS.md TCB rule:
      `os.CreateTemp(dir, ".name-*.tmp")`, mode 0600, write→Sync→Close→Rename — NEVER a predictable `path+".tmp"`;
      rename is the single commit point, no fallible step after). REQUIRES a read-write grant; a write against a
      read-only grant is REJECTED.
    - `stat` → kind/size/mtime for one entry.

- **Scope enforcement (the security core) in `agent/capabilities/files/scope.go`.** Resolve the request's relative
  path against the grant's absolute base and PROVE the result stays inside the base. Fail CLOSED on: absolute paths,
  `..` traversal, empty/`.`/`..` segments, NUL bytes, and — critically — **symlink escape** (a symlink inside the
  scope that points outside it MUST NOT be followed for read/write/list; resolve with `filepath.EvalSymlinks` (or an
  O_NOFOLLOW open) and re-check containment, OR refuse to traverse symlinks at all and document the choice). Mirror
  the existing segment-rejection discipline in `agent/capabilities/storage/storage.go:416` and the `..` checks in
  `identity.go`/`pdssync.go`; do NOT re-roll a looser check. The check is a pure, well-tested function
  (`ResolveWithinScope(base, rel) (abs string, ok bool)`); a no-op/allow-all impl MUST fail the suite.

- **Unprivileged on-device wiring.** Add `os/.../ts/vita/files-client.ts` (a thin typed client over the existing
  `createDenoUnixSocketAgentTransport`) and call it from `main.ts`. The runtime keeps its AF_UNIX-only Deno sandbox
  (the socket-path-scoped `--allow-read/write` for the SOCKET ONLY, P1-035) — it gets NO filesystem allow for the
  data root. Emit a MEASURED marker proving a real round-trip: write a file → list it → read it back (bytes match) →
  stat it, all via agentd; THEN attempt an out-of-scope op (a `../escape` path AND a write against a read-only grant)
  and prove agentd REJECTS it.
  Markers: `VITA-FILES: grant=<name> op=write+read+list+stat bytes=<n> roundtrip=OK status=OK` (gated on the real
  write→read-back byte match, never synthesized); `VITA-FILES-REJECT: reason=<sanitized step, e.g. path_traversal |
  read_only_grant | unknown_grant> status=OK`; `VITA-FILES-ERROR: status=FAILSAFE`. Keep ALL prior markers.

## User value
The node becomes a real personal data product: an app (capsule) or the owner's runtime can store and retrieve files in
a folder it was granted — and provably ONLY that folder. The unprivileged runtime never holds raw FS access; the
privileged agent is the single mediator and enforces the scope (path-traversal- and symlink-safe, fail-closed), so a
compromised or buggy runtime cannot read or clobber anything outside its grant. This is the first deliverable of spec
§21 Phase 5 "Files and shared folders" and the substrate later shared-folder/role work builds on.

## Non-goals
NO multi-user/household roles or per-user ACLs (later Phase-5 slice). NO sharing a folder between capsules, NO
cross-grant access. NO directory create/delete/rename/move ops this slice (list/read/write/stat of FILES only; agentd
auto-provisions the grant ROOT, the runtime does not mkdir arbitrary subdirs — keep the op set minimal). NO quotas/
encryption (storage arc). NO controller UI. NO remote/network file access (local socket only). NO chunked/streaming or
random-access I/O (whole-file read/write within the size cap). The runtime never receives a raw FS path or
`--allow-read`/`--allow-write` for the data root. agentd composes/acts ONLY from the re-validated request + its own
granted-set; never from raw runtime text used as a path.

## Performance & security constraints
- **Unprivileged runtime, mediated FS (spec §3.4, §7.1):** the runtime gets NO raw FS access to the data root; agentd
  is the single mediator. agentd acts ONLY from the re-validated request + its own granted-set, NEVER from raw runtime
  text used directly as a path.
- **Fail-CLOSED everywhere:** invalid op / unknown grant / out-of-scope / traversal / symlink-escape / RO-write /
  oversize / malformed → reject with a sanitized reason; default-deny. A guard over untrusted input MUST NOT throw
  (a throw at the trust boundary is a DoS — return a rejection); prove with a malformed/cyclic regression.
- **Path-traversal- AND symlink-safe:** containment re-checked after symlink resolution (or symlinks refused +
  documented). Reuse the canonical segment-rejection discipline, not a looser local re-check.
- **Atomic writes (AGENTS.md TCB rule):** `os.CreateTemp(targetDir, ".name-*.tmp")` (random, O_EXCL), mode 0600,
  write→Sync→Close→Rename single commit point, no fallible work after; never a predictable temp name (TOCTOU/symlink
  hazard). Prove with a pre-existing-temp/symlink regression.
- **Size cap:** whole-file read/write bounded (e.g. ≤ 8 MiB per op — fix a constant, reject over it with a typed
  error) so a single op cannot OOM agentd.
- **Strict decode:** reject duplicate JSON keys before decoding; validate the FULL required shape (absent ≠ empty for
  optional fields). No keys/secrets — TEST data only; never commit/generate production key material (§16).
- **No remote imports** in the TS client; lockfiles mandatory; no package lifecycle scripts. R2 → reviewer gate
  (`npm run review` must APPROVE before merge, per the standing R2/R3/R4 gate).
