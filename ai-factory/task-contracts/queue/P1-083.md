## Objective
App-catalog arc capstone (spec §21 Phase 4 "Signed application catalog" + FR-010 "Install … apps"): the node turns a
**verified, signed catalog entry into a RUNNING capsule** — the supply-chain → run join. agentd gains a `capsule.install`
capability (R3) that, from a **re-validated resolved install descriptor**, drives the existing capsule primitives as ONE
fail-closed transactional flow:

1. **REGISTER** the installed-capsule entry in the registry (reuse `capsule.NewCapability()` /
   `installed-capsule-registry.json` — `agent/capabilities/capsule/capsule.go`), composed ONLY from the re-validated
   descriptor (`id`, `version`, `integrity`, `packageRef`, `packageClass`, declared `resourceLimits`/`grants`).
2. **FETCH BY SRI** the capsule package (reuse `capsulestorage.FetchCapsuleFor(ctx, ref, integrity, id, version)` from
   `agent/storage/capsules/fetch.go` — the P1-045 SRI gate; bytes are verified against the SRI BEFORE extraction, nothing
   staged on mismatch).
3. **EXECUTE** it as a hardened systemd transient unit (reuse `capsule.NewExecuteCapability()` /
   `agent/capabilities/capsule/execute.go` — the P1-044 jailer: DynamicUser, empty caps, NoNewPrivileges,
   ProtectSystem=strict, seccomp, cgroup caps from `resourceLimits`). agentd looks the executed capsule up in the
   registry it just wrote, so register→execute are consistent.

The whole flow is **fail-CLOSED**: if the catalog/entry/integrity does not verify — an unverified/tampered descriptor, a
malformed/absent SRI, a `packageRef` that is not a references-only mirror/`file://` artifact, an SRI mismatch at fetch, or
a registry/execute failure — agentd REGISTERS NOTHING that would leave a half-installed capsule and starts NO unit, with a
transactional undo that unwinds any partial state (unregister + stop/unlink the unit). The privileged mutation happens
ONLY in the narrow Go agentd from a **re-validated manifest**, never from raw runtime text.

**TS / host side (the trust the agentd descriptor stands on):** the UNPRIVILEGED runtime FIRST resolves the install
plan from a VERIFIED signed catalog before it ever proposes an install — reusing P1-063 `verifyCatalog` (the catalog
signature/per-entry integrity gate) and P1-071 `resolveFromCatalog` (verified-catalog entry → mirror-resolved → install
plan). A new SHARED, pure `sdk/typescript/src/catalog-install-plan.ts` exports `toAgentInstallDescriptor(plan)`: it maps a
verified `resolveFromCatalog` result to the exact `{ id, version, integrity, packageRef, packageClass, resourceLimits,
grants }` install descriptor agentd re-validates — fail-closed (`safeNormalize` the input; reject if the plan is not
`ok:true`/verified, if any SRI is malformed, or if `packageRef` embeds material §13.1). The on-device runtime calls a thin
`install-client.ts` over the existing unix transport (ADR-0008 / P1-035) to propose `capsule.install` for a BAKED
test catalog entry, and prints a MEASURED marker only after agentd reports the capsule verified + running:

- `VITA-CAPSULE-INSTALL: id=<id> version=<v> sri=<algo>-<short> verified=OK running=OK status=OK`
  (gated on agentd's real outcome: the registry entry exists, the package was SRI-verified+staged, and the transient unit
  is `active`/health=OK — NEVER synthesized).
- `VITA-CAPSULE-INSTALL-REJECT: reason=<sanitized code, e.g. catalog_unverified | sri_mismatch | unknown_app |
  policy_rejected | embedded_material> status=OK` (a tampered/unverified catalog entry OR a forced-bad SRI → fail-closed,
  nothing installed, nothing running).
- `VITA-CAPSULE-INSTALL-ERROR: status=FAILSAFE` (transport/unexpected — never crash the oneshot).

## User value
This closes the largest Phase-4 gap (STATE.md: "no app supply chain yet") end-to-end: a node can take an app from a
trusted, signed catalog and have it **installed and running** as a hardened, resource-capped, unprivileged capsule —
"install an app" (FR-010) realized on-device. The catalog signature, the per-entry integrity, and the mirror byte-SRI are
the chain of custody; a tampered catalog, a substituted/corrupt artifact, or an unknown app each fail closed before
anything is registered or executed. It composes the already-merged supply-chain (P1-063/064/071/072) with the already-
merged capsule lifecycle (P1-044/045) into the single operation the SDK/CLI and a future controller drive.

## Non-goals
- **NO new fetch/execute/registry mechanism** — REUSE the merged `FetchCapsuleFor`, `NewExecuteCapability`,
  `NewCapability` (registry) and their hardening; do NOT re-implement or loosen any of them. This slice is the
  ORCHESTRATION + the install descriptor seam, not new primitives.
- **NO network registry pull / OCI image install** — the package artifact is a local/mirror `file://`/tar(.zst) bundle
  baked or mirror-staged into the image (per P1-045/072); ts-service class only (OCI/WASM install is a later slice).
- **NO catalog signature verification IN agentd** — agentd's trust anchor is the re-validated descriptor + the SRI it
  re-verifies at fetch; the ed25519 catalog-signature gate stays TS-side (P1-063 `verifyCatalog`, run before the runtime
  proposes). agentd MUST still independently re-validate every descriptor field and SRI fail-closed (defense in depth);
  it never trusts the runtime's "I verified the catalog" claim — it refuses any artifact whose bytes do not match the SRI.
- **NO update / stop / start / remove / restore** (those are sibling FR-010 verbs — separate slices). NO multi-version /
  rollback / dependency-closure install on-device (the dep closure is resolved host-side by P1-071; this slice installs
  ONE resolved capsule). NO controller UI / CLI command (the CLI `vita install` is P1-070, host-side).
- **NO real keys/secrets** — TEST catalog signing key only (P1-063 fixture, §16: real release/signing/TPM/recovery keys
  are OWNER-HELD, never committed or generated). NO embedded package bytes/secrets in the catalog/descriptor (references
  only, §13.1).

## Performance & security constraints
- **Runtime PROPOSES; agentd VALIDATES + ACTS + fails closed.** The privileged register/fetch/execute happens ONLY in
  agentd, composed from a re-validated descriptor — never from raw runtime text. The runtime gets no new privilege; it
  reaches agentd ONLY over the existing AF_UNIX-only transport (P1-035), keeping its socket-scoped Deno sandbox.
- **SRI is the on-device trust anchor (defense in depth).** agentd re-verifies the fetched bytes against the descriptor
  SRI before extraction (reuse the P1-045 gate); a tampered/substituted artifact is refused, nothing staged/registered/
  run. The catalog ed25519 signature is verified TS-side (P1-063) BEFORE the runtime proposes; agentd does not trust that
  claim, it independently re-validates every field + the SRI.
- **Fail-CLOSED + transactional.** Validate → register → fetch → execute, recording undo at each step (unregister +
  stop/unlink) so any failure unwinds to no half-installed capsule; default-deny on every invalid/ambiguous/exotic input;
  a guard over untrusted input MUST NOT throw (a throw at the trust boundary is a DoS — return a rejection). Strict decode
  (reject duplicate JSON keys; validate the full required shape; absent ≠ empty).
- **New attack surface (ADR-0009): agentd now installs+spawns a workload from catalog data.** The spawned capsule MUST run
  under the full P1-044 hardening (unprivileged DynamicUser, no caps, seccomp, ProtectSystem=strict, cgroup-capped) so a
  malicious catalog app cannot escalate — ties to the Phase-4 exit gate "Untrusted TS package cannot access undeclared
  file/network/env/subprocess/FFI resources" and "Community app failure cannot disable the controller."
- **References only, no embedded material (§13.1); ts-service class only.** **NO real keys/secrets** — TEST catalog
  signing key only (§16: real keys owner-held; never commit/generate production material). No remote imports in the TS
  client; lockfiles mandatory; no package lifecycle scripts; no FFI/native addons. R3 (boot/identity-adjacent privileged
  TCB: agentd installs+runs untrusted catalog code) → **parallel-candidate strategy (two independent worker attempts) +
  reviewer gate** (`npm run review -- P1-083` must `VERDICT: approve`) + independent orchestrator verify + host-verify
  before merge.
