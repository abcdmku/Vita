## Objective
Formalize the THREE-LAYER desktop architecture (owner directive): a STABLE public **Vita Desktop SDK** that a SWAPPABLE
desktop **UI package** (screens/elements/theme) targets, with CEF as a separate shared engine the SDK exposes (not
bundled in the UI package). Pure, deterministic, headless TypeScript.
1. **`@vita/desktop-sdk` public surface (`sdk/typescript/src/desktop-sdk/index.ts`):** a SINGLE curated public API a UI
   package imports — re-export + stabilize ONLY the consumer-facing types/ports from the merged platform: the surface/
   window model (PSD-005), WM intents + layouts/workspaces (PSD-004/014), app+window launch/lifecycle (PSD-008/013), the
   compositor render seam (PSD-009 CompositorPort/placement, no-repaint), capability ports (notifications/tray PSD-016,
   files PSD-007, settings, launcher), theme tokens, and the preview/apply/rollback lifecycle. It MUST NOT expose
   platform internals (agentd, capsule runtimes, the native compositor binding, the substrate seam) — those stay private.
   Carry an explicit `SDK_VERSION` (semver).
2. **UI-package contract (`ui-package.ts`):** a `DesktopUiPackage` interface — a manifest (`id`, `version`,
   `sdkVersion`, `entry`, declared capability grants) + a `mount(host: DesktopHost): DesktopUiInstance` where `DesktopHost`
   is the SDK-provided handle the package uses to register screens/components, request surfaces, launch apps, post
   notifications, read theme — ALL via the SDK, never platform internals. `unmount()` tears it down cleanly.
3. **Loader + swap (`loader.ts`):** `loadUiPackage(manifest, host)` — validate `sdkVersion` COMPAT (semver; reject
   incompatible fail-closed), mount, and support SWAP (unmount current → mount next) with the PSD-005 preview/apply/
   rollback + a KNOWN-GOOD FALLBACK package so a broken/incompatible UI package can never brick the desktop. Deterministic;
   injected ports (tests use fakes); fail-closed everywhere.

## User value
The architecture that lets users build/ship/SWAP their own desktop UI: a robust stable SDK contract, a clean UI-package
boundary, and a fail-closed loader with fallback — so the screens/look/theme are a swappable package, CEF is a shared
engine, and the platform internals stay hidden.

## Non-goals
- NO GPU/CEF here (the SDK exposes the render seam; CEF integration is PSD-000/020). NO concrete UI/screens (the flagship
  UI is a SEPARATE package built on this SDK — a later slice). Don't re-implement the merged modules — RE-EXPORT/wrap them.

## Acceptance
`acceptance_command` passes: the SDK surface exposes the consumer API + hides internals (a test asserts internals are not
re-exported); manifest + sdkVersion-compat validation (incompatible rejected fail-closed); load→mount a fake UI package
against a fake host; swap (unmount→mount); a broken/incompatible package falls back to known-good without bricking;
comprehensive deterministic unit tests. Pure, headless.

## Security/constraints
- The SDK is the ONLY surface a UI package may use; platform internals stay private. Capability-mediated (the host
  enforces the package's declared grants), fail-closed; preview/apply/rollback + known-good fallback. Pure/deterministic,
  injected ports. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `@vita/desktop-sdk` public surface (versioned, internals hidden) + `DesktopUiPackage`/`DesktopHost` contract + loader
  with sdkVersion-compat + swap + known-good fallback; comprehensive headless unit tests (incl. internals-not-exposed,
  incompat-rejected, swap, fallback); typecheck clean. R2 reviewer gate.
