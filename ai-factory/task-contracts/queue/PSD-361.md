## Objective
Build the **app-package SDK/contract foundation** that every first-party app (PSD-362..PSD-368) implements, plus the pure
app-registry/loader view-model that lists/launches them. This realizes ADR-0016 (PSD-360) decisions (a)+(c). Two parts:

1. **`AppPackageManifest` type + helpers** at `sdk/typescript/src/desktop-sdk/app-package.ts`, mirroring
   `DesktopUiPackageManifest` (`sdk/typescript/src/desktop-sdk/ui-package.ts:43-49`) but for an APP:
   - `interface AppPackageManifest { readonly id; readonly version; readonly sdkVersion: DesktopSdkCompatibility;
     readonly entry: string; readonly capabilityGrants: readonly DesktopCapabilityGrant[]; }` — reuse the EXISTING
     `DesktopCapability`/`DesktopCapabilityGrant`/`DesktopSdkCompatibility` types from `ui-package.ts` (import, do NOT
     redefine). `entry` is the CEF-rendered web-app bundle entry (HTML, like `DESKTOP_UI_ENTRY`).
   - `interface AppPackage { readonly manifest: AppPackageManifest; readonly descriptor: WebAppDescriptor; }` — the unit a
     first-party app exports (a manifest + the `WebAppDescriptor` from `../appshell/index.ts:85` that
     `DesktopHost.launchApp` consumes; `surfaceKind:"web"`, `runtime:{ url, partition }`).
   - A pure `hasAppCapabilityGrant(manifest, capability): boolean` (mirror `hasDesktopCapabilityGrant`) and a
     `defineAppPackage(input): AppPackage` that validates/freezes (fail-closed on a malformed manifest: empty id, missing
     entry, duplicate/unknown capability, or a descriptor whose `runtime.url` !== `manifest.entry`).
   - Export all of the above from `sdk/typescript/src/desktop-sdk/index.ts` (add to the existing barrel; do NOT remove
     existing exports).
2. **Pure app-registry/loader view-model** at `ui_kits/desktop/viewmodels/app-registry.ts`, in the SAME headless,
   deterministic, injected-port style as the existing view-models (`ui_kits/desktop/viewmodels/files.ts`,
   `dock.ts`, `Settings.ts`): a factory taking an injected `Pick<DesktopHost, "launchApp" | "stopApp">` (+ optionally
   `emitLauncherIntent`) port subset and a frozen list of installed `AppPackage`s; a frozen `snapshot()` and actions:
   - `list()` — deterministic, sorted (by `manifest.id`) view of installed apps + their running state.
   - `launch(appId)` — looks up the app, calls `host.launchApp(app.descriptor)`, records the running launch (surface/
     window/texture ids from `DesktopAppLaunch`); fail-closed if the app is unknown, already running, or the port denies.
   - `stop(appId)` — calls `host.stopApp(appId)`, removes it; fail-closed if not running or the port denies.
   - All results are frozen discriminated-union `{ ok:true; value } | { ok:false; error }` like the SDK host results.
   - NO DOM/CSS/rendering, NO ambient I/O, NO platform internals — only injected SDK ports.

## User value
The single contract every first-party app implements (`AppPackageManifest` + `AppPackage`) and the pure logic the dock/
launcher uses to list + launch + stop installed apps on the real `DesktopHost` seam — the foundation that lets the 7
first-party apps build concurrently and lets users ship/swap their own apps.

## Non-goals
- NO DOM/CSS/CEF/rendering. NO platform internals. NO host-backend wiring (that is ADR-0015/PSD-340). NO compositor code.
- Do NOT redefine `DesktopCapability`/`DesktopCapabilityGrant`/`WebAppDescriptor` — import the existing types.
- Do NOT implement any specific app here (that's PSD-362..PSD-368). Do NOT change the `DesktopHost` interface.

## Acceptance
`acceptance_command` passes: deterministic `node --test` unit tests at
`sdk/typescript/test/ui-kits/app-registry.test.ts` cover `AppPackageManifest`/`defineAppPackage` validation
(valid manifest accepted+frozen; empty id, missing entry, unknown/duplicate capability, descriptor-url mismatch each
fail-closed), `hasAppCapabilityGrant`, and the registry view-model state transitions (`list()` deterministic ordering;
`launch`/`stop` happy paths against fake ports; fail-closed on unknown app, double-launch, stop-when-not-running, and a
denying port). `npm run typecheck` is clean. Pure, headless, no network. (The exact test path exists only when the work
lands — an empty branch fails.)

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic (same inputs ->
  byte-identical snapshot). No remote imports; lockfile; no lifecycle scripts; no FFI/native addons.

## Hardware profiles
Portable-first; host-agnostic, runs on any dev box (no GPU/VM needed).
