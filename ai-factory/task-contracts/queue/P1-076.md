## Objective
Phase 2 "system control" gap (spec §8.4 lines 365-366: *"Manual host changes are detected as drift. Drift is either
reverted or explicitly adopted into TypeScript state."* — and the §17.x roadmap "Drift detection", spec line 1069):
detect **config drift** between the node's DECLARED plan and the ACTUAL observed host state, ON-DEVICE, deterministically,
and fail-CLOSED — REUSING the evaluator (P1-033) + the `TransactionPlan` diff (P1-034) + the read path (P1-038).

The model: the evaluator turns the declared node config into a `TransactionPlan` (the *intent*). agentd's per-capability
`/read/{cap}` reports the *observed* host state (e.g. `hostname.set` → `{ "current": "<live-hostname>" }`,
`agent/capabilities/hostname/hostname.go:49`). Drift = the observed state DIFFERS from what the declared plan asked for.
This slice computes that diff and surfaces it as added / removed / changed capabilities, on-device, gated on a REAL
agentd read round-trip.

Concretely:

- **A pure `computeDrift` module — the source-of-truth in `sdk/typescript/src/drift.ts`, vendored on-device.** Define a
  pure, deterministic, no-I/O function:
  `computeDrift(declared: TransactionPlan, observed: ObservedState): DriftResult`
  where `ObservedState` is a map `{ [capability: string]: PlainJsonObject }` of the per-capability state agentd returned
  (the `AgentCapabilityState` shape from `agent-client.ts`, e.g. `{ current: "<value>" }`). `computeDrift`:
    1. **Projects** the observed per-capability state into a synthetic OBSERVED `TransactionPlan` whose operation
       `request` for each declared capability is built from that capability's observed `current` value (a tiny,
       capability-keyed, EXPLICIT projection table — see Non-goals: hostname.set is the v1 entry; the table is the only
       per-capability knowledge and is data-driven so more caps add a row, not a branch). A declared capability with NO
       observed entry → it is ABSENT from the observed plan (so the diff reports it `removed`/`changed` per the rule below).
    2. **Reuses `diffTransactionPlans(declared, observedPlan)`** (P1-034, byte-for-byte — do NOT re-roll a diff) to get
       `{ added, removed, changed }` by capability, where for drift:
         - `changed` = a declared capability whose observed `request` differs from the declared `request` (the host was
           manually changed away from intent — REAL drift).
         - `added` = a capability observed but not declared (host has state the plan never asked for).
         - `removed` = a capability declared but not observed/unreadable (intent the host no longer reflects).
    3. Returns a FROZEN `DriftResult { drifted: boolean; added; removed; changed }` where `drifted` is
       `added.length + removed.length + changed.length > 0`. Deterministic + sorted (inherit the diff's sort).
  The module is PURE (no FS/network/privilege); it runs the SAME under `node --experimental-strip-types` and Deno.

- **Fail-CLOSED on malformed observed state.** The observed state comes from agentd (trusted) but is treated as
  UNTRUSTED at this boundary (mirroring the diff's discipline): run every observed-state object through `safeNormalize`
  before projecting; a Proxy / accessor / exotic-prototype / non-object / cyclic observed value → REFUSE (throw a
  `DriftError`, never a benign `drifted=false`). The on-device caller catches it and emits the FAILSAFE marker — NEVER a
  bogus `drift=no`. A drift result that silently claimed "no drift" because it could not read the observed state would be
  fail-OPEN (the whole point of drift detection is defeated). Prove with a malformed/lying-Proxy observed regression.

- **On-device wiring (`os/.../ts/vita/drift.ts` vendored from the SDK + `main.ts`).** Vendor `drift.ts` into
  `os/x86_64/ts-overlay/usr/lib/vita/ts/vita/drift.ts` (byte-identical except a `// Vendored from sdk/typescript/src/
  drift.ts` header + import-path adjustments to the already-vendored `./evaluate.ts` / `./transaction-plan-diff.ts` /
  `./safe-normalize.ts`). In `main.ts`, AFTER `VITA-STATE` (the read path is already up — reuse the SAME `AgentClient`
  over the unix socket), for the declared registry's capabilities: evaluate the declared config → declared plan; read the
  observed per-capability state via the existing `client.getState(<cap>)` (reuse, do NOT add a Deno permission or a new
  endpoint); `computeDrift(declared, observed)` → emit the MEASURED marker:
    - `VITA-DRIFT: declared=<N> observed=<M> drifted=<true|false> added=<a> removed=<r> changed=<c> status=OK`
      (gated on a real `getState` round-trip — the observed counts/booleans are MEASURED from agentd, never synthesized).
    - On a malformed observed value (`DriftError`) → `VITA-DRIFT-REJECT: reason=<sanitized> status=OK` (fail-closed).
    - On any transport/read failure (never crash the oneshot) → `VITA-DRIFT-ERROR: status=FAILSAFE`.
  Demonstrate BOTH outcomes deterministically: emit one `VITA-DRIFT` for the live observed state (the node's real
  hostname vs the declared one — `drifted` is whatever the boot actually measures, true OR false, both valid) AND, to
  prove the detector actually detects, a second `VITA-DRIFT` over a SYNTHETIC observed map that deliberately differs from
  the declared plan → `drifted=true changed>=1` (proving the projection + diff catch a real divergence on-device). Keep
  ALL prior markers (VITA-TS → EVAL → PREVIEW → EXPLAIN → CONNECT → STATE → APPLY → CAPSULE-* → PDS → FILES).

## User value
The node can tell when reality has drifted from its declared TypeScript intent — a manual `hostnamectl` on the box, a
hand-edited config, anything that moves the live host away from the plan is DETECTED, deterministically, on-device. This
is the read-only first half of spec §8.4's drift contract ("detected as drift" — the revert/adopt half is a later slice)
and a load-bearing piece of self-managing system control: without drift detection the node cannot know it needs to
re-converge. It reuses the proven evaluator + diff + read path, so it adds the *detection* with near-zero new surface.

## Non-goals
- NO revert and NO adopt (spec §8.4's second half) — this slice DETECTS drift only; remediation (re-apply to revert, or
  fold observed state into declared intent) is a separate later slice. The runtime gains NO new mutation authority.
- NO new agentd endpoint and NO new Deno permission — REUSE the existing `/read/{cap}` via `client.getState` over the
  already-open unix socket (P1-035/P1-038). If a needed read genuinely does not exist, the slice still ships using
  `hostname.set` (which DOES expose `current`) — do NOT add a privileged surface to widen coverage.
- NO multi-capability projection table beyond what's cleanly observable: ship `hostname.set` as the v1 projected entry
  (clean `current` string). The projection table is DATA-DRIVEN (one row per capability) so future caps are additive; do
  NOT hand-roll per-capability `if` branches or invent observed→request mappings for caps whose `/read` shape isn't a
  clean field map yet.
- NO re-rolled diff — reuse `diffTransactionPlans` exactly. NO forking/rewriting the evaluator (vendor exact source, per
  P1-033). Do NOT weaken `safeNormalize`. Do NOT touch the verity/SB/agentd-binary paths or `build-and-boot.mjs`.

## Acceptance tests
`acceptance_command` — `node --experimental-strip-types --test "os/x86_64/ts-overlay/usr/lib/vita/ts/drift.test.ts"`
(runnable by the worker on Windows/any OS, NO Deno/agentd needed — the test drives `computeDrift` directly + against a
MOCK observed map). The test MUST assert:
1. **No-drift** — declared plan vs an observed map projecting back the SAME values the declared plan asked for →
   `drifted=false`, all of added/removed/changed empty.
2. **Drift detected (changed)** — observed map gives a DIFFERENT `hostname.current` than declared → `drifted=true`,
   `changed` contains `hostname.set`, added/removed empty.
3. **Drift detected (removed)** — a declared capability with NO observed entry → it appears in `removed`, `drifted=true`.
4. **Determinism** — `computeDrift` over the same inputs returns a byte-identical (deep-equal + same sorted order) result
   across repeated calls.
5. **Fail-closed** — a malformed observed value (a lying Proxy over the state object that reports a fake shape; an
   accessor/getter property; a non-object; a cyclic value) → `computeDrift` THROWS `DriftError` (never returns a benign
   `drifted=false`). A no-op/always-`drifted=false` implementation MUST fail tests 2/3/5.
6. **Diff reuse (no drift)** — assert the result is consistent with `diffTransactionPlans` (import both; a drift over
   projected plans equals the underlying capability diff) — proving the slice composes the proven diff, not a weaker copy.
Also include the SDK-side `sdk/typescript/test/drift.test.ts` (the source-of-truth tests) and `npm run typecheck` clean

## Performance & security constraints
- **Pure/deterministic (spec §8.2/§8.4):** same inputs → byte-identical `DriftResult`; no FS, no network, no clock, no
  privilege inside `computeDrift`. Sorted/stable output (inherits the diff's determinism).
- **UNPRIVILEGED runtime, mediated read (spec §3.4/§7.1):** drift detection only OBSERVES (via the existing read path);
  it gains NO mutation authority and NO new Deno permission. agentd remains the only privileged actor and is untouched.
  The runtime never reverts/adopts here — detection only.
- **Fail-CLOSED at the observed-state boundary:** every observed-state object passes through `safeNormalize` BEFORE
  projection; malformed/exotic/lying-Proxy observed input → REFUSE (throw `DriftError`) → the caller emits
  `VITA-DRIFT-REJECT`/`VITA-DRIFT-ERROR`, NEVER a fail-open `drifted=false`. A guard at this boundary must not silently
  swallow into "no drift".
- **MEASURED marker:** the `VITA-DRIFT` counts/booleans for the live state are gated on a real `client.getState`
  round-trip; never synthesized. The boot is the real floor.
- No keys/secrets — TEST data only; never commit/generate production key material (§16: signing/TPM/recovery/mesh keys
  are owner-held). No remote imports in the SDK module or the vendored copy; lockfiles mandatory; no package lifecycle
  scripts; no FFI/native addons. R2 (control-plane drift surface + reads observed host state) → reviewer gate
  (`npm run review` must APPROVE before merge, per the standing R2/R3/R4 gate).
