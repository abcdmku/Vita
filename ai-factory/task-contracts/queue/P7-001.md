## Objective
A transactional capability `agent/capabilities/network/` that stores a validated **default-deny inbound
firewall policy** (spec §12.1) to a FIXED agent state path, atomically with rollback — same proven
pattern as nodeconfig (P1-007). A typed `Policy` is an explicit ALLOWLIST of inbound rules (proto +
port + source CIDR + interface); everything not explicitly allowed is denied (default-deny). `Handle`
reads the current policy; `Apply` validates a desired policy and writes it via a single atomic commit
point (temp + rename — nothing fallible after the rename), returning an `Undo` that restores prior bytes.
Integrate with the transaction engine (commit + rollback proven). Implements `Validate()` for the
transport pre-transaction gate (P1-008). Injected FS facade for tests.
- **Validate fail-closed**: reject rules with invalid proto/port (0 or >65535)/malformed CIDR; reject an
  allow-rule that is effectively "allow all" inbound (e.g. 0.0.0.0/0 to all ports) unless an explicit
  typed `unsafeWideOpen` flag is set (default-deny posture). Request data never becomes a path/command.

## User value
The on-host firewall desired-state (FR-017, §12.1 default-deny perimeter) the controller will manage —
the security boundary for the node. Proves the capability pattern for network policy.

## Non-goals
- No real nftables/netlink application to the kernel (needs a privileged host — a later enforcement
  contract). Store + validate the typed policy only. No `os/exec`/shell. No `cmd/agentd/main.go` edits
  (registration is a follow-up). No outbound/NAT policy (inbound default-deny only here).

## Dependencies
P1-006 (engine), P1-007 (atomic-file capability pattern). Both merged.

## Acceptance tests
`acceptance_command` (go test in golang:1.26) + orchestrator `go vet`. Cover: Handle reads current;
Apply writes + restoring Undo; transaction commit; rollback (later op fails ⇒ prior policy restored);
malformed rule (bad proto/port/CIDR) rejected without writing; an implicit allow-all rejected unless
`unsafeWideOpen`; atomic-write-failure leaves the live file unchanged (single commit point). Injected FS.
