## Objective
Extend the **`DesktopHost` port** (`sdk/typescript/src/desktop-sdk/ui-package.ts:123`) with three session/WM
capabilities the flagship desktop needs but the port does not yet expose: `focusWindow`, `requestLock`, and
`authenticateOwner` (the latter introduced by PSD-381). Today `DesktopHost` carries `launchApp`/`stopApp`,
notifications, tray, files, settings, and launcher-intent ports — but has no owner-auth, no focus/raise-window,
and no request-lock method. Add all three as **optional** host methods (same `DesktopMaybePromise<DesktopHostResult<T>>`
shape as `launchApp`/`stopApp` at `ui-package.ts:130-131`), each **capability-gated** and **plain-JSON** end to end.
- **Single enforcement point.** Wire each new method through the scoped proxy in
  `createDesktopHostForPackage` (`loader.ts:424`) exactly like `launchApp`/`emitLauncherIntent` do
  (`loader.ts:457-466`, `loader.ts:599-614`): normalize the request to plain JSON (a `normalize…` snapshot like
  `normalizeLauncherIntent` at `loader.ts:1048`), reject malformed input via `hostRejectFromValidation`, then
  check `hasDesktopCapabilityGrant(manifest, …)` (`loader.ts:408`) and `hostReject("MISSING_CAPABILITY", …)` on
  deny, and only then delegate to the underlying host port. The proxy must be installed conditionally
  (`if (host.focusWindow !== undefined) { scoped.focusWindow = … }`) mirroring the existing optional-port blocks.
- **New capabilities.** Add the new entries to the `DesktopCapability` union (`ui-package.ts:25`):
  `"wm.focus"`, `"session.lock"`, and `"session.authenticate"` (reuse the PSD-381 owner-auth capability name if
  PSD-381 already defines one — do not duplicate it).
- **Request/response types.** `focusWindow(request: { windowId: WindowId })` → `DesktopHostResult<true>`
  (use `WindowId` from `../wm/policy.ts`, already imported at `ui-package.ts:21`); `requestLock()` →
  `DesktopHostResult<true>`; `authenticateOwner(request: …)` → the PSD-381 result type. All inputs/outputs are
  plain JSON (`PlainJson`/`PlainJsonObject` from `../safe-normalize.ts`); no functions, no class instances.
- **Degraded-host fallback.** When the underlying `host.<method>` is absent at call time (degraded host), the
  proxy returns `{ ok: false, error: { code: "<PORT>_UNAVAILABLE", message, path } }` via `hostReject` — exactly
  as the settings/launcher blocks do (`loader.ts:572`, `loader.ts:612`). Never throw.
- Reuse existing helpers (`normalizeHostRequestObject`, `normalizePlainString`, `hostReject`,
  `hostRejectFromValidation`, field-list constants). Do not introduce new ambient I/O or remote imports.

## User value
Gives the CEF-rendered flagship desktop the owner-authenticated, focus-window, and lock primitives it needs to be
a real session shell — capability-mediated and fail-closed — so window-manager and lock-screen view-models can be
built on the public SDK instead of reaching into platform internals.

## Non-goals
- NO lock-screen UI / WM layout / DOM / CSS / CEF — this is the **port surface + proxy enforcement** only.
- NO new authentication backend or credential storage — `authenticateOwner` is the typed port; the credential
  check itself is PSD-381's concern and is consumed, not re-implemented here.
- Do NOT change the existing `launchApp`/`stopApp`/notifications/settings/launcher behavior or their grants.
- Do NOT loosen `snapshotCallableObject`/`safeNormalize` invariants or weaken any existing capability check.

## Acceptance
`acceptance_command` passes. The new deterministic test file
`sdk/typescript/test/ui-kits/SessionWmPort.test.ts` (created by this task) covers, against a fake underlying
`DesktopHost` and a manifest produced via the real `createDesktopHostForPackage` proxy:
- **grant path** — `focusWindow`/`requestLock`/`authenticateOwner` with a matching `capabilityGrants` entry
  delegate to the underlying host and return `{ ok: true }`;
- **deny path** — with the grant missing, each returns `{ ok: false, error.code === "MISSING_CAPABILITY" }`
  and the underlying host method is **not** called;
- **malformed input** — non-object / wrong-type / unexpected-field requests return a validation `ok:false`
  (e.g. `INVALID_HOST_REQUEST`) and never reach the underlying host;
- **degraded host** — when the underlying host omits the method, the proxy installs no method OR the call
  returns `{ ok: false, error.code }` ending in `_UNAVAILABLE` (assert the chosen, documented behavior), never throws;
- **plain-JSON** — the request object forwarded to the underlying host is a snapshot (mutating the caller's input
  afterward does not change what the host received).
`npm run typecheck` is clean. Pure, headless, no network.

## Security/constraints
- Capability-mediated, **fail-closed**; single enforcement point in the loader proxy (no second code path).
- Plain-JSON only across the boundary; snapshot inputs (no shared mutable references; no function/proxy leakage).
- Deterministic / no ambient I/O. No remote imports; lockfile mandatory; no package lifecycle scripts; no FFI.
- `allowed_network: false`.
