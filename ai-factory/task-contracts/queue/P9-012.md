## Objective
Add four GOVERNED, purely-STRUCTURED string formats to the closed `StringFormat` set (TS + Go, identical
structured checks — no regex engine, no canonicalization parity risk, so these are low-risk vs the IP/datetime
formats). They gate the accounts/services/storage migrations. Match the AGENT validators' exact rules (read
the cited cap files):
- **`posixUsername`** (accounts `name`/`primaryGroup`/`groups`, identity) — `agent/capabilities/accounts`:
  `^[a-z_][a-z0-9_-]{0,31}$` structurally (first char `[a-z_]`, rest `[a-z0-9_-]`, length 1–32). ASCII only.
- **`groupName`** — same rule as `posixUsername` (POSIX group name). (May alias the same checker.)
- **`systemdUnitName`** (services `name`) — `agent/capabilities/services`: a non-empty prefix + a recognized
  unit SUFFIX from the CLOSED set `.service .socket .device .mount .automount .swap .target .path .timer
  .slice .scope`; prefix charset `[A-Za-z0-9:._@-]` (match the agent's `validServiceName` EXACTLY); reject no
  suffix / empty prefix / leading `.`.
- **`absolutePath`** (storage/backup paths) — match the agent's `agent/capabilities/storage`
  `isCanonicalAbsolutePath` EXACTLY: `/`-prefixed; **REJECT root `/` itself** (`value == "/"` ⇒ reject);
  reject a trailing slash; each `/`-separated segment non-empty and not `.` or `..` and no NUL; printable
  ASCII; bounded length; reject relative paths. (Root `/` is REJECTED — it is not a valid managed subvolume
  path. The round-2 reviewer that said to "restore `/` as accepted" misread this contract; the agent
  validator rejects `/`, so the manifest format MUST reject `/` for manifest≡agent.)
All four: ASCII, deterministic, `noInlineSecrets`/`maxLength` still compose. Each implemented as a structured
check identical in TS + Go; document them in the closed `StringFormat` set.

## User value
Four reusable governed formats unblocking the accounts (posixUsername/groupName), services (systemdUnitName),
and storage/backup (absolutePath) migrations — low-risk structured checks (no canonicalization parity), so
they land fast via the conformance-corpus pattern.

## Reviewer revision (round 2 — BLOCKING, from P9-012.review.md — absolutePath must match the agent)
`absolutePath` accepts root `/` (both validators `if value=="/" return true`, corpus vector "absolutePath
root accepts"), but the agent STORAGE path validator REJECTS `/`. The corpus blessed the wrong expectation,
so TS≡Go agree while diverging from the agent the contract says to match. Round 2: RE-READ the agent
`agent/capabilities/storage` AND `agent/capabilities/backup` path validators and make `absolutePath` match
their EXACT rule — in particular REJECT root `/` (and reconcile any other divergence; if storage + backup
differ on a rule, the shared format must be the rule BOTH enforce, or note the difference). Fix the corpus
vector(s) to the AGENT's actual accept/reject (root `/` ⇒ reject). The corpus must encode the AGENT's
behavior, never a guess — a later migration's manifest≡agent proof depends on this. Re-verify the other
three formats (posixUsername/groupName/systemdUnitName) against their cited agent validators too.
