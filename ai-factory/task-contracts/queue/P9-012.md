## Objective
Add four GOVERNED, purely-STRUCTURED string formats to the closed `StringFormat` set (TS + Go, identical
structured checks — no regex engine, no canonicalization parity risk, so these are low-risk vs the IP/datetime
formats). They gate the accounts/services/storage migrations. Match the AGENT validators' exact rules (read
the cited cap files):
- **`posixUsername`** (accounts `name`/`primaryGroup`/`groups`, identity) — `agent/capabilities/accounts`:
  `^[a-z_][a-z0-9_-]{0,31}$` structurally (first char `[a-z_]`, rest `[a-z0-9_-]`, length 1–32). ASCII only.
- **`groupName`** — same rule as `posixUsername` (POSIX group name). (May alias the same checker.)
- **`systemdUnitName`** (services `name`) — `agent/capabilities/services`: a non-empty prefix + a recognized
  unit SUFFIX from the CLOSED set `.service .socket .device .mount .automount .swap .target .path .timer
  .slice .scope`; prefix charset `[A-Za-z0-9:._@-]` (match the agent's `validServiceName` EXACTLY); reject no
  suffix / empty prefix / leading `.`.
- **`absolutePath`** (storage/backup paths) — `agent/capabilities/storage` / `backup`: an absolute POSIX path
  (`/`-prefixed), no `..` segment, no NUL, no trailing slash (unless root), bounded length, printable ASCII;
  reject relative paths + `..` traversal. Match the agent's path validator rules.
All four: ASCII, deterministic, `noInlineSecrets`/`maxLength` still compose. Each implemented as a structured
check identical in TS + Go; document them in the closed `StringFormat` set.

## User value
Four reusable governed formats unblocking the accounts (posixUsername/groupName), services (systemdUnitName),
and storage/backup (absolutePath) migrations — low-risk structured checks (no canonicalization parity), so
they land fast via the conformance-corpus pattern.
