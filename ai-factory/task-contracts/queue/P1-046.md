## Objective
W4-S3 (ADR-0009 condition 3 — the volume user/group model): give a capsule a PERSISTENT data volume that survives
reboot, mounted into its hardened transient unit. Resolve the DynamicUser-vs-persistent-ownership problem with the
ADR-0009-recommended model: **DynamicUser + a per-capsule supplementary group that owns the volume dir** (generalizing
the `vita-agent` group pattern). Implement `agent/storage/capsules/volumes.go`:
`SetupVolume(capsuleId, volumeSpec) (mount, error)` creates `/var/lib/vita/runtime/volumes/<capsuleId>/<volName>`
(VOLUME_MOUNT_ROOT, on the persistent /var), owned `root:<capsule-group>` mode 02770 (setgid so files inherit the
group), and returns a `BindPaths=` entry for the unit. Extend `capsule.execute` (`execute.go`) to: create the
per-capsule group, set `SupplementaryGroups=<capsule-group>` + `BindPaths=<volume>` on the transient unit (so the
DynamicUser can read/write the volume), `TeardownVolume` on undo (unmount only — the DATA persists). The capsule
writes to its volume; on reboot the data is still there (persistent /var, P1-029). Marker:
`VITA-CAPSULE-VOLUME: id=<id> vol=<name> path=<p> mounted=OK status=OK` (+ `…-ERROR: FAILSAFE`).

Concretely:
- **Persistence:** the volume is under the persistent vita-data /var (P1-029) → survives reboot. The test capsule
  writes a record; orchestrator host-verifies it PERSISTS across a 2-boot verity check.
- **Ownership model (ADR-0009 cond 3):** per-capsule group owns the volume dir (02770 setgid); the capsule's
  DynamicUser joins it via `SupplementaryGroups`. NO fixed per-capsule UID needed (DynamicUser stays). Document it.
- **Least privilege:** the unit gets ONLY its own volume bind + group; no broader /var access. Manifest-driven (the
  volume spec from the validated capsule manifest `data.volumes`).
- **TS side**: the baked test capsule declares a volume + writes to it; `main.ts` emits `VITA-CAPSULE-VOLUME`.

## User value
Capsules can keep durable state across reboot — stateful apps on the node — while staying unprivileged (DynamicUser)
with least-privilege, persistent, group-owned volumes the privileged agent provisions.

## Non-goals
NO encryption/quota (later). NO shared-between-capsules volumes (per-capsule only). NO OCI. Manifest-driven volume
spec only. The runtime never touches /var directly — agentd provisions + mounts.
