## Objective
SDK type + fail-closed, SECURITY-AWARE validator for the node's managed local user accounts (FR-007).
`Account { name: string; uid: number; primaryGroup: string; groups: string[]; shell: string; enabled: boolean }`
and `AccountsConfig { accounts: Account[] }`. `validateAccountsConfig(input)` uses `safeNormalize`, then
validates on the trusted value.
- **Validate fail-closed + security gates**:
  - `name` (POSIX username): `^[a-z_][a-z0-9_-]{0,31}$` (lowercase start, bounded 32); reject anything else.
  - `uid`: a non-negative integer; **REJECT uid 0 (root) and the system-reserved range < 1000** — managed
    accounts MUST be regular users (no creating/owning root or system accounts). Bounded ≤ 60000.
  - `primaryGroup` + each `groups` entry: valid group name `^[a-z_][a-z0-9_-]{0,31}$`; `groups` deduplicated;
    reject a `groups` entry equal to a privileged group (`root`, `sudo`, `wheel`, `admin`) UNLESS … no —
    REJECT membership in `root`/`sudo`/`wheel`/`admin` outright (no silent privilege grants via this model).
  - `shell`: an absolute path from a closed allowlist `{ /bin/bash, /bin/sh, /usr/bin/bash, /usr/bin/zsh,
    /usr/sbin/nologin, /bin/false }` — reject anything else (no arbitrary shells / inline content §13.1).
  - `enabled`: boolean and PRESENT (absent ⇒ reject).
  - Reject duplicate account `name` AND duplicate `uid` across the list. `accounts` present + array (explicit
    empty `[]` valid + distinct from absent; absent ⇒ reject). Reject unknown keys (entry + envelope).
  - §13.1: reject any string field carrying inline key material (PEM/`data:`/long base64).

## User value
The typed, security-gated contract for managed local accounts (FR-007) — the controller authors it and the
node applies it — with privilege-escalation guards (no root/uid<1000, no sudo/wheel membership, allowlisted
shells) enforced before anything reaches the node.

## Non-goals
- No real `useradd`/`/etc/passwd` writing, no agent, no I/O. Types + pure validator only. No password/secret
  fields at all (accounts carry NO credentials here — auth is separate). No shared-index edits.

Strict TS (no `any`). R1 → orchestrator-reviewed.
