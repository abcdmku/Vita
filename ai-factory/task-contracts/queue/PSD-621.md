## Objective
A **pure/offline** mirror-build tool (`packages/install/src/mirror-build.ts`) that takes a project
lockfile (npm `lockfileVersion` 3 OR JSR/Deno `specifiers`+`resolved`) plus a directory of
**already-downloaded** tarballs and produces the deterministic, content-addressed mirror store layout
that `packages/install/src/mirror-store.ts` (`OnDiskMirrorStore`) already reads — i.e. content blobs at
`<algorithm>/<shard>/<hex>` plus the sorted `index.json` mapping `name@version` → SRI (see
`mirror-store.ts:742` `contentPath`, `:716` `indexJson`, `:578` `packageKey`). NO network: the operator
supplies tarball bytes out-of-band (spec §9.3 — production artifacts have no remote imports / install I/O).
- **Input:** `{ lockfile: unknown, tarballs: ReadonlyMap<string, Uint8Array> | record keyed by `name@version` }`
  (operator-provided bytes; no filesystem reads required for the pure core — keep the byte-mapping injected so
  the function is deterministic and testable).
- **Behavior:** walk the lockfile using the SAME parsing surface `resolveFromMirror` uses — npm packages map
  (`node_modules/...` paths) vs JSR `resolved` map, strongest-SRI selection, exact-version/package-name
  validation, and lockfile-policy / lifecycle-script rejection (`resolveFromMirror` in
  `packages/install/src/mirror.ts:99`; reuse its primitives, do NOT fork the policy). For each lockfile package,
  look up its tarball bytes, compute the digest with the lockfile's strongest SRI algorithm, and **reject any
  package whose bytes do not match the lockfile SRI** (`INTEGRITY_MISMATCH`) and any package with **no supplied
  tarball** (`MISSING_TARBALL`, fail-closed). On success, emit the store: write each verified blob at its
  content-addressed path and a byte-identical `index.json` (sorted by key, same formatter as `mirror-store.ts`).
- **Output:** a `{ name@version → { sri, path } }` manifest plus the on-disk store. For **identical inputs the
  emitted store + manifest are byte-identical** on re-run (deterministic; sorted keys; no timestamps/ordering nondeterminism).
- Put the implementation at `packages/install/src/mirror-build.ts` and tests at
  `packages/install/test/mirror-build.test.ts`. Reuse `parseSriIntegrity` (`sdk/typescript/src/sri.ts`) and the
  existing store path/index helpers rather than re-deriving them; a follow-up may extract shared helpers — do
  NOT weaken or duplicate `mirror-store.ts`'s validation here.

## User value
Lets an operator stand up the Phase-4 app-catalog mirror **entirely offline** from a pinned lockfile + a folder
of vetted tarballs, producing exactly the store `OnDiskMirrorStore`/`resolveFromMirror` consume — so a node can
install catalog apps with zero network and full SRI provenance. Closes the supply-chain loop between "resolve
against a mirror" (already built) and "build that mirror" (this slice).

## Non-goals
- NO network, NO downloading, NO registry/JSR client (operator supplies bytes; spec §9.3).
- NO tarball extraction / dependency-graph install (that is `resolve.ts`'s job) — this only verifies + stores bytes.
- NO new lockfile policy: consume `resolveFromMirror`'s parsing + `validateLockfilePolicy`; do not re-implement or relax them.
- NO mutation of `mirror-store.ts` semantics or the on-disk format; NO lockfile-version inference beyond the npm-v3 / JSR branches already supported.

## Acceptance
`acceptance_command` passes. The test suite at `packages/install/test/mirror-build.test.ts` MUST exist and
contain real cases (not a vacuous empty glob — see lesson `vita-vacuous-acceptance-hole`), covering, against
in-memory fixtures:
1. Happy path: a fixture lockfile (cover BOTH an npm `lockfileVersion:3` fixture and a JSR `specifiers`+`resolved`
   fixture) + matching tarballs → builds a store; the resulting store is readable by `OnDiskMirrorStore.get(...)`
   for every package, and the emitted manifest maps each `name@version` → `{ sri, path }`.
2. SRI mismatch: a tarball whose bytes don't hash to the lockfile SRI is **rejected** (`INTEGRITY_MISMATCH`,
   fail-closed, no partial store committed for that package).
3. Missing tarball: a lockfile package with no supplied bytes is **rejected** (`MISSING_TARBALL`, fail-closed).
4. Determinism: building twice from identical inputs yields a **byte-identical** `index.json` and identical
   manifest (assert exact byte/string equality).
`npm run typecheck` is clean. Pure + headless (no real network, no ambient I/O beyond the store root the test
points at, ideally a tmp dir).

## Security/constraints
- Offline / fail-closed: missing or mismatched bytes are hard rejects, never best-effort. No network (`allowed_network: false`).
- Reuse capability-mediated/validated primitives; do NOT weaken SRI verification or lockfile policy to make a
  package pass (protected-boundary: never weaken acceptance/verification). Content-addressed paths stay inside the
  store root (path-traversal guarded as in `mirror-store.ts`). Deterministic: same inputs → byte-identical output.
- No remote imports; lockfile mandatory; no package lifecycle scripts; TS strict (`tsconfig.base.json`).

## Performance
- Pure in-memory verification + a single pass over lockfile packages; O(n) hashing in package count. No network round-trips.

## Hardware profiles
- Host/dev only (pure Node TS via `--experimental-strip-types`); no device/boot dependency.

## Allowed tools / network
- Read/write under `packages/install/**` and the test's store root (tmp). `allowed_network: false`.
