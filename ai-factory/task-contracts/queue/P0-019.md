## Objective
A pure, standalone SDK type model + fail-closed validator for the storage layer (spec §10): Btrfs
subvolume layout, snapshots, and disk-health summary. `storage-model.ts` exports the types
(`StorageLayout`, `Subvolume`, `SnapshotPolicy`, `DiskHealth`, etc.) and a
`validateStorageLayout(input): Result` that fail-closes on untrusted input. Because this is a NEW
validator, use the canonical `safeNormalize` (sdk/typescript/src/safe-normalize.ts) for the
trust-boundary normalization, then validate structure on the trusted plain value (do NOT re-walk
untrusted input). Standalone module — do NOT edit any shared barrel/index file.

## User value
The typed contract the controller + Go storage capability will share (FR-014 disk health, §10.2
volumes). Lets storage desired-state be authored + validated deterministically before it ever reaches
the host.

## Non-goals
- No real disk/LUKS/Btrfs I/O; no agent code. Types + pure validator only. No shared-index edits.

## Dependencies
P0-015 (`safeNormalize`) — merged.

## Acceptance tests
`acceptance_command` — `storage-model.test.ts` covers: a valid layout validates; missing/wrong-type
fields rejected with clear paths; fail-closed on hostile input (garbage, cyclic, accessor/exotic) via
safeNormalize; snapshot-policy + disk-health bounds enforced. Orchestrator also runs `npm run typecheck`.

## Performance & security constraints
Pure/deterministic, no I/O. Fail-closed via `safeNormalize`. Strict TS (no `any`/suppressions),
exactOptionalPropertyTypes/noUncheckedIndexedAccess clean. R1 → orchestrator-reviewed.

## Reviewer revision (round 2 — BLOCKING, from P0-019.review.md)
1) Reject PARTIAL layouts: `validateStorageLayout` must require the full §10 set of storage areas
   (system-state, user-data, app-state, snapshots, local-backup-cache) — a layout missing any required
   area is rejected fail-closed (not merely "non-empty + duplicate-free").
2) Enforce role/appId invariants (§10.2): an `app-state` subvolume MUST carry an `appId`; non-app roles
   MUST NOT carry an `appId`. Reject violations with precise paths.
3) Restrict subvolume `path` to a canonical absolute form (reject `.`/`..`/non-normalized), not just
   `startsWith("/")`.
Add regression tests for each (missing-area ⇒ reject; app-state-without-appId ⇒ reject;
non-app-with-appId ⇒ reject; non-canonical path ⇒ reject).
