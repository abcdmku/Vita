## Objective
Build the **network half** of §9.3 that P1-064 deliberately left out. P1-064 (`resolveFromMirror`,
`packages/install/src/mirror.ts`, MERGED) is **pure over an in-memory `MirrorStore`**: it byte-verifies that a
caller-supplied artifact map matches the lockfile SRI, but it does **not** fetch anything and does **not** persist
anything. This slice implements the **mirror downloader + an on-disk content-addressed store (CAS)** that materializes
that map: fetch one pinned artifact by integrity from a mirror, store it content-addressed on disk, byte-verify SRI,
and reject remote/un-pinned/lifecycle — fail-closed.

Implement in `packages/install/src/mirror-store.ts`:

1. **`OnDiskMirrorStore` — a deterministic, content-addressed disk store** that **implements the existing
   `MirrorStore` interface** from `mirror.ts` (`{ get(key: string): Uint8Array | undefined }`) so the merged
   `resolveFromMirror` consumes it **unchanged** (do NOT modify `mirror.ts`). Layout is keyed by the **verified SRI
   digest**, not by package name: `<root>/<algorithm>/<hex[0:2]>/<hex>` (e.g.
   `sha256/3f/3f786850e387550fdab836ed7e6dc881de23001b…`), where `<hex>` is the lowercase hex of the digest. The
   `name@version` → digest mapping is held in a committed-by-the-caller, in-store index file
   (`index.json`: `{ "<name>@<version>": "<sri-integrity>" }`); `get(key)` looks up the integrity for the key, reads
   the content-addressed blob, **re-verifies the bytes against the SRI before returning them** (a corrupted/tampered
   on-disk blob returns `undefined` — never unverified bytes), and returns `undefined` for any unknown key. The
   on-disk layout is **deterministic**: the same artifact bytes always land at the same path on any host, x86_64 or
   arm64.

2. **`fetchAndStore(spec, deps)` — the downloader.** Given a pinned spec `{ name, version, integrity, mirrorUrl }`
   (where `mirrorUrl` MUST be a configured `local-mirror://` / `vita-mirror://` reference resolved against a
   caller-supplied **mirror base URL**, OR an explicit allowed mirror origin — NEVER an arbitrary remote registry):
   - Reject **before any fetch**, fail-closed: a non-exact `version` (reuse the exact-semver rule), a malformed/absent
     SRI `integrity` (reuse `parseSriIntegrity` from `sdk/typescript/src/sri.ts`), a `mirrorUrl` that is not an
     allowed mirror reference/origin (a bare `https://registry.npmjs.org/...` or any non-mirror origin is rejected —
     **no remote fallback, ever**), and any lifecycle/`hasInstallScript`/`requiresBuild` indicator on the spec.
   - Fetch the bytes via an **injected `MirrorFetcher`** (`{ fetch(url: string): Promise<Uint8Array> }`) — dependency
     injection so the acceptance test runs **offline** against a loopback `node:http` server / in-memory fetcher,
     while production wires the platform's real fetch. The fetcher is the ONLY thing allowed to touch the network;
     the store/verify path is pure-compute + filesystem.
   - **Byte-verify the fetched bytes against the SRI** with `node:crypto` (`createHash(algorithm).update(bytes)`),
     compared in the SRI's declared encoding (reuse the digest/length discipline already in `mirror.ts` / `sri.ts`).
     On mismatch → reject `INTEGRITY_MISMATCH`, write **nothing** to disk (no partial/poisoned blob).
   - Persist **atomically and content-addressed**: write to a temp file in the store root, fsync-then-`rename` into
     the final `<algorithm>/<hex[0:2]>/<hex>` path (atomic publish — a concurrent reader never sees a torn blob), then
     update `index.json` with the `name@version → integrity` mapping. Storing an artifact whose bytes already exist is
     idempotent (same path, byte-identical).
   - Path-safety: the store key and digest are validated before being used in a path; reject any traversal /
     absolute / `..` / control-char component fail-closed (the blob path is derived ONLY from the verified hex
     digest + algorithm, never from attacker-controlled `name`).

3. **Result shape — match the package-platform idiom.** Return a discriminated result
   `{ ok: true, stored: { name, version, integrity, key, path } } | { ok: false, errors: readonly StoreError[] }`
   with `StoreError.code ∈ { "INVALID_SPEC", "REMOTE_REJECTED", "LIFECYCLE_REJECTED", "FETCH_FAILED",
   "INTEGRITY_MISMATCH", "STORE_IO" }` and a JSON-pointer-escaped `path` (mirror the `error(...)`/`reject(...)` helpers
   in `mirror.ts` / `resolve.ts`). **Never throw at the boundary** — a fetch rejection, an I/O error, a hostile spec
   (accessor/`__proto__`/cyclic), or a fetcher that returns a non-`Uint8Array` all return a structured rejection.

4. **End-to-end seam.** A small exported helper / test demonstrates the round trip: `fetchAndStore` a pinned artifact
   into a fresh temp store, then construct an `OnDiskMirrorStore` over that root and feed it to the merged
   `resolveFromMirror` with a matching one-package lockfile → `resolveFromMirror` returns `ok: true` with that
   artifact. This proves the disk store is a drop-in backing for the pure resolver.

## User value
This is the missing network half of the supply-chain guarantee (spec §9.3 "dependencies are mirrored, hashed, …
retained for reproducibility"; §15 "npm supply-chain compromise" mitigation). P1-064 proved the *pure* verification;
real installs need the *bytes on disk*. With this slice a Vita node can fetch a pinned package **only** from its own
mirror, prove every byte matches the lockfile integrity **before and after** it touches disk, and lay it down in a
deterministic content-addressed store that the existing resolver consumes unchanged — so a compromised/unreachable
upstream registry cannot inject or substitute code, a tampered on-disk blob is caught on read, and the store is
reproducible across hosts. Closes the fetch+CAS gap between policy-validation (`validateLockfilePolicy`),
byte-verification (`resolveFromMirror`), and a real install.

## Non-goals
- **No install / host mutation.** This produces verified bytes on disk + an index; it does NOT unpack, link, run, or
  apply anything. The privileged install/apply step is a separate later agentd (R3) slice that re-validates from a
  typed manifest — NOT from raw runtime text. The TS runtime here is UNPRIVILEGED.
- **No changes to `mirror.ts`, `lockfile-policy.ts`, `resolve.ts`, the SDK, the agent, or the OS image.** The disk
  store must satisfy the EXISTING `MirrorStore` interface; if you think the interface needs to change, that is a
  separate contract — do not loosen or fork it here.
- **No new policy.** Reuse the exact-version / SRI / mirror-source / lifecycle constants already enforced in
  `mirror.ts` / `lockfile-policy.ts` / `sri.ts`; do not invent stricter or looser rules. No signature/catalog
  trust-tier logic (that is the catalog slices).
- **No real registry, no real network in the test.** No new runtime dependency, no OCI/registry client, no CLI, no
  scanning/AV. The fetcher is injected; the acceptance test uses a loopback/in-memory fetcher only.
- **No on-device boot marker.** This is a portable host-side TS module (matches the P1-064 / P1-071 SDK-floor style);
  no `main.ts` / overlay change and no Borg51 boot check.

## Acceptance tests
Restated `acceptance_command`:
`node --experimental-strip-types --test "packages/install/test/mirror-store.test.ts"` — runs **offline** (Node ≥22
built-ins only: `node:test`, `node:assert/strict`, `node:crypto`, `node:fs`, `node:os`, `node:path`, optionally a
loopback `node:http` server; NO real outbound network). Each test writes into a fresh `mkdtemp` store root and cleans
it up. The suite MUST include at least:
- **Happy path:** `fetchAndStore` a pinned artifact (via a loopback/in-memory fetcher returning the correct bytes) →
  `ok: true`; the blob exists at the deterministic `<algorithm>/<hex[0:2]>/<hex>` path; `index.json` maps
  `name@version → integrity`.
- **Deterministic layout:** the same bytes always produce the same content-addressed path (assert the path equals the
  recomputed digest hex layout); re-storing the same artifact is idempotent (byte-identical, no error).
- **Read-back verification:** an `OnDiskMirrorStore` over the populated root returns the verified bytes for the key;
  **corrupting the on-disk blob** (or the index integrity) makes `get(key)` return `undefined` (never unverified
  bytes); an unknown key returns `undefined`.
- **INTEGRITY_MISMATCH on fetch:** a fetcher that returns bytes hashing to a different digest than the spec SRI →
  rejected, and **nothing** is written to disk (assert the store root has no blob / no index entry).
- **REMOTE_REJECTED / un-pinned:** a `mirrorUrl` that is a bare remote registry origin (e.g. `https://registry.npmjs.org/...`)
  or any non-mirror origin → rejected before any fetch (the fetcher is NEVER called — assert via a fetcher spy);
  a non-exact `version` and a malformed/absent SRI → rejected before any fetch.
- **LIFECYCLE_REJECTED:** a spec carrying a lifecycle script field / `hasInstallScript: true` / `requiresBuild: true`
  → rejected before any fetch.
- **FETCH_FAILED / fail-closed:** a fetcher that rejects (network error), times out, or returns a non-`Uint8Array`
  → structured rejection, NOT a thrown exception; nothing written.
- **Trust-boundary:** a hostile spec (accessor getter, `__proto__` key, cyclic) and a digest/key containing
  `..`/`/`/control chars do NOT throw and do NOT write outside the store root — each returns a rejection.
- **End-to-end seam:** `fetchAndStore` then `resolveFromMirror(matchingLockfile, new OnDiskMirrorStore(root))` →
  `ok: true` listing that artifact (proves drop-in backing for the merged resolver).
Run `npm run typecheck` yourself (the strip-types acceptance erases types and does NOT type-check) and fix every

## Performance & security constraints
- **Fail-CLOSED everywhere.** Every invalid / ambiguous / exotic input (bad SRI, non-exact version, non-mirror URL,
  lifecycle indicator, fetch error, I/O error, hostile spec) returns a structured rejection; a throw at this trust
  boundary is a DoS and a test failure. Verify EVERY byte: re-hash on fetch (before write) and again on read-back;
  never return or persist unverified bytes; write atomically (temp + fsync + `rename`) so a torn blob is never
  observable and a mismatch leaves zero residue.
- **No remote fallback, no remote imports in production artifacts** (§9.3). The ONLY network touch is the injected
  `MirrorFetcher`, and it may target ONLY a configured mirror reference/origin — a bare upstream registry is rejected.
  No lifecycle scripts, no subprocess, no FFI, no native addons. Lockfiles/pins mandatory and verified.
- **UNPRIVILEGED TS runtime.** This module only fetches + verifies + writes content-addressed bytes under a
  caller-supplied store root; it performs NO privileged host mutation (install/apply is the narrow Go agentd's job,
  acting from a re-validated typed manifest, never from raw runtime text).
- **NO real keys/secrets.** Integrity uses PUBLIC SRI hashes only (`node:crypto` `createHash`, no key/HMAC material);
  signing / TPM / recovery / mesh key material is OWNER-HELD (§16) and must never be committed or generated — TEST
  fixtures only.
- **Determinism + bounds.** Content-addressed layout is byte-identical across hosts; linear-time over the artifact;
  bounded by `safeNormalize` depth/node caps on the spec. Path components derive ONLY from the verified hex digest +
  algorithm — never from attacker-controlled name strings.
