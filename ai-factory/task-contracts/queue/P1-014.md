## Objective
The **A/B disk image layout PLAN** (spec §6 RAUC A/B, ADR-0005; Phase 1): `planImageLayout()` assembles
the GPT partition layout — ESP, root-A, root-B, recovery, and a data partition — plus the RAUC slot
mapping and a RAUC update-bundle manifest plan, all deterministic + offline (like P1-011/P1-012, NOT a
real image build). Consumes the UKI (P1-012) output as the boot artifact for each root slot.
- `os/x86_64/image.conf`: pinned partition sizes/types/GUIDs (fixed, deterministic), slot mapping
  (A/B + recovery), RAUC compatible string. No eval-time network.
- `os/x86_64/image-layout.mjs`: `planImageLayout()` (pure) returning the normalized byte-deterministic
  layout + RAUC slot/bundle plan; references the UKI + root-image outputs as digest-pinned/unresolved
  external inputs (reuse P1-012's external-precondition + canonical-path model — inputs unresolved until
  the upstream build supplies real digests; unresolved blocks assembly). SOURCE_DATE_EPOCH set.
- `os/x86_64/test/image-layout.test.ts`: asserts the layout is byte-deterministic; A/B+recovery slots
  present + non-overlapping; sizes/GUIDs pinned; RAUC slot mapping coherent; external inputs are
  digest-verified preconditions (sentinels rejected); all container/host paths canonical (reject `..`).

## User value
The partition/slot/bundle plan the installer + RAUC updater (FR-023) build on — the structure for
atomic A/B updates with rollback, the core Phase-1 reliability property.

## Reviewer revision (round 2 — BLOCKING, from P1-014.review.md). Cross-contract coherence with the ACTUAL merged P1-011/P1-012 outputs:
1) **Slot-coherent boot artifacts.** Round 1 used the single fixed P1-012 UKI (whose cmdline is
   `root=LABEL=vita-debian-trixie-x86_64-root`) for root-A, root-B, AND recovery — that UKI cannot select
   a slot, so the layout is incoherent. Model a SLOT-SPECIFIC boot artifact per slot: each root slot's
   boot UKI carries a cmdline selecting THAT slot's root label (`root=LABEL=vita-root-a` /
   `vita-root-b`), and recovery its own. Reference them as distinct external preconditions (per-slot UKI
   builds are upstream outputs of P1-012's planUKI parameterized by slot). The test must assert each
   slot's boot artifact selects that slot's root label (no shared/ambiguous UKI).
2) **Reference P1-011's ACTUAL output.** P1-011 emits a mkosi `Format=directory` output named
   `vita-debian-trixie-x86_64-root` (a directory), NOT a `.img`. Do not invent a `.img` path. Either
   reference that directory output, AND model a declared "root directory → partition image" conversion
   as a separate external precondition step (with its own unresolved digest), so the precondition can
   only be satisfied by an artifact that actually exists in the pipeline.
Keep the round-1 canonical-path / unresolved-digest / sentinel-rejection / accessor regressions (approved).
