## Objective
W5-S2 (ADR-0010 slice 2): agentd FETCHES + verifies a local OCI image and ASSEMBLES a read-only rootfs that W5-S1's
`RootDirectory=` launcher (P1-052) can run. Extend the fetch path (a new `agent/storage/capsules/oci_fetch.go` that
reuses `fetch.go`'s SRI gate + `safeArchiveName`/`safeExtractPath` + P1-051's extraction caps). Steps, preserving the
P1-045/P1-051 trust order (SRI-verify the full artifact bytes BEFORE any decode; nothing staged until an atomic rename):
1. **Artifact** = a LOCAL `oci-image` layout tar(.zst) (`oci-layout` + `index.json` + `blobs/sha256/<digest>`); offline,
   no registry pull (file:// / local path only). Outer artifact SRI-verified as today.
2. **Two-level digest verify**: `index.json` → image manifest digest → EACH layer + config blob `sha256` matches its
   `blobs/sha256/<name>` AND the manifest's declared digests; the image-manifest digest matches the
   manifest-pinned `runtime.ociImageIndexes[].digest`. Any mismatch → fail-closed, NOTHING staged.
3. **Rootfs assembly**: apply layers in order into a temp dir (each layer a gzip/zstd tar) using the SAME traversal
   guards + P1-051 caps, with the caps enforced ACROSS THE WHOLE LAYER STACK (total uncompressed bytes + entry count),
   AND OCI whiteout handling (`.wh.<name>` deletes, `.wh..wh..opq` opaque-dir) — a missed whiteout is a correctness/
   security bug, so whiteouts get dedicated table tests. Atomic rename → `/var/lib/vita-agent/capsule-storage/<id>/
   <version>/rootfs/` (RO, agentd-owned 0700). Idempotent re-fetch (extend the `existingComplete` self-heal to
   "rootfs assembled + digest-verified").
Marker: `VITA-CAPSULE-OCI-FETCH: id=<id> image-digest=<algo>-<short> layers=<N> verified=OK status=OK`;
fail-closed `VITA-CAPSULE-OCI-FETCH-REJECT: reason={sri_mismatch|digest_mismatch|whiteout|bomb|traversal} status=OK`;
`…-FETCH-ERROR: status=FAILSAFE`. Bake a tiny first-party OCI-layout test image + its SRI for the boot.

## User value
The node can acquire OCI images by content-addressed integrity (outer SRI + the full OCI digest graph) and assemble a
verified, DoS-resistant, traversal-safe rootfs — the acquisition half of running real OCI capsules.

## Non-goals
NO registry/network pull (later). NO crun/runc. NO running the rootfs (that's P1-052's launcher; this only assembles).
NO layer sharing/overlay dedup (each capsule its own rootfs). NO full OCI Runtime Spec (config.json mounts/caps/hooks
ignored — only the rootfs + the entrypoint/env from config, surfaced for P1-052).

## Dependencies

## Acceptance tests

rootfs path + the resolved entrypoint/env, image-digest verified; a TAMPERED layer/config blob (sha256 mismatch) →
fail-closed, nothing staged; a digest != the manifest-pinned digest → reject; a whiteout correctly deletes/opaques a
lower-layer file (assert the resulting rootfs); a layer-stack exceeding the total/entry caps (bomb) → reject; an

## REVISION REQUIRED (cross-review verdict: REVISE — 2026-06-23) — DECOMPRESSION-BOMB FAIL-OPEN
The multi-lens review found a real, BLOCKING supply-chain DoS hole: a digest-valid, SRI-valid HOSTILE OCI image can
stream unbounded decompressed bytes past the caps. Extend THIS branch (task/P1-053); keep all prior work.

BLOCKING (must fix before merge):
1. **Stack-wide decompressed-byte backstop.** `applyOCILayer`/`ociLayerTarReader` (oci_fetch.go ~548, ~619-662) pass
   the layer reader straight into `tar.NewReader` with NO `maxBytesReader` aggregate guard — UNLIKE `extractOCIArtifact`
   (~460-465) and `extractTar` (fetch.go) which wrap their decompressor in `maxBytesReader{remaining:
   maxCapsuleDecodedTarBytes}`. The cross-stack `caps.payloadBytes` only counts `header.Size` for `tar.TypeReg`. zstd
   `WithDecoderMaxMemory` is only a streaming WINDOW bound; gzip has none. FIX: wrap each layer reader in a maxBytesReader
   whose **remaining budget is SHARED ACROSS LAYERS** via the caps struct, counting ACTUAL decompressed bytes (not just
   declared header.Size). Exceed → `ErrOCIBomb`, fail-closed, nothing staged.
2. **Cap/count the whiteout-discard and TypeDir paths.** (a) Whiteout discard (~584-588)
   `io.Copy(io.Discard, io.LimitReader(tarReader, header.Size))` — header.Size is attacker-controlled, only checked >=0,
   NEVER bounded by `maxCapsuleTarEntryBytes` (that per-entry check lives only in the TypeReg branch ~603-604) and the
   discarded bytes are NEVER added to `caps.payloadBytes`. (b) TypeDir branch (~597-601) — header.Size never validated,
   the loop stream-skips that many decompressed bytes from the uncapped decoder. A single `.wh.`/dir entry with
   header.Size=2^40 = a multi-GB bomb the entry-count cap can't stop. FIX: bound + count EVERY entry's consumed bytes
   (the stack-wide backstop from #1 covers it; also validate dir/whiteout header.Size against the per-entry cap).
3. **Add the missing fail-closed tests** (the harness already has `ociLayerEntry.size/fill` + `gzipLayerArchive` wired
   but NO case uses them): (a) a digest-valid layer with a `.wh.<name>` TypeReg entry whose header.Size exceeds
   `maxCapsuleTarEntryBytes`; (b) a multi-layer case whose actual decompressed bytes exceed
   `maxCapsuleTarPayloadBytes`; (c) a LYING-HEADER case (actual decompressed > declared header.Size). Each MUST reject
   with `ErrOCIBomb` and stage NOTHING. Also add the hardlink-escape (`tar.TypeLink`) traversal subcase alongside symlink.

Verify via `node tools/build/go-in-docker.mjs --dir agent test ./storage/...` (LINUX). Re-review re-runs the gate.
