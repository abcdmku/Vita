## Objective
Build the **TS driving seam** that turns the merged shell's surface model (PSD-005) + WM placement intents (PSD-004)
into an ordered stream of **compositor commands** against a `CompositorPort` — the layer that will let the real shell
drive the native compositor (PSD-002) to show REAL windows, instead of the compositor's built-in demo layout. Pure,
deterministic, headless-testable TypeScript; NO GPU, NO FFI — the actual compositor is an injected port (the real
implementation binds to the native compositor later; tests use a fake recording port).
- A `CompositorPort` interface: `registerSurface(id, kind, size)`, `updatePlacement(id, rect, z, visible)`,
  `removeSurface(id)`, `present()` — the minimal command set the native compositor seam (desktop-substrate) needs to
  composite + reposition (no-repaint) windows. Mirror the existing `desktop-substrate` compositor seam types where they
  exist; do not duplicate/fork them — import + extend.
- A `CompositorDriver`: given a shell surface model (PSD-005) + WM placement (PSD-004 intents), compute the MINIMAL
  diff of compositor commands to reconcile the compositor to the desired window layout (added/removed/moved/restacked/
  shown-hidden surfaces), emitting `updatePlacement` (NOT re-register) for pure moves/resizes so the native side can do
  no-repaint reposition. Deterministic ordering (stable z-order, remove-before-add or add-before-remove — pick + test).
- Reconcile is **idempotent** (reconciling to the same model twice emits no commands the second time) and **fail-closed**
  (a port command failure stops the batch in a well-defined state, surfaced as an error — no partial-but-claimed-success).

## User value
The missing link between the merged TS desktop (shell + WM, headless) and the GPU compositor: it converts "where the
windows should be" into "what the compositor must do", with no-repaint moves — the core of the render/composite split.
A later slice binds this to the native compositor over the substrate seam; this slice is fully unit-tested headless now.

## Non-goals
- NO GPU / native compositor / FFI here (injected port + fake in tests). NO web engine. NO new window-management policy
  (consume PSD-004's intents; don't re-implement tiling).
- Not the native binding — that's a follow-up that implements `CompositorPort` against the real compositor.

## Acceptance
`acceptance_command` passes: a driver reconciles a shell+WM model into the correct minimal compositor command stream
(add/remove/move/restack/visibility), pure moves emit `updatePlacement` only (no re-register → enables no-repaint),
reconcile is idempotent, and a failing port command fails closed with a defined state. Deterministic; comprehensive unit
tests incl. the fail-closed + idempotence cases. Headless; no boot marker.

## Security/constraints
- Pure/deterministic, no ambient I/O; compositor is an injected capability port; fail-closed on port failure. No remote
  imports; lockfile; no lifecycle scripts. Reuse the desktop-substrate compositor seam types (don't fork).

## Definition of done
- `CompositorPort` + `CompositorDriver` (minimal-diff reconcile, no-repaint moves, idempotent, fail-closed) over the
  merged shell+WM model; comprehensive headless unit tests; typecheck clean. R1 (review + integrate).

## REVISION 1 (Codex R1: windowIntents mis-reconciles the PSD-004 WM intent stream — 2026-06-25)
`windowIntents` (index.ts:407-425, :461-464) doesn't correctly consume the merged PSD-004 `WindowManagerIntent` stream:
- A newly-VISIBLE window arrives as `setTextureVisibility(true)` + `repositionTexture`, but the code REJECTS an unknown
  texture instead of REGISTERING it → new windows never appear.
- An absent/closed surface with `setTextureVisibility(false)` is reinserted as hidden, so a removed window can FAIL to
  emit `removeSurface` → closed windows linger.
FIX: reconcile WM intents to compositor commands per the add/remove/visibility contract: an unknown texture becoming
visible → `registerSurface` + `updatePlacement` (don't reject); `setTextureVisibility(false)` for a surface absent/closed
in the desired model → `removeSurface` (don't reinsert as hidden). Add tests: (a) WM stream makes a NEW window visible →
registerSurface emitted; (b) stream hides+removes a window → removeSurface emitted. Keep idempotence + the existing 7 tests.

## REVISION 2 (Codex R1: delta WM-intent stream wrongly removes unmentioned surfaces — 2026-06-25)
The rev1 register-on-visible fix landed (9 tests). New blocking issue: the PSD-004 `WindowManagerIntent` stream is a
DELTA (mentions only CHANGED windows), but `windowIntents` (index.ts:267, :293-301) builds the next authoritative window
map from ONLY the mentioned intents (defaulting `input.windows` to empty), and `diffCommands` (:543-548) then REMOVES
every current surface absent from that map. So current `{mail, chat}` followed by only `repositionTexture(mail)`
incorrectly emits `removeSurface("texture-chat")` — violating minimal-diff.
FIX: for a delta intent stream, SEED the next window-surface map from the CURRENT (committed) surfaces, then apply the
windowIntents as deltas on top (add/show/move/restack/hide the MENTIONED windows; leave unmentioned ones UNCHANGED). A
surface is removed ONLY by an explicit close/remove (e.g. setTextureVisibility(false) for a surface no longer in the
shell model, or an explicit close intent) — NEVER by mere absence from a delta. If an authoritative `windows` snapshot IS
provided, use it as before; only delta-only inputs seed from current. Also tighten tests to assert `registerSurface.size`
(the rev1 tests projected size away). Tests: current {mail,chat} + reposition(mail) → ONLY updatePlacement(mail), NO
removeSurface(chat); explicit close still emits removeSurface. Keep idempotence + all existing tests.

## REVISION 3 (Codex R1: setFocus restack + fail-closed on visible-without-placement — 2026-06-25)
rev2 delta-seeding landed (unmentioned surfaces preserved; 10 tests). Two new blocking issues mapping PSD-004 intent
variants:
1. `setFocus` (index.ts:415-420) is a no-op. PSD-004 uses `setFocus` for focus/restack-only changes; the driver MUST
   reconcile z-order — emit a restack (updatePlacement with the new z / the compositor restack command) so compositor
   z-order isn't left stale. Test: a setFocus intent → a z-order/restack command emitted.
2. An unknown `setTextureVisibility(true)` WITHOUT a paired placement (index.ts:434, :513-525) registers + presents a 0x0
   ZERO_RECT surface. FAIL CLOSED instead: a window becoming visible MUST have a known placement (from this stream's
   repositionTexture or the current/shell model); if none is available, do NOT touch the port (no register/present of a
   0x0 surface) — surface an error/skip per the fail-closed contract. Test: visible intent without placement → fails
   closed (no registerSurface at ZERO_RECT).
Keep idempotence + the existing 10 tests + the delta-preservation test.
