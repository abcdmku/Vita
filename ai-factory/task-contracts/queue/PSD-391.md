## Objective
Headless, deterministic **view-model** for the per-app **window chrome / decorations** (the
titlebar traffic-light controls + titlebar drag-to-move + focus-on-click) that every rendered app
window draws, mapping those interactions to `WindowManagerEvent`s the WM policy already reduces
(`sdk/typescript/src/wm/policy.ts`). The WM policy has minimize/maximize/move/resize/focus and the
applier (PSD-349) routes intents to the compositor, but the per-window chrome is **not wired** from
the rendered app window through to those WM intents — so traffic-light buttons and titlebar drag do
nothing on real windows.

Build `ui_kits/desktop/viewmodels/window-chrome.ts` (a `WindowChromeViewModel` class + a
`createWindowChromeViewModel(...)` factory, in the style of
`ui_kits/desktop/viewmodels/stage.ts`) that:
- Reads the current `WindowModel` through an **injected** WM port (a `readWindowModel()` /
  `applyWindowManagerIntents(...)`-shaped port like `StageWindowManagerPort` in `stage.ts`) — NO
  ambient I/O, NO platform internals, NO DOM/CEF.
- Exposes per-window chrome state for the active window(s): `{ windowId, title, focused, maximized,
  minimized, controls: { close, minimize, maximize } }` where each control carries an
  `enabled` flag (a control is disabled when its target window is absent from the model).
- Maps chrome interactions to `WindowManagerEvent`s and commits them via the WM port:
  - **close** → `{ type: "close", windowId }` (the host turns this into `stopApp`; the view-model
    only emits the WM `close` event — it does NOT call `stopApp` directly).
  - **minimize** → `{ type: "minimize", windowId }` (toggles via `minimized` flag).
  - **maximize** → `{ type: "maximize", windowId }`, toggling `maximized` against current state
    (maximize when restored, restore when maximized).
  - **titlebar drag** (pointer delta from a drag start) → `{ type: "move", windowId, rect }` where
    `rect` is the window's current rect translated by the drag delta and **clamped to the screen
    bounds** (no off-screen titlebars; the titlebar grab-point stays reachable).
  - **focus-on-click** (pointer-down anywhere on the window) → `{ type: "focus", windowId }`
    (i.e. `setFocus` via the model reducer's focus path).
- **Fails closed**: a disabled control, an unknown `windowId`, a malformed pointer/rect, or a WM
  port read/apply error returns a typed `{ ok: false, error }` result (mirroring
  `StageViewModelResult` / `StageViewModelError`) and emits **no** events. Disabled-state controls
  never commit.
- Is **pure / deterministic**: same model + same interaction → byte-identical emitted events and
  state. Reuse the public WM policy + intents; do NOT re-implement window-model reduction.

Put the code under `ui_kits/desktop/viewmodels/window-chrome.ts` and the tests under
`sdk/typescript/test/ui-kits/window-chrome.test.ts`. Import the SDK exactly as `stage.ts` does
(`../../../sdk/typescript/src/desktop-sdk/index.ts`); use ONLY public exports.

## User value
Makes window decorations *functional across all real app windows*: clicking close/minimize/maximize
and dragging a titlebar actually moves, minimizes, maximizes, and closes the live window through the
WM policy + compositor applier — turning the static chrome the CEF-rendered HTML draws into real,
testable desktop behavior.

## Non-goals
- NO DOM/CSS/CEF/rendering, NO native/Rust changes. The HTML titlebar markup is the design of record.
- Do NOT call `stopApp`/`launchApp` or any host capability directly — emit WM `WindowManagerEvent`s
  only; the host backend already maps `close` → `stopApp`.
- Do NOT re-implement `reduceWindowModel` / move/resize/clamp internals — consume the WM policy.
- No resize-handle / edge-drag interactions (drag-to-move titlebar only), no snap (that is the
  window-snap view-model), no new visual design, no ambient I/O, no changes to any acceptance/eval
  suite.

## Acceptance
`acceptance_command` passes. Deterministic unit tests in
`sdk/typescript/test/ui-kits/window-chrome.test.ts` cover, against a fake WM port that records the
events applied to it:
- **close** emits `{ type: "close", windowId }` and the window is gone from the next model read.
- **minimize** emits `{ type: "minimize", windowId }` and flips the chrome `minimized` flag.
- **maximize** toggles: emits `maximize` (maximized=true) from a restored window and restores
  (maximized=false) from a maximized one.
- **titlebar drag** emits `{ type: "move", windowId, rect }` with the rect translated by the drag
  delta and **clamped to the screen bounds** (a drag past an edge keeps the window on-screen).
- **focus-on-click** emits `{ type: "focus", windowId }` and the window becomes the chrome's focused
  window.
- **fail-closed**: a control marked disabled, an unknown `windowId`, a malformed pointer/rect, and a
  throwing WM port each return `ok: false` with a typed error code and emit **zero** events.
typecheck clean; pure and headless.

## Security/constraints
- Injected WM port only (no ambient I/O); capability-mediated; fail-closed on every malformed
  interaction or port error. Pure/deterministic — same inputs → byte-identical emitted events.
- No remote imports; lockfile mandatory; no package lifecycle scripts; no FFI/native addons.
