## Objective
Promote the compositor from a one-shot **verification self-test** to a **production long-lived daemon**.
Today the only unit is the SMOKE-only `os/x86_64/smoke-overlay/.../vita-compositor-selftest.service` (a
`Type=oneshot`, `RemainAfterExit=yes` shot that runs `vita-compositor-selftest.sh`, renders a baked
`vita-compositor-smoke.commands` file once, holds 30s, emits `VITA-COMPOSITOR`, then exits — explicitly
"not part of the production OS image"). Build a real production service:
- New **production** overlay at `os/x86_64/overlay/` (NOT `smoke-overlay/`) containing
  `usr/lib/systemd/system/vita-compositor.service` plus its `multi-user.target.wants/` (or a
  `vita-desktop.target.wants/`) symlink so it is enabled in the shipped image.
- `vita-compositor.service` is **long-lived**: `Type=notify` (preferred; the daemon calls
  `sd_notify(READY=1)` once the KMS master is acquired) or `Type=simple`, with `Restart=on-failure`,
  `RestartSec`, and `WatchdogSec` if notify. It **holds the KMS DRM master for the whole session** and
  does not exit after first paint.
- It **reads its command stream from the PSD-308 unix socket** (the live command channel), NOT from a
  baked `*.commands` file. The daemon connects/listens on the documented PSD-308 socket path, applies
  surface/reposition/present commands as they arrive, and keeps compositing until stopped.
- It is **hardened** for a privileged display daemon: `ProtectSystem=strict`, `PrivateTmp=yes`,
  `ProtectHome=yes`, `NoNewPrivileges=yes`, `ProtectKernelTunables`/`ProtectKernelModules`/
  `ProtectControlGroups` where compatible, a **minimal** `CapabilityBoundingSet` (only what KMS master +
  input needs, e.g. `CAP_SYS_TTY_CONFIG`; `AmbientCapabilities=`), `DevicePolicy=closed` with
  `DeviceAllow=char-drm rw` + `DeviceAllow=char-input r` (and the specific tty/dri nodes it requires),
  and a private/empty network unless PSD-308's socket requires otherwise (prefer AF_UNIX, no AF_INET).
  Use `RuntimeDirectory`/`StateDirectory` rather than writing ad-hoc into a shared `/run`.
- The compositor binary (`os/x86_64/compositor-core`, the existing Rust `vita-compositor-core`) gains a
  long-lived **socket-driven mode** (e.g. `--serve <socket>`) that supersedes the one-shot
  `--commands < file` path. The selftest path/flags stay intact.
- **Keep the selftest overlay** (`smoke-overlay/.../vita-compositor-selftest.service`) untouched for
  verification only; production boots the new long-lived unit, not the selftest.

Provide a small, **pure, headless TypeScript service model** under
`sdk/typescript/test/ui-kits/compositor-service-model.test.ts` (+ its implementation module imported by
the test, e.g. `ui_kits/desktop/viewmodels/compositor-service.ts`) that models the daemon's
command-stream state machine (connect → READY/notify → apply commands from the socket → stay-active →
restart-on-failure transitions) so the production behavior is unit-checkable deterministically without a
real GPU. This is the file the acceptance command runs.

## User value
The desktop survives the session. A real user's compositor stays up holding the display, applying live
window/surface changes from the running OS over the PSD-308 channel — instead of a 30-second one-shot that
renders a baked frame and exits. This is the unit that makes Vita a usable desktop rather than a boot demo.

## Non-goals
- Do NOT delete or weaken the smoke selftest overlay or its hidden boot markers — it remains the
  verification path. Do NOT bake a static `*.commands` file into the production unit. Do NOT add network
  egress (AF_UNIX only). Do NOT loosen Secure Boot / dm-verity / overlay assumptions. No new visual design.
- Do NOT re-implement the PSD-308 socket protocol — consume it.

## Acceptance
`acceptance_command` passes: `npm run typecheck` is clean and the deterministic headless service-model
test at the EXACT path `sdk/typescript/test/ui-kits/compositor-service-model.test.ts` passes (covers
connect → ready → live-command-apply → stay-active → restart-on-failure, and fail-closed when the socket
is absent). On an empty branch this exact-path test does not exist, so acceptance fails.

Additional verification (orchestrator, on the serial-boot gate — NOT part of the worker command):
`rust-in-docker` builds the compositor clean; the production `os/x86_64/overlay/` unit installs into the
image; a QEMU/wsl-verify boot shows `VITA-COMPOSITOR ... present=kms status=OK` emitted by the
**long-lived `vita-compositor.service`** (not the selftest); `systemctl is-active vita-compositor.service`
is `active` and the unit stays up past first paint; `systemd-analyze security vita-compositor.service`
confirms the hardening directives above are in effect; and the node survives all 21 boot markers.

## Security/constraints
- R3 (boot/display privileged component): two human approvals required before merge; orchestrator runs
  the R2–R4 Codex reviewer gate (`npm run review -- PSD-309`) and parallel-candidate strategy.
- Strict service hardening as enumerated (ProtectSystem=strict, PrivateTmp, ProtectHome, NoNewPrivileges,
  minimal CapabilityBoundingSet, DevicePolicy=closed + char-drm/char-input allow-list, AF_UNIX-only).
- `allowed_network: false`. No remote imports; lockfile mandatory; no package lifecycle scripts; no FFI in
  TS sandboxes. Deterministic, pure service model (no ambient I/O in the unit test).

## Hardware profiles
Borg51 QEMU/wsl-verify x86_64 guest with virtio/vmwgfx DRM (`/dev/dri/card0`); same KMS master path the
selftest exercises.

## Allowed tools / network
Local toolchain only (npm, node --experimental-strip-types, rust-in-docker for the binary). No network.

## Budget
120 worker-minutes.

## Required artifacts
- `os/x86_64/overlay/usr/lib/systemd/system/vita-compositor.service` (+ enabling `*.wants/` symlink).
- Long-lived socket-driven mode in `os/x86_64/compositor-core` (Rust), selftest path preserved.
- `ui_kits/desktop/viewmodels/compositor-service.ts` + `sdk/typescript/test/ui-kits/compositor-service-model.test.ts`.
- Boot evidence (serial log showing long-lived `status=OK present=kms`, `systemctl is-active`,
  `systemd-analyze security` excerpt) attached to the result report.

## Rollback plan
Revert the production `os/x86_64/overlay/` unit + the compositor-core socket mode; the SMOKE selftest
overlay is untouched, so verification boots continue to work and the image falls back to no production
compositor unit. Single-commit revert on `task/PSD-309`.

## Definition of done
Production `vita-compositor.service` long-lived + hardened + socket-driven (PSD-308) lands in
`os/x86_64/overlay/`; the selftest stays verification-only; the exact-path headless service-model test +
typecheck pass; QEMU boot shows the long-lived unit emitting `present=kms status=OK`, the unit stays
active, hardening confirmed by `systemd-analyze security`, and all 21 boot markers + node survival pass.
R3 — two human approvals + Codex reviewer `approve` recorded before merge.
