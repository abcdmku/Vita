## Objective
Implement the canonical **plan envelope** — the inspectable, signing-ready structure the system
database records (spec §8.2 step 5 "converted into a canonical signed plan", §8.4 "records both
source and normalized plan"). Provide:
- `PlanEnvelope` = `{ schemaVersion: number; planHash: string; plan: CanonicalPlan; createdAtRef: string }`
  where `createdAtRef` is a CALLER-SUPPLIED reference (NOT read from the clock — determinism, §8.2).
- `sealEnvelope(plan: CanonicalPlan, meta: { createdAtRef: string }): PlanEnvelope` and
  `verifyEnvelope(env: PlanEnvelope): boolean` (recomputes `planHash` from `plan` and checks it).
- A stable canonical serialization `encodeEnvelope(env): string` suitable for hashing/signing later.

Build on `CanonicalPlan`/`planHash` from P0-001. No actual signing (keys are out of scope, spec §16).

## User value
A tamper-evident, inspectable envelope is the unit that later gets signed and applied; it makes the
plan auditable and migratable (spec §8.4).

## Non-goals
- No real cryptographic signing / keys (spec §16: keys unavailable to dev agents).
- No clock/IO reads — time is passed in as `createdAtRef`.

## Dependencies
P0-001 (`CanonicalPlan`, `planHash`).

## Acceptance tests
`acceptance_command`. `sdk/typescript/test/envelope.test.ts` must prove:
1. `sealEnvelope` then `verifyEnvelope` round-trips true.
2. Tampering with `plan` (without updating `planHash`) makes `verifyEnvelope` return false.
3. `encodeEnvelope` is deterministic (same envelope → identical string).

## Performance & security constraints
Pure/deterministic, no I/O. `node:crypto` built-in only. Fail-closed verification.
