## Objective
Headless, deterministic **view-model** for the flagship desktop's `Lock` screen, built ONLY on `@vita/desktop-sdk` public ports
(the auth/session/passkey port (owner passkey, P1-069) or a minimal injected AuthPort) — injected ports, NO platform internals, NO DOM/rendering (pure interaction logic the rendered design binds to later).
- State: lock state (locked/authenticating/unlocked), user, error/attempt count, clock display. Actions: submit(credential) -> authenticate via the port, cancel(), tick(now) for the clock (injected). Deterministic; NEVER store/echo the raw credential (pass-through to the port only); fail-closed + rate-limit attempts. Mirrors Lock.html.
- Code under `ui_kits/desktop/viewmodels/Lock.ts`, tests under `sdk/typescript/test/ui-kits/Lock.test.ts`. Import the SDK exactly as `ui_kits/desktop/package.ts` does; ONLY public exports.
- If the SDK lacks the exact port, define a MINIMAL injected port interface in the view-model module (typed, fail-closed) that a later slice implements — the view-model must be fully testable against a fake of that port now.

## User value
Turns the static `Lock` mockup into real, testable desktop behavior on the SDK — the logic the CEF-rendered HTML hydrates against.

## Non-goals
- NO DOM/CSS/rendering/CEF. NO platform internals. NO new visual design. Don't re-implement SDK ports — consume them.

## Acceptance
`acceptance_command` passes: deterministic unit tests cover the described state transitions + fail-closed paths against fake ports; typecheck clean. Pure, headless.

## Security/constraints
- Injected ports only (no ambient I/O); capability-mediated, fail-closed; pure/deterministic. No remote imports; lockfile; no lifecycle scripts.

## Definition of done
- `ui_kits/desktop/viewmodels/Lock.ts` + `sdk/typescript/test/ui-kits/Lock.test.ts`, deterministic, typecheck clean. R1.
