## Objective
Prove the **Phase-5 exit gate** (spec §21 Phase 5, line 1152: *"Complete node restore succeeds from independent
backup."*, FR-015): restore the node's **ENTIRE authoritative persistent data set in one operation, onto a
fresh/empty `/var`**, integrity-verified before any byte is applied, atomic / all-or-nothing. P1-066 (MERGED) gave us
`backup.archive` `create`/`verify`/`restore` — but its `restore` materialises a backup into a SINGLE side
`destinationRoot` directory (each manifest root becomes a sub-dir of one destination), which proves round-trip
integrity but does NOT prove the exit-gate scenario: re-hydrating a clean node where each authoritative root must land
back at its OWN canonical path (`/var/lib/vita/runtime/volumes`, `/var/lib/vita-agent`, …) and the node is otherwise
empty. This slice adds that "full node restore" operation.

Add a NEW closed operation to the EXISTING `backup.archive` capability (do NOT add a new capability; do NOT change
`create`/`verify`/`restore` behaviour, the manifest format, the object store, or `backup.policy`): **`restore-all`**.
Thin vertical slice — one fresh-node full-restore round-trip + the fail-closed rejects. Put the new code in a NEW file
`agent/capabilities/backup/restore_all.go` (a `//go:build linux` file mirroring `archive.go`, with a matching
`!linux` arm appended to the existing `archive_unsupported.go` so cross-platform `go build` stays green) and reuse
`archive.go`'s helpers verbatim (`verifyArchive`, `loadArchiveManifest`, `materializeArchive`, `treeMatchesManifest`,
`renameExchange`, `syncTreeDirs`, `archiveStepError`/`archiveStepPathError` step+errno discipline,
`normalizeAbsolutePath`, `normalizeDigestToken`, `normalizeArchiveSourceRoots`, `containsInlineSecretMaterial`).

`restore-all` semantics (extend the typed `ArchiveApplyRequest` with `Op:"restore-all"` + an optional
`RestoreAll *ArchiveRestoreAllRequest` arm; exactly-one-arm rule stays enforced):
- **Request:** `{ targetPath, backupId, rootMappings: [{ name, path }] }` — `targetPath` is the independent backup
  store (validated absolute), `backupId` the content-addressed id (`normalizeDigestToken`), and `rootMappings` maps
  EACH manifest root NAME to the absolute authoritative destination path it must be restored to (validated absolute,
  pairwise non-overlapping, none overlapping `targetPath`, reuse the `normalizeArchiveSourceRoots`/`pathsOverlap`
  discipline). `rootMappings` MUST cover EXACTLY the set of roots recorded in the backup manifest — a missing or extra
  root name is a fail-closed reject (a full restore must be total, never partial). If `rootMappings` is omitted, the
  capability uses a CLOSED built-in default map (the canonical authoritative roots:
  `capsule-volumes → /var/lib/vita/runtime/volumes`, `vita-agent → /var/lib/vita-agent`) — but the mapping set must
  still EXACTLY match the manifest's roots or reject.
- **Verify FIRST (no partial trust):** call the existing `verifyArchive` (recompute every content digest + the
  manifest digest + backup-id match). ONLY if it passes does ANY destination get touched. A tampered/bit-rotted/
  unknown backup ⇒ REFUSE, mutate NOTHING (fail-CLOSED).
- **Fresh-node precondition (encode it):** each mapped destination root must be ABSENT or EMPTY (a clean `/var`). If
  any destination root already contains data, REFUSE with a specific reason (`restore_all_destination_not_empty:<root>`)
  rather than overwriting authoritative live data — "complete restore onto a fresh node" is the gate, not an in-place
  clobber. (The marker driver provisions fresh empty dirs to exercise the success path.)
- **Atomic all-or-nothing across ALL roots:** stage the COMPLETE restored tree (every root) under a temp staging dir,
  `materializeArchive` it, re-confirm the staged tree matches the manifest (`treeMatchesManifest`), `fsync`
  (`syncTreeDirs`), THEN commit each root into place with the proven single-commit-point rename/`renameExchange`
  pattern. If any root fails to commit, the `Undo` rolls back EVERY already-committed root so the node is left as it
  was found (no half-restored authoritative state) — exactly two outcomes: all roots restored (with a working Undo) OR
  nothing changed. Reuse `archive.go`'s `archiveRestoreUndo`/`renameExchange` discipline; the multi-root undo composes
  the per-root undos in reverse.
- **Idempotent re-restore:** if every destination already byte-matches the manifest (`treeMatchesManifest` true for
  all roots), succeed as a no-op (so a re-run on the boot is stable).

Set `c.last` to an `ArchiveStatus{Op:"restore-all", BackupID, Files, Restored:true, Verified:true, Status:"OK"}` so
the TS driver reads a MEASURED status (mirror the existing `restore` case in `Apply`). Register nothing new (the op
routes through the already-registered `backup.ArchiveName` decoder in `agent/transport/server.go:504`).

**Markers (emitted on-device by `main.ts`, MEASURED — never synthesised):** on a real backup→full-restore round-trip
(create a backup of TEST authoritative roots, then `restore-all` it onto FRESH/empty TEST destination roots under
`/var`, and prove the restored bytes hash-match the manifest for every root), emit
`VITA-RESTORE-FULL: restored=OK verified=OK volumes=<N> id=<digestPrefix> status=OK`
ONLY when verify passed AND every mapped root was restored AND the restored entries hash-match the manifest digests
(N = number of restored roots/volumes). Plus a fail-closed reject
`VITA-RESTORE-FULL-REJECT: reason=<sanitized-step> status=OK` for a forced-invalid case (a `restore-all` of a TAMPERED
/ wrong-id backup MUST refuse and mutate nothing), and `VITA-RESTORE-FULL-ERROR: status=FAILSAFE` on transport/setup
failure with a SPECIFIC `reason=<step+errno>` (the P1-066 diagnosability lesson). Keep ALL prior markers (the
VITA-TS→EVAL→PREVIEW→EXPLAIN→CONNECT→STATE→APPLY→CAPSULE-*→PDS→FILES→BACKUP chain) intact, and emit VITA-RESTORE-FULL
AFTER the VITA-BACKUP markers in the boot sequence.

## User value
The owner can lose a node entirely (dead disk, stolen device) and bring the WHOLE thing back from an independent
backup onto fresh hardware/clean storage: every capsule's state volume, the PDS sync cursor, and the node config land
back at their real paths, integrity-guaranteed (a corrupted backup is refused, never silently restored), with the node
left untouched on failure. This is the literal Phase-5 exit gate (spec line 1152, FR-015) and the backend the Restore
UI drives. It closes the loop opened by P1-066 (backup + side-restore) into a provable disaster-recovery story.

## Performance & security constraints
- **Security model (encode it):** the TS runtime is UNPRIVILEGED; ALL privileged FS mutation (reading the backup
  store, staging, the per-root rename-swap onto the authoritative paths) belongs ONLY to the narrow Go `agent`. agentd
  acts ONLY from a RE-VALIDATED typed request (validated absolute target/backupId/rootMappings, exact-coverage check)
  — NEVER from raw runtime text used as a path/command. `restore-all` is a CLOSED named op; unknown/invalid ⇒
  fail-CLOSED reject. The runtime never receives raw FS access.
- **Verify-before-apply, fail-CLOSED:** integrity (content-addressed SHA-256 + manifest digest + backup-id) is
  recomputed and MUST pass before any destination is touched; a tampered/bit-rotted/unknown backup is detected and
  REFUSED, never silently restored. Any validator over the request REJECTS malformed/cyclic/partial shapes — never
  throws at the trust boundary (a throw is a DoS); prove with a malformed/cyclic regression.
- **Atomicity / single commit point (R3, AGENTS.md §2):** stage the full tree → fsync → per-root rename/exchange as
  the only commit points; no fallible step after an irreversible effect; multi-root rollback Undo composes per-root
  undos so the node is either FULLY restored (with a working Undo) or UNCHANGED — never mutated-but-reported-failed.
  Prove the partial-failure no-mutation case.
- **Fresh-node precondition:** destinations must be absent/empty (no clobber of populated authoritative roots);
  totality enforced (mappings exactly cover the manifest roots).
- **No secrets:** reuse `containsInlineSecretMaterial` on every string entering the request/metadata; NO real keys/
  TPM/recovery/signing material generated or committed (owner-held §16) — TEST data only. NO remote imports; vendored
  deps only; lockfiles mandatory; no package lifecycle scripts; offline.
- **Determinism:** restore is driven by the canonical manifest; the same backup yields the same restored tree.
- R3 (privileged TCB FS mutation of ALL authoritative node data) → reviewer gate (`npm run review -- P1-085`) +
  independent host-verify before merge.
